# 任务 PR 双审查

双审查是本 skill 的正式任务 PR 审查流程，审查前读取本文件。
本文件维护角色、输入隔离和复核规则，GitHub 交付及状态契约仍
按 [github-delivery](github-delivery.md) 与 [workflow](workflow.md) 执行。
适用于任务 PR 的生产代码、测试基础设施和可执行行为契约变更，包含 pr_only 和
auto_merge；纯拼写/排版只做相关检查，沿用原 PR 独立审查要求，不强制双角色。
local 或 no_change 不因双审查流程新增 PR 审查。只修改本 skill 不启动网站任务。

## 首轮输入与隔离

实现并自测后停止源码写入，固定同一 PR base/head、候选 manifest 和完整差异。
两个不同的新上下文分别承担测试有效性、缺陷审查，均不得是主控或实施者；
首轮不继承作者推理、自评或另一角色结论。PR 描述中此类内容须从委派输入裁去，
保留原始需求、已确认决策、变更事实和可复查的原始证据。

默认在当前工作区串行审查，复用构建缓存；每次只读源码，报告写各自私有路径。
两次首轮前后核对实际 base/head、工作区差异与构建身份。期间源码变化时，先固定
新候选再补受影响审查；不得把不同候选的两份报告拼成同一首轮。
不为上下文隔离创建 worktree，也不在审查期间让实施者并行修改源码。

委派包包含以下内容；两个角色获得相同原始输入，角色职责按下节分别附加：

```text
角色：测试有效性 Agent / 缺陷 Agent（二选一）
原始用户任务、验收条件、规范/公开契约、已确认决策：<原始引用>
任务 ID、repo/PR、base/head、candidate manifest、完整差异：<精确身份与路径>
允许读取范围、只读工作区、独立报告位置：<路径>
现有测试入口、原始验证证据、环境/构建身份：<引用>
阶段、剩余预算、本步上界、返回位置：<首轮只读 / 定向复核>
首轮不得读取作者自评、其他角色报告或评测答案；未运行的检查写未验证。
```

测试角色先读取原始需求和契约并记录行为预期，再读取实现、diff 和测试。
任一角色能力不足或预算不足时保留缺口，不把主控换角色名称当独立审查。

## 两个角色的职责

**测试有效性 Agent**

- 从用户任务和规范推导重要行为；检查成功结果、相关失败/恢复、状态转换和副作用。
  审查断言能否发现错误、mock 是否绕过变更边界、测试是否实际执行且产物新鲜，
  不把退出码、调用次数、帧序号或截图存在当作充分结果。
- 对照实际风险选层级：规范语义用常驻 WPT/reftest；IPC/生命周期核对新鲜 peer
  binaries 和恢复路径；存储/权限验证拒绝后无副作用及失败不丢数据；热路径保留
  同条件性能与正确性证据。沿用入口要求的 Rust 全量门禁与适用生产 parity，
  不用双审查替代 GUI/GPU、状态、事件、几何及像素验收。
- 返回短表 `行为/风险 | 实际断言 | 证据 | 通过/缺口/未验证`。
  Bug 回归优先检查旧错误实现因目标行为失败、修复后通过；编译失败不冒充行为失败。
  无旧版本时可按具体风险做少量有目的的行为破坏检查，不设全量变异或覆盖率门槛。

**缺陷 Agent**

- 沿变更及受影响调用链、生命周期和并发时序寻找可成立的错误，不扩为全仓巡检。
  每项阻断发现给出 `触发条件 → 预期 → 实际 → 代码/执行/完整时序证据 → 用户影响`。
- 主动检查已有上游校验、锁、事务、取消和恢复保护，尝试推翻自己的发现。
  难稳定复现的竞态可用完整时序举证并注明未运行；按已证明影响定级。
- 返回已查/未查范围及发现。风格、无依据的重试/缓存/兜底建议、无关旧问题单列，
  不当成阻断项；罕见但有证据的权限或数据风险不能因发生率低而忽略。

## 修复、复核与回执

两份首轮均归档后，由主控安排单写入者串行修复。测试角色可以另领补测试任务，
默认不改生产语义；失败交实现者修根因，不把预期改成当前错误行为。
每个生产、测试及辅助补丁均由非作者定向复核；通常测试角色核验生产修复的行为，
缺陷角色复核测试补丁。角色写过该补丁时换未编写者，不能自行签字。

补测试同样属于 implement operation，记录实际作者。最终汇总 reviewer 须满足现有
检查器的独立身份要求：不是主控，也未作为该运行的任何 implement 执行者。
优先复用没有写过补丁的首轮 reviewer；两者都参与实施时才另派新上下文汇总复核。
汇总者读取两份首轮、发现处置和非作者复核证据，不仅转抄两个结论。

每次首轮、定向复核及必要的汇总沿用独立 review operation，串行保存
intended/running/completed 和原报告；角色与阶段记在 result 报告，不新增 operation kind。
只在汇总完成后更新 delivery.review；首轮即使无发现也不能单独作为交付 PASS。
恢复先核对已有 operation 和原始报告，只接续缺失部分，不重复首轮或覆盖历史。

汇总沿用 workflow 的 review schema，通过 artifacts 引用两份首轮及必要复核记录。
证据写明实际角色 ID、受审身份、行为与断言、发现及处置理由、补丁作者/非作者复核者、
修复前后结果、实际门禁及未验证范围。最终回执绑定当前 head/base/manifest；
旧报告保留原身份，新增差异由非作者复核并重跑受影响验证，不能改旧 SHA 冒充新执行。
不新增账本或修改 checkpoint。检查器解析现有 artifacts，核对以下字段及 operation；
主控仍须核验上下文隔离、输入包和报告内容，不能以结构通过代替真实执行。

### 可检查的报告字段

每份首轮和复核使用 JSON：保留 schema_version=1、task_id、五项 PR 身份、
subject、reviewer、verdict、open_findings、artifacts；另含：

- `stage: "first" | "recheck"`，`role: "test_validity" | "defects"`。
- `candidate_manifest: {path,sha256}`，subject 等于此摘要；清单的 source_sha/base_sha
  与报告一致、dirty_patch=null。artifacts 引用原始输入/派发完成记录及实际审查产物。
- recheck 的 `from` 保存原双首轮的五项 PR 身份和 subject；
  `covers_operations` 列出此次已复核补丁的 implement operation ID。每个返修操作
  都须在非作者复核之前完成。复核绑定当前候选，并检查原首轮到当前的完整差异；
  只改 base/head、没有新增 implement 时也需复核，covers_operations 可为空。

汇总保留原公共字段并增加 `stage: "summary"`、`review_scope: "dual"`，artifacts
引用同候选两份首轮及当前复核。存在发现时加 `resolution_ref`，指向处置及验证证据。
每份报告及汇总都必须是对应 completed review operation 的 result，执行者须一致。
artifacts 还可引用原始日志、Markdown 等附件；这些只校验摘要，不当作角色报告解析。
operations 按真实派发顺序追加；首轮之间不得夹入实施。历史报告保持不可变，
新汇总可引用原首轮，但不能将旧复核改绑当前版本。无发现无需制造补丁或复核。

纯拼写/排版沿用单独汇总，`review_scope: "editorial"`，另给 `scope_reason` 和
`scope_evidence`（完整 diff 的证据引用）；独立汇总者、完成 operation 仍必需。
主控核对确属纯文字，不能凭此字符串豁免规则、脚本或产品行为变更。
旧运行缺字段时保留原报告及宿主记录；没有证据则保持未完成，不把已发生的旧 operation
重写成新报告。需要适配时，另记实际核验旧报告的 review operation，在新报告的 artifacts
引用原摘要，按原预算完成缺失角色和汇总。已 done 或升级前已确认合并的历史任务不补造
新审查；按 workflow 的相邻快照兼容规则保留，并披露 legacy_delivery_tasks。
尚未交付的任务须补齐新契约，不以跳过 previous 或伪造成功绕过。

只阻断本次引入/加剧的已确认缺陷、重要行为缺少必要证据和相关测试失败。
高后果风险有具体线索但缺关键证据时保留未完成；建议及已证伪项保存处置理由，
不放入未解决阻断清单。一项有证据的缺陷不能被另一人的“无发现”抵消。
默认一轮双审查加一轮定向闭环；仍有阻断项就处理该项或保留未完成，不因轮数到达通过，
不追求连续多轮零发现。范围重大变化导致原判断失效时才扩大审查。
复用输入未变化的有效测试；新候选仍按既有版本门禁核验，预算耗尽按原停止契约收尾。

在 run.md 记录各角色独有的已确认发现、误报处置、实际审查/测试耗时与后续漏出。
无发现允许无补丁结束；未知耗时不估造，不以测试条数、评论数或“两票通过”证明收益。
