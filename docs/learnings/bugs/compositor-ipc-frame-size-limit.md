# Compositor IPC 合法帧超过通用管道上限

- 日期：2026-08-14
- 相关模块：`crates/protocol`、`apps/browser`、`apps/compositor`

## 问题描述

Compositor 正常启动后在第一帧退出，日志显示收到约 20.8 MiB 的消息，但通用管道只允许 16 MiB。Browser 随后遇到 broken pipe 并回退到 legacy frame publishing。

## 根因分析

16 MiB 上限建立时 IPC 只承载较小的控制消息。后续 `CompositorFrame` 开始携带完整绘制快照，其中包含解码图片的 RGBA 像素，但协议上限没有随消息模型更新。发送端也没有执行同一上限检查，因此无效帧会先写入管道，再由接收端断开连接。

## 解决方案

将仍然有界的管道消息上限提高到 64 MiB，以容纳当前绘制快照和单张 4K RGBA 帧；发送端和接收端复用同一校验，避免不对称断连。测试锁定实际观测到的 21,797,029 字节合法帧，并继续拒绝超过 64 MiB 的长度。

更大的像素载荷不应继续通过抬高管道上限解决；需要支持 8K 或大量图片时，应将图片像素迁移到共享内存，只在 IPC 消息中传递描述符。
