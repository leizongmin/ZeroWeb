# 编译断窗落库的钉测首执即 DOA——断言必须以实证行为为准

## 问题描述

共享树多流并行期间，引擎钉测随机制码落库，但 `zero-engine` lib test 因对端在飞件断编译（`part116` include! 悬空），钉测从未执行。编译恢复后补跑，同模式连续两例首执即失败（DOA）：

- 刀 A1c 双钉（`test_allow_discrete_registers_discrete_pair` / `test_allow_discrete_keyword_endpoints_flip`）：s560 全桥窗（b560.k）首次执行暴露 2F，由 html-semantics 流代修（4d82f45e4 提交消息在册「刀 A1c 双钉 DOA 有效值断言适配」）。
- 刀 B1 `test_border_image_width_lerp`：补跑首执 1F——断言写 `10%→20px at(0.3) → "10%"`（按早期设计意图「跨型离散翻转」推演），而 v3 终版实现契约是 t≠0 跨型走 echo 保留门返回空串（电池 REG=0 实证）；修复即对齐实证契约并补 at(0.0) 翻转位断言。

## 根因分析

钉测断言在「实现被电池验证之前/之外」凭设计意图书写，且落库后长期无执行窗：编译断把整条验证链切断，错误断言以「已在册」状态潜伏。提交时的挂账措辞（「钉测待补跑」）掩盖了断言本身未经验证的事实。两例中实现都是对的（语料电池面已验证），错的是钉测——但若顺序相反（实现错、断言对），DOA 就会变成真回归潜伏。

## 解决方案

- 钉测随码落库但**从未执行过**时，提交消息必须显式标注「钉测从未执行」，编译恢复后的第一个窗口补跑，并预期首执暴露问题。
- 断言书写以**已验证的实证行为**为真值源（corpus 电池结果、单页探针 JSON），不凭设计推演；推演断言（如 at(0) 翻转位）补写后必须立即运行验证而非直接落库。
- 共享树编译断期间新写的钉测，修复时优先补「契约两端」断言（正常位 + 边界豁免位），一次锁定完整契约。
