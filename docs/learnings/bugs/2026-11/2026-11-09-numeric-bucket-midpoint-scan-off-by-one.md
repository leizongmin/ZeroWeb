# 数值分桶中点扫描在整档值上系统性差一档

## 问题描述

F6b 刀（sub/sup×fontsize carry）中 `__zw_f6b_bucket_of` 用中点扫描把 px 归 7 个档位（10/13/16/18/24/32/48）。整档输入系统性错桶：`bucket_of(16)` 归档 2（应为 3）、`bucket_of(13)` 归档 1（应为 2）。capture 侧把实测 px 映射成 `size` 档位后回放时，凡整档值全部掉一档，16 案 probe 中多案复现桶漂移。

## 根因分析

原实现按 `px >= (lo+hi)/2` 逐档推进。整档值恰等于某档边界，而中点在它与下一档之间——条件在到达本档前已满足更早档的推进，即 `(10+16)/2 = 13`，`px=13` 时第二档条件 `13 >= 13` 成立便停在档 2，永远到不了档 3。这类"扫描条件含等号 + 分界取中点"的组合对恰好落在分界上的输入必然偏移一档；非整档值（10.79、13.28）反而常被浮点噪声掩盖。

## 解决方案

改为最近距离式：遍历 7 档取 `|px - bound|` 最小者，整档值距离为 0 必然归本档（`crates/engine/src/js_dom_shim/part01.js:9623`）。教训：分档逻辑不要用"跨过中点即升级"的扫描写法，直接最近邻比较在边界值上更稳；fixture 设计须显式含每个整档值，只有整档值能暴露这类差一。
