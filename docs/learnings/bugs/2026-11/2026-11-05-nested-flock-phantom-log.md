# 嵌套 flock 同锁致内层 -n 静默跳跑，复跑判读读到幻影旧账

## 问题

门禁复跑「无变化」假象：外层 `flock <lock> bash -c '… bash self-flocking-script.sh …'` 调用自带 `flock -n <同一锁>` 的脚本时，内层非阻塞加锁因外层持锁必然失败并静默退出（脚本继续执行后续 echo，制造出跑过的假象），目标日志根本未生成；后续判读 `cat` 旧日志文件，把修复前的旧账当作本轮复跑结果，连续两轮误判「修复无效」。

## 根因

flock 锁与 open-file-description 绑定：外层 flock 工具进程持有锁期间，内层新开的 fd 无法再获锁；`-n`（非阻塞）使内层立即放弃并跳过被包命令，无报错无日志。bash -c 子进程不继承可解锁的外层 fd，语义上就是两个独立竞争者。

## 解决

- 判读任何日志前核对 `stat -c %y <log>` 晚于本次源码/页面变更时刻；mtime 早于变更 = 幻影，结果作废。
- 自 flock 的脚本不得再被外层同锁 flock 包裹；批量串行用一层锁（脚本自带），或在批内直接内联被包命令而不复入脚本。
- 计数证据用日志行数与行名核对（rows= 段），不仅看退出码。
