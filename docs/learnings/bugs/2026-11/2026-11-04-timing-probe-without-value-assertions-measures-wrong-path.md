# 计时探针不带值断言会测到错误路径——「便宜读数」可能是零矩形快速回落

## 问题描述

dom-ops 热点归因（2026-11-04）：探针脚本 probe8 的写+读微基准两轮都测得 ~12-30µs/op（便宜态），而同一二进制、同一 fixture、同形代码在 15+ 个其他臂（含两个与 probe8 执行序逐步一致的复刻脚本）全部 ~13-21ms/op（昂贵态，与基准 12.4ms/op 一致）。便宜态无法归因到任何已识别代码路径。

## 根因分析

probe8 的计时断言只测时长、不测返回值：若读走的是错误路径（如失效句柄的零矩形快速回落、no-op 写不进队列），读数同样「便宜」且计时器无法区分。跨脚本不可复现说明该态与脚本身份携带的某种状态相关（领先假设：前序 evaluate 的 drain+apply 后句柄/队列状态），黑盒 bisect（setup/timer 间隙/队列长度/脏元素数/前序子场景/evaluate 序数/机器负载）全部排除仍无法定位。本次处理：按 ≥3 次规则将不可复现的便宜读数**降级为未解决异常，不作为归因依据**——昂贵态 20+ 次复现、有代码路径、有值断言（33px/24px 正确）、有墙钟交叉验证，归因成立。

## 解决方案

probe8f 补齐了缺失的断言维度：Node 侧 evaluate 墙钟（验证逐 op 计时合计 ≈ 墙钟，成本确在读内而非未计时邻区）+ 读值断言（rect.width 应为 33px/24px 而非 0/stale）。昂贵态在此双口径下自洽。

## 如何避免

- 计时探针的每个测量点必须同时断言**返回值语义**（几何读断言矩形非零且随写变化；替换读断言子树身份），时长+值双断言才能证明测的是目标路径——单独的时长断言与「测到了更快的错误路径」不可区分。
- 探针结论要求跨脚本复现（≥3 次、含执行序复刻），只在单脚本内可复现的「好数字」按噪声处理；写探针时给关键读数补值采样（哪怕只采首尾 3 个）。
- 逐 op 计时要配 evaluate 总墙钟：若两者量级不符，说明成本落在未计时邻区（如写侧延迟失效），per-op 剖面会系统性误导归因。
