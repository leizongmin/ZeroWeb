# 在飞批脚本冻结纪律与裸腿日志独立判读：脚本文件被并发改写后 bash 按偏移错位执行，批内判读行不可作终态依据

## 问题描述

多席共用 `.acceptance/dps/` 时，同一批脚本文件名被并发席以 `sed >` / heredoc 重写（本例 v1-v5 五连异常：截断为 0 字节、内容被换、同名额发射）。bash 逐块读脚本、fd 偏移随执行推进，文件被改短后偏移落在错位字节，残片当指令继续跑或静默终止；若终态判读转抄批内打印的 judge 行，等于把被污染的执行流当证据。

## 根因分析

- bash 对脚本文件持有打开 fd，读进度是字节偏移；改写（尤其截断）后偏移处内容与原语义无关，产生"脚本看似还在跑、实际执行的是碎片"的幻觉态。
- 批内 judge 行与腿数据若同源于被改写脚本，其输出不可信；腿命令的标准输出若落回脚本所在管道，同样被截断波及。
- 长批期间 docs-only 提交照常落库，按完整 commit hash 锚定的 `chk_head` 会把无关提交判为域漂移而 ABORT（v2 死因）。

## 解决方案

- **在飞文件冻结**：批发射后任何人不得改写同名脚本；发现被改即按协议停批、换新随机名重射，不原位续跑。
- **腿数据与脚本解耦**：每条腿命令直写独立腿日志（如 `ipm3-c6c3-v6-ip.log`），数据完整性不依赖脚本文件存活。
- **终态独立重算**：验收判读一律从裸腿日志重做（行恒一 + F2P/P2F/lost/newF 计数 + 白名单恰等 + judge-dps 漂移门），批内 judge 行仅留痕不作依据；多席各算一遍互为复核。
- **子树哈希锚**：锚定用 `git rev-parse HEAD:crates`、`HEAD:wpt-data` 等子树哈希而非 commit hash，docs-only 提交不再触发假 ABORT；发射前 flock 仲裁 + EXPECTED_HEAD 重锚。
- 例证：v6 批五腿全绿后，验收由核验席从六份裸腿日志独立重算（ip 7195 行恒一 F2P=4 恰等、ab 10092/0/0、mt/ilb judge-dps 零漂移、enginelib 4032P/0F 空册），与批内判读逐项吻合，脚本文件此后被改写也不影响定谳。
