# 表单控件事件链不能依赖渲染缓存

- 日期：2026-08-11
- 相关模块：`host-runtime`、`apps/browser`、`apps/renderer`、`crates/engine`

## 问题描述

通过 `scripts/browser.ps1` 启动多进程 GPU 浏览器后，表单输入框无法可靠获得焦点或输入文字，按钮点击也可能无效。早期测试只断言“渲染快照序号增加”，空白首帧或无关重绘也能满足该条件，因此出现了测试通过但功能仍不可用的假阳性。

## 排查结论

Windows 鼠标坐标不是根因。winit 提供物理坐标，浏览器按内容区原点和 DPI 缩放转换为 CSS 逻辑坐标；真实渲染子进程测试已覆盖 100%、125%、150%、200% 缩放，输入框与按钮均能命中预期目标。

实际存在七个连续断点：

1. 页面 `mousedown` 和后续 click 状态错误地依赖 glyph 缓存。合成器首帧尚未同步 glyph，或页面几乎没有文本时，DOM 指针事件会被直接跳过。
2. 页面键盘事件仅转发单字符键，Backspace、Tab、Enter 等没有进入渲染器默认动作；渲染器多进程路径也缺少与单进程一致的输入、焦点、复选框、单选框、重置和提交默认行为。
3. 命中元素没有 `id`/`class` 时，事件选择器退化成标签名。多个 `<button>` 都得到 `button`，`querySelector` 永远选择第一个按钮，导致无 id 的重置和提交按钮被派发给错误目标。
4. 鼠标释放是否生成 click 错误地依赖文字选区是否折叠。控件内轻微抖动会改变 caret 命中并吞掉 textarea/button 激活。
5. 页面 IME 事件在浏览器主进程只允许地址栏和查找框，页面焦点路径直接返回，中文 commit 完全丢失。
6. 渲染进程把 live DOM mutation 增量渲染后，又调用 `reload_html_after_script` 重复做一次全量解析和布局，每个按键承担两遍渲染成本。
7. input value 的 baseline 固定为内容盒顶部加 font-size，没有计入 line box 剩余高度，带 `line-height` 的控件文字明显上偏。

Git 追溯显示坐标转换与页面输入处理最初来自 2026-06 的浏览器输入实现，后续多进程/合成器切换保留了对浏览器侧渲染缓存的隐式依赖；唯一选择器能力已经存在于 DOM bridge，但命中测试路径没有复用。

## 解决方案

- DOM 指针事件始终按页面坐标派发；glyph 仅用于可选的文本插入符/选择计算。
- 浏览器命中缓存缺失时把真实文档坐标交给渲染进程命中，不再静默丢弃事件。
- 完整转发页面 keydown/keyup，并在渲染进程执行文本输入、删除、焦点、选择控件、重置和提交默认动作。
- 命中快照携带 DOM bridge 生成的唯一选择器；无 id/class 的歧义元素使用 `nth-child` 结构路径，并跨 IPC 保留。
- click 用同次按下/释放的移动距离阈值判定，文字选择只负责选区，不再决定控件激活。
- 页面 IME commit 以一个文本批次发送到当前事件目标，整段中文只做一次 DOM mutation 和帧发布。
- live DOM 已完成增量渲染时直接发布快照，禁止再次 reload/reparse；input baseline 在内容盒中垂直居中。

## 自动验证

- 真实示例页输入 `A` 后，精确断言 `#name.value == "A"` 且结果文本为“输入事件：A”。
- 精确断言普通按钮、无 id 的重置按钮、无 id 的提交按钮分别触发对应页面结果；提交事件必须被 `preventDefault()` 阻止。
- 扫描真实示例页布局，断言三个按钮拥有三个不同且可命中的事件选择器。
- 启动真实 `zero-renderer.exe` 子进程，经 compositor IPC 在 100%、125%、150%、200% DPI 下，将逻辑命中点转换为物理窗口坐标并走带 1px 抖动的完整按下/释放状态机，断言目标分别为 `#name`、`#note` 与 `#click`；向 `#note` 提交“中文备注”后必须产生新帧。
- 精确断言一次批量写入后 `#name.value == "A中文"`、`#note` 文本为“第二个输入框”，以及 input glyph baseline 位于内容盒垂直中心。
- 不再把“快照序号变化”单独视为交互成功；必须同时验证目标身份和最终 DOM 状态。

## 如何避免

页面交互的必要条件只能是 DOM、布局命中和事件状态，不能是 glyph、绘制图元或某一帧缓存是否存在。跨进程行为必须在渲染进程默认动作层和最终 DOM 层各有断言；涉及重复标签的事件目标必须使用文档内唯一身份。
