# CPU path_fill 无 AA 保守光栅化——亚像素贴边曲线放大成整像素差

## 问题

R5179 corner-shape：`superellipse(-100)`（深凹 K，n=200）的凹曲线对 notch 阶梯的
真实偏差 ≤ 0.38px，ref（clip-path 两层叠）与 test（shaped ring）几何逐点一致，corpus
却差 204px（全 >120 通道值）；8→16 段加密采样零改善。

## 根因

CPU 管线的 path_fill 光栅化**无 AA、按「像素矩形与多边形相交即全填」的保守语义**。
深凹曲线采样折线沿阶梯腿悬停在真阶梯 ±0.26px 内（T^(1/n) 参数化在 T∈(0,1) 全程
贴腿但不重合），每行都有一条亚像素 sliver 落进边界外侧的相邻像素 → 整像素被填上
边框色/背景色，表现为**腿位整体位移 ±1px**。对照组：clip-path 渲染走带覆盖率的
软边路径（39%/61% 混合像素），同一几何差一个光栅化器。

判别方法：dump PNG 后沿腿做 run-length 扫描——**全填（255,0,0 无混合）= 保守填充；
出现中间色 = 有 AA**。注意 reftest dump 的 ref 也由本引擎渲染，两侧行为差只能说明
「两个渲染路径不自洽」，不能直接归因 ZW vs chromium。

## 解决

几何层收拢：深凹 K（n ≥ 64，曲线对阶梯偏差 ≤ r·√2·(½−2^(−1/n)) ≈ 0.38px @ r=25，
低于 8 段圆弧弦高容差 ~0.049r）直接输出 notch 阶梯折线（helpers.rs `R5179` 注）。
加密采样不解决问题（径向系统偏差不是弦高），修光栅化 AA 是独立大工程。

## 避免

- CPU path_fill 上渲染**任何**与整数坐标不重合的曲线/斜边，都要预期 ±1px 整像素
  溢出；WPT ref 若是 clip-path/精确折线，把几何收拢到与 ref 相同的折线是最小修。
- 调「差几个像素」之前先跑 run-length 扫描判定光栅化语义，再决定是改几何还是改
  光栅化器。
