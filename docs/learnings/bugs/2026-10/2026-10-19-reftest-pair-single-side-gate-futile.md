# 配对型 reftest 单侧门控无法恢复双侧一致

## 问题

R5183 修形角 `%` 半径解析（`length_to_f32` 把 Percentage 当 0）后，
corner-shape-backdrop-filter 配对翻红 3.11%：ref 侧（无 backdrop-filter）开始
正确成形，test 侧元素带 `backdrop-filter: brightness(0)`、其滤区仍是矩形，
黑色矩形溢出形角外。为保零新红，尝试在半径解析处加「元素带 backdrop-filter
则回退旧行为」的单侧门，结果 corpus 持平、双案仍红。

## 根因

WPT reftest 的判定单位是 **test 与 ref 两页渲染结果的像素差**，不是单页的
绝对正确性。门控只作用于 test 侧命中的元素属性；ref 侧页面没有该属性，门
永不触发。于是修复使 ref 成形、门使 test 保持方角——两侧朝相反方向变化，
配对从「双侧同错自洽一致」变成「一侧修复一侧未修」的必失配。3.11% 的差
恰好就是四个角上方角与形角的面积差。

推论：只要一个渲染缺陷被 self-source corpus（test 和 ref 都由本引擎渲染）
的双侧同错掩盖，任何「只让 test 侧回到旧行为」的门都无法恢复一致性。可行
方向只有两个：双侧同修到一致（本例 = 实现滤区形状裁剪），或整体回退。

## 解决

删掉单侧门，给 `FilterPrimitive` 加 `clip_polygon`，CPU 光栅侧快照-恢复式
多边形裁剪，engine 对形角元素发射形角轮廓滤区。双案真翻绿（0.01–0.02%，
AA 边缘差在 WPT fuzzy 容差内）。

## 避免方式

遇到 self-source 掩盖型翻红时，先画两侧的预期渲染对照（各侧会不会被候选
方案影响），确认「双侧一致」这个不变式在方案下成立，再动手。单侧门只适用
于「缺陷本身只在单侧出现」的场景，不适用于「修复改变了双侧平衡」的场景。

## 附：批量探针必须逐页独立输出

同轮第二坑：多页隔离渲染循环共写 `product-smoke-cpu.png` 且渲染失败被吞，
读到前一页的内容，产出「test 形角 / ref 方角」与代码逻辑完全相反的假象，
误判门控失效达数轮。`product-smoke --out <png>` 逐页独立输出 + 像素级 diff
bbox 后行为与逻辑逐位吻合。批量探针一律逐页独立输出文件，渲染命令失败要
显式报错不吞。
