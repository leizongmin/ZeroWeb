# 单案 reftest % 值有运行间波动——归因实验前先同二进制连跑采样，单采样会钉出无辜代码片

## 问题描述

R5275 全量 corpus A/B 出现 `css/css-sizing/contain-intrinsic-size/contain-intrinsic-size-014.html` 0.10→0.33（✓ 内漂移）。归因过程中连续得出两个相互矛盾的结论：FILTER 单跑两次均 0.33 → 判「确定性、归因我的改动」；stash 撢片 bisect 时「撤 utf16 片」单跑得 0.10 → 又判「该片致漂移」。两结论都错——最后同二进制连跑 4 次得 0.10/0.33/0.33/0.33，证明该案本身运行间波动，与代码片无关。

## 根因

1. 部分语料案（本案、text-decoration-inset-orthogonal-block-001）的 mismatch % 存在**运行间非确定性**（疑似 HashMap 迭代序/绘制序抖动放大到亚像素 AA 差），值在两个稳定档间跳。
2. 单采样恰好连续命中同档时呈现「确定性」假象；而 bisect 实验每臂只跑一次，把波动误读成代码差。
3. 该案 R5269 已归档为 harness flake、R5273 再次记录——归因前没有先查历史档案，重复踩坑。

## 解决方案

归因协议固定三步（本轮后入 R5275 证据）：

1. **先采样**：同二进制对目标案连跑 ≥3–4 次；值有波动即判 flake，退出代码 bisect。
2. **再查档**：corpus A/B 出现的任何漂移案名，先 grep goal 文档证据链（flake 案通常已被先前轮次归档）。
3. **后 bisect**：仅对采样稳定的案做 stash/撤片实验；wall-ms 类指标（bench first_paint_wall_ms）同规则——本轮 morning 首跑 181.14 超预算、二跑 171.39 PASS，负载窗 flake。

## 避免方式

凡「单跑数字」支持一个归因结论、而机制分析（本例：案内无 pre/tab/选区，三片修复按门控均不可达）不支持时，优先怀疑采样不足而不是修补机制解释——两者矛盾时波动概率高于「未发现的隐性代码路径」。机制矛盾是比数字更硬的证据，因为门控谓词是静态可读的。
