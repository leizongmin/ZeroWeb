# 双端同时漏采导致一致性比较假通过

## 问题描述

Chrome parity 比较器在两个 manifest 同时缺失 state、events、geometry 时仍能报告通过。
合成故障测试保留截图与区域引用，删除三个字段并改变 ZeroWeb viewport；使用像素 mock
隔离证据校验层后，旧比较器退出 0。该实验不涉及真实浏览器或 GPU 像素正确性。

## 根因分析

状态直接比较两个 undefined，事件默认成空数组，几何仅遍历两边实际存在的键。
两边都漏采时，这三个维度分别退化成“相等”“空序列相等”“没有失败项”。
manifest 的 viewport、环境和动作也没有与请求场景绑定。

生产路径还有独立的声明风险：CDP 连接成功后直接标记 GUI，无法区分 headless 与
无法核验模式的外部浏览器。数据相等和来源可信是不同的验证条件。

## 解决方案

比较前从场景确定必需字段与观察 selector，检查身份、版本、环境、检查点数量/顺序、
动作与完整几何，再分别比较状态、事件和像素。显式 JSON null 状态合法，字段缺失不合法。
生产器同步输出已应用的环境；旧记录需重新采集，不能手工填字段冒充采集证据。

Chrome 外部连接通过版本及 CDP 启动参数核验模式；无法核验时标为 unverified，完整生产
门禁拒绝放行。默认保留浏览器沙箱。Rust 点击动作的 offset/jitter null 与省略按契约
归一化，其余动作字段保持严格比较，避免校验修复破坏现有生产器。

常驻 self-test 覆盖双端漏采、观察项缺失、动作/环境漂移、重复检查点和未验证 CDP 模式。
像素比较 mock 仅验证比较器控制流；真实采集路径仍需独立生产验收。
