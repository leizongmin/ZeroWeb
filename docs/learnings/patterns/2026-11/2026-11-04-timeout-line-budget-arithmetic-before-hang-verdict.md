# Timeout 行不是挂死证明——判读前先做 solo/in-face 预算算术

## 问题描述

WPT editing corpus 全文件跑批中，尾页 variant 反复出 `Timeout` 行（V8
看门狗 `ZW_SCRIPT_TIMEOUT_MS` 到点，`state={pending:1}`），跨二进制代际
同案同位复现。前两轮位点插桩（循环计数 + 进出追踪）击杀时快照全部落
健康页正常带，但「尾页存在挂死案」的先入判断使归因沿「自旋站点在哪」
推进了四轮（环进展守卫、solo 修复定谳、全页反证、更细插桩），每轮结论
局部自洽，整体方向错误——最终证明不存在任何挂死案。

## 根因分析

`Timeout + pending=1` 与「看门狗到点时任务仍在正常推进」二义：

- 挂死模型：某案进入不终止循环，预算必然耗尽，截断深度恒定；
- 慢化模型：跨页累积慢化（进程内单调增长态，本例 ~1.5×）使尾页需求
  时间越过预算，截断深度 = 到点时的进度位。

两者在同一次 in-face 跑批的出账上不可区分（同 T 行、同 pending=1、
trace 尾同为「正常节拍中段」），位点插桩也区分不了——挂死若发生在
未插桩区域，其击杀快照与慢化模型完全同形。区分只需一次对照算术：
同二进制 solo（variant 裁剪页）完走时长与 in-face 截断深度相除即得
慢化倍数。spin2 窗实测：del solo 267s 完走 842 案 vs in-face 300s 只
走到 637 案（均速比 1.48×）；mt solo 211s 完走 1,092 案 vs in-face
300s 走到 939 案（1.65×）——两站点同量级慢化，挂死模型是多余假设。

## 解决方案

- 判读 T 行先跑 solo 对照臂：variant 裁剪页 + 加大预算
  （`ZW_SCRIPT_TIMEOUT_MS=1200000` 直呼 runner，make 配方内联 300000
  会覆盖环境变量），拿到 T_solo 与尾段完整行集。solo 完走本身即证页内
  无无条件挂死案。
- T_solo < 预算而 in-face T → 累积慢化 × 预算耗尽；慢化倍数 =
  in-face 均速（截断深度/预算）÷ solo 均速（全集案数/T_solo）。
- 决定性复核 = 2× 墙钟 in-face 跑批：慢化模型预测两腿 0T + 尾段全量
  出账且对 solo 行集逐位恒等（spin2d 实证：del 7,842/mt 10,092 案行
  0T，尾页 == solo，非尾页 == 基线，P→F=0）。
- 位点插桩「全正常带」只是挂死不在已插桩环体的证据，不是问题不存在
  的证据；把「插桩已尽」读成「问题不存在」会闭环在错误模型上。
- 旁证通道：页尾探针 script 带全局 onerror/unhandledrejection 钩子，
  完走跑批 `err:[]` 可同时排除异常早止通道（diag7 形态）。
