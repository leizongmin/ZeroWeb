# rustfmt 规范形等价判定——「机械格式化零行为变化」归因的确定性判法

## 问题描述

归因一份 diff「只是机械格式化、零行为变化」时，`git diff -w` 不够用：尾逗号、
引号风格、`where` 子句排布这类变化对 `-w` 是不可见的空白差异，但它们是 token
级别的差异——`-w` 相等既不能证明是纯格式化，`-w` 有差也不能证明有语义变化。
凭肉眼逐 hunk 判断既慢又不可复现（T62/T63 链多次需要此归因）。

## 根因分析

「纯格式化」的严格定义是：旧版与新版在 rustfmt 的规范化输出下**逐字节相等**。
比较对象应该是两个规范形，而不是工作区原文加空白折叠近似；rustfmt 本身就是
确定性的规范形生成器，可以直接当作判定器用。

## 解决方案

对旧版文件执行
`rustfmt --edition 2024 --config-path rustfmt.toml --emit stdout <旧版>`，
取 stdout 并剥掉头两行文件名标注，再与新版文件内容逐字节比对：

- 相等 → 纯机械格式化，可归因零行为变化（行为门禁仍按常跑，不靠此判据豁免）；
- 不等 → 存在 rustfmt 不会产生的差异，必然含格式化之外的改动，逐 hunk 审查。

注意：`--emit stdout` 的输出带两行文件名头，剥头时按固定行数处理；多文件场景
逐文件判，不允许目录级抽样。该方法只回答「是否纯格式化」，不回答「格式化后的
代码是否正确」——后者仍由测试与行为门禁覆盖。
