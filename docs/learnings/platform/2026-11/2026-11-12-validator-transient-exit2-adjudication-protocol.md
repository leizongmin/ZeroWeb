# 校验器 exit 2 暂时性判读协议——直调探针取真错 + CLI 重跑双过=暂时，确定性复现=断链

## 问题描述

交付/复核链校验器（verify-review.mjs 等）约定 exit 1=校验过未完成（正常返回，
非失败）、exit 2=失败。无人值守跑链时偶发 exit 2，直接判链断会触发不必要的
返修重放；直接重跑又可能掩盖真实断链。

## 根因

exit 2 有两类来源，症状不可分：

1. **暂时性**：外部依赖分层抖动（GitHub web API 分时段 5xx/超时，见
   baserefoid 系列学习点），本轮失败下轮自愈；
2. **断链**：账本/回执字段违约（硬字段缺失、绑定 head-blob 漂移等），
   重跑必然复现。

## 解决

exit 2 后按序三步裁决，不跳步：

1. **直调探针**：绕过 CLI 包装直接 import 校验器函数喂同一输入，异常栈
   `REAL_ERROR` 给出被 CLI 包装吞掉的真错（网络类 vs 字段违约类一眼可分）；
2. **CLI 重跑**：原命令原输入重跑，连续 2 次过=暂时性（记录在案继续链）；
3. **确定性复现=断链**：两跑同错或直调即字段违约 → 按断链返修，不重放。

双跑判读期间不改校验器、不改账本（改了就不叫复现）；GitHub 类抖动同时满足
「探活连续 2 次过再重跑同 step」前置。
