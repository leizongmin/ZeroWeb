# 绑核后退出成功，不代表相对性能预算已通过

## 问题描述

下载字体案例固定 CPU 重跑 `make bench-gate`，16 个 crate 和页面测量完成，
命令退出 0，但日志明确跳过了相对预算比较。直接把退出码当作完整通过会漏掉
超预算项。

## 根因分析

`tests/wpt-runner/src/main.rs` 使用 `std::thread::available_parallelism()` 填充
报告的 `cpu_cores`。它反映当前进程可用的并行度，而不是不受 affinity 影响的
机器逻辑核数。通过 Cargo runner 将测量进程绑定单核后，报告为 1；原基线为 16。

`scripts/perf-gate.sh` 发现该字段不同，走 hardware-mismatch 分支：保留页面总耗时
及表单硬预算，跳过相对预算并返回成功。该保护避免直接比较不同运行配置，不能
删除它来放行；真正需要区分的是执行成功、硬预算通过、相对比较完成三个状态。

## 解决方案与边界

本次未改工具或基线，保留报告中真实的可用核数。额外直接执行仓库现有 jq 预算
表达式，核对指标完整性并拒绝 NEW/SKIP，得到 113 项中 18 项超预算；用旧报告
验证同一表达式能重现原来的全部 15 个失败 ID。补验不是不同 affinity 配置已完全
可比的证明，因此案例继续保持 Draft，没有用退出 0 宣称性能验证完成。

后续工具设计可分别记录 CPU 型号、机器可见逻辑核数、进程可用并行度和 affinity，
并使退出状态区分“全部比较通过”和“仅部分预算已检查”；这需要单独的契约与
回归测试，不在字体修复中顺手修改。

完整测量边界与证据见 [字体首例记录](../../../acceptance/site-optimizer-font-pipeline.md)。
