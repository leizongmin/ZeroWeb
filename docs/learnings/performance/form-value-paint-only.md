# 表单当前值更新应走 paint-only 路径

- 日期：2026-08-12
- 相关模块：`zero-engine` 渲染管线、renderer 表单输入

## 问题描述

文本框每输入一个字符都会记录 `value` 属性变更。旧分类器把它当作普通属性变化，虽然不再重新解析 HTML，仍会重新计算整页样式和布局，造成连续输入卡顿。

## 根因分析

输入框的外部尺寸由控件样式和 UA 尺寸规则决定，当前值只参与控件内部文字绘制。把所有属性变化统一归入完整管线，丢失了这一条稳定的失效边界。同时，CSS 的 `[value]` 属性选择器确实可能让当前值影响样式，因此不能无条件跳过样式计算。

## 解决方案

将文本型 `<input>` 的单纯 `value` 变化分类为 paint-only，复用缓存的 computed styles 和 layout；若页面样式包含 `[value]` 选择器则保守退回完整样式与布局。通过 `parse_count/style_count/layout_count/paint_count` 自动断言快速路径为 `0/0/0/1`，并断言选择器依赖场景为 `0/1/1/1`。

## 如何避免

新增高频交互属性时先定义其最高失效级别，并同时提供“可走快速路径”和“必须回退”的成对测试。不要仅以“没有重新解析 HTML”作为增量渲染已经完成的判断。
