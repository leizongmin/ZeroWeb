# 滚动 translate-blit 实现与 region 语义坑（M1-S1，2026-08-08）

**相关模块**: apps/browser（render_scene_cpu）、render-foundation CPU 光栅器
**背景**: 大页面滚动卡顿优化——纯滚动帧不再全量光栅，改为「平移上一帧 + 只重绘新露条带」。

## 方案

浏览器 UI 线程保留上一帧 `FrameBuffer`（`BrowserApp.retained_fb`）。滚动帧
（整数像素位移、同小数位、无选区/查找栏/上下文菜单/拖拽、快照序号未变）时：

1. `copy_within` 平移页面内容矩形内的行（向上滚动自上而下复制，向下滚动自下而上，防覆盖）；
2. 新露出的条带渲染到 **scratch 帧缓冲**（白清 + `render_full_scene_region_into`，
   region 只做「剔除不相交图元」加速）；
3. **只把条带行拷回保留帧**；
4. overlay 层（滚动条/查找栏）每帧重画正确位置，全高滚动条自愈。

失效条件（任一即全量渲染并刷新缓存）：新快照到达（`TabManager.snapshot_seq` 递增）、
缩放/窗口尺寸变化、选区存在/拖拽中、滚动条拖拽、触摸滚动、水平滚动、亚像素滚动
（小数位变化）、**查找栏/上下文菜单可见**（部分高度 overlay 平移后留残影）、
`ZERO_SCROLL_BLIT=0` kill-switch。

## 踩坑 1：region 语义是「剔除」不是「裁剪」

`render_full_scene_region(region)` 的 region 只用于**跳过不相交图元**（提速），
**不裁剪绘制范围**——穿过条带的高图元（如 270..330 的半透明 fill 跨 290..300 条带）
会被完整绘制，覆盖条带外的保留像素 → 平移+条带 ≠ 全量渲染（像素等价测试抓到：
`blit(38,270)` = 双重混合 78,108,213 vs 全量 137,157,227）。

**修复**：条带渲染到 scratch 帧缓冲，只拷条带行回保留帧——scratch 内越界绘制无害。
（替代方案「逐图元裁剪到条带」需处理圆角边半径归零、线段 Cohen-Sutherland 裁剪、
阴影模糊越界，复杂度高且易错；scratch 方案简单且精确。）

## 踩坑 2：部分高度 overlay 的平移残影

overlay（查找栏、上下文菜单）是**固定位置** chrome：平移后旧 overlay 像素随内容
位移到新位置，而新 overlay 只覆盖其原区域 → 残影条带。全高滚动条自愈（overlay
每帧重画全覆盖）；部分高度 overlay 只能**禁 blit**（guard 列表）。

## 踩坑 3：blend 非结合性 & 像素等价测试的必要性

半透明混合 `round` 后不可结合——「复用上一帧像素」与「从头混合」必须保证完全
相同的操作序列。等价测试（平移+条带 vs 同滚动全量，逐像素对比，覆盖 ±1/10/12/25/
37/40 六种位移 + 半透明叠加 + overlay）是唯一可靠的正确性锚点。**任何 blit 类
优化必须先过像素等价测试再谈收益。**

## 经验

1. 「复用上一帧像素」类优化（blit/脏矩形/缓存帧）的正确性证明 = 与全量渲染的
   逐像素等价，不是代码审查。
2. region 参数在光栅器里通常只做剔除——使用前确认语义，别假设它裁剪。
3. 固定位置浮层与内容平移天然冲突：要么浮层全区域自愈，要么禁优化。
4. 整像素位移 + 同小数位保证 floor/ceil 光栅化的一致性（亚像素滚动退化全量）。
