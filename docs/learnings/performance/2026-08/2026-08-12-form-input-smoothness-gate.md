# 表单输入流畅度需要双层自动门禁

## 问题描述

真实窗口里的输入卡顿同时受页面管线、进程通信、窗口调度和测试轮询粒度影响。只测窗口端到端时间会把调度噪声算成渲染回归；只测微基准又可能漏掉焦点、坐标、IME 和按钮路由错误。

## 根因分析

表单交互有两个不同的失败面：一是控件命中与事件路由是否正确，二是一次 value-only 编辑是否错误触发 HTML parse、style 或全量 layout。二者需要不同且互补的自动化证据。

## 解决方案

使用双层门禁：

1. 多进程浏览器测试覆盖物理坐标点击、两个文本控件、按钮、1.0～2.0 缩放和中文 IME，验证产品链路正确性。
2. release 模式 retained-input 报告测量 input-to-publish 事务，并硬断言每次 `parse=0`、`style=0`、`full_layout=0`、`paint=1`、`publish<=1`。所有平台执行 20ms/5% 绝对预算；有固定机器基线的平台再执行 `p95 <= baseline * 1.10 + 2ms` 和卡顿率相对预算。

测量与判定脚本保持分离，使报告可进入趋势系统，门禁也可独立用构造报告做失败路径测试。
