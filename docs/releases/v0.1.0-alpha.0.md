# ZeroWeb `v0.1.0-alpha.0` 发布说明草稿

`v0.1.0-alpha.0` 是 ZeroWeb 的首个公开预发布版本。

先把话说在前面：这还是个实验性版本，主要面向学习、研究和工程探索，不是稳定浏览器发布。无论是商用还是其他生产用途，功能、安全、兼容性、性能和许可证边界风险都需要你自己评估。

## 版本亮点

- 建起了浏览器内核和浏览器产品层的初始多 crate Rust workspace。
- DOM、CSS parser、style system、layout engine、rendering pipeline、networking、storage、IPC、Canvas 2D、WebView API 和 WASM sandbox 都已经有了早期版本。
- 提供了基于 `wgpu` 的可运行入口 `webview-demo`。
- 加上了跨 crate 集成测试、benchmark，以及覆盖 Linux、macOS、Windows 的 CI。
- 补齐了 AI 辅助开发和许可证边界相关的协作文档。

## 本次预发布包含的内容

### 引擎和运行时基础

- `dom`: 基于 `html5ever` 的 DOM 树模型
- `css-parser`: tokenizer、parser、selector 和值解析
- `style-system`: cascade、inheritance、computed values、selector matching、shorthand expansion
- `layout-engine`: 基于 `taffy` 的 block / flex / grid 布局整合
- `engine`: render pipeline、paint、dirty tracking、compositing
- `render-foundation`: GPU / CPU 渲染基础设施
- `host-runtime`: 窗口与事件循环基础能力

### 其他基础能力

- `net`: HTTP/HTTPS client 基础、URL 处理、导航历史、Cookie
- `security`: 同源策略、CORS、CSP 基础能力
- `storage`: localStorage、sessionStorage、IndexedDB 基础能力
- `protocol`: IPC 消息定义与序列化
- `canvas`: Canvas 2D 图元与绘制能力
- `wasm-sandbox`: 基于 `wasmi` 的 WASM 执行能力

### 嵌入与测试

- `webview`: 可嵌入渲染表面和生命周期 API
- `tests/integration`: 跨 crate 集成测试
- `tests/wpt-runner`: 早期 WPT 相关基础设施
- GitHub Actions CI：覆盖 `cargo check`、`cargo clippy`、`cargo test` 和 release build 验证

## 现在还没到位的地方

- `browser-shell` 还谈不上是可用的浏览器 UI。
- `script-sandbox` 仍是占位实现。
- 页面级 JavaScript 执行和 Web API 覆盖尚未完成。
- 真实站点兼容性和浏览器级加固还在继续做。

## 这次预发布更适合谁看

这个版本主要适合这几类人：

- 想理解或扩展当前架构的贡献者
- 想评估 AI 辅助开发工作流在复杂 Rust 项目中表现的人
- 对浏览器内核、渲染管线或可嵌入 WebView 设计感兴趣的工程师

现在还不适合把它对外说成日常使用的浏览器。

## 当时的仓库状态

写这份草稿时，仓库大概是这个状态：

- 一个 16-crate workspace，其中 14 个 crate 已有实质实现
- 主工作区约 1,000 个测试通过
- 大部分已实现核心 crate 具备 criterion benchmarks
- 覆盖 Linux、macOS、Windows 的 CI

## 试用前先知道这些

- 试用前请先阅读 [README.md](/home/lei/work/ZeroBrowser/README.md)。
- 目前更适合体验的入口是 `cargo run --bin webview-demo`。
- API 形态和 crate 边界都还会继续动，稳定版本前出现 breaking changes 很正常。
