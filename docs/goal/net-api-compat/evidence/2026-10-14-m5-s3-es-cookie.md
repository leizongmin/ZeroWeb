## ④ eventsource request-cache-control Timeout 归因与修复

**归因链**（探针页三级定位，临时 zz-es-probe.any.js 跑后删除）：
1. 页级 Timeout、4 子测试仅同源 2 腿打印 → 挂点在跨源腿首连。
2. 分腿探针：跨源 **fetch** 同 URL 正常 resolve、timer 存活 → 非 host 路由/线程冻结。
3. 直探 EventSource：onerror 触发（readyState 0 = reestablish 路径）→ **ES 的
   fetch promise rejected**。头复刻探针：`Cache-Control: no-cache` 单独即复现拒绝
   （Accept 单独通过）。
4. 根因：ES 请求恒携带 `Cache-Control: no-cache`（HTML spec ES 构造步骤；非
   CORS-safelisted request-header——fetch spec §3.1.1），跨源 → **须 preflight**；
   runner 的 `eventsource/resources/cors.py` fixture（M4-S13 落，上游逐字等价——
   上游无 OPTIONS 分支、无 ACAM/ACAH）应答缺 ACAH → shim preflight 门（M4-S23
   spec 化判定）拒 → Failed to fetch。测试页只接线 onmessage（onerror 未接线）→
   pending 挂死 → 页级 Timeout。M4-S13 当时的 4/4 与 M4-S29 收口全绿系彼时
   preflight 门/ES 面行为时点差异，非本轮引入（M5-S2 轮 stash 对照已证与 WS 面无关）。

**修复（runner fixture，零产品面改动）**：cors.py fixture 增 OPTIONS preflight
应答——ACAM ← 回显 ACRM（缺省 GET）+ ACAH ← 回显 ACRH（缺省 cache-control），语义
= 「支持 ES 跨源的合规 CORS 服务端」（真实部署本须如此才能用跨源 SSE）。

**结果**：eventsource 35P/0F/0T（收口口径 35/35 = 100% 回归；同源+跨源 ×2 全绿）。

## ① WS cookie jar 集成（4 案全绿）

**断缝定位**：`document.cookie` 读写走 shim 侧 **JS jar**（`_zwCookieJar`，part06
IIFE 内闭包，cookies-compat M2 落地）——而 WS 握手 Cookie 取
`zero_net::shared_cookie_store()`（Rust jar，fetch 响应写入面；zero-web 流
caf3b3373 接线）。**双 jar 不通**：001（document.cookie → 握手不带 Cookie）、
002/007（101 响应 Set-Cookie 不落 jar）、cross-origin（两腿均断）。

**修齐三面**：
1. **net**（`crates/net/src/websocket.rs`）：101 响应全部 `Set-Cookie` 头收集透出
   （`response_cookies()`，重复头逐条）。
2. **bridge**（`crates/engine/src/ws_bridge.rs`）：新内部事件 `WsEvent::SetCookie`
   （wire `cookie\x1f<set-cookie>`，sanitize_field 过 wire 元字符），于 Open **前**
   派发（cookies/007「onopen 时已可见、脚本执行期不可见」执行序面——sync XHR 阻塞
   期泵不跑，事件序天然满足）；握手 Cookie 双源合并
   `merge_handshake_cookie(jar, shim)`——Rust jar 检索优先，追加 JS jar 面未含名字。
3. **shim**（part06）：cookie 存储核心抽 `_zwCookieStoreSet(raw, scope)`（scope =
   {host, requestPath, secureContext, viaHttpApi}）——`_zwCookieSetFromDocument`
   （原语义不变，httpOnly 恒拒存）+ 新 `_zwCookieSetFromWs`（request-uri = 连接
   URL，wss 计安全上下文，**HttpOnly 按 bis §5.3 置位存储**——document.cookie 不
   可见面由既有 getter 过滤承担）+ `_zwCookieHeaderForUrl`（RFC 6265 §5.4 出站
   Cookie 头：domain/path/secure 匹配、**含 HttpOnly**、长路径优先）。构造器第 5 参
   传 JS jar 检索值（bridge 原本转发但宿主弃用——本片起消费）。跨闭包桥接：cookie
   函数在 part06 大 IIFE 内、WS 段在外——`globalThis._zwCookieSetFromWs/
   _zwCookieHeaderForUrl` 桥（part03 `_zwFireTracksAdded` 跨段口同款；**首版直引
   报 ReferenceError 即此因**）。

**迭代记录**：
- 首轮 `make testharness-net-api FILTER=websockets/cookies` 五案全 Fail
  `_zwCookieHeaderForUrl is not defined`——二进制已含函数（strings 核验）仍
  ReferenceError → part06 双闭包结构定位（cookie 段止于 14988 `})();`）→
  globalThis 桥接修复。
- product 面 ws_bridge.rs trait 参数名 `_cookie` → `cookie`（原弃用参起用）。
