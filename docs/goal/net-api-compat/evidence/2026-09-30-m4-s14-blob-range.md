## 修齐内容

- **fetch spec blob-url-scheme step 11-13 Range 支持**（part01 `_zwFetchSchemeDispatch`
  blob 分支，`headersWire` 经调用方透传）：
  - **Range 头存在而提取 failure**（malformed / 多区间含尾逗号 / 单位非 bytes /
    起点缺失 / 起点>终点）→ **network error**（现 spec 语义——无 200 回落；
    `bytes=100000-` / `bytes=13-` 起点 ≥ size 同 network error）。
  - **提取成功** → 206 切片响应：`Content-Range: bytes S-E/total` +
    `Content-Length`（钳制 E = min(E, size-1)）+ Content-Type；后缀 `-N` →
    `S = max(0, size-N)`。
  - 头缺省 → 200 全量（原路径不变）。
  - `_zwExtractBlobRange`（HTTP byte-range 单区间 + OWS 容差正则）+
    `_zwGetWireHeader`（\x1e wire 头取值）helper。
- **同步 XHR scheme 分派先行**（part03 send 同步路径——host 同步契约无 shim blob
  store 视角）：`_zwFetchSchemeDispatch` 命中 → 本地填充返回；reject → 同步抛
  `NetworkError` DOMException；未命中（http/https）→ 原 host 同步 wire 不变。
- **`getAllResponseHeaders` 实现**（xhr.spec §4.6.5——原为 `return ''` 桩，本页
  `getAllResponseHeaders().includes()` 断言面首个消费者）：响应头逐项
  `name: value\r\n` 拼接（空值头照序列化——`content-type: ` 缺省 Blob 断言）。
