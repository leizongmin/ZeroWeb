# M5-S9 — bad-chunk 注入 2 腿：流中段网络错误面（2026-10-14）

**背景**：goal 内结构性挂账「bad-chunk 注入 2 腿（需 .asis + chunked 解析面）」
——实为 `fetch/api/basic/error-after-response.any.js` 两腿（上游依赖 wptserve
流式端点 `bad-chunk-encoding.py`：delay 后逐个写合法 chunk `a\r\nTEST_CHUNK\r\n`
× count，再写裸 `garbage`——客户端 chunk 解析失败 → 中段网络错误）。合成通道
无 chunk 帧语义，按既有内置 fixture 生成器模式承接（非 .asis 通道）。

## 实施

1. **runner fixture**（testharness.rs，trickle.py 同型）：`bad-chunk-encoding.py`
   内置等价生成器——body = `TEST_CHUNK`×count + `garbage`；中段错误语义经内部
   标记头 `x-zero-body-error-after: <good_len>` 承载（Consumed 后剥离，JS 不可见）。
2. **shim marker 消费**（part01 `_makeResponseFromWire`）：`_bodyErrorAfter` 字段
   （`x-zero-body-error-after` 取出即删，对齐 `x-zero-body-error` 既有机制）。
3. **流语义**（`_zwCreateBodyStream`）：enqueue 前 N 字节为单 chunk；错误在
   **首个 read 兑现后**经 getReader 包装触发（controller.error）。**时序要点**：
   start 内同步 error 会清空队列令首 read 拒——与真网络序（错误异步于 chunk
   到达）矛盾，首版即此翻车，改首个 read 兑现后置发。
4. **consume 族同步**（`_zwBodyErrorPromise`）：`_bodyErrorAfter` 置位时
   text()/arrayBuffer()/... 同拒 TypeError（fetch spec：body 传输失败 → 消费
   promise 拒）。
