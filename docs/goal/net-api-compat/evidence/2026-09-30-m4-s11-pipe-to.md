## 修齐内容（part02.js pipeTo/pipeThrough 重做）

- **shutdown / shutdown-with-action / finalize 三段收尾机**（spec ReadableStreamPipeTo）：
  动作在 `currentWrite` 稳定后执行；dest **writable** 才有等待跳（erroring/closed 时动作
  同步执行——erroring 的 abort 须抢在 start 微任务 FinishErroring 前发起，
  wasAlreadyErroring 路径以 storedError 拒绝 = 「Trying to abort a stream that is erroring
  will give the writable's error」）；动作拒绝优先于原错误传播（rejected cancel/abort
  promise 双向）；`finalize(err, errGiven)` 显式区分 resolve 与 reject(undefined)。
- **read-ahead 泵**（背压门控 `desiredSize ≤ 0/null` 不读；写完成 + `writer.ready` 级联
  监听续泵——页自持 writer 在飞写完成后的背压解除驱动）。
- **源状态监视**：`reader.closed` 兑现 → 条件 3（关 dest）/ 拒绝 → 条件 1（abort dest），
  以 `pendingRead`/`activeOps` 在飞门控——背压窗口读出未写的 chunk 不被 shuttingDown
  门控丢弃（'does not desire chunks, but then does' 丢 b、'xy' 桥测丢 y 根因）。
- **错误面**：pipeTo 同步置 `source.[[disturbed]]`（spec 步骤 11）；undefined 拒绝值传播。
- **abortAction 覆盖 dest erroring 态**；signal 路径 abort 动作 writable-only（AbortError
  不被 erroring dest 的 storedError 劫持）。
- **pipeThrough 成员读取序** = WebIDL ReadableWritablePair 定义序（readable 先于 writable，
  品牌校验失败时 writable getter 不被触）+ getter 错误原样重抛 + options 读取后复核
  writable 锁定（option getter 抓 writer → TypeError）。
- **原型委托防自递归**：非流 this 缺实例别名时 pipeTo 返回 rejected promise、其余抛
  TypeError；实例别名赋值移到方法定义之后（原赋值在方法定义前捕获到委托自身——
  'Maximum call stack size exceeded' 根因）。
