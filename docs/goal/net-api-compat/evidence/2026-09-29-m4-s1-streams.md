## 修齐内容（part02.js / part01.js）

1. **queuing strategies**：`CountQueuingStrategy` / `ByteLengthQueuingStrategy` 全局
  （构造存 highWaterMark；size 方法——count 恒 1 / byteLength 取 chunk.byteLength）；
  `_zw_streamHwm` 读 strategy.highWaterMark → 即插即用。queuing-strategies 0/20→7/20、
  writable-streams/count-queuing-strategy 0→3/3。
2. **`ReadableStream.from` 静态**（spec §rs.from）：async-iterable → 流（getMethod/
   迭代器获取错误同步重抛；@@asyncIterator 优先回落 @@iterator；done → close、error →
   controller.error、cancel → 迭代器 return best-effort）。
3. **brand 校验**（pipeTo/pipeThrough）：`_zwRsBrand`/`_zwWsBrand` 内部锚 + dest.locked
   先检（不锁源）——piping/general +2、pipe-through +4。
4. **byob getReader 守卫 + response body 字节流标记**：非 bytes 流
   `getReader({mode:'byob'})` → TypeError；`_zwCreateBodyStream` 产物标记
   `_zwIsByteStream = true`（fetch spec——response body 为字节流），response-consume-stream
   恢复 14/15。
5. **回退注记（两处，随基线甄别）**：
   - **构造严格校验回退**：start/pull/cancel/type 严格校验在 templated/default-reader/
     piping 家族引入回归（页面 test-utils 工厂 `new ReadableStream(undefined)` 形态
     ——'start' of undefined 簇），回退 `underlyingSource || {}` 宽松形态；严格校验
     （含 spec dictionary 转换序）后续切片重做。
   - **values() 命名方法回退**：两版实现（常规 IteratorResult 版 / 旧闭包别名版）均在
     async-iterator 页面挂 settle（leg 9 起 33 pending）——维持
     `[Symbol.asyncIterator]` 旧闭包（页面完整跑通 41 腿基线）；完整 values 语义
    （preventCancel/return-across-pending）后续切片。
