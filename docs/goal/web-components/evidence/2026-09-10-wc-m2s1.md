## 修复内容

### ① parser 真实化（spec the-template-element）

- `get_template_contents` 为每个 `<template>` 惰性创建**独立 DocumentFragment**
  （contents），html5ever 把模板子解析进 fragment；contents 不挂 template.children
  ——文档树遍历/查询天然不可见。
- **contents 侧表**：`Document::template_contents_map`（template → frag）。首版用
  ElementData 字段，bench 实测 dom 微基准全线 +2-3x（NodeData 尺寸跨分配粒度阈值的
  layout 劣化）——回退改侧表（仅 template 有条目，绝大多数文档空表），微基准回预算。
- DomBuilder 侧同款 map，`into_document` 移交 `from_builder_parts`。

### ② serializer/clone/import 的 contents 语义

- `serialize_node_inner_ctx`/`inner_html` 对 template 读 contents 子序列化
  （`<template>…</template>` round-trip 保真）。
- `Document::clone_node`/`import_node` 深复制 contents 到新 template（spec clone a node
  步骤 6.7）；engine `copy_subtree_from`（innerHTML/insertAdjacentHTML 路径）同款，
  contents 子的 id 从文档 id 索引摘除（`Document::remove_id_entry`）。

### ③ R145 查询例外规则收敛

- `is_query_opaque` 恒 false：解析产物进 fragment 后 children 只含真 light-DOM 子
  （appendChild），查询应命中——direct-address 例外随数据面真实化自然消亡。
- `test_query_explicit_template_addressing_r145` 更新为 spec 语义（任何 light 查询
  不可达 contents；contents 经 `template_contents` API 直达）。

### ④ host 桥与 shim content 视图切换

- 新回调：`__zw_template_contents_deep`（主文档快照，深 JSON——contents 子在 fragment
  非文档树，浅 selector 二次定位不可达）+ `__zw_parse_template_contents`（参数化 html 串
  域，iframe/detached shim 文档 JS 树构建用）。
- shim：R95/R145 content 视图（part04）经深 JSON 本地构建（`_zwMBuildDeepEntry`）；
  `_zwMBuildNode` 对 template 读参数化 contents（iframe 树零改动继续工作）；
  `template.content.cloneNode` 以 `document.createElement` 重建为 **handle 子**（host wire
  展开只认 handle 子——R380 replaceWith 融合消费面）。

### ⑤ 顺带修复（模板克隆路径暴露的 pre-existing bug）

- text/comment handle 的 `outerHTML` 序列化走元素 DIV 回落（`<div>New </div>`）——
  补 text/comment 特判。
- handle 元素 innerHTML 序列化的 registry 兜底（host mutations 无 SetInnerHTML 记录时
  从 `_handleChildren` 递归——createElement+appendChild 子树的同步融合视图）。
