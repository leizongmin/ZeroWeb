## 修复内容

### ① attachShadow slotAssignment 枚举（双世界）

- plain 轻量 shadow + part05 handle 容器统一：仅 'manual'/'named' 合法，其余 TypeError
  （WPT 'attachShadow can take slotAssignment parameter.'——含 'exceptional' 抛错与
  `shadowRoot.slotAssignment` 回读）；缺省 'named'。

### ② `slot.assign(...slottables)`（HTMLSlotElement.prototype，双世界共享）

- 参数仅 Element/Text（Attr/Comment/DocumentFragment/DocumentType → TypeError）；
  detached slot 不抛 NotSupportedError（WPT 'Nodes can be assigned even if slots or
  nodes aren't in the same tree'）。
- 同参去重首见保留（assign(c1,c1,c2,c2,c1) → [c1,c2]）。
- **抢占**：新列表节点的当前 claimant（`__zwFindManualClaimant`——plain/handle 双世界
  宿主 shadow 树 DFS）移除该节点——跨 shadow root 抢占 + 抢到 disconnected slot 均成立。
- 列表**跨树持久**：slot 移宿主/slottable 出宿主均不清列表，可见性在读面过滤
  （`__zwManualVisibleList`：parent === 根宿主）——'Moving a slot to a new host' /
  'Previously assigned node... re-assigned when moved back' 的隐/现语义。

### ③ assignedNodes / assignedSlot 的 manual 分支

- assignedNodes：manual 树返回 manual 列表按宿主过滤（flatten 走同一 spec 形递归）——
  plain（part03）与 handle（part05）双路径。
- assignedSlot：manual 树 find-a-slot = shadow 树 DFS 树序首个 manual 列表含本
  slottable 的 slot（`__zwFindManualSlotInShadow`；name 匹配不参与）；handle 域
  ShadowRoot wrapper 不直挂 slotAssignment——经 `_shadowHandleMeta` 回落判定。

### ④ manual slotchange（微任务、树序、精确计数）

- `slot.assign` 路径：**raw 列表** diff（跨宿主获配也 fire——cross-shadow-root 语义）；
  变异移除路径：**可见列表** diff（`__zwManualMutationRemoved`——宿主子移除/出树 slot）。
- 派发：同一微任务去重、按根分组、根内树序 DFS（'Signal a slot change should be done
  in tree order'）；**级联**：manual 列表含已变化 slot 的上层 slot 一并 fire、含嵌套
  shadow 树下探（'assign node to nested slot' 的 s3 二次 fire）。
- name-mode 通用变异队列维持切片 3 的「变异触发即全树派发」近似（见挂账）。
