# M6 残留收口——KDF 语义 + [SecureContext] 门禁（2026-10-17）

非 tentative 挂账失败清零的最后一个实现里程碑。四组语义修齐：KDF（PBKDF2/HKDF）
hash 注册校验与 deriveBits length 矩阵、HMAC 归一化注册集、sign/verify 跨家族
算法不匹配错误分类、`crypto.subtle`/`CryptoKey` 的 [SecureContext] 暴露门禁
（含 isSecureContext init 时序根修与 runner 页锚双态）。全量 **33,109 = Pass
25,788（77.89%）+ Fail 7,320 + Timeout 1**（M5 22,836 → **+2,952**，逐 subtest
与 M5 evidence 对比**零回归**）；全绿案 67→**73**（+6）；**Fail 7,320 全部为
.tentative. 案挂账域**（ML-KEM/ML-DSA/X448/Ed448/AES-OCB/kmac/
chacha20_poly1305/argon2/cSHAKE 等），非 tentative 失败为 0。

## 改动

1. **shim** part01b.js——`_zw_normalizeImportAlgorithm` HMAC 臂 hash 注册集
   白名单：归一化后非注册摘要名（`MD5` 等）置 null → `generateKey`/`importKey`
   NotSupportedError，且**先于** usages SyntaxError（spec getHash 步骤在
   usages 校验前）。`_zw_performDerive` KDF 臂（deriveKey 路径）加 hash 注册
   校验：`badHash`（如 `"SHA384"` 传入 PBKDF2 声明但 hash 非注册名——注意
   `_zw_hashName` 只大写不去连字符，`"SHA-384"` 合法、`"SHA384"` 非法）与
   非摘要名（`"PBKDF2"` 作 hash）→ NotSupportedError。
2. **shim** part02.js——deriveBits 入口（KDF 组）两段：hash 注册校验同上；
   length 矩阵按 spec deriveBits 第 4 步——非 number/负数/非 8 倍数/null/
   省略 → OperationError；**length === 0 → resolve 空 ArrayBuffer**（与
   deriveKey 的 length 0 = 全宽分支区分，`kdf.js` 断言面）。spec 链接：
   <https://w3c.github.io/webcrypto/#SubtleCrypto-deriveBits>。
3. **shim** part02.js——sign/verify HMAC 兜底拆分：非 HMAC 算法仍
   NotSupportedError；但算法名与 `key.algorithm.name` 不匹配（如 ECDSA key +
   `{name:'HMAC'}`，`mac.js`「wrong algorithm name」组）→ **InvalidAccessError**
   （spec sign 公共步骤：algorithm 与 key 不同族 → InvalidAccessError，此前
   误归 NotSupportedError）。
4. **shim** part01b.js + part02.js——[SecureContext] 暴露门禁：`_zwSubtle`
   对象字面量改存局部 var（原写法在 part01b 直接挂 `globalThis.crypto.subtle`，
   跨文件无门禁位）；part02 尾按 `globalThis.isSecureContext === true` 挂载
   `crypto.subtle` 与 `CryptoKey`（`SubtleCrypto` 接口对象本就不暴露）。
   spec：[SecureContext] 成员仅安全上下文可见，
   <https://w3c.github.io/webcrypto/#securecontext>；`getRandomValues`/
   `randomUUID` 不受门禁（Crypto 接口非 [SecureContext]）。
5. **shim** part01.js——isSecureContext getter init 时序根修：原实现读
   `location.protocol`，其 getter 经 `_hist_current` → `_hist_entries[
   _hist_cursor]`（part02 后段 ~5896 才赋值）；shim 拼接为单脚本按源序执行，
   part01b 门禁在 init 期访问必抛 TypeError，被 getter 的 `catch (_e) {
   return true; }` 兜底**吞成 secure**——http 页锚下门禁恒开，historical 案
   2F 顽固的根因。改为直读 `__zw_get_page_url()` 的 scheme（`http:`/`ws:`
   前缀 → false，余皆 true），绕开 location facade 与 history 状态机；
   pushState/history 不换源，scheme 语义等价。
6. **runner** tests/wpt-runner/src/testharness.rs——页锚双态对齐上游文件名
   约定：`webcrypto_case_uses_http_page`（文件名含 `.https.` 中缀 → https
   页锚，否则 http；historical.any.js、getRandomValues.any.js 跑 http，与
   上游一致）。~7700 行预热行改 `execute_script_with_dom`（裸 execute_script
   先触发 ensure_js_shim，无 DOM 回调 → `__zw_get_page_url` 未注册 → scheme
   回退 about:blank → 门禁误判）。
