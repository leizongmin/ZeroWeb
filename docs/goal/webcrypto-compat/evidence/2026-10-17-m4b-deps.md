# M4b EC 签名系依赖选型（2026-10-17）

## 范围

EC 家族（ECDSA/ECDH，namedCurve P-256/P-384/P-521）全链：importKey
（spki/pkcs8/jwk/raw + 压缩点）、generateKey、exportKey、ECDSA sign/verify、
ECDH deriveBits/deriveKey。OKP（Ed25519/X25519）为后续片，本次不引依赖。

## 选型

RustCrypto elliptic-curves 家族（与 M4a `rsa 0.9` 同生态、同 pkcs8/spki/der
栈、同 rand_core OsRng，纯 Rust 无 C 依赖）：

- `p256 = "0.13"`（features: `ecdsa`, `ecdh`, `pkcs8`, `arithmetic`）
- `p384 = "0.13"`（同 features）
- `p521 = "0.13"`（同 features；P-521 是 WebCrypto 规范曲线之一，corpus
  ec_importKey/ecdsa/ecdh 均覆盖）

ecdsa 签名/验签经各 crate 的 `ecdsa` feature（`ecdsa 0.16` 泛型实现）；
ECDH 经 `elliptic_curve::ecdh::diffie_hellman`（`ecdh` feature）；spki/pkcs8
编解码复用 `elliptic-curve 0.13` 的 pkcs8 模块（`der 0.7`/`spki 0.7`/
`pkcs8 0.10` 已为 `rsa 0.9` 传递依赖，无新底层 crate）。MSRV：elliptic-curve
0.13 线 1.65，低于 workspace 1.85。

## 对比

- `p521`（RustCrypto，0.13）**选**：与 p256/p384 同 trait 族
  （`PrimeCurve`），三曲线一份泛型代码路径；纯 Rust，RustCrypto 维护。
- ring/rustls-ring 系列：非纯 Rust（C/asm），引入跨语言构建面；且项目既有
  crypto 栈全 RustCrypto，混栈无收益。
- `k256`（secp256k1）：WebCrypto 规范曲线集合外（P-256≠secp256k1），不引入。

## 影响面

- Cargo.toml workspace deps +3（p256/p384/p521，均为叶子新增，无版本冲突面：
  elliptic-curve 0.13 线已被 rsa 生态共享）。
- crates/engine/Cargo.toml +3。编译增量约数秒（无 proc-heavy 依赖）。
- 性能：EC 密钥生成/签名均在 ms 级，非热路径（subtle API 调用粒度），
  无 bench-gate 敏感面（JS 桥回调按次计费，与 RSA M4a 同级）。

## 验证

- `cargo add`/构建后以 corpus 分域（ec_importKey、generateKey EC、
  sign_verify ecdsa、derive_bits_keys ecdh、serialization ecdsa/ecdh）
  A/B 记录于 M4b 主 evidence。
