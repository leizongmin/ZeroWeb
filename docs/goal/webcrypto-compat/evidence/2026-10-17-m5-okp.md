# M5 OKP 家族——Ed25519/X25519（2026-10-17）

crypto.subtle OKP 全链落地：importKey（raw 公钥 32 字节 / spki / pkcs8 / jwk
x(/d)）、generateKey CryptoKeyPair（publicKey 恒 extractable、privateKey 按
请求值 + usages 类型拆分）、exportKey 四格式（RFC 8410 定长 DER、jwk 定宽
base64url）、Ed25519 sign/verify（RFC 8032 纯 EdDSA 确定性，`verify_strict`
拒小阶伪造）、X25519 deriveBits/deriveKey（RFC 7748 钳位标量 + 全零共享秘密
拒绝 + length 位截断）。全量 **33,109 = Pass 22,836（68.97%）+ Fail 10,272 +
Timeout 1**（M4b 20,900 → **+1,936**，零回归）；全绿案 53→**67**（+14）。明细
见本文件验证节。

## 改动

1. **依赖**：`ed25519-dalek = "3.0"` + `x25519-dalek = "3.0"`（features
   `static_secrets`；curve25519-dalek 同代 audited 纯 Rust，MSRV 1.85 与
   workspace 一致）。DER 编解码按 RFC 8410 定长结构手写（SPKI 44 / PKCS#8
   48 字节前缀常量），不引 `pkcs8` feature。选型对比与影响面见
   [M5 依赖选型](2026-10-17-m5-okp-deps.md)。
2. **host** js_dom_bridge/crypto.rs：OKP 段——`OkpKind` 枚举 + RFC 8410 前缀
   常量四枚 + `okp_random_seed`（getrandom OS 熵源）+ pkcs8 组装/公钥派生
   四个内部原语 + pub 八枚——`okp_generate`（返 raw 公钥 + pkcs8；X25519 存
   钳位后标量）、`okp_import`（spki/raw/pkcs8 前缀 + 总长校验，规范化再编码）、
   `okp_jwk_import`（x 32 字节定宽；含 d → 私钥并派生公钥与 x 比对，失配
   DataError）、`okp_export_der`（公钥 raw 透传 / pkcs8 私钥透传 / 私钥导出
   公钥派生）、`okp_export_jwk`（x(/d) 定宽 base64url 源字节）、
   `ed25519_sign`（`Signer` trait，64 字节 R||S）、`ed25519_verify`
   （`verify_strict`——plain verify 对小阶 A 误 true，eprint 2020/1244 伪造
   面；拒小阶 R + 小阶 A）、`x25519`（钳位标量 × 对端点；全零共享秘密返空 →
   OperationError）。callbacks.rs 注册 `__zw_crypto_subtle_okp_*`/
   `_ed25519_*`/`_x25519` 八枚。密钥材料零落 tracing（csv 桥进出）。
3. **shim** part01b.js：`_zw_normalizeImportAlgorithm` ED25519/X25519 臂
   （规范名大小写折叠）；`_zw_performDerive` X25519 臂（镜像 ECDH——
   base/peer 校验、`_zw_x25519Validate`、length null → 全宽 256、截断/超宽
   语义同 ECDH）；OKP helper 簇十一枚（镜像 EC 结构）——家族判定/全 usages
   （Ed: sign,verify；X: deriveKey,deriveBits）/类型子集/jwk use 映射/jwk
   alg（Ed 导入接受 "Ed25519"|"EdDSA"，导出恒 "Ed25519"；X 忽略导入 alg、
   导出无成员）/csv 桥/`_zw_okpKeyFromDer`/`_zw_okpImportKey`（kty='OKP' →
   crv 精确 → alg → use → key_ops → 类型子集 → ext → x(/d) base64url →
   host 配对校验，private 空 usages SyntaxError 置最后）/`_zw_okpGenerateKey`
   （usages → 家族 → 生成后 privateKey.extractable=请求值）/`_zw_okpExportKey`
   （非 extractable InvalidAccessError、pkcs8 仅 private）/`_zw_x25519*`。
4. **shim** part02.js：importKey/generateKey/exportKey/sign/verify/deriveBits
   六方法加 OKP 分派；Ed25519 sign/verify 无 hash 成员（算法不匹配/类型/
   usage → InvalidAccessError，坏签名 resolve false）；X25519 deriveBits
   length 矩阵（null/省略 → 256、0 → 空 ArrayBuffer、>256 → OperationError、
   非 8 倍数 → 左起位截断）。
5. **测试**：part53 `test_crypto_subtle_okp_m5`——WPT eddsa_vectors fixture
   锚定（pkcs8/spki/64 字节消息/64 字节签名逐字节，RFC 8032 确定性 ×2）+
   RFC 7748 §6.1 Alice/Bob 双向 KAT（共享秘密逐字节）+ 小阶 A 验签 false +
   generateKey 结构（usages 拆分、privateKey extractable 按请求值）+ 四格式
   round-trip 逐字节稳定 + jwk alg 行为（Ed 双别名/错拼 DataError、X 导入
   忽略导出无成员、成员数 Ed 7/X 5-6）+ d/x 失配 DataError + 错误矩阵
   （31 字节 raw/kty/crv/alg 错拼/非法 usages）+ X25519 length 矩阵
   （256/230 截断 0x1e&0xFC/0 空/null 全宽/384 OperationError）+ 小阶公钥
   全零 OperationError + deriveKey→AES-GCM round-trip。
