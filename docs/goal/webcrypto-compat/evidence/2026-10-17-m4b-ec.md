# M4b EC 签名系——ECDSA/ECDH P-256/P-384/P-521（2026-10-17）

crypto.subtle EC 家族全链落地：importKey（spki/pkcs8/jwk/raw 含 SEC1 压缩点）、
generateKey（CryptoKeyPair，publicKey 恒 extractable + usages 类型拆分）、
exportKey 四格式（spki/raw=SEC1 未压缩点/pkcs8/jwk x/y/d 定宽零填充）、ECDSA
sign/verify（RFC 6979 确定性 nonce，IEEE P1363 r||s 定宽）、ECDH
deriveBits/deriveKey（共享点 x 坐标 + length 位截断）。全量 **33,028 =
Pass 20,900（63.3%）+ Fail 12,127 + Timeout 1**（M4a 17,741 → **+3,159**，
零回归文件）；全绿案 41→**53**（+12）。明细见本文件验证节。

## 改动

1. **依赖**：`p256`/`p384`/`p521 = "0.13"`（RustCrypto elliptic-curves，features
   `arithmetic`/`ecdsa`/`ecdh`/`pkcs8`；与 M4a `rsa 0.9` 同生态同 pkcs8/spki/der
   栈）。选型对比与影响面见 [M4b 依赖选型](2026-10-17-m4b-deps.md)。
2. **host** js_dom_bridge/crypto.rs：EC 原语八枚——`ec_generate`（pkcs8 生成）、
   `ec_import`（spki/raw/pkcs8 解析后规范化再编码，OID×曲线校验）、
   `ec_jwk_import`（x/y(/d) 坐标合成，域宽显式校验前置防 `FieldBytes::from_slice`
   panic，曲线外点/越界标量拒绝）、`ec_export_der`（私派生公/SEC1/raw）、
   `ec_export_jwk`（x/y/d 定宽大端，P-521 66 字节零填充——generateKey successes
   长度一致性断言面）、`ecdsa_sign`（RFC 6979 + bits2int 自行归一——RustCrypto
   `bits2field` 的 ≥域宽/2 下限会拒 SHA-1×P-384/P-521 合法组合）、
   `ecdsa_verify`（坏签名返 "0" 不报错）、`ecdh`（`diffie_hellman` 共享点 x
   坐标）。callbacks.rs 注册对应 `__zw_crypto_subtle_ec*` 八枚。密钥材料零落
   tracing（csv 桥进出）。
3. **shim** part01b.js：`_zw_normalizeImportAlgorithm` EC 臂（namedCurve 原样
   透传，曲线名精确匹配大小写敏感）；EC helper 簇——家族判定/全 usages/类型
   子集/jwk alg 映射（RFC 7518 §A.2，ES256/384/512）/use 映射、`_zw_ecImportKey`
   （namedCurve 缺失 TypeError → 曲线未注册 NotSupportedError → usages 家族
   SyntaxError → 格式分派 DataError 链 → private 空 usages SyntaxError 置最后）、
   `_zw_ecGenerateKey`（usages SyntaxError → 曲线 TypeError/NotSupportedError →
   生成后私钥空 usages SyntaxError）、`_zw_ecExportKey`（非 extractable
   InvalidAccessError、pkcs8 仅 private、jwk kty/crv/alg/key_ops/ext）、
   `_zw_ecdhValidate`（public 成员缺失/非 CryptoKey TypeError → base/peer 校验
   InvalidAccessError）、`_zw_ecdsaHash`（hash 缺失 TypeError → 未注册名
   NotSupportedError——digest host 兼容无连字符别名不能作注册语义）。
4. **shim** part02.js：importKey/generateKey/exportKey/sign/verify/deriveBits
   六方法加 EC 分派；ECDH deriveBits length 语义（null/省略 → 域全宽、0 → 空、
   超域宽 → OperationError、非 8 倍数 → 左起 N 位尾字节掩码）。
5. **derive 共享路径修齐**（EC enablement 揭示的既有缺口，与 EC 同提交）：
   - `_zw_performDerive` 补 baseKey.algorithm.name 与派生算法匹配校验
     （InvalidAccessError）——spec derive 公共步骤；此前 ECDH generateKey 失败把
     WPT `wrongKey` 降级为 null 而掩盖（hkdf/pbkdf2 "with wrong (ECDH) key"
     deriveKey 全组 2,496 断言翻红后修齐翻绿）。
   - deriveKey 目标 HKDF/PBKDF2 → length null（get key length → null，WebKit
     bug 282096 断言面）：派生取摘要输出全长（SHA-1/256/384/512 →
     20/32/48/64 字节）后 raw 导入 KDF 密钥；deriveBits HKDF/PBKDF2 错配键
     NotSupportedError → InvalidAccessError（spec 序）。
   - ECDH deriveKey：length null → 全域宽 x 坐标（超域宽 OperationError 同径）。
6. **测试**：part53 `test_crypto_subtle_ec_m4b`——RFC 6979 §A.2.5 向量锚定
   （P-256/SHA-256/msg "sample"，签名 64 字节逐字节）+ spki 导入验签 true/
   篡改 false + 签名确定性、generateKey 结构断言（usages 类型拆分、ECDH
   public usages 恒空）、ECDH 双向共享秘密一致 + length 矩阵（256/128/0/255/
   257）、deriveKey → AES-GCM round-trip、P-384/P-521 曲线覆盖（签名 132 字节、
   deriveBits 缺省 48 字节、jwk x/y/d 66 字节定宽 + ES512）、四格式 round-trip
   逐字节稳定（pkcs8/jwk/原始 SEC1/压缩点导入 → spki 一致）、错误矩阵 ×13
   （public sign/private verify/跨算法/hash 缺失 TypeError/未注册 hash/
   曲线不匹配/public 缺失 TypeError/长度超域/spki+sign SyntaxError/pkcs8 空
   usages/jwk kty/crv DataError/非 extractable 导出/缺 namedCurve TypeError/
   未注册曲线/非法 usage）。
