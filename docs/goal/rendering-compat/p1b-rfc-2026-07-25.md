**关联**：[blockers-resolution-plan-2026-07-25.md](blockers-resolution-plan-2026-07-25.md) §4、[p1b-slice1](p1b-slice1-event-loop-microtask-mechanism-2026-07-25.md)（**v0.2 撤销：microtask 已工作**）、[js-dom-bridge-design.md](js-dom-bridge-design.md)

## 1. 背景与目标

P1b = JS Bridge 从「selector-shim + 同步 execute」原生化为「真实 DOM 绑定 + 异步回调 + HTML spec event loop」，解锁**交互式网站**（fetch / MutationObserver / 事件循环 / setTimeout 真实化）。M11「浏览器日常可用」最后非环境缺口（master.md line 2776）。

## 2. 现状（代码核实）

### 2.1 Sandbox trait（`script-sandbox/src/lib.rs:95-110`）
```rust
fn register_callback(&mut self, name: &str, callback: Box<dyn Fn(&[String]) -> String + Send + Sync>);
```
- **同步**：回调返 String，无 async/Promise resolve
- **参数/返回全 String**：无原生对象绑定
- 无回调 ID、无异步 resolve 通道

### 2.2 dom_bridge / js_dom_bridge
- JS element = **selector 字符串句柄**（非 NodeId）
- DOM 操作 → `__zw_*` → `DomMutation`（selector-based）→ apply 改 HTML 快照
- Promise = **V8 原生**（dom_bridge 未 `globalThis.Promise =` 覆盖，v0.2 核实）

### 2.3 V8 runtime（`v8_runtime.rs`）
- `perform_microtask_checkpoint`（line 270/337）已存在 —— execute 后 drain 原生 microtask
- HOST_CALLBACKS thread-local（按 index 调度同步回调）
- 仅 `v8::FunctionTemplate::builder().data()` + `global.set()`（line 235/242）—— 无 `v8::External`/Object 绑定

## 3. 缺口分析（v0.2 核实修正）

| 缺口 | 状态（v0.2 核实） | 影响 |
|---|---|---|
| **异步回调通道**（Rust→JS Promise resolve） | **缺失**（register_callback 同步 String） | fetch net 结果无法 resolve JS Promise；setTimeout/rAF 不可实现 |
| **节点身份**（String selector → NodeId handle） | **缺失**（参数全 String）+ **v8::External API 未用** | MutationObserver childList 不可行；需扩展 V8Sandbox 暴露对象绑定 |
| ~~microtask queue~~ | ✅ **已工作**（V8 原生 Promise + perform_microtask_checkpoint） | ~~p1b-slice1 microtask queue~~ **撤销/降级**（假设不必要） |

★ **v0.2 核心修正**：microtask 已工作（p1b-slice1 撤销）；真硬阻塞 = **异步回调通道** + **节点身份（需 v8::External 扩展）**。

## 4. 目标架构（v0.2 修正）

### 4.1 异步回调通道（核心）
扩展 Sandbox trait 支持异步回调（向后兼容同步 `__zw_*`）：
- 回调返回「回调 ID」；Rust 异步完成后，经 **新 channel marshal 回 JS worker 线程**，调 `__zwResolveCallback(id, result)` resolve Promise
- marshal 设计：tab_js_worker.rs 加「异步完成 → JS worker」channel（现有 mpsc 模式扩展），对接 InProcessFetchHost 完成事件

### 4.2 节点身份 wrapper（需扩展 V8Sandbox API）
- JS element = Rust `NodeId` 的 wrapper（非 selector 字符串）
- **须扩展 V8Sandbox** 暴露 `v8::External` / WeakMap 绑定（v8.150.2.0 支持，当前未用）
- querySelector/getElementById 返 NodeId handle；DOM 操作按 NodeId
- MutationObserver childList 可用（addedNodes = NodeId 列表）

### 4.3 microtask（v0.2 确认）
- **已工作**（V8 原生 Promise + perform_microtask_checkpoint），不需新做
- p1b-slice1 撤销

## 5. 分阶段切片（multi-month，v0.2 修正）

- **S1 异步回调通道**（核心）：Sandbox trait 扩展（回调 ID + 异步 resolve）+ tab_js_worker marshal channel + 向后兼容。**解 fetch/setTimeout/rAF 基础**。
- **S2 节点身份 wrapper**：扩展 V8Sandbox `v8::External` 绑定 + selector→NodeId（替换 `__zw_query_*`/`__zw_set_*`）。**解 MutationObserver childList**。
- **S3 fetch 真实化**：net crate（M7）+ S1 异步 resolve。
- **S4 MutationObserver 真实化**：S2 节点身份 + dom record_mutation（已完备）→ 异步交付 JS callback。
- **S5 setTimeout/setInterval/rAF/requestIdleCallback**：S1 异步 + 定时器队列。

## 6. 风险（v0.2 修正）

- **★ QuickJS 不对等**（v0.2 核实）：`quickjs_runtime.rs` 仅同步回调，无异步/对象绑定。异步回调通道 + 节点身份 **仅 V8 可行**。RFC 作用域 = V8-first（QuickJS 后端降级或扩展 roadmap）。
- **trait 改动影响**：register_callback 改动影响 V8 + QuickJS 双实现 + 全 `__zw_*` callback。须向后兼容。
- **线程 marshal**：JS worker 单线程（tab-js-{tid}）+ Rust 异步 net —— resolve 须 marshal 回 JS 线程（现有 mpsc channel 扩展）。
- **替换 dom_bridge shim**：节点身份 wrapper 替换 selector-shim 全部，大规模分批。
- **p1b-slice1 撤销**：microtask queue 假设被 v0.2 核实推翻（Promise.then 已工作）。

## 7. 依赖 + 决策点

- **依赖**：M6 JS 运行时（V8/QuickJS gate）✓；net crate（M7）✓；rusty_v8 v150.2.0（支持 v8::External）✓
- **决策点**：授权 multi-month + 接受 V8-first（QuickJS 不对等）+ trait 改动风险
- 本 RFC = master.md line 2743 所指独立 RFC v0.2

## 8. v0.2 技术核实结果（2026-07-25，Explore agent）

1. **Promise.then ✅ 已工作**：V8 原生 Promise（dom_bridge 未覆盖）+ `perform_microtask_checkpoint`（v8_runtime.rs:270/337）drain。`Promise.resolve(x).then(cb)` 经 execute_script_direct 后 cb 真实触发。
2. **rusty_v8 对象绑定 ⚠️**：v8.150.2.0 支持基础对象 API，但节点身份 wrapper 需 `v8::External`/WeakMap（当前 v8_runtime.rs 仅 FunctionTemplate + global.set，未用 External）。**须扩展 V8Sandbox 暴露对象绑定**。
3. **QuickJS 对等 ⚠️**：`quickjs_runtime.rs:174-177` 仅同步 `Fn(&[String]) -> String`，无异步/对象绑定。**与 V8 不对等**，P1b 须 V8-first。
4. **异步 resolve marshal 🔄**：JS worker（tab_js_worker.rs:66-68 tab-js-{tid} 线程）+ tab worker（tab_worker.rs:154-155 AsyncPageLoad/InProcessFetchHost 非 tokio，tick 推进）分离。fetch 完成 → JS Promise.resolve 须**新 channel marshal 回 JS worker**（现有 mpsc 扩展）。

## 9. v0.3 选型（实施前设计细化，2026-07-25）

- **异步回调 trait**：推荐**方案 A**（回调返「回调 ID」+ Rust 异步完成后 `execute_script_direct` 调 `__zwResolveCallback(id, result)`）—— 最小改动 + 复用 `perform_microtask_checkpoint`（已 drain）+ 向后兼容（同步 callback 不变）。方案 B（`register_async_callback` 专用 channel）更干净但 trait 扩展大，备选。
- **节点 wrapper**：`v8::External` slot（JS object 挂 `External(NodeId)`），优先于 WeakMap（更直接）。
- **QuickJS**：V8-first 标注（异步/对象绑定 V8-only），QuickJS 后端保持同步（降级，不阻塞 P1b V8 推进）。
- **marshal channel**：扩展 `tab_js_worker` 现有 mpsc（异步完成事件 → JS worker 线程 → `execute_script_direct` resolve）。

> **实施边界**：P1b S1（异步回调通道）= Sandbox trait 扩展 + V8 实现 + tab_js_worker marshal + 向后兼容全 `__zw_*` callback，**multi-week 架构级**。本会话 goal「主要是做方案，不陷改代码」约束下推进到 v0.3 选型就绪；完整实施待专项 multi-week 会话。
>
> **★ S1 incr1+incr2+incr3 LANDED（R2028，2026-07-25）**：**incr1** Sandbox trait 加 `resolve_async_callback(id, result)`（默认 no-op，QuickJS 降级）+ V8 实现（防御性 execute `__zwResolveCallback`，复用 microtask checkpoint drain）+ `js_string_literal` 注入转义 + 4 单测。**incr2** 生产 DOM shim（`js_dom_shim.js`）注入 `__zwResolveCallback`+`__zw_pending` 表 + e2e 单测。**incr3** `tab_js_worker`（browser）marshal channel：`JsWorkerCommand::ResolveAsyncCallback` 复用 cmd mpsc + worker arm + `async_resolver()` 返 clonable `AsyncResolver` + 2 单测（跨命令 marshal 验证）。**S1 通路贯通**——任意线程 `resolver.resolve` → cmd → worker → `sandbox.resolve_async_callback` → shim → Promise resolve。向后兼容（register_callback 不变）。⚠️ renderer mirror（`js_worker.rs`）延后至 S3（无 crate-level allow(dead_code)，随 fetch host 接通一并加）。**剩余 S1**：接通真实 fetch（S3，net + InProcessFetchHost 完成 → async_resolver）/setTimeout 真实延迟（S5）+ renderer mirror。S2 节点身份（v8::External）独立轨道。

## 10. S3 fetch 真实化设计（2026-07-25 R2029 细化）

**R2029 prep LANDED**：`AsyncResolver` 改 `Arc<Mutex<Sender>>`（`mpsc::Sender` 非 `Sync`，原版无法被 `register_callback` 的 `Send+Sync` 闭包捕获）→ 现 `AsyncResolver: Send+Sync+Clone`，可被回调闭包捕获。+ 跨线程 resolve 单测 + 编译期 trait 断言。

**★ R2030 incr-a LANDED**：`__zw_fetch` 真实抓取通路贯通（机制层）：
- `js_worker_main` 注入 `cmd_tx`（构造 AsyncResolver）+ `Arc<Mutex<Option<FetchHandler>>>` cell
- `register_fetch_callback` 注册 `__zw_fetch(id,url)`：捕获 resolver+cell，同步抓取 → `resolver.resolve(id,body)` 排队 ResolveAsyncCallback（worker 下轮处理 → Promise resolve，**FIFO 确定性无 polling**）
- `SetFetchHandler` 命令 + `set_fetch_handler()` 解 chicken-and-egg（测试合成 handler 无网络）
- shim `globalThis.fetch` 包装（无 `__zw_fetch` 时 stub resolve 空，零回归）
- 2 单测全绿

**★ R2031 incr-b LANDED**：生产 fetch wiring 真实网络抓取：
- `default_fetch_handler()`（`tab_js_worker.rs`）：`zero_webview::fetch_text_async(url).recv()`（net pool OnceLock 自动初始化，js_worker spawn 后即可注入——chicken-and-egg 因 fetch_text_async 自带 net pool 无需 WebView 句柄而消解）
- `tab_worker` `#[cfg(not(test))]` 块 spawn 后 `set_fetch_handler(default_fetch_handler())`
- 本地 HTTP server 单测验端到端：JS fetch → net pool GET → local server → body → Promise resolve（不依赖外部网络）

⚠️ incr-a/b 限制：① fetch resolve **body 字符串**（非标准 Response 对象）；② handler **同步阻塞 recv**（JS worker 在 fetch 期间冻结，慢网络退化）；③ 仅 browser `tab_js_worker`。

### S3 剩余切片（待实施）

**目标**：JS `fetch(url)` 经 net crate 真实抓取，Promise resolve 出 response。

**架构约束（code 核实）**：
- `tab_worker_main`（browser）持 `InProcessFetchHost` + `WebView`（fetch 能力所在）；`js_worker_main` 在**独立线程**，无 fetch_host 直接访问。
- `js_worker` 早于 `WebView` 创建（`tab_worker.rs:137` js_worker 先于 `:147` builder/WebView）→ fetch 句柄无法在 js_worker spawn 时传入（chicken-and-egg）。

**fetch host 接通方案（推荐 D）**：

| 方案 | 机制 | 裁决 |
|---|---|---|
| A. 共享 cell | `Arc<Mutex<Option<FetchFn>>>`，tab_worker init 后注入 | FetchFn 须捕获 WebView（非 Send）→ 退化为 channel 代理 = D |
| B. SetFetchHandler 命令 | tab_worker 后注入 fetch_fn 到 js_worker | 同 A 的 Send 问题 |
| C. 直连 zero-net | js_worker 直接用 net crate 抓 | 绕过 WebView CORS/security；测试需 local server；非首选 |
| **D. fetch 请求 channel** | js_worker → tab_worker 抓 → `async_resolver.resolve` 回投 | **推荐**：复用现有 fetch_host/WebView 路径（CORS/security 一致） |

**D 方案流程**：
1. js_worker_main 注册 `__zw_fetch(url)` 回调（捕获 fetch_request_tx + resolver）→ 返调 ID + 发 (id, url) 到 fetch_request channel
2. tab_worker 起 fetch drain 线程 / tick 内 drain fetch_request_rx：对每条 (id, url) 调 `fetch_host.fetch_text(url)` → `recv` → `_js_worker.async_resolver().resolve(id, response_json)`
3. shim `globalThis.fetch = url => new Promise(r => { const id = __zw_fetch(url); __zw_pending[id] = r; })`

**增量拆分**：
- S3 incr-a：`__zw_fetch` 回调注册 + resolver/fetch_request_tx 注入 js_worker_main（须扩 `js_worker_main` 签名 + `TabJsWorkerHandle::spawn` 传 fetch_request_tx）
- S3 incr-b：tab_worker fetch drain（tick 内 or 专用线程）+ WebView 注入
- S3 incr-c：shim `globalThis.fetch` 包装 + 单测（local HTTP server fixture 仿 fetch）
- S3 incr-d：renderer mirror（`js_worker.rs`，随真 consumer 加）

**风险**：fetch_request channel 增 js_worker↔tab_worker 耦合；drain 时机（tick 内 vs 专用线程）影响 fetch 延迟与死锁面（tab_worker tick 阻塞 recv 会卡渲染）。**推荐专用 drain 线程**（fetch_host.fetch_text 本身返 Receiver，drain 线程遍历 in-flight requests recv）。
