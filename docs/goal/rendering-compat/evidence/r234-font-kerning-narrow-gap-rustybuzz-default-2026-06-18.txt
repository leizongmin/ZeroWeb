# font-kerning wiring 精确方案 + 优先级修正（R234，read-only，docs-only，基线 438/490 持平）

**日期**: 2026-06-18
**承接**: R232 标 font-kerning 为「font 属性 plumbing 第二项（已 parse 只差 wire，比 text-emphasis 轻）」。本轮追踪精确 wiring 并**修正其优先级**。

## 精确 wiring 状态
1. **parse = 仅名称合法性检查**：`matcher/mod.rs:897` 只判 `font-kerning` 是已知属性、值 ∈ {auto,normal,none}——属 `is_supported_property` 类**名称门控**，非真值解析。
2. **存储 = 丢弃**：`computed.rs`/`properties.rs`/`values.rs` grep `font_kerning` **零命中**——值被静默接受后丢弃，不入 ComputedStyle。
3. **shaper = rustybuzz 默认含 kern**：`shape_with_rustybuzz`（shaper.rs:75-84）调 `rustybuzz::shape(&face, &features, buffer)` 时 **`features: Vec::new()` 空** → rustybuzz 应用默认 OpenType feature（含 `kern`）。

## 关键优先级修正（纠正 R232 的「轻量第二项」框架）
rustybuzz **默认就 kern ON** → ZeroWeb 对所有文本**都做 kerning**，与 chromium 一致（`font-kerning: auto` 默认开）。故：
- **common case（无 font-kerning 声明 / normal / auto）**：ZW 与 chromium 都 kern → **本应一致**，gap 不在此。
- **唯一 gap = `font-kerning: none`**：ZW 错误地仍 kern（rustybuzz 默认），chromium 按 none 关闭 kerning → 仅此类用例有 diff。
- → font-kerning 的真实 gap 是**「无法禁用 kerning」**（narrow），非「特性缺失」（feature missing）。**优先级低于 R232 框架**（修正）。

## R229-style 精确方案（若实现轮要做）
1. parse+store：ComputedStyle 加 `font_kerning: FontKerningValue{Auto,Normal,None}`，属性解析器真解析值（非仅 matcher 门控）。
2. shaper 接入：`shape_with_rustybuzz` 收 font_kerning 参数，`None` 时传 disabled feature（`rustybuzz::Feature::new(Tag::from_bytes(b"kern"), 0, ..)`）；`Auto/Normal` 保持默认（空 features）。
3. paint 透传：text.rs 把节点 font_kerning 传入 shaper 调用。

## 对 font-plumbing 系统化（R232 模式）的优先级修正
| 项 | R232 框架 | R234 修正 | 实际影响 |
|----|-----------|-----------|----------|
| font-weight (R229) | 模板 | 确认 | **高**（welcome 17% + bold 全丢） |
| font-kerning | 「轻量第二项」 | **降级** | 低（仅 font-kerning:none，默认已 kern） |
| text-emphasis | feature 实现 | 确认 | 中（15 case 但标记小） |
| underline-offset/thickness | feature 实现 | 确认 | 小 |

**结论**：font-plumbing 系统化中 **font-weight（R229）是唯一高影响项**；font-kerning 实现简单但收益窄（仅 none-case）；text-emphasis 是中收益 feature 实现。R232「font-kerning 次之」应修正为「font-weight 唯一高杠杆，其余窄/feature 级」。
