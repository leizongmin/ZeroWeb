R916 — reftest harness 不执行 DOM-modifying JS（机制发现 + 接线状态）
========================================================================

日期：2026-06-30（发现）/ 2026-07-01（接线落地）

背景
----
reftest 的两条渲染路径（render_to_framebuffer_with_base +
render_via_webview_to_framebuffer_with_base）用裸 V8 sandbox 执行页面
`<script>`（execute_scripts @ reftest.rs），注释明载「执行但不修改 DOM / 不
提供 DOM API / JS 执行结果不影响后续渲染」。

后果：DOM-modifying JS（如 background-root-101 的
`<body onload="setTimeout(test,5)">` 改 head.className）静默 no-op →
ZeroWeb 截 pre-JS 状态，chromium oracle 截 post-JS 状态 → ~100% 假发散。

而 DOM-mutation 全链路在 browser/renderer 路径已实现且活跃，仅 reftest
未接：
- generate_js_dom_shim()（engine/js_dom_bridge.rs，selector-based shim）
- register_dom_callbacks(...)（原 renderer/browser 各一份私有副本）
- apply_mutations_to_html(html, &mutations)（engine/js_dom_bridge.rs）
- browser tab_scripts.rs::apply_recorded_mutations 完整 cycle

R916 实证
---------
手工把 background-root-101 的 post-JS 状态渲染对比 chromium oracle = 1.51%
（从 100% 降）。证 JS 是唯一 gap（CSS `head.after + body` 相邻兄弟选择器
+ canvas 背景传播均已正确工作）。

影响面：全 wpt-data 176 个 reftest-wait + 1250 个含 <script>。

========================================================================
R917（2026-07-01）接线落地 + 调查结论
========================================================================

实施
----
1. 抽取共享：register_dom_callbacks 从 renderer/browser 两份 251 行的私有
   副本抽到 zero-engine::js_dom_bridge::register_dom_callbacks（pub）。
   zero-engine 加 zero-script-sandbox 依赖（叶 crate，无环）。renderer/
   browser/reftest 三处共用，消除第三份拷贝。
2. reftest 接线：新增 apply_scripted_dom_mutations(html, base_dir) 替换
   execute_scripts。流程：extract_page_scripts + extract_onload_handlers →
   V8Sandbox(persistent_context) + register_dom_callbacks + generate_js_dom_shim
   → 按序执行内联/外链脚本 → 派发 load 事件（执行 <body onload> handler 体
   + window 'load' 监听器）→ apply_mutations_to_html → 用 mutated HTML 重渲染。
   shim 的 setTimeout 经 microtask 立即跑（V8 execute 返回前
   perform_microtask_checkpoint）。
3. shim 补 insertBefore（见下）。

测量（make reftest-oracle DIR=css/CSS2，6232 案）
-------------------------------------------------
- 基线 R916：3009/6232 = 48.3%（oracle-pass z_vs_chr<1%）
- R917 接线后：3010/6232 = 48.3%（净 +1）
- DOM mutation 触发广度：118 个 case 产生 mutation（共 2278 条）
- insertBefore 失败：64 → 0（shim 补全后）

关键调查：为何聚合持平（+1）
---------------------------
A. background-root-101/102（head+body 相邻兄弟选择器 + body 背景传播）
   即便 mutation 正确应用（head→class="after"，实测 `<head class="after">`
   已写入 mutated HTML），渲染仍 ~100% 发散。逐项隔离发现：
   - 最小 HTML + CDATA + head 子元素 + DOCTYPE 全部正确渲染（绿色/红色）。
   - 真实 background-root-101.xht 完整文档渲染 body 盒内 (400,30) = 灰
     216,216,216（非红非绿），canvas (400,300) = 白 → body 背景在完整真实
     文档中不正确染色 / 不传播到 canvas。
   - 此为预存在的 CSS 渲染 bug，影响**未变异**文件（head=before 时也应红
     却白），非 JS wiring 所致，独立多会话调查。
   - R916「手动 post-JS = 1.51%」可能用了更简洁的手工 HTML 或不同渲染路径。

B. insertBefore 缺失（已修）：118 个 mutating case 中 64 个因
   `insertBefore is not a function` 中断 DOM 构建（createElement/
   createTextNode/appendChild 工作但 insertBefore 失败致结构不完整）。
   R917 补 shim insertBefore（+ __zw_insert_before[_handle] 回调 +
   DomMutation::InsertBefore[_ByHandle] + apply_dom_mutations 处理 +
   proxy 暴露 __zwSelector）后失败归零。

残余 yield 阻塞（次级渲染 bug）
-----------------------------
即使 DOM 正确构建（insertBefore 全工作），动态内容 reftest 多不翻转，
因渲染层对 JS 动态构建的结构（动态生成的 span/div 列表、动态样式切换）
有次级缺口。聚合 +1 反映：DOM-mutating JS 现在正确执行，但下游渲染/布局
对动态结构的支持是下一个 yield 杠杆（独立多会话）。

门禁
----
- make test：exit 0（全绿）
- make product-smoke：welcome 16.11%（< 20% DC-13 gate，零回归）
- cargo clippy --workspace --all-targets -D warnings：clean
- cargo fmt：clean

意义
----
reftest harness 从「裸 sandbox 忽略 DOM 变更」升级到「真正执行 DOM-mutating
JS（含 insertBefore）并渲染 post-JS 态」。这是 DC-1（reftest 基础设施）
的真实正确性提升——harness 现在能驱动 118 个 DOM-mutating case 的 JS。聚合
reftest 通过率受次级渲染 bug 阻塞（独立 lever），但 harness 的 JS 执行能力
本身达到正确，为后续渲染修复解锁 yield。

========================================================================
R917 后续：dom serializer raw text 转义 bug 修复（同 session）
========================================================================

R917 调查 background-root-101 head+body 背景在完整真实文档不染色时，定位到
真正的根因 = **zero_dom serializer 对 raw text 元素内容的 HTML 转义 bug**：
`serialize_node_inner` 对所有 `Text` 节点一律 `escape_text`（转义 `&`/`<`/`>`），
但 `<script>`/`<style>` 是 raw text 元素，内容应原样保留。

后果链：
1. `apply_mutations_to_html`（R917 接线的核心）= parse HTML → apply_dom_mutations
   → `Document::outer_html` 序列化回 HTML。
2. `<style>` 内的 `<![CDATA[`（XHTML 常见）被序列化成 `&lt;![CDATA[`。
3. 再次 parse 时，CSS 解析器首字符是 `&lt;`（5 字符实体），错误恢复贪婪吞噬
   到首个 `]` → CSS 规则全被破坏 → body 背景不应用 → 渲染白/灰。
4. 这也解释了为何 R917 接线对 background-root 簇无效——roundtrip 破坏了 CSS。

实证（探针）：真实 background-root-101.xht 经空-mutation roundtrip 后，
`<style>` text_content 从 `<![CDATA[\n head.before + body {...}` 变成
`&lt;![CDATA[\n head.before + body {...}`（`<` 被转义）。

修复（crates/dom/src/serializer.rs）：
- `serialize_node_inner_ctx` 新签名带 `parent_tag: Option<&str>` 上下文。
- Element 序列化子节点时传当前标签名（小写）。
- Text 节点：父为 raw text 元素（script/style）→ 不转义（原样）；否则 escape_text。
- `inner_html` 同样传父标签上下文（对 `<style>` 取 innerHTML 不转义 CSS）。
- 新增 `is_raw_text_element(tag)` = script | style（textarea/title 是 rcdata，
  `escape_text` 对它们正确 round-trip，故不在此列）。
- 新增 2 回归测试：test_raw_text_element_content_not_escaped +
  test_normal_text_still_escaped。

修复后验证：
- background-root-101/102/103 oracle：~100% → **2.01%**（接近 R916 的 1.51%
  目标；残余 = 粗体文字 font/AA 噪声）。Roundtrip 后 `<style>` text_content
  正确保留 `<![CDATA[`，CSS 规则应用，head=after → body 绿。
- 这 3 案降到 2% 仍未过 oracle 1% 阈值，故聚合 CSS2 oracle 仍 3010（持平）；
  但修复本身是真实的 serializer 保真度提升，影响所有 script/style 序列化
  roundtrip（含 JS DOM-mutation 路径 + innerHTML 应用）。

门禁：make test exit 0（dom 758 含 2 新测试）；make product-smoke welcome
16.11%（零回归）；cargo clippy --workspace --all-targets -D warnings clean；
cargo fmt clean。

意义：dom serializer 对 raw text 元素的正确序列化是 JS DOM-mutation 路径
（apply_mutations_to_html）和 innerHTML 应用的基础保真前提。修复后 R917 的
JS wiring 才能在含 CDATA 的 XHTML 测试上真正生效。
