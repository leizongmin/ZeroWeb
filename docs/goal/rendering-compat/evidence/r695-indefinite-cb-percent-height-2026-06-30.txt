============================================================
1. 缺口（anchor）
============================================================
css/CSS2/normal-flow/height-percentage-005.xht — chromium-Oracle 88.42%

结构：
  div#grandparent {height: 0px}      ← 明确（0）
    div#parent                      ← height:auto → 不明确 CB
      div#child {height: 100%}       ← CB=parent 不明确 → 应 compute-to-auto
        img {height: 100%}           ← CB=child（现 auto）不明确 → auto → 固有 96px

参考：ref-filled-black-96px-square.xht（96px 黑方块）。chromium 把整条 %height 链
collapse 到内容/固有（img=96×96），因每级 CB 都不明确。

ZW 旧行为（LAYOUT_DUMP 实证）：
  grandparent h=0（正确）
  parent      h=784   ← auto，但被 child 的 %height 反推拉到 784
  child       h=784   ← height:100% 被 taffy 回退到 CB **宽度**（body content width=784）
  img         h=784   ← 同上
根因：taffy 0.7 对「百分比 height + 不明确 CB」回退到 CB 宽度解析（非规范）。
ZW converter 无条件把 height:Percentage → taffy Percent，无 CB 明确性感知。

============================================================
2. 修复（apply_indefinite_percent_height_to_auto，engine.rs）
============================================================
新增两趟 pass，复用既有 apply_intrinsic_content_sizing 的「set_style + mark_dirty
+ 重跑 taffy + 重新 extract」基础设施（compute_with_img_sizes 步 3.2，与 3.1 共用
一次重算）。

机制：自上而下按**样式**判定 CB 高度明确性（与 clamp_percentage_max_height 的
my_definite_content_height 同语义）：
  - height:Px → 明确（按 box-sizing 折算内容高），供子元素
  - height:Percentage + CB 明确 → 解析为百分比（明确）
  - height:Percentage + CB 不明确 → **compute-to-auto**：改写 taffy size.height=Auto
  - height:Auto / Em / Rem → 不明确（normal-flow 块）
对改写为 auto 的**替换元素**同时补设固有绝对尺寸（img_intrinsic_sizes；无 HTML
width/height 属性时 taffy style 仅含 aspect_ratio，缺绝对值）。

关键洞察：第二趟 taffy 重算**自动**正确处理非替换块（内容高度）与替换元素（固有
尺寸），无需手工重算内容高度——只需在第一趟把 %height 改成 Auto + 补替换元素固有。

范围限定（防回归）：
  - 跳过 abspos（position absolute/fixed）—— 由 adjust_absolute_pct_to_viewport 处理
  - 跳过 flex/grid item —— 其 %height 有独立 stretch 语义（taffy-gated，R691）
  - 仅水平书写模式（垂直模式块轴为 X，高度语义不同）
  - 常见 html,body{height:100%} 不受影响：根 CB=视口（明确），整链明确
