# R486 — 伪元素渲染地基（parser 分类 + matcher 路由 + 单测）；compute+layout 多会话拆分

**日期**: 2026-06-21
**前置**: R485 定位伪元素渲染 = CSS2 最大 coherent 缺口（463 case 单一根因）。
**目标**: 实现 `::before`/`::after` generated-content 的地基（4 子系统中的前 2 个：parser + matcher），用单测验证；compute+layout 因 plumbing 规模拆到下轮。

---

## 1. 本轮交付（parser + matcher 地基，2/4 子系统）

### 1.1 Parser：单冒号伪元素分类（`crates/css-parser/src/parser.rs`）

CSS2 允许 `:before`/`:after`/`:first-letter`/`:first-line` 单冒号语法（等价 CSS3 `::`）。原实现把单冒号 `:name` 一律归为伪**类** `PseudoClassSelector::Simple(name)` → 无元素匹配 → 规则永不生效（R485 根因）。

**修复**：单冒号非函数分支，4 个伪元素名归为 `SubclassSelector::PseudoElement`：
```rust
match name.as_str() {
    "before" | "after" | "first-letter" | "first-line" =>
        SubclassSelector::PseudoElement(PseudoElementSelector::Standard(name)),
    _ => SubclassSelector::PseudoClass(PseudoClassSelector::Simple(name)),
}
```
双冒号 `::` 原已正确（parser.rs:302-309）。`node --check` 不适用（Rust）；`cargo build -p zero-css-parser` 通过。既有测试 `coverage_round3.rs:34` / `matcher/tests/pseudo.rs:388` 已直接构造 `PseudoElementSelector::Standard("before")`，与本改动方向一致，零冲突。

### 1.2 Matcher：伪元素声明路由（`crates/style-system/src/matcher/mod.rs`）

原 `collect_from_rules` 对尾部带 `::before` 的选择器，`matches_compound` → `matches_subclass(PseudoElement)` 返回 false → 整个选择器不匹配 → 声明丢弃（content 永不到达任何 ComputedStyle）。

**新增**（3 个 pub/fn + 1 个 param 线程化）：
- `selector_pseudo_element(selector) -> Option<&str>`：返回尾部伪元素名（最后一个复合选择器的最后一个子类）。
- `matches_selector_for_pseudo(doc, element, selector, name)`：尾部伪元素 == name 时，克隆选择器 pop 尾部伪元素得「主体」，复用 `matches_selector` 匹配元素。特异性用原选择器（含伪元素贡献）。
- `collect_pseudo_declarations_with_media(doc, element, stylesheets, media, container, pseudo_name) -> Vec<MatchingDecl>`：收集元素指定伪元素的声明。
- `collect_from_rules` 增 `pseudo: Option<&str>` param（线程化 5 个递归调用 + 2 个 pub caller）。`pseudo=None` 时行为与改动前**完全一致**（既有路径传 None）→ **零回归**。

`cargo build -p zero-style-system` + `cargo test -p zero-style-system --no-run`（编译不运行）通过。

### 1.3 单测（`matcher/tests/pseudo.rs`，2 个端到端）

- `test_pseudo_element_declaration_routing`：`div:before { content:"X"; color:red }` → (1) parser 归伪元素 `selector_pseudo_element==Some("before")`；(2) `collect_pseudo_declarations_with_media(...,"before")` 收到 content+color；(3) 元素本体 `collect_matching_declarations_with_media` 不收 content（伪元素规则不作用于元素本体）；(4) after 槽为空。
- `test_double_colon_pseudo_element_routing`：`div::after { content:"Z" }` 双冒号等价路由到 after 槽。

**成功标准**（code-guidelines #4）：单测证明 parser+matcher 端到端把伪元素声明正确路由到伪元素槽、不污染元素本体。由 `make test` 验证全绿（含 12280 既有测试零回归）。

## 2. compute+layout 拆分到下轮（plumbing 规模实证）

伪元素渲染的后 2 个子系统（compute 伪 ComputedStyle + layout 合成盒）需要把伪样式从 style-system 传到 layout-engine。两条 plumbing 路径均规模可观，单轮强行实现回归风险高（12280 测试），按 code-guidelines #1/#2 拆分：

### 路径 A：ComputedStyle 加 `before_pseudo`/`after_pseudo` 字段
- 优点：build_subtree 已持有元素 ComputedStyle（tree.rs:393），直接读字段，零签名改动。
- 风险：`compute_inherited_style_with_quirks` 构造**全新** `ComputedStyle::default()`（非父字段拷贝）→ 继承不传播，**安全**；但仓库有 **~7 处字面 `ComputedStyle { ... }` 构造未用 `..Default::default()` 展开**（converter/tests/coverage_round3.rs ×5、engine/tests/coverage.rs ×1、engine/tests/mod.rs ×1）→ 加字段会破这些测试，需逐个补字段或改展开。

### 路径 B：side-map `HashMap<NodeId, PseudoElementStyles>` 线程化
- 优点：零 ComputedStyle 结构改动 → 不破字面构造。
- 风险：需线程化 `compute_with_img_sizes`（engine 入口）+ `build_layout_tree`（**已有 5 个参数、10+ 测试 caller**）+ `build_subtree`（7 个递归调用点）+ engine 4 处 compute_styles caller。机械但面广。

**裁决**：两路径均非单轮可安全完成。本轮交付地基（parser+matcher+单测，已验证），下轮择一路径做 compute+layout。推荐路径 A（build_subtree 零签名改动，仅需补 ~7 处字面构造——机械可控），并把 default display=Inline（已确认 `default_impl.rs:14`）利于 `::before`/`::after` 默认 inline。

## 3. 影响与下一步

- **零渲染变更**（matcher None 路径不变；compute+layout 未触）→ reftest 数字不动（CSS2 44.1% / 10-dir 36.2% 不变），符合地基定位。
- **下轮**：路径 A 实现 compute（伪 ComputedStyle，跳过 inline+UA、parent=元素自身样式、save/restore custom_properties）+ layout（build_subtree 读 `computed.before_pseudo`，content:String 时合成文本盒；content:None/Normal 不生成盒）→ 用 generated-content 簇 chromium-oracle A/B 验证 → 目标 CSS2 44.1% 上拉（generated-content 58 case + 连带 first-letter-punctuation 405 case 中 content-driven 子集）。
- first-letter/first-line（IFC 耦合）仍 Phase-A 多会话，不在下轮 scope（下轮只做相对独立的 before/after generated-content）。
