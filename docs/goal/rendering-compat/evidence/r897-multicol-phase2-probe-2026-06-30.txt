R897 multicol Phase 2 入口 probe — 单层 multicol + 单一 block 子元素 breaking 跨列
日期: 2026-06-30
目的: 为 ColumnFragmentationContext 设计文档提供经验证据（单层 R109-independent 碎片化子集的真实缺口）

== Probe A: height=60px, 12 lines × 16px Ahem, column-count:3, column-fill:auto ==
结构: <div class="mc">(column-count:3;column-fill:auto;height:60px) > <div>12 行文本</div>
ZW 渲染: col0/col1/col2 各 4960 dark px（均匀），但 col0 文本连续 y=[8,71]=64px=4 行
结论: ZW 把 12 行按 4-4-4 分配，每列 64px **超出** 60px 列高（overfill，列边界未裁断行）
对比 chromium 期望: 列高 60px / 16px = 3.75 行 → 每列 3 行（避免裁断），余下溢出

== Probe B: height=48px (= 3 行 × 16px 整数倍), 同结构 ==
ZW 渲染: col0/col1/col2 各 y=[8,55]=48px=3 行（共 9 行），y>56 无 dark px
结论: ZW 渲染 floor(48/16)=3 行/列 × 3 列 = 9 行；**第 10-12 行被静默丢弃**（不渲染、不溢出）
对比 chromium 期望: 3 行/列填满 3 列 = 9 行，第 10-12 行应溢出 multicol 盒（overflow:visible 默认）

== 根因（代码 + 探针实证） ==
assign_children_to_columns_with_breaking（multicol.rs:336）对单一超高 block 子元素：
- max_col_height=48, child_height=192(12行), col_count=3
- 产 3 fragments: col0(off0,vis48) / col1(off48,vis48) / col2(off96,vis48)
- 覆盖 child y=[0,144]（前 9 行），child y=[144,192]（第 10-12 行）**在 assignment 阶段丢弃**
- 循环在 current_col=2（末列）停止（current_col+1 < col_count 守卫），余量永不分配
paint 侧 vertical-window（mod.rs:840）按 fragment 重绘 child + 列裁剪，本身工作（9 行正确分布），
但无法恢复 assignment 阶段丢弃的余量。

== 关键发现（区别于 nested case R201） ==
- nested multicol（multicol-breaking-001/002/003）：R201 实证「文本只在 col0」（inner 自身是 multicol）
- 单层 + 单 block 子（本 probe）：文本**正确分布到各列**，但**余量丢弃 + 非整数高度 overfill**
- 即：单层 slice 的缺口 ≠ 「文本不出现在非主列」，而是 **assignment 阶段静默丢弃 + 列高未严格 respected**
- 此 slice 真实存在且有可测几何缺口（区别 column-aware-IFC-spec Phase 1 的 0-case 停止）

== 对设计的影响 ==
ColumnFragmentationContext 须在 layout 侧（非 paint）：
(a) 精确计算每列容纳的行盒（respected 列高，避免 overfill）；
(b) 处理超出 col_count×列高的余量（overflow 到 multicol 盒外，非丢弃）；
(c) 为后续 Phase 2b（mixed content）/ Phase 3（nested）提供统一 IFC 碎片化接口。
Phase 1 = 接口 + dormant 字段（net 0，守 multicol-fill-auto-001），镜像 font-bridge R885。
