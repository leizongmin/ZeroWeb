R645 — SEA 词典分词文字 fallback line-breaking + IFC 测量路径 white-space 尊重·LANDED

================================================================
背景（css-text near-miss 簇扫描）
================================================================
R644（Cc control-char 可见性）后继续 css-text near-miss 簇扫描。下一批 0.00% FAIL
mismatch 簇：line-breaking-024/025/026/027（Khmer/Lao/Thai/Burmese fallback 断行）。

4 测均为 <link rel="mismatch">：test.html 的 .test（blue, normal white-space）应换行，
ref.html 的 .test（blue, white-space: pre）不应换行 → 二者不同 = PASS。
基线实测 4 测全 0.00% FAIL（test.png == ref.png 字节相同）。

================================================================
根因（双层）
================================================================
像素 dump（line-breaking-026 Thai）揭穿：test/ref 均渲染 .test 蓝边框为 8 行高
（14784 blue px = 96px 边框宽 × ~8 行），二者完全相同 → 0.00%。

【层 1 — 缺 SEA fallback 断行】
split_into_words 把无空格的 SEA 文本（Thai/Lao/Myanmar/Khmer）当作 1 个不可拆单词
（非 CJK → 走 split_whitespace 单词分支），无任何断行机会 → .test 溢出单行。
CSS Text 3 §line-break-details：需词典分词的文字，UA 若无词典能力**必须**做某种
fallback 断行（不允许溢出）。ZeroWeb 无 SEA 词典 → 须按字符断行作 fallback（同 CJK）。

【层 2 — IFC 测量路径忽略 white-space（pre-existing bug，被层 1 掩盖）】
即便实现层 1 的 per-char 断行，ref.html 的 .test（pre）仍被测成多行——因为
measure_text_content（taffy MeasureFunc）+ remeasure_text_with_float_exclusions +
remeasure_inline_only_containers 构造 IFC 时**从不传 white-space**（no_wrap 恒 false）。
故 pre/nowrap 容器在**测量高度**时被当可换行处理 → box content_height = 多行 →
边框多行高。该 bug 长期被「单 token 无法换行」掩盖；层 1 让每个 SEA 字符成为独立
断行点后才暴露（pre 容器被测成 8 行）。

paint 路径（text.rs:744）与 store 路径（inline_finalization.rs:377）早已正确解析
white-space，唯独 3 个测量路径漏了。

================================================================
修复
================================================================
【层 1】crates/layout-engine/src/inline/text_metrics.rs：
  - 新增 is_sea_word_script(c)：Thai U+0E00-0E7F / Lao U+0E80-0EFF /
    Myanmar U+1000-109F / Khmer U+1780-17FF。
  - 新增 is_per_char_break_script(c) = is_cjk_character(c) || is_sea_word_script(c)
    （集中判定，供 split_into_words 3 处调用点）。
  inline/mod.rs split_into_words：3 处 is_cjk_character → is_per_char_break_script
  （preserve_whitespace 分支 + normal 分支 has_cjk 检测 + 内层 per-char 拆分）。
  **仅影响断行点判定，不影响 advance 宽度**——estimate_char_width 仍把 SEA 当
  「其他 Unicode」0.5×fs（SEA 非全角），故不影响非溢出文本。

【层 2】crates/layout-engine/src/inline_finalization.rs：
  - 新增 resolve_no_wrap_for_ifc_measure(style) -> bool（Pre|Nowrap → true）。
  - measure_text_content / remeasure_text_with_float_exclusions /
    remeasure_inline_only_containers（含 balance col_ctx）4 处 IFC 构造补
    .with_no_wrap(no_wrap)。

  **关键 scoping**：仅传 no_wrap，**不**传 preserve_whitespace。初版同时传 preserve 致
  letter-spacing-201（pre-wrap + 多空格）测量行断变化而回归（base PASS→with FAIL）。
  no_wrap 是修 pre/nowrap「测量时不换行」的最小充分条件；preserve 仅影响空白折叠，
  对 box 高度测量非必要，测量路径保持 preserve=false（与历史一致），空白保真由 paint
  路径负责。Scoped 后 letter-spacing-201 恢复 PASS（4.39%），7 wins 全保。
