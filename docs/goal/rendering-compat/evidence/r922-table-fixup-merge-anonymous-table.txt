R922 — table-fixup merge（CSS2 §17.2.1.1 连续孤立 table-internal 兄弟合并到一个匿名表）
================================================================================================

日期：2026-07-01
承接：R919 续 3（精确诊断 + 修复指针）

背景
----
R919 named-access shim 让 css-tables/fixup-dynamic-anonymous-inline-table-001
的 JS（`rm.remove()`）正确执行，暴露一个预存 table 渲染 bug：

结构 = 外层 `<span>`(inline) 含两个 `display:table-row-group` 兄弟（各含
100×50 绿 cell）+ 中间 `<span id="rm">`；脚本 `rm.remove()` 后两 row-group
相邻，CSS2 §17.2.1.1 要求**合并到一个匿名 inline-table**（100×100）。

ZW 渲染 100×50（仅一个 row-group）；oracle 100×100（两 row-group 堆叠）。
LAYOUT_DUMP 实证：两个 `span.group` 都 `abs_y=51.0 h=50.0`（**重叠**非堆叠）。

根因（R919 续 3 定性）
----------------------
`adjust_table_layout_inner`（table.rs else-branch）对每个孤立 table-internal
子元素**独立**调 `layout_table`，连续 row-group 兄弟未按 §17.2.1.1 合并到一个
匿名表（`mark_anonymous_table_roots` 仅置 per-node `is_anon_table_root` BFC 标志，
不创建合并包装盒）。每个 row-group 各自成独立 anon 表，落 inline `<span>` 内都
在 y=51 重叠（R109 block-in-inline 不堆叠）。

实施（crates/layout-engine/src/table.rs，net 源码）
---------------------------------------------------
1. **else-branch run 检测**：`adjust_table_layout_inner` 改为先识别连续孤立
   table-internal 兄弟的 run（run_len ≥ 2 时合并，=1 走原逻辑）。
2. **`merge_orphan_table_run` 新函数**：
   - 计算原 run 的垂直 footprint（max bottom − min top，正确反映重叠）；
   - drain run 子元素到新匿名 `LayoutBox`（`LayoutBox::default()`，无 node_id，
     `is_anon_table_root=true` + `is_block_level=true`），继承首位 child 的
     x/y/width + 父 writing_mode；
   - 插入到 run_start；
   - `layout_table(wrapper)`：build_grid 正常路径（wrapper 无 node_id → get_display
     返回 None → is_orphan=false → 正常路径收集多个 row-group → 多行堆叠）；
   - 按 `new_height − old_footprint` 差异推进后续兄弟 y + 调整父高度
     （镜像 reflow_siblings_after_table_height_change 但用 footprint 而非 sum，
     正确处理原重叠情形）。
3. 匿名包装盒无 node_id：paint/layout 全 None-safe（`let Some(style) = styles.get
   (&node_id)` 模式，无 unwrap/expect），wrapper 无背景/边框，paint 递归其子
   （row-group → row → cell）正常。

意义
----
CSS2 §17.2.1.1 匿名表对象生成的核心缺口补上：连续孤立 table-internal 兄弟现正确
合并到一个匿名表（多 row-group → 多行堆叠），而非各自独立成表重叠。这是 R919
named-access shim 暴露的 table 渲染 bug 的直接修复，css-tables 净 +4。零回归
（CSS2 tables 380 案字节不变 + welcome 不变 + make test 绿）证明 merge 仅作用于
其目标结构。

注意：本修复是 CSS §17.2.1.1 的「连续兄弟合并」部分；R109 block-in-inline
堆叠（独立的匿名块盒生成）仍未实现，但 merge 绕过了该需求（合并后只有一个
block-level 匿名表，无需多块堆叠）。
