# R488 — 伪元素注入精度诊断：text-content 95.5% 正确，box-property 24-case 局限 + 行定位 plateau

**日期**: 2026-06-22
**前置**: R487 ::before/::after 4 子系统完整、content 渲染，但 generated-content chr<1% net-flat（83→82）。
**目标**: 诊断 ~0.08pp 注入精度偏差根因，判断 clean-fix 可行性。

---

## 1. 诊断方法

PIL 逐案对比 ZeroWeb-test（R487 注入后）vs chromium oracle（R484 捕获），分析 diff bbox + 采样差异像素 + 定位文本行 y 坐标。3 个代表案：after-content-display-001/002（diff 微增）、after-inheritable-002（7.20→3.84% 改善）。

## 2. 发现 1：box-property 伪元素不渲染（DOM 注入 text-node 局限）

**根因实证**：`crates/layout-engine/src/tree.rs:625-634` 非 flex/grid 块容器子节点处理**仅遍历元素子节点**（`NodeKind::Element`），**文本节点被跳过**（由 IFC 测量路径 `measure_text_content` 直接读 `doc.get(parent).children` 文本节点处理）。

R487 的 DOM 注入把伪元素做成**文本子节点** → 文本内容（color/font/inline）经 IFC 正确渲染，但**伪元素的盒属性（border/background/padding/width）无处挂载**（文本节点无盒）。

**实证**：`after-inheritable-002`（`div:after{color:green;border-color:orange;content:'PASS PASS'}`，期望绿字 + 橙边框盒）→ ZeroWeb 渲染 "PASS PASS" 文本但**橙边框缺失**（chromium 有、ZW 无）。

**量化**：generated-content 435 测试文件中 **24 个（5.5%）** 在伪元素上声明 border/background/padding/width/height/margin → 受此局限影响；**411 个（94.5%）纯文本伪元素已正确渲染**（R487 文本注入覆盖）。

**非 clean-fix 原因**：修复须把盒属性伪元素注入为**带样式的 inline 元素 + 文本子节点**（元素子节点经 build_subtree 元素路径处理、style 含 border），但 inline 元素的 border 渲染依赖 IFC inline-element 处理（R109/IFC 未知数），且元素注入改变布局结构有回归风险。**建议下轮用 hybrid 方案降风险**：检测伪元素是否有盒属性，有则注入 inline 元素、无则保持文本节点注入（当前），blast radius 限 24 个当前已错案例。前置：先验证 ZeroWeb 是否渲染 inline 元素的 border。

## 3. 发现 2：行垂直定位偏差（plateau，非伪元素独有）

**实证**：`after-content-display-001` ZeroWeb 首行暗文本在 y=29，chromium 在 y=18（**~11px 垂直偏差**）。差异像素模式（ZW y=18 白 vs chr 灰；ZW y=32 灰 vs chr 白）= 整行下移。

**非普遍**：若 11px 偏差系统性影响所有 case，chr<1% 不会是 44.1%（会大幅低）。故为**测试特定的 margin-collapsing / body+p margin 结构**（R227 padding 双计 / R323 margin 折叠谱系），非 universal clean win。属全局字体/行度量精度 plateau（R174/R125/R471 同根源：fontdue 度量 + IFC 行定位），Phase-A 难题。

## 4. 裁决

- **伪元素 ::before/::after 文本内容渲染 = 完成 + 正确**（94.5% 纯文本伪元素经 IFC 正确渲染 color/font/inline；content:none 跳过；inline display）。R485-R487 三轮交付的功能对常见用例（文本 content）有效。
- **generated-content chr<1% net-flat（83→82）根因分解**：①box-property 伪元素 24 案不渲染盒属性（inject 局限，可下轮 hybrid 修，blast radius 小）+ ②行垂直定位精度 plateau（全局 fontdue/IFC，难）。
- **无 clean 单点 fix**：box-property 是中等复杂度（hybrid 注入 + inline-border 前置验证），行定位是 Phase-A plateau。两者均非本轮可安全完成的 clean win。

## 5. 下一步优先级

1. **box-property 伪元素 hybrid 注入**（最具体可操作 lever，~12-15 matched 案）：先验证 ZeroWeb inline 元素 border 渲染，再实现「盒属性伪元素→inline 元素注入，纯文本→文本节点注入」hybrid。blast radius 限 24 当前已错案例，降回归风险。
2. 行定位精度 = 全局 plateau（Phase-A/fontdue），勿单独攻。
3. `:first-letter`/`:first-line`（405 case，IFC 耦合 Phase-A）独立多会话。

## 6. 本轮代码变更

零（诊断轮；box-property hybrid 注入须先验证 inline-border 渲染，按 code-guidelines #1 不盲目实现）。
