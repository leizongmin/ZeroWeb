1. 方法论：dead-value 探针（R353 pattern 的系统化）
============================================================

R491–R511 的 CSS-correctness vein 共性 = 「ZeroWeb 完全未实现某 CSS spec 条款」
（§9.7 / §14.2 / Appendix E / §3.6 / §4.1.8 / content:attr / opacity-SC）。
最可靠的此类缺口检测器 = **dead-value pattern**：属性已 parse + store(ComputedStyle)
+ apply 分支齐全，但 layout-engine / paint **从不读该字段** → 渲染零效果。
补一处 consume 即可翻 failing reftest（§9.7 即此模式）。

本轮对非-CSS2 全量目录（css-tables / css-position / css-writing-modes / css-flexbox
/ css-grid / css-multicol / css-text-decor / css-fonts）系统跑 dead-value 探针。

5. 裁决
============================================================

§9.7-pattern（stored value + 恰好缺一处 consume）lever 族**在非-CSS2 全量目录趋尽**：
- 每个 dead value 均落三桶之一：(1) rustybuzz/Phase-A same-source 墙（font-feature 族，
  shaper.rs:82 单一硬阻塞）；(2) 须 IFC / stacking-context / fragmentation 管线的 pervasive
  结构改造而非单 consume 点（isolation / box-decoration-break / unicode-bidi / caption-side
  §17.4）；(3) 零 reftest footprint（scroll-container / UI 属性，静态光栅无效果）。
- 每个有真实局部 consume 点的属性均已接线。
- 产出 §9.7/§14.2 lever 的模式（stored value 恰缺一处 consume）在剩余非-CSS2 面不复现。
