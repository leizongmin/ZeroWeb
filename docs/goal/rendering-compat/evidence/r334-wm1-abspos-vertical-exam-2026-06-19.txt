实证 2：direction-rtl 镜像修复（spec-correct）
----------------------------------------------
§10.3.7 + writing-modes §7.1 推导：all-three-auto（top/bottom 即映射后的 left/right 均 auto）
时，ltr 把 inline-start 边置静态、rtl 把 inline-end 边置静态，两者最终盒位沿 inline 轴镜像：
  rtl_top = CB_inline_extent - ltr_top - height
（worked example 双证：vrl-002 ltr top=160；vrl-012 rtl top=80 = 320-160-80。）

实现（engine.rs fix_vertical_mode_abs_pos，all_inset_auto 块末尾 +10 行）：读 CB 的
direction（ComputedStyle.direction），rtl 时 child.y = (container_width - child.y -
child.height).max(0.0)。container_width 在垂直模式 = CB 视觉高度（inline 可用）= 320。

验证（LAYOUT_DUMP，Ahem 真实字体）：
  vrl-012(rtl) 修复后：span 相对 CB y=80, x=160（col 2）。worked example 期望 top=80 ✓✓
  vrl-002(ltr) 不变：span 相对 CB y=160, x=160。worked example 期望 top=160 ✓
镜像机制 spec-correct，vrl-012 现在几何完全正确。

实证 3：0 clean win —— 真阻塞 = paint-IFC 颜色（Phase A），非 positioning
--------------------------------------------------------------------------
修复后跑 abs-pos-non-replaced 子集 strict（0.1%/0.5%）：
  vrl-012(rtl): 5.03% → 3.67%（改善，但仍 fail）
  vrl-002(ltr): 1.33%（不变，fail）
  全 14 case 仍 0 strict pass。
positioning 已 spec-correct（实证 2），为何仍 fail？PNG 像素分析：
  - vrl-002 test 的 span 区域（abs [168,247]×[228,307]）= 100% red（6400px），**零 green**。
  - 整张 test 图零 pure-green 像素。
  → 绿色 "X" glyph **完全未绘制**（span 显示纯红背景，green X 不可见）。

根因（代码追踪）：div(CB) 有 `color: transparent`（隐藏 "1 2 34"），span 有 `color: green`。
paint_text（text.rs:654）用**容器** style.color 绘制其 IFC 收集的全部 inline 文本（"1 2 34 X"）
→ "X" 被当作 div 文本以 transparent 绘制 → 不可见。per-fragment 颜色覆盖逻辑（text.rs:1028
frag_color = styles.get(owner_id)…）**仅在 multicol 分支**（line 1012 「多列分支统一绘制全部
片段」）；非 multicol 的 vertical-rl CB 不触发 → span 的 green 不生效。

= goal doc 已知缺口 #3（inline formatting 所有权分裂）+ #4（Layout/Paint IFC 双路径）=
Phase A IFC 统一死锁区（R125-R213）。**WM-1 的真阻塞是 paint-IFC 颜色，非 R238 推断的
positioning**。R238 的 positioning 假设部分正确（direction 确实被忽略，镜像修复正确）但
**非 cluster 主导失败因**——positioning 修对了，cluster 仍 fail 因为 green 文本不绘制。
