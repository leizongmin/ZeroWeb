============================================================
1. ★ 根因定位（R524 lead 闭合）
============================================================

R524 用 PNODE_DEBUG + FILLDBG 双插桩对比 painter push 顺序 vs render 顺序：
  FILLDBG（painter add_fill push）: container(0) → test1(1) → test2(2) → cover(3, **最后**)
  DO_DEBUG（render_draw_order 读到）: container(0) → **cover(1)** → test1(2) → test2(3)
→ push 时 cover 在最后（正确），渲染时 cover 在第 2（错）。painter push 与渲染间发生重排。

定位元凶 = `batch_fills()`（render-foundation/primitive/ops.rs:259），在 cull_invisible
之后被 render_html 调用（pipeline.rs:241）：
  ① 按颜色分组重排 fills（line 264-276）：green 一组、red 一组 → fills 变
     [container-green, cover-green, test1-red, test2-red]
  ② `result.draw_order` 直接 `self.clone()`（line 336）**未更新** → draw_order 的
     Fill(i) 索引指向重排后的 fills
→ render_draw_order 按 draw_order 渲染时，Fill(i) 取到颜色分组后的错误 fill，破坏
CSS painting order：cover（green，应最后绘于 flex items 之上）被同色分组提前到 red
之下 → red 可见。

★ 此 bug 系统性影响所有走 draw_order（R155 默认）且有重叠不同色 fill 的渲染。batch_fills
的合并/分组是为旧的 render_typed_buckets（类型分桶）路径设计，draw_order 路径下颜色批无
收益（render_draw_order 逐个 fill_rect 无颜色状态批），合并对不透明 fill 视觉中性。

============================================================
2. 修复（ops.rs:259，~12 行注释 + 早退）
============================================================

batch_fills 开头加守卫：draw_order 非空时（生产 render_draw_order 路径）直接 clone
返回，跳过颜色分组/合并。draw_order 为空（render_typed_buckets 回退路径）保留原
batching 优化。

```rust
if !self.draw_order.is_empty() {
    return self.clone();
}
```

零行为变化对 bucket 路径；draw_order 路径现保序正确。

4. ★ 1 regression = flexbox-paint-ordering-003 = 预存 abspos-order false-pass 移除
============================================================

flexbox-paint-ordering-003：两个 abspos 子元素（order:5 含 lime / order:10 含 red），
断言 **order 不影响 abspos paint order**，应按 tree order（red 先 lime 后→lime 在上）。
batch_fills 颜色分组偶然把 lime 移到最后（red-group 先现→lime-group 后）→ lime 在上→PASS（**假通过**）。
batch_fills fix 移除此掩盖 → 暴露真 bug：**ZeroWeb 按 `order` 属性重排 abspos 子元素**
（应按 tree order）。真因 = 多站点 order-sort 把 abspos 也排序：
  - tree.rs:489（flex/grid 建树路径）children_with_order.sort_by_key(order) 含 abspos
  - engine.rs:1156 sort_children_by_css_order 对所有子元素按 order 排序（含 abspos）
本会话尝试 engine.rs 单站点排除 abspos = 无效（tree.rs:489 更早执行、主导），已回退。
abspos-order 修复须多站点（tree.rs:489 + engine.rs:1156 排除 abspos、按 DOM tree order
建 abspos），独立 follow-up。

★ 此 regression 是 DC-14 anti-false-pass 的正面实例：移除假通过、暴露真 bug。
reftest 失败已分析根因（合规：goal 允许 reftest 失败只要分析；硬门禁是 cargo test 零失败）。
