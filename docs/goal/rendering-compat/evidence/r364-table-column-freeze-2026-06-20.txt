R364 — table 显式 width 列冻结 + min-content floor（CSS 正确性修复，chromium-Oracle 方向改善）
Date: 2026-06-20 (R364) | 触发案：table-cell-width-0（self-source 31.57% FAIL）

================================================================
诊断（REFTEST_DEBUG + LAYOUT_DUMP + PIL 对 chromium Oracle）
================================================================
table-cell-width-0 的 9 个子表，**definite-width 表**（width:100% / width:100px，table 4-9）
全部错：显式 width 单元格（width:0/2px/20px）的列被按比例扩展撑大，而非保持其宽度。
例（修复前）：table 6（width:100%）td.big-positive-width(20px) → 列宽 529.7px（应为 20），
剩余分给 td.normal → 254.3（应为 764）。auto-width 表（1-3）正确（不触发扩展）。

根因 1（compute_column_widths 扩展填满块，table.rs）：
  has_explicit_width && total < available 时，旧代码按比例扩展【全部】列
  （ratio = available/total），把显式 width 列也撑大。
根因 2（cell_used_width 显式分支）：显式 width < min-content 时直接返回 explicit，
  不 floor 到 min-content（width:2px cell 内容 "1" 需 9.6px → 旧列宽 2px，内容溢出列）。

================================================================
修复（2 处，table.rs compute_column_widths）
================================================================
(A) R364 扩展冻结：新增 col_explicit[col_count] 标记（Pass 1 中单元格 style.width 非 Auto
    即标记）。扩展填满块改为：显式列冻结（不吸收剩余），仅 auto 列按当前宽比例吸收剩余；
    全部列均显式时回退按比例扩展（避免留白）。
(B) R364b min-content floor：cell_used_width 显式分支返回 base.max(intrinsic)，
    显式 width 不小于单元格 min-content（CSS 表格列宽下限 = 内容 min-content）。

  故 REF 的 auto 行（1-3）渲染 784 宽，TEST 的 auto 表渲染 ~23 宽 → 同源发散。
  TEST 正确但 REF 错 → self-source 假阴性（非 TEST bug）。

裁决
================================================================
