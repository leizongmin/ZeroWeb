R784 — canvas 替换元素 aspect-ratio sizing（css-flexbox +1 PASS，aspect-ratio-intrinsic-size 簇 15.67%→1.86%）
================================================================================

承 R783 CONTINUE「替换元素 aspect-ratio 宽修复」。R783 修了 inline-flex shrink-to-fit，
但 aspect-ratio-intrinsic-size 簇（001/003/006/008）仍 15.67%（cluster 内容宽错）。
R784 定位第二层 bug。

## 真因（两层）

1. **`<canvas>` 未被替换元素 sizing 处理**：`apply_replaced_element_sizing`
   （tree.rs:189）`if tag != "img" { return; }` 仅处理 `<img>`。canvas 当普通 block →
   拉伸填满父宽（aspect-ratio-intrinsic-size-001 的 canvas 渲染 784px，应 100px）。
2. **HTML-attr 分支 auto 侧推导错**（即使 img）：both-attrs 分支（line 220-228）auto 侧
   无条件设为 HTML 属性绝对值（`size.width = HTML w` when css_w_auto），而非按固有宽高比
   从显式侧推导。canvas HTML 10×10 + CSS height:100%（显式）+ width:auto → 旧设 width=10
   （应按 1:1 从 height 100px 推导 100px）。

## fix（crates/layout-engine/src/tree.rs，2 处）

1. tag 检查 `img` → `img | canvas`（video/iframe 等无 driving reftest 暂不处理）。
2. both-attrs 分支：仅当两侧 CSS 都 auto 时才用 HTML 固有尺寸；一侧显式（可为 %）时不设
   auto 侧，由 taffy 按 aspect_ratio 从显式侧解析后推导（auto 侧推导逻辑与 decoded-intrinsic
   分支 line 273-285 的显式推导一致）。
