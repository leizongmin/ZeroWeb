R787 — abspos/fixed CB origin content→padding-box（margin-padding-clear +4 PASS）
================================================================================

承 R786 CONTINUE「修 abspos CB origin」。R786 用 decisive minimal test 定位：abspos 元素
被定位在 CB 的 content-box origin（应为 padding-box，CSS §10.1）。R787 实施修复。

## 真因（R786 已定位，R787 实施）

extract_layout（engine.rs:821-828）对 abspos/fixed 子节点 `continue` 跳过
`child.x -= content_x`（content_x = border+padding）换算，保留 taffy 的 location
（border-box 相对、content-box origin）。绘制层（painter）对子节点统一加父 content origin
（border+padding），对 abspos 双计 padding → abspos 落在 content-box origin（多 padding）。

旧设计是「abspos border-box 相对 + 绘制层双计补偿自洽」workaround。R787 改为：abspos
也减去父 padding（不减 border+padding），使其 LayoutBox.x/y 变为**父 content-box 相对**
（与普通子节点一致），绘制层统一处理不再双计。

## fix（crates/layout-engine/src/engine.rs，1 处）

extract 的子节点坐标换算：abspos/fixed 从 `continue` 改为 `child.x -= padding_left;
child.y -= padding_top`（减 padding 不减 border → padding-box origin，仍 border-box 相对
但与普通子的 content-box 相对约定统一）。viewport-CB abspos 由 adjust_absolute_pct_to_
viewport 覆写 x/y，此处调整被覆盖，无冲突。
