# advance-width 估计误差诊断（R222）

**日期**: 2026-06-17
**目的**: 量化 layout-engine `estimate_char_width` 启发式（字母 0.55×fs、数字 0.5、标点 0.4、空格 0.25）与真实系统字体 advance（FontLoader::measure_advance，fontdue）的系统性误差，为 advance-width plumbing（R221 识别的 183-case 1-3% 噪声桶）提供数据依据。

## 结论

estimate_char_width 的**逐字符误差极大**（±44%~98%）：
- 宽字母 W/m 实际 ≈0.97-0.99×fs，estimate 0.55 → **欠估 44%**
- 窄字母 i/l 实际 ≈0.28×fs，estimate 0.55 → **过估 98%**
- t/f 实际 ≈0.35-0.39，estimate 0.55 → 过估 40-56%
- 数字实际 ≈0.636，estimate 0.5 → 欠估 21%
- 标点 ./, 实际 ≈0.318，estimate 0.4 → 过估 26%

总和部分抵消（-6.9%），但**逐字符累积定位**完全错误（如 "Will" 按 0.55 均匀放置，实际 W 应近全宽、i/l 极窄）→ 致换行点错误 + glyph x 坐标错误。

## 与 R221 的关联

R221 测得 183 case 在 1-3% chromium 差异（系统性噪声）。AA 基准已排除字体光栅化。本诊断证实**根因 = estimate_char_width 逐字符误差**：布局 IFC + paint IFC + intrinsic_sizing 三处均用此启发式，导致文本宽度/换行/glyph 定位与 chromium（真实字体度量）系统性偏离。

## 修复路径（advance-width plumbing，多轮）

engine 预解析 font-family → FontId，构建 advance 源，传入 layout-engine IFC + intrinsic_sizing + paint IFC，替换 3 处 estimate_char_width 调用点为 FontLoader::measure_advance（已存在，loader.rs:289）。self-source 中性（test/ref 同改故同源 439/490 不变），但降 chromium 一致率噪声（183-case 桶）。复现：`cargo test -p zero-render-foundation --lib diag_advance_vs_estimate -- --nocapture`
