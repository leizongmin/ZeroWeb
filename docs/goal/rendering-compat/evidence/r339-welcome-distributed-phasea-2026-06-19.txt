line-height 计算（resolve_font_metrics, inline/mod.rs:341）核验 = **正确**
-----------------------------------------------------------------------
- Normal → font_size × 1.2（NORMAL_LINE_HEIGHT_RATIO=1.2）；Number(n) → font_size×n；Length Px → v。
- welcome 用**显式** line-height（1.08 / 1.5 / 1.45 / 1.25），非 `normal` → ratio 不介入；显式值 resolve 正确。
- **结论：welcome 17% 非 line-height 计算 bug**（显式值正确解析）。

真因 = 非-Ahem font ascent 近似（Phase A offset 语义）
-----------------------------------------------------
paint 路径 `v_offset = is_ahem ? 0 : font_size`（text.rs:1208，Path A；Path B 类似 baseline_fs）把 font_size 当 ascent。
对 sans-serif（welcome 字体），实际 ascent（fontdue 度量）≠ font_size → 字形垂直锚定偏 → 每文本行系统性偏移 →
分布式 diff。这是 Phase A 设计文档 §6.3B 的 offset/baseline 语义（R306 证伪 geometric baseline frag.height → 16.67%
FAIL，offset load-bearing 不可单点改）。= goal doc 缺口 #4 Layout/Paint IFC 双路径 + 非-Ahem ascent 近似。

裁决
----
welcome 残余 17% = Phase A 非-Ahem font ascent（分布式、line-height 计算正确、非局部 bug）。无单点修路径。
**纠正潜在误判**：若未来据「welcome 17% 文本度量」推断 line-height 计算 bug 须先核 resolve_font_metrics（已实证正确），
勿重投 line-height。真阻塞 = Phase A offset 语义（须多会话 IFC 统一 + 非-Ahem 真 ascent 接入）。

连同 R337（小聚类穷尽）/ R338（text-emphasis self-source 回归陷阱）/ R334-R336（WM-1 三角度 Phase A），
rendering-compat 全部 bounded 单会话渲染 lever + 产品 smoke 局部 bug 均穷尽。唯一 forward motion = 多会话 Phase A。

代码变更：零（read-only 实证）。基线持平。

追加（同日）：font-ascent 前提实证确认（探针 probe_ascent_vs_font_size）
────────────────────────────────────────────────────────────────
fontdue horizontal_line_metrics（FontLoader::line_metrics）对**系统 sans-serif 字体**
（welcome 用的字体族）实测：

    PROBE ascent@16:  ascent=14.852 (92.8% of size) descent=-3.773
    PROBE ascent@32:  ascent=29.703 (92.8% of size) descent=-7.547
    PROBE ascent@80:  ascent=74.258 (92.8% of size) descent=-18.867

= sans-serif 实际 ascent = **92.8% × font_size**（非 100%）。ZeroWeb paint v_offset 用 font_size
（100%）当 ascent → sans-serif 文本基线每行偏低 7.2% × font_size → welcome 分布式垂直 diff。
Ahem（方框 em-square 字体）ascent ≈ 100% × font_size（设计如此）→ v_offset 改为 actual_ascent 对
Ahem WPT 测试为 no-op（**低风险**）。

**这是未测试过的 fresh 角度**：R306 证伪的是 `v_offset = frag.height`（行盒几何基线，错误指标）；
actual_ascent（字体真实 hhea ascent，fontdue 已暴露于 loader.rs:291 line_metrics）是**理论上正确的
基线度量**（baseline = line_top + ascent），与 frag.height 不同。
