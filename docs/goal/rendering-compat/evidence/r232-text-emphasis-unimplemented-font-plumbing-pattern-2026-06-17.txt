# text-emphasis 未实现（非 clean win）+ DC-14 1-3% 簇的「字体/文本属性 plumbing 缺口」统一模式（R232）

**日期**: 2026-06-17
**承接**: R231 标 text-emphasis(15) 为「新候选，可能比 multicol-breaking 更 contained」。本轮核实发现该判断**过于乐观**。

## text-emphasis = 完全未实现（非定位 bug，非 clean win）
- 全仓库 grep `emphasis` 在 `crates/css-parser`、`crates/style-system`、`crates/engine` **零命中** —— 特性整体缺失，`text-emphasis-{position,style,color}` 静默丢弃，强调点**根本不渲染**。
- 15 case 的 1.0-1.3% chromium-diff **不是因为标记位置略偏**，而是**标记完全缺席但标记本身很小**（CJK 字符上的小点）→ 像素占比 ~1%。**低 diff 误导**：看似近似实为缺失。
- test HTML 确认（text-emphasis-position-property-001）：测 `text-emphasis-position: over right` horizontal-tb 把强调点置于文字上方——属特性渲染验证，未实现则全无点。
- 修复 = **从零实现特性**（parse `text-emphasis-{position,style,color}` + paint CJK 强调点），属 feature implementation，非 contained positioning fix。**降级 R231「clean candidate」判断**。

## 更广模式：DC-14 1-3% 簇含一个内聚子类「字体/文本属性 plumbing 缺口」
这些 CSS 属性**已 parse（或可 parse）但未 wire 到 ComputedStyle→shaper/paint**，且因视觉效果细微产生欺骗性小 diff：
| 属性 | 状态 | 簇内 case | 备注 |
|------|------|-----------|------|
| font-weight | FontDesc.weight 字段存在但 find()/paint 不用 | welcome 产品 + 非 Ahem reftest | R229（plumbing 模板） |
| font-kerning | matcher/mod.rs:897 parse，**ComputedStyle/paint/shaper 不消费** | 5 | rustybuzz 默认 shaping 含 kerning，但 CSS 属性未控制 |
| text-emphasis | **完全未 parse/未实现** | 15 | 本轮 |
| text-underline-offset / decoration-thickness | 未实现 | 4 | |
| @font-face / font-family 边界 / font-051(large-font) | 部分实现 | ~10 | font-051=Phase A font_size 死锁 |

**统一洞察**：这不是「碎片化噪声」（R231 部分印象），其中 **~15-25% 是字体/文本属性 plumbing 缺口**，共享同一修复模式（把已 parse 的字体属性 wire 到 ComputedStyle→fontdue/rustybuzz）。**R229（font-weight）是该模式的模板**，可系统化推广到 font-kerning / text-emphasis / underline-offset。

## 结论（细化 R231）
- DC-14 183 簇 = **结构性多轮(38%: multicol/writing-modes/floats-clear) + 字体/文本属性 plumbing 缺口(~15-25%，内聚模式) + 真碎片**。
- 无单一 clean win；但**字体属性 plumbing 是系统性方向**（R229 先行作模板，font-kerning 次之——已 parse 只差 wire，比 text-emphasis 从零实现更轻）。
- 每个 plumbing 修复的 per-case 收益小（属性效果细微，diff 本就 ~1%），但累加 + 自源中性下提 DC-14 chromium 一致率。
- **勿把 text-emphasis 当 quick win**；它是 feature 实现，与 multicol 同属需投入项，只是维度不同。

无代码变更，基线 438/490 持平。
