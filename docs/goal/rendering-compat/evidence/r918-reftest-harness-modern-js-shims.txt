R918 — reftest harness 现代 JS 模式 shim（rAF / takeScreenshot / append / getBoundingClientRect）
================================================================================================

日期：2026-07-01
承接：R917（harness 执行 DOM-mutating JS 落地）+ R917 续（dom serializer raw text 修复）

背景
----
R917 把 reftest harness 的 JS 执行从「裸 sandbox 忽略 DOM 变更」升级到「真正执行
DOM-mutating JS 并渲染 post-JS 态」，聚合 CSS2 oracle 持平 +1（3010/6232）。R917
调查指出 yield 阻塞转移到渲染层。但本轮复查 R917 跑出的 JS 执行警告，发现**还有
一类 harness JS 缺陷未被 R917 覆盖**——现代 reftest 常用的全局 API / 方法根本未
shim，导致脚本回调不触发或方法调用抛异常中断：

1. `requestAnimationFrame`（rAF）未 shim → 现代动态 reftest 标准模式
   `requestAnimationFrame(() => requestAnimationFrame(() => { …setup…; takeScreenshot(); }))`
   的回调**永不执行** → setup mutation（style.color/class 切换）**永不记录** →
   ZeroWeb 渲染 pre-JS 初态，chromium oracle 渲染 post-JS 终态 → 假发散。
   R917 报「118 case 产生 mutation」时，rAF 测试（回调不触发）的 mutation 从未
   进入那 118 个——它们在被忽略的集合里。

2. `takeScreenshot`（`/common/reftest-wait.js` 提供）未定义 → `takeScreenshot is not
   defined` 抛异常。虽多在 mutation 之后，但破坏脚本链式调用（`.then(...)`）。

3. `Element.append(...nodes)`（现代 API，区别于 appendChild）未 shim →
   `document.getElementById(...).append is not a function` 中断 DOM 构建。

4. `Element.getBoundingClientRect()` 未 shim → proxy 对未知属性返回 undefined →
   调用 `el.getBoundingClientRect()` = `undefined()` 抛 TypeError → **中断整个
   脚本**，其后的 DOM mutation 全部丢失。120 个 reftest 文件用它作「强制 reflow」
   触发器（返回值不使用，仅触发 layout）。

频率（全 wpt-data，13707 个非-ref 测试文件）
--------------------------------------------
- requestAnimationFrame：42 文件（+ DOM/style mutation 内嵌的 38 文件）
- takeScreenshot：27 文件（+ style mutation 内嵌的 20 文件）
- getBoundingClientRect：120 文件（其中 13 文件后跟结构性 mutation）
- .append()：19 行
- 注：offsetHeight(203)/offsetWidth(140) 是属性访问，返回 undefined 不抛异常、
  仅值错误，作 reflow 触发器时无害；不特例化以免改变 `<` 条件逻辑（精准修改）。

实施（crates/engine/src/js_dom_shim.js，纯 JS，零 Rust 改动）
------------------------------------------------------------
1. `globalThis.requestAnimationFrame(fn)`：同步立即执行 fn（带 _rafBudget=64 上限
   防动画循环无限链式，`__zw_begin_script` 时重置）。`cancelAnimationFrame` no-op。
   前缀别名 webkit/moz 同指。双 rAF 嵌套 `rAF(()=>rAF(()=>{...}))` 同步收敛到
   setup 立即执行。
2. `globalThis.takeScreenshot(cb)`：no-op（harness 在 load 后统一截图），调 cb，
   返回 resolved Promise（部分测试链式 `.then`）。
3. `Element.append(...items)`：JS-only，复用既有 `__zw_append_child[_handle]` +
   `__zw_create_text` 回调（字符串自动包 Text 节点），无需新增 Rust callback。
4. `Element.getBoundingClientRect()`：返回零 DOMRect `{x,y,top,left,right,bottom,
   width,height,toJSON}`；`getClientRects()` 返回 `[]`。防方法调用中断。

为何 yield 受限（字体墙，与 R388/R633 一致）
--------------------------------------------
rAF 测试多为 dynamic-color（`style.color="green"`），shim 后 mutation 正确触发、
ZeroWeb 渲染正确颜色，但字形光栅噪声（fontdue vs Skia per-glyph 0.1-3%）使 diff
停在 ~1.04%，刚过 1% oracle 阈值 → 不计 oracle-pass（但计入近似通过 +1）。
例：list-item-dynamic-color 经 product-smoke 验证 rAF 回调触发、渲染绿色，
diff = 5012/480000 = 1.04%（残余 = 绿字 font/AA 噪声）。

结构性动态测试则不同：normal-flow/block-in-inline-{append,empty}-* 经 shim 后
diff 落到 0.06-0.11%（接近/低于 strict 阈值），证明 shim 对结构动态测试有效
（mutation 触发且渲染正确）。这些 case 多被 DC-14 非平凡性检查标「退化可疑」
（oracle 近纯色 + 低 diff）。

意义
----
reftest harness 的 JS 执行能力从「能跑 DOM-mutating JS」（R917）进一步到「能跑
现代 reftest JS 模式（rAF 延迟 setup / reflow 触发 / takeScreenshot 完成信号 /
append 批量追加）」。这是 DC-1（reftest 基础设施）的真实正确性提升——harness 不
再因缺失全局 API 而静默跳过或异常中断现代 reftest 的 setup 脚本。

oracle 通过率 yield 在 CSS2 受字体光栅墙封顶（+1），但 shim 在 css-tables 等
现代目录（13 个 getBoundingClientRect + 结构性 mutation case）可能 yield 更高，
留待后续会话 A/B。

残余 / 下会话
------------
1. css-tables / css-flexbox 等现代目录的 R918 shim A/B（gBCR + 结构性 mutation
   case 13 个，潜在更高 yield）。
2. background-root-101/102/103 残余 ~2.01%（粗体字体墙，R917 续后非 clean lever）。
3. shim 其余低频缺口：createElementNS(5)/cloneNode(7)/getComputedStyle(41，但
   返回 computed value 复杂，须 layout 查询)/createDocumentFragment(1)。
4. reftest-wait.js 未 vendored（非致命，缺失只记 warning；takeScreenshot 已 no-op）。
