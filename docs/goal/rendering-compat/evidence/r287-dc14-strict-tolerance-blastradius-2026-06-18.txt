日期：2026-06-18

## 1. 机制

`ReftestCategory` 新增 DC-14 锁定严格容差（goal doc DC-14 line 162-163/315-316，硬上限不可放宽）：

| 分类 | 默认松容差（ratio / channel） | DC-14 严格容差（ratio / channel） | 倍率 |
|------|------------------------------|----------------------------------|------|
| Layout | 1% / 5 | 0.1% / 2 | 10× |
| Text   | 5% / 15 | 0.5% / 5 | 10× |
| Unknown | 2% / 8 | 0.1% / 2（未知按最严） | — |

`ReftestConfig::for_category` 经 env `ZERO_REFTEST_STRICT` 门控：设置则用严格值（同时切换计数阈值 `compare_pixels_labeled` 的 threshold 与通过阈值，二者须一致才反映真实差异），否则用默认松值。

单元测试 `test_strict_tolerance_dc14_locked` 断言严格值 == DC-14 锁定 + 严格恒为默认 1/10。

## 2. 三态 blast radius（self-source，reftest-upstream 490）

`comm` 双跑（loose 默认 vs `ZERO_REFTEST_STRICT=1`）：

| 三态 | 数量 | 占比 | 定义 |
|------|------|------|------|
| 真通过（true-pass） | 293 | 59.8% | strict 容差下通过 |
| 近似通过（near-pass） | 145 | 29.6% | loose 通过但 strict 失败（loose-pass − strict-pass） |
| 失败（fail） | 52 | 10.6% | loose 也失败（已知结构性死锁 + REF 怪异） |
| **合计** | **490** | 100% | |

- loose pass = 438（89.4%，master.md 既记录的 self-source-loose 基线）
- strict pass = 293（59.8%，strict ⊂ loose 因 strict 更严）
- near-pass = 438 − 293 = 145

**关键**：这是 **self-source @ strict**（59.8%），区别于 master.md 的 **chromium-oracle @ strict**（39.6%，188/475，evidence/cross-validate-full-2026-06-17.txt）。两者衡量不同 false-pass 源：
- 59.8% 衡量「loose 容差掩盖的」——ZeroWeb-test vs ZeroWeb-ref 在 0.1%-1% 区间的自不一致。
- 39.6% 衡量「self-source reference 掩盖的」——ZeroWeb-test vs Chromium，捕获 test/ref 同错（两者一致但都偏离标准）。
- 完整 DC-14 达标需两者都满足：strict 容差 + chromium Oracle。

## 7. 默认翻转决策（R280 推荐 phased）

本轮**未翻默认**（make test/reftest-upstream 仍用松容差，保持 438/490 头条稳定）。理由：
- R280「先测 blast radius 再翻默认」——本轮完成测量。
- 翻默认会让头条从 89.4% 跌到 59.8%，需配合真实修复逐步上推后再翻，避免「数字突然变差」的误读。
- 严格容差**能力已就绪**（env 门控），后续每轮修复可用它度量「真通过」增量。

下一步建议：攻 near-pass 前 20 个 CSS2 clean win 候选（strict diff <1%），用 `ZERO_REFTEST_STRICT=1` 度量每项修复的 strict 增量。
