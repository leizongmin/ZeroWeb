# R487 — 伪元素 ::before/::after 完整实现（4/4 子系统：compute + layout）；content 渲染通，chr<1% net-flat（精度瓶颈）

**日期**: 2026-06-22
**前置**: R486 parser 单冒号分类 + matcher 声明路由（2/4 子系统，单测验证）。
**目标**: 实现 compute（伪 ComputedStyle）+ layout（合成文本盒），让 `::before`/`::after` 的 `content:String` 实际渲染。

---

## 1. 本轮交付（compute + layout，4/4 子系统完成）

### 1.1 Compute（`crates/style-system/src/lib.rs` + `property/computed_style.rs` + `default_impl.rs`）

- `ComputedStyle` 增 `before_pseudo: Option<Box<ComputedStyle>>` + `after_pseudo` 字段（default None）。**路径 A 零冲突**：仓库字面 `ComputedStyle{}` 构造均用 `..Default::default()` 展开（R486 担心的 ~7 处未发生）→ `cargo build --workspace --tests` 直接通过。
- `compute_element_style_internal` 增 `pseudo: Option<&str>` param：`Some(name)` 时用 `collect_pseudo_declarations_with_media` 收集、跳过内联样式与 UA 标签默认值（伪元素无 style 属性/无标签；default display=Inline 由 `ComputedStyle::default` 提供，利于 `::before`/`::after`）；**早返**：伪元素无匹配规则时直接返回 default（content:Normal），避免无伪元素规则的元素产生 2× 管线开销。
- `compute_styles_recursive` 在主样式计算后计算 before/after 伪样式（parent=元素自身样式，save/restore custom_properties 防污染子元素继承）；仅当 `content == String` 时设置字段（content:None/Normal 不生成盒）。
- 单测（`tests/shorthand_coverage.rs` ×2）：`div:before{content:"X";color:red}` → before_pseudo content=String("X")、元素本体 content=Normal、无 ::after 规则时 after_pseudo=None；`content:none` 不设置 after_pseudo。

### 1.2 Layout（`crates/engine/src/pipeline.rs`）— DOM 注入法

**关键架构发现**：`render_html` 每帧 `parse_html(html)` 重建 Document → DOM 注入天然幂等（无累积、JS 不可见）。文本测量经 `doc.get(NodeId)→NodeKind::Text`，故合成伪元素为**普通文本子节点**即可复用全部既有机制（测量/匿名盒/绘制）。

- 新增 `inject_pseudo_text_nodes(&mut doc, &mut styles)`：遍历 styles，对 `before_pseudo`/`after_pseudo` 的 `content:String`，`create_text_node` + 伪 ComputedStyle 入 styles；before 经 `insert_before` 插为首子节点、after 经 `append_child` 追加为末子节点（content 字段清为 Normal 防下游误判）。插入失败回滚 styles。
- `render_html`（reftest 路径）在 compute_styles 后、布局前调用注入。
- 单测（`pipeline.rs::pseudo_tests` ×2）：before 注入为首文本子节点 "Y" 且原 "X" 仍在第二位；after 追加为末子节点 "Z" 且原 "X" 仍在首位。

## 2. 验证

- **make test：12286 passed / 0 failed**（R486 的 12284 + 本轮 2 inject 单测；注入仅对有 content:String 伪元素规则的元素生效，多数元素不受影响 → 零回归）。
- **机制验证**：单测证明 parser→matcher→compute→inject 全链路；content:none 正确跳过（content-001 渲染 before=after，未注入）。

### 2.1 实证 re-dump + cross-validate（generated-content 簇）

REFTEST_DUMP=1 REFTEST_DUMP_PASS=1 reftest-upstream generated-content（test-guard 包裹，212 case 全量重 dump）→ cross-validate vs chromium oracle（R484 捕获）：

| 指标 | BEFORE（R484） | AFTER（本轮） | 变化 |
|------|---------------|--------------|------|
| generated-content chr<1% | 83/211 = 39.3% | 82/211 = 38.9% | **−1（噪声内 net-flat）** |
| chr<5% broad | — | 207/211 = 98.1% | 高（多数接近） |
| near-miss(1-2%) | 81 | 81 | 不变 |

**逐案对比**（join before/after）：注入**确实生效**（多案 z_vs_chr 变化）；content:none 案 before=after（正确跳过）。少数显著改善：`after-inheritable-002` 7.20%→**3.84%**（content 现渲染，接近 chromium）。多数微变（±0.08pp 噪声）。

**为何 net-flat 而非提升**：注入让伪元素 content **从完全不渲染（0 green pixels）变为渲染**（机制正确：after-content-display-001 的 `:after{content:" Filler text";display:inline}` 在 div 文本后同行渲染 inline，符合预期）。但渲染**精度**（字体度量/精确像素定位）未达 chromium 级 → 注入的伪文本与 chromium 有 ~0.08pp 系统性小偏差，改善（content 出现）与精度损失（位置不完美）大致抵消。此精度瓶颈与 near-miss 簇（R471 css-text / R174 字体）同一根源（fontdue 度量/IFC 定位），非本特性 bug。

## 3. 影响范围与裁决

- **影响范围**：注入仅触发于 `content:String` 的 `::before`/`::after`（compute 只算 before/after，不算 first-letter/first-line）。`first-letter-punctuation`（405 case）用 `:first-letter`（本轮未实现渲染）→ 不受影响。故全套件影响≈generated-content（flat）。
- **裁决**：伪元素 `::before`/`::after` **4 子系统完整实现、回归干净（12286/0）、content 实际渲染**。chr<1% net-flat 是**渲染精度**瓶颈（与 near-miss 簇同根源），非回归或 bug。功能完成是真实进展（content 从 0 green pixels 到渲染），解锁后续精度攻坚。
- **诚实声明**：本轮**非 chr<1% 度量胜利**（flat）。下轮若要 chr<1% 实际提升，须攻注入伪文本的像素精度（fontdue 度量/IFC inline 定位）——与全局 near-miss 精度同一硬骨头（Phase-A/metric），非伪元素特性独有。
