1. border-001 (2.77%) — 非 border bug
   TEST(ZeroWeb 渲 border-001.xht)：真 border 150×150 空心方框，y[51,200] 顶/底边 25px +
   左/右边全高 = 正确。REF(ZeroWeb 渲 -ref.xht)：用 top/bottom 黑条纹 + 中间 Ahem 文字
   `1 2 3 4 5 6 7 8`(word-spacing 3em) 模拟方框；ZeroWeb 把中间 div 文字塌缩成 ~1 行
   (y[89,104] 仅 16px，应 4 行 100px) + 底条纹下移到 y[251]。→ 发散在 REF 的 Ahem 文字
   布局，非 border 渲染。根因 = Phase A IFC(font/word-spacing 度量)，border 实现正确。

2. multicol-block-no-clip-002 (1.81%) — multicol 分布 + image-ref
   REF 用 7 个绝对定位色块图(swatch-blue/orange/pink/yellow + black20x20)模拟列分布。
   需 multicol 内容碎片化(内容溢入列间隙不裁剪) + 列内分布。根因 = multicol fragmentation
   (R128/R131 谱系)，非单点。

3. multicol-collapsing-001 (1.68%) — multicol BFC margin 隔离 + image-ref
   断言「multicol 元素的首子块盒 margin-top 不与 multicol 自身 margin-top 折叠」。
   REF 用 3 个 yellow swatch 图模拟。需 multicol BFC margin 隔离 + orphans/widows。
   根因 = multicol fragmentation 边界(R113)，image-ref 依赖。

4. multicol-count-computed-003 (1.78%) — multicol 分布精度 + image-ref
   column-count:3 / column-gap:5em / column-rule；断言列规则只在「两列都有内容」间绘制 +
   内容溢入列间隙不裁剪。需 orphans/widows + 列规则条件绘制 + 内容分布。
   根因 = multicol fragmentation(R113)。

5. float-006 (7.47%) — 零高 float 边缘 case
   「零高(margin-box)空 float 不缩短行盒」。涉及零高 float 排除区 + abspos 重叠 + z-index。
   根因 = 零高 float 排除(R57 谱系，结构性边缘 case)。

6. baseline-007 (1.04%, 最小 diff) — multicol baseline-export + column-span
   flex(align-items:baseline) + 第二 item 是 columns:3 multicol 含 column-span:all spanner。
   需 column-span:all(完全未实现 R353) + multicol baseline-export(R266/R313/R316 穷尽)。
   根因 = multicol fragmentation + baseline-export，双架构缺口。

7. clear-inline-001 (5.86%) — 非 clear bug，REF 的 inline-block IFC bug
   断言「clear 不适用于 inline 盒」。TEST(ZeroWeb 渲 .xht)：clear 对 inline span2 正确忽略，
   blue "Filler Text" 正确出现在 orange float 右侧(x[104,791] y[51,69]) = 正确。
   REF(ZeroWeb 渲 -ref.xht)：<img 96×96 inline-block> + <span>Filler Text</span>，
   ZeroWeb 把 span 放到 img「下方」(blue y[147,165] 全宽 x[8,791]) 而非右侧 = REF 错。
   根因 = inline-block(映 taffy block)与 inline 文本的 IFC 所有权分裂 = Phase A。
   （img UA display=InlineBlock 正确 lib.rs:70；collect_inline_items 有 inline-block 分支
    mod.rs:770，但 div 容器对 inline-block+inline 子树的 IFC 建立仍走 taffy block 堆叠路径）

8. flexbox-column-row-gap-004 (3.98%) — writing-mode + 百分比 gap
   % row-gap 在不定 block-size 视作 normal；4 容器含 2 个 vertical-lr。R353 已证 percentage-gap
   正确(convert_length_to_lp Percentage→Percent)；残余发散在 vertical-lr 轴(R109)。
   根因 = writing-mode 垂直轴(R57/R114/R164 谱系)。
