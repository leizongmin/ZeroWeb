修复 1：flex-basis em/rem/ch→Px 解析（style-system/computed.rs）
----------------------------------------------------------------
根因：resolve_computed_style 的 resolve_length_field 列表（width/height/min/max/
margin/padding/border）不含 flex_basis（FlexBasisValue 包装 LengthValue）→ `flex:0 0 4em`
的 flex-basis em 从未解析 → converter（convert_length_to_dimension `Em(v)=>length(v)`）
当裸数字 → span 4em→4px（应 64），flex base size 错误。

修复（computed.rs resolve_computed_style，border_left_width 解析后）：
  + use FlexBasisValue
  + if let FlexBasisValue::Length(ref mut lv) = resolved.flex_basis {
        resolve_length_field(lv, font_size_px, viewport_width, viewport_height);
    }
Percentage/Auto/Content 不改写（仅 Length 分支解析）。CSS-correct。

修复 2：inline-block 垂直 margin 在 IFC 应用（layout-engine/inline/mod.rs）
-------------------------------------------------------------------------
根因：InlineBlockBox 无 margin 字段，IFC 完全忽略 inline-block margin——
margin_left/right 不推进水平位置、margin_top/bottom 不计入行盒高度、margin_top
不偏移盒 Y。self-source REF（block+inline-block）的 span margin-top:1em 记录 mt=16
但 abs_y=17（应 33），与 flex test（abs_y=33 正确）16px 垂直差持续 FAIL。

修复（inline/mod.rs）：
  - InlineBlockBox 新增 margin_top/right/bottom/left 四字段（从 computed style 读）
  - TextFragment 新增 margin_top 字段（文本运行=0，仅 inline-block 透传）
  - layout_inline：current_x += margin_left（推进）+ box_width + margin_right；
    current_line.height = max(height, box_height + margin_top + margin_bottom)
  - apply_vertical_alignment：run.y += run.margin_top（★ 关键缺失步——前一会话
    记录了 margin_top 字段但未在此偏移；本会话补上）
  - 垂直模式（vertical-rl/lr）镜像：margin_top/bottom 沿 inline(depth) 推进，
    margin_left/right 计入列宽

双 bug 互锁机制（为什么必须配对）
---------------------------------
flexbox_flex-0-0-N.html：test=flex（span `flex:0 0 4em` + `width:5em`），
ref=block+inline-block（span `display:inline-block` + `margin-top:1em`）。
  - test 侧受 bug 1 影响（flex-basis em→span 宽错）
  - ref 侧受 bug 2 影响（inline-block margin→span Y 错）
self-source reftest 须 test 与 ref 一致才 PASS；任一 bug 单独修→两侧仍不一致→FAIL。
配对修复→两侧都正确→PASS。
