逐案证伪：false-neg 候选均结构性，非易修 ref bug
================================================================
① flex-abspos-inset-nested-001/002（z_vs_chr 0.73/0.74% 看似 test 已对）：
   像素分析（PIL green bbox）揭穿——**ZeroWeb-test 与 chromium-oracle 均退化**（非 200×200
   绿方块）：ZW-test green=344×8 条纹、chr-oracle green=236×44、ZW-ref=360×216（正确
   200×200）。z_vs_chr 0.73% 仅意味「两者都退化且主体皆白」相似，非 ZW 正确。img 在 ZW
   layout w=0（inner-flex abspos 无 left/right → shrink-to-fit=0）。退化案，非 clean win。

② flexbox-baseline-multi-line-horiz-004（z_vs_chr 1.08%，self 47.17% 最大反差）：
   test = inline-flex + flex-wrap:wrap-reverse + align-content:center + baseline 项；
   ref = outer column-reverse flex + 两单行 flex（不同结构达同视觉）。ZW-test≈chr 说明
   inline-flex baseline 对 test 正确，但 ref 的 column-reverse+justify-content 结构 ZW
   渲染错。属 **baseline-export 聚类**（master.md 卡点#4），须 taffy 0.8+ baseline_overrides
   或自建 baseline 合成（多会话），非单点 ref 修复。

③ box-offsets-rel-pos-vlr-005（z_vs_chr 4.38%）：WM rel-pos 结构性（R114/R164 谱系）。

结论（DC-14 方法论的双面价值）
================================================================
正面：DC-14 交叉验证是**可信判据**——R369 用它确证 R368 为真 chr 大胜（ifc-011 12.30→
2.22%）、border-box 为真 chr 退步（+0.28pp）。后续修复应一律用 z_vs_chr 验证，勿信 self-src。

负面：DC-14 扫描**未发现易修 false-negative**——5 个候选逐案证伪均结构性（退化 / baseline-
export / WM）。这反向印证 master.md plateau 结论：剩余 48 失败（含 false-negative）全结构性，
self-source pass count 非因「易修 ref bug」而人为偏低。forward motion 仍须多会话架构

只让验证更可信。
