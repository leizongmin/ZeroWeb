R338 — text-emphasis self-source 回归陷阱 + 指标膨胀洞察（read-only 实证，基线持平）
====================================================================================

日期: 2026-06-19
基线: self-source loose 438/490 (89.4%) / strict 295/490 (60.2%)（read-only，零代码变更）
承接: R337 收尾 CONTINUE 指 text-emphasis（DC-12 in-scope feature，+7 潜力，自包含）。本轮实施前
      核实关键前提（ZeroWeb 是否渲染 <ruby>/<rtc>）+ 32 text-emphasis 测试用例的当前 pass/fail，
      裁决 text-emphasis 是否可单会话实施。

关键实证（决定性）
------------------
text-emphasis 子集当前（text-emphasis 完全未实现，R232/R337 确认）：
- **loose 32/32 全过**（100%）
- **strict 25/32 过 / 7 fail**（cross-validate 的 7 self-fail = 这 7）

即：**32 个 text-emphasis 测试当前几乎全过**——因为 TEST 用 `text-emphasis`（未实现→无标记）
且 REF 用 `<rtc>&#x25CF;</rtc>` + `<ruby>` 模拟标记（ZeroWeb 也不完整渲染 rtc/ruby）→ **两侧
都缺标记 → 互相匹配 → 过**。这是「test==ref 同错即过」的 DC-14 false-pass 结构。

text-emphasis 实施的 self-source 回归陷阱
-----------------------------------------
若单方面实施 text-emphasis 渲染（TEST 出现标记）但不匹配 REF 的 rtc/ruby 模拟：
- TEST 有标记、REF 无（或位置/尺寸不匹配）→ 两侧分歧 → **当前 25 strict-pass + 32 loose-pass
  会回归**（净大负向）。
- 即：**实施一个 in-scope feature 会让 self-source 指标回归**—— perverse incentive。
- 要避免回归须**同时**完整实现 (a) text-emphasis 渲染（标记尺寸/位置匹配 chromium）(b) ruby/rtc
  渲染（REF 模拟机制）(c) Unicode 标点跳过 = 多会话 feature，且须两侧（TEST 的 emphasis 算法 +
  REF 的 rtc 模拟）像素对齐。

裁决
----
1. **text-emphasis 作为单会话目标关闭**：实施会回归 25-32 当前通过的 self-source 用例（test/ref
   两侧缺 feature 的虚假匹配被打破）。须多会话完整实现（emphasis + ruby/rtc + 标点跳过，两侧
   对齐）才可能净 ≥0。
2. **self-source 指标膨胀洞察**：438/490 loose / 295/490 strict 含**未实现 feature 的虚假通过**
   （test==ref 同缺 feature）。text-emphasis 贡献 32 loose / 25 strict 此类通过。其他未完整实现
   的 feature（ruby、可能更多）同理膨胀分子。这强化 DC-14：**chromium-Oracle（~35.6%）才是诚实
   指标**，self-source 数字不可作达标依据（goal line 329 已声明，本轮实证具体机制）。

   ⚠️ **对 rally 的结构性含义**：在 self-source 指标下，**实施 in-scope feature 单会话会回归**
   （打破 test==ref 同缺的虚假匹配），除非完整到两侧像素对齐。这使「修渲染 bug 提升 self-source」
   与「实施 feature 提升产品能力」在 self-source 指标下方向相反。rally 单会话提升 self-source
   的唯一安全路径仍是「修 test/ref 共有的渲染 bug」（Phase A 双路径类），非「实施新 feature」。

综合
----
text-emphasis（feature）+ 此前 WM-1（3 角度 Phase A）+ multicol（Phase 2 多会话）+ 小聚类
（R337 AA/JS-dynamic）全部排查完毕。**rendering-compat 无安全的单会话 forward-motion 路径**：
- 修渲染 bug（Phase A 类）→ 受 IFC 双路径死锁阻塞，bounded 切片全 net-negative（R327/R335/R336）。
- 实施 feature（text-emphasis 类）→ self-source 回归陷阱（25-32 用例）。
- 唯一 forward motion = 多会话架构（Phase A 完整 / Phase 2 嵌套 multicol / text-emphasis+ruby
  完整两侧对齐），或接受 plateau。

R305-R338（33 轮）一致收敛。需用户决策「多会话架构承诺 vs 接受 plateau vs 重定 95% 目标」。
