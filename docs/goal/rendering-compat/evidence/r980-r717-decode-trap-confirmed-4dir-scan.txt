**trap 精确机制（独立确证 R740 + 新数据）**：
   chromium 对 partial-attr SVG（缺一侧 width/height attr）的 `<img>` 渲染 = **CSS 默认 300×150**
   （实测 all-auto oracle：fuchsia=300×150 / blue=300×150，partial-attr SVG 全 300×150，非 attr-推导尺寸）。
   - decode fix 前：img2（h=25 viewBox 1000×500）= usvg 1000×25（ratio 40）→ all-auto 1000×25（与 chr 300×150

   - explicit-dim（width:40px）：decode fix 后 img2 = 40×20（ratio 2 推导，正确，与 chr 一致 → -1pp 改善）。

**根本矛盾（(w,h) 编码无法同时表达）**：
   - all-auto 需 partial-attr SVG → **300×150 默认**（忽略 attr-推导尺寸）。
   - explicit-dim 需 partial-attr SVG → **viewBox ratio 推导**缺失侧（40/2=20）。
   - image_sizes (w,h) 编码无法区分「真固有尺寸」（PNG/JPEG/both-attr-SVG，all-auto 用之）vs
     「ratio-only 推导尺寸」（partial-attr-SVG，all-auto 应 300×150 但 explicit-dim 用 ratio）。
   - img4/5/7（无 viewBox）= 无 ratio，任何 (w,h) 编码均造假 ratio，explicit-dim 永远错。
