1. is_clearable 定向修复（clear-applies-to-014/015）— A/B 实测 net-negative，已回退
============================================================

假设: §9.10 clear 仅适用 block-level。is_block_level（engine.rs:719-720）误含 InlineTable
+ TableCaption → clear 被施加（014 inline-table / 015 table-caption FAIL）。
方案: 新增 LayoutBox.is_clearable 字段（真块级 Block/Flex/Grid/ListItem/FlowRoot/Table
+ anon-fragment），clear 代码（float_positioning.rs:528）用 is_clearable 替 is_block_level，
不动 load-bearing 的 is_block_level（margin-collapse:58/float-shrink:337/float-exclusion:616）。
改动: types/mod.rs（字段+default）+ engine.rs（compute+set）+ float_positioning.rs（guard）。

A/B（test-guard, floats-clear）:
  clear-applies-to-014: 3.81% → 3.81%（未翻转）
  clear-applies-to-015: 3.84% → 3.65%（未翻转）
  floats-clear: 123/214 (57.5%) → 119/214 (55.6%) —— **−4 回归，0 翻转**

裁决: **net-negative，已 REVERT（git checkout 3 文件）**。
★ 机制: 014/015 的 FAIL **非仅 clear**（inline-table/table-caption 渲染另有 IFC/表格结构
  残差，clear 修正不足以翻转为 PASS）；且移除 atomic-inline-level 的 clear 施加使 **4 个
  其它 floats-clear 用例回归**（它们依赖 inline-table/table-caption/inline-flex/grid 当前
  被 clear 的行为达成 test==ref）。
教训: clear-applies-to-014/015 非单点 clear 缺陷；is_clearable 定向（不动 is_block_level）
  亦 net-negative。勿再以 is_clearable / is_block_level clear 路径为 lever 重试。

2. JS-DOM-bridge 可行性门控 — V8Sandbox 无 binding API
============================================================

最高杠杆（50+ 动态案：grid img-src ~13 + box-display delete/insert ~20 + CSS2 dynamic）。
核查 script-sandbox API（crates/script-sandbox/src/v8_runtime.rs）:
  V8Sandbox 仅有 new / with_config / execute / execute_json / reset_context。
  **无 register_callback / set_global / custom-binding API**。

→ 建 DOM 绑定（document.querySelector + element.src/className/style/textContent setter
  + reflow-after-JS）须先为 V8Sandbox 加 rusty_v8 function-template 基础设施（多会话硬核），
  再建 DOM proxy + harness reflow。非单会话，非 bounded 首步（首步 = V8 binding infra，
  0 reftest yield）。reftest execute_scripts（reftest.rs:675）当前对 HTML 串跑 JS、结果
  丢弃、无 DOM 绑定（注释「不影响渲染输出」）。
