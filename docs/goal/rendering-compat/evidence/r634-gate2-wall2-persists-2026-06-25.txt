================================================================================
裁决：证伪——墙②非行盒度量分歧，是 multicol column 分配
================================================================================

Gate 2 放宽致 multicol -10，墙②**没被 R630/R632 吸收**。R630/R632 修的是行盒度量
（多行 y 分行 + line-height），product-smoke 零变化证实 Path A/B 行盒度量已趋同。
但墙②是更深的 **multicol column 分配**分歧——multicol 容器 paint Path A（stored）
不跑 column 重分配，Path B（重跑）跑 column 分配；test（真 multicol）vs ref（float
模拟列）在 Gate 2 放宽后切不同路径致几何分歧。这与行盒度量无关，是 column-aware IFC
（Phase 2 独立 RFC，multicol-fragmentation-design.md）。

================================================================================
结论：Phase A 完整（消灭 Path B）需先解墙②column-aware（多会话）
================================================================================

R630-R632 修了 Path B 的行盒度量（不依赖 column 分配部分），但**没消灭 Path B**——
Path B 仍重跑 IFC（含 multicol column 分配）。消灭 Path B（Gate 2 放宽）需 Path A
也能处理 multicol column 分配 = Phase 2 column-aware IFC，多会话架构。
