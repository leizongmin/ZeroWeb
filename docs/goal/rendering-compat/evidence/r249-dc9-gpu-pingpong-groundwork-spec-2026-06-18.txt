核心纠正：post-process pipeline 已存在（dead-coded），非「缺失」
================================================================
R220 记「headless_texture 就绪，ping-pong 差第 2 纹理 + post-process pipeline」。
R244 沿用此判断（「filter/transform/blend 需渲染到 offscreen A→后处理 pass 读 A 写 B」，
「差第 2 纹理 + post-process pipeline」）。本轮读源码实证纠正：

【post-process pipeline 实际已构建，仅 dead-coded】
  - crates/render-foundation/src/gpu/pipeline.rs:703  pub fn create_blur_pipeline
    （vs_fullscreen 全屏三角顶点 + fs_blur 高斯模糊片元，采样 src_texture/src_sampler）
  - pipeline.rs:337  fn vs_fullscreen  —— 3 顶点覆盖全 NDC 的全屏三角形（标准 post-process 几何）
  - renderer/mod.rs:63  blur_pipeline: wgpu::RenderPipeline  —— 标记 #[allow(dead_code)]
  - renderer/mod.rs:222 创建 blur_pipeline；mod.rs:216 创建 blur_bgl（src 纹理 BGL）
  - 实证从未被 draw：grep "set_pipeline.*blur|blur_pipeline)" 在 renderer/ 零命中
    → blur_pipeline 是纯死代码（创建后从不 set_pipeline/draw）。

【结论】DC-9 ping-pong 地基比 R220/R244 判断的更 contained：
  - ✅ 已就绪：post-process pipeline（blur_pipeline + vs_fullscreen + fs_blur）、
    通用 src 纹理 BGL（create_texture_bind_group_layout，pipeline.rs:807，gradient 已复用）、
    headless_texture 已带 TEXTURE_BINDING usage（可被采样作 src，create_headless_texture:1568）。
  - ❌ 真正缺失：① 第 2 张 offscreen 纹理 B（仅 headless_texture 一张，ping-pong 需两张）；
    ② 接线（一个 draw_post_process_pass helper 把 src 纹理绑到 blur_bgl + 开 pass 写 dst +
    set blur_pipeline + draw 全屏三角 + 专用 uniform buffer）；③ 消费者（filter/transform/blend
    当前在 render_full_scene_gpu 完全静默丢弃，gpu/ 零引用）。

================================================================
单 pass 直合成流程实证（为何 ping-pong 必须）
================================================================
render_full_scene_gpu（renderer/mod.rs:651-763）：
  Phase1: 各图元类型收集顶点 → Vec<f32>（fills/rounded_rects/gradients/images/strokes/
          path_fills/path_strokes/glyphs/overlay）。
  Phase2: acquire_render_target（→ headless_texture view 或 surface），开【单个】render pass，
          按绘制顺序把所有图元类型 draw 进同一 view，submit。
  → 无中间纹理、无 readback-in-pipeline、无后处理 pass。filter/transform/blend 无法生效。

【三图元均为 rect-scoped group 操作（实证 paint 侧生成）】
  - FilterPrimitive { rect, filters: Vec<FilterKind> }
    effects.rs:266  add_filter(FilterPrimitive{rect,filters})（apply_filter / apply_backdrop_filter）
  - TransformPrimitive { rect, origin_x/y, a/b/c/d/tx/ty }
    helpers.rs:182  add_transform(tp)（compute_transform_matrix helpers.rs:53）
  - BlendModePrimitive { rect, mode }
    effects.rs:313  add_blend_mode(BlendModePrimitive{rect,mode})
  三者语义均为「对 rect 区域内所有图元应用操作」= group op。即便 Transform（含 a/b/c/d
  旋转/倾斜）也需把区域内容渲染到 offscreen 再矩阵采样→main（非顶点级平移可解）。
  → 全三图元需 ping-pong（render 区域→offscreen A→后处理/变换/混合→写 B/main）。
  FilterKind（primitive/mod.rs:232）11 变体：Blur/Brightness/Contrast/Grayscale/HueRotate/
  Invert/Opacity/Saturate/Sepia/DropShadow。Opacity 最简（alpha 乘法）。

================================================================
最小 contained 地基 spec（零行为变更，un-dead-code blur_pipeline）
================================================================
 prerequisite: R244 alpha groundwork 先行（mesh.rs color vec3f→vec4f + WGSL fragment
   合成色彩 alpha×coverage）——无正确 alpha，后处理合成错。

 Step 1（基础设施，零生产行为变更）:
  (a) 第 2 offscreen 纹理：renderer struct 加 offscreen_texture_b: Option<wgpu::Texture>，
      复用 create_headless_texture 同参（RENDER_ATTACHMENT|COPY_SRC|TEXTURE_BINDING），
      from_device/resize 同步创建。
  (b) 专用后处理 uniform buffer：blur shader 的 Uniforms 期望 screen_width/height +
      blur_radius + direction（fs_blur 引用），但 render_full_scene_gpu 的 uniform_data 仅
      [f32;4]=[w,h,0,0]→ 不匹配。需独立 post-process uniform buffer + bind group
      （或扩展现有 uniform struct 至含 blur_radius/direction）。
  (c) draw_post_process_pass helper（renderer/mod.rs 新增）：
        fn draw_post_process_pass(&self, encoder, src_view, dst_view, pipeline,
                                  src_bg, uniform_bg) {
            let mut pass = encoder.begin_render_pass(... color_attachments=[dst_view],
                load=Load, store=Store);  // 注意 load=Load（保留底色）或 Clear 视消费者
            pass.set_pipeline(pipeline);
            pass.set_bind_group(0, uniform_bg, &[]);
            pass.set_bind_group(1, src_bg, &[]);   // src 纹理 + sampler
            pass.draw(0..3, 0..1);                  // 全屏三角
        }
      移除 blur_pipeline 的 #[allow(dead_code)]。
  (d) 单测验证（DC-9 要求「输入图元→framebuffer→断言关键像素」）：构造 RenderPrimitives
      含一个 FillPrimitive（纯色）→ render 到 A → draw_post_process_pass(blur) A→B →
      read_pixels(B) → 断言边缘像素被模糊（颜色向背景过渡，非硬边）。证明 ping-pong 机制
      端到端工作 + un-dead-code。生产路径不接线（零行为变更）。

 Step 2（首个真实消费者：filter:opacity，最简）:
  - 新增 fs_opacity WGSL（复用 vs_fullscreen）：return vec4f(src.rgb, src.a * opacity);
    新建 opacity_pipeline（同 create_blur_pipeline 模式，换 fragment entry）。
  - 接线 FilterPrimitive 消费：在 render_full_scene_gpu 末尾（主 pass submit 后），
    对 primitives.filters 中每个 FilterKind::Opacity(p) 跑 draw_post_process_pass
    （全屏或 scissor 限到 filter.rect）A→B→present B。
  - 单测：filter opacity=0.5 → 断言目标像素 alpha 减半。

================================================================
架构 caveat（明确 defer，勿在地基阶段做）
================================================================
真实 CSS 语义 = rect-scoped 区域隔离：需把「属于该 filtered/transformed/blended 元素的图元」
隔离渲染到 offscreen（空间查询 flat 图元列表 + 从主 pass 排除该区域）。涉及重叠元素、
部分落入 rect 的图元、绘制顺序——多轮架构项（layer-tree 或 flat-list 区域隔离）。
【地基阶段不做区域隔离】：首个消费者用「全屏后处理」或「scissor 限到 filter.rect」证明
机制 + 满足 DC-9 单测验证即可；区域隔离是后续多轮。R244/R220 已标 ping-pong 为
「DC-9 真正大头 / 结构多轮」——本 spec 不改该定性，仅纠正「pipeline 缺失」误判 +
把首步锐化到 un-dead-code + 2nd texture（contained）。
