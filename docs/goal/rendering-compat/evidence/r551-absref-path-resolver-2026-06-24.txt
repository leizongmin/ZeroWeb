================================================================================
根因（DC-14 分母真实性缺口，R546 缺失共享 ref 谱系）
================================================================================

很多上游 WPT reftest 的 `<link rel="match">` 用**绝对 WPT 路径**引用共享参考
文件，例如：
    <link rel="match" href="/css/reference/ref-filled-green-100px-square.xht">
    <link rel="match" href="/css/CSS2/generated-content/content-auto-reset-001-ref.html">

ZeroWeb reftest runner 加载器（wpt_file_loader.rs）此前用 Rust `Path::join` 把
ref 路径拼到测试文件父目录上：
    let ref_path = test_path.parent().unwrap().join(&reference.ref_path);

但 `Path::join` 的语义是：当 join 的参数是**绝对路径**（以 `/` 开头）时，Rust
会**丢弃 base**、从文件系统根查找。即：
    /home/.../wpt-data/css/css-tables + "/css/reference/green.html"
    => "/css/reference/green.html"   （文件系统根，不存在）

→ `read_to_string(ref_path)` 报 `No such file or directory (os error 2)`
→ 加载器 line 65-69 `continue` **整条 reftest case 被跳过**（不进 cases 向量）
→ 该测试**被静默排除出分母**（从未运行）。

这正是 DC-14「分母真实性（去子集化）」缺口（goal line 317/843）的分母静默缩小：
被排除的测试既不拖累通过率也不被审计，与 R546（缺失共享 ref 文件）同源。区别：
R546 是 ref 文件**物理缺失**（需从上游 fetch 导入）；R551 是 ref 文件**已存在**
（在 wpt-data/css/reference/ 等）但**路径解析错误**导致加载器找不到。

================================================================================
修复
================================================================================

新增 helper `resolve_ref_path(wpt_data_dir, test_path, ref_path) -> PathBuf`：
- 绝对 WPT 路径（`/` 开头）：相对 wpt-data 根解析（`wpt_data_dir.join(stripped)`，
  手动 `trim_start_matches('/')` 避免 Path::join 丢 base 的语义陷阱）。
- 相对路径：相对测试文件父目录解析（行为不变，向后兼容）。

调用点 load_file_reftests line 63 由 `.join(&reference.ref_path)` 改为
`resolve_ref_path(...)`。零行为变更对相对路径 ref（占绝大多数）。
