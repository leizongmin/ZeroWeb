【背景】R242 收窄 morning-work 67% 压缩到 body 12 个 `<pre><code>` 高度欠计算，列候选机制(a)
pre IFC 多行高度欠计算（最可能）。本轮读 committed engine.rs / inline/mod.rs 验证机制(a)，**得到
一个否定+精化结论**（R164：勿据推断断言，须读码实证）。

────────────────────────────────────────────────────────────────────
1. R84 多行守卫确实跳过 `<pre>` 的 inline_layout 存储（已确认）
────────────────────────────────────────────────────────────────────
engine.rs:1667 `compute_final_inline_layouts` 对 `<pre>`（block-level + 文本子节点，非
flex/grid/table/multicol）**会处理**：跑真实样式 IFC（line 1901），但 line 1909 守卫
`if inline_ctx.lines.len() > 1 || !is_pure_ahem { return; }`——`<pre>` 多行 + 非 Ahem（code 字体）
→ **不存储 inline_layout**，paint 回退非存储路径。这一步 R242 推测正确。

────────────────────────────────────────────────────────────────────
2. 否定：paint 空样式路径**已恢复** font_size/line_height（非简单 font-size 缺口）
────────────────────────────────────────────────────────────────────
原想「空样式 → font_size 默认 16 → pre 行高错 → 渲染更短」。读 inline/mod.rs:1063-1072 paint IFC：
  let (font_size, line_height) = if style.is_some() { resolve_font_metrics(style) }
      else if let Some(&(fs,lh)) = self.inline_element_metrics.get(&child_id) {
          // paint IFC（空 styles）：使用 layout IFC 存储的 (font_size, line_height)
          // 这仅影响行盒高度（垂直定位），不影响行断。
          (fs, lh)
      } else { self.default_font_metrics... };
⇒ 非存储路径会从 `inline_element_metrics`（layout IFC 存下的每元素 font_size/line_height）**恢复**
度量，且注释明言「仅影响行盒高度（垂直定位），**不影响行断**」。故「空样式致 font-size 错」
子假设**弱化/排除**——度量被恢复，行断（line count）才是不被恢复的部分。

────────────────────────────────────────────────────────────────────
3. 关键判别：压缩是 LAYOUT（盒矮）还是 PAINT（字只在盒顶）？
────────────────────────────────────────────────────────────────────
**盒高度是 LAYOUT 属性**（taffy + IFC 在 compute 阶段定），paint 重跑只影响**已定尺寸盒内**的
glyph 位置。故 morning-work 高度压缩有两种互斥可能，R228b 的「暗内容（深色像素）分布」**无法
区分**二者：
  (a-LAYOUT) **布局阶段 `<pre>` 盒 content_height 欠算**：IFC 多行 line-count 或 total_height
    （inline/mod.rs:2008）未正确反馈到 pre 盒 → 盒本身矮 → 整文档压缩。真因在 LAYOUT-time
    IFC（行计数/高度反馈），不在 R84 守卫。
  (a-PAINT) **布局盒高度正确（高），但 paint 只在盒顶部画 glyph**：空样式重跑 line-break 与 layout
    不一致（注释「不影响行断」指度量不影响，但空样式 line-break 本身可能与 layout 不同）→ glyph
    堆在每盒顶部 → 深色像素集中 y=150-300，盒下半（浅背景）y=300-525 看似空白。

R228b 测「暗内容集中 y=150-300」对两者都成立：a-LAYOUT（盒矮，内容物理压缩）或 a-PAINT（盒高
但字只在顶）。**须 LAYOUT_DUMP 区分**：dump 12 个 `<pre>` 盒的 content_height——若≪预期
（行数×24.5px+padding）→ a-LAYOUT；若≈预期但 glyph 只在顶 → a-PAINT。
