## 真因（R781-class 漏诊）：inline-flex shrink-to-fit 缺失

aspect-ratio-intrinsic-size-001：`display: inline-flex; height: 100px`（width:auto 应 shrink-to-fit
到内容 100px）含 canvas。PIL 对比发现 ZW 把 inline-flex **拉伸到 784px（满宽）**，chromium 是 100px。

**isolation 实验**（区分 inline-flex shrink-to-fit vs canvas aspect-ratio）：
  - `<inline-flex><div width:100px>` → ZW **784px**（应 100px）= 纯 inline-flex shrink-to-fit bug
  - 确认与 canvas aspect-ratio 无关（固定宽子也拉伸）

**根因**：`shrink_inline_blocks_to_content`（float_positioning.rs:111）的 `is_shrinkable` 仅匹配
`InlineBlock`（+ 带 bg 的 Inline），漏掉 `InlineFlex | InlineGrid`。taffy 0.7 把 width:auto 的
inline-flex/inline-grid 当 block 拉伸到可用宽（满宽），违反 CSS §10.3.10/§10.3.11（inline-level
容器应 shrink-to-fit）。R370 曾定位此 bug 但判「零杠杆」（当时失败案不用 inline-flex width:auto）——
R783 发现 aspect-ratio-intrinsic-size 簇 + flexbox-baseline-align-self-baseline 簇均用它。

## fix（crates/layout-engine/src/float_positioning.rs，1 处 match arm）

`is_shrinkable` 加 `InlineFlex | InlineGrid`：
```rust
DisplayValue::InlineBlock | DisplayValue::InlineFlex | DisplayValue::InlineGrid => true,
```
intrinsic 宽复用现有 `box_content_max_width`（block 子取 max；单 item 等价于 flex-row 求和）。
多 item flex-row 的 main-axis 求和语义此处用 max 近似（单 item 等价；多 item 罕见且满宽→max 仍优于
784px 拉伸）。
