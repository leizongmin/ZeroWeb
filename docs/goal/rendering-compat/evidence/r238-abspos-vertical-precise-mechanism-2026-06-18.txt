────────────────────────────────────────────────────────────────────
1. 测试规范锚点（关键）
────────────────────────────────────────────────────────────────────
abs-pos-non-replaced-vrl-002 / -012 等 link 两个 spec：
  - css-writing-modes-3 §7.1 "Principles of Layout in Vertical Writing Modes"：
    "Layout calculation rules (such as those in CSS2.1, §10.3) that apply to the
     horizontal dimension in horizontal writing modes instead apply to the vertical
     dimension in vertical writing modes."
    ⇒ vertical-rl 下 *-top↔*-left、*-bottom↔*-right；§10.3.7 abspos-width 规则
      改管 vertical（block）轴。
  - CSS2.1 §10.3.7 abspos-non-replaced：left/width/right 三 auto 时，按 direction
    决定 left（ltr）或 right（rtl）置为静态位置，再据 rule 1/3 解另一个。

测试结构（vrl-002 / vrl-012 同型）：CB `writing-mode:vertical-rl; position:relative;
width/height:320px; direction:ltr|rtl`；子 span `position:absolute; top:auto;
bottom:auto; height:auto`。期望=绿色方块在静态位置（vrl-002 ltr→top 置静态；
vrl-012 rtl→bottom 置静态）。

────────────────────────────────────────────────────────────────────
2. 现状：§7.1 处理已存在但 INCOMPLETE（核心发现）
────────────────────────────────────────────────────────────────────
§7.1 维度交换**并非完全缺失**，ZeroWeb 已有两层部分实现：

(a) converter 层（crates/layout-engine/src/converter/mod.rs:196 apply_vertical_writing_mode）
    交换 inset(left↔top, right↔bottom) + size(w↔h) + min/max_size + flex-direction。
    ⇒ taffy 已收到轴交换后的 abspos 数据。✓

(b) engine.rs:1394-1426 静态位置修正（显式注释 "CSS §10.3.7 + writing-modes §7.1"）：
    - 守卫 `all_inset_auto`（top:auto && bottom:auto，line 1401）→ 用 IFC fragment
      的静态位置覆盖 taffy 的水平模型位置（child.x/y = fragment.x/y）。
    - 守卫 `height_auto`（line 1417-1425）→ shrink-to-fit：child.height = fragment.width
      （内容 inline 跨度），纠正 taffy 把 auto height 当 cross-axis stretch（给 320=CB 高）。
    ⇒ all_inset_auto + height_auto 路径已实现。✓

故 WM-1 不是「§7.1 完全没做」，而是「做了 all-inset-auto 这一最简分支，剩余分支缺」。

────────────────────────────────────────────────────────────────────
3. 两个系统性残差（精确缺口）
────────────────────────────────────────────────────────────────────
对照 Oracle diff（vrl-002 ltr 1.28% / vlr-003 ltr 1.28% / vrl-012·122·130 rtl 均 5.03%，
vlr-013·155·163 rtl 4.09%）：

缺口 A（ltr all-auto 残差 ~1.28%）：
  vrl-002 / vlr-003 走的就是 all_inset_auto + height_auto 路径，**仍失败 1.28%**。
  ⇒ 已实现路径本身有 fine error：疑点 = IFC fragment 的静态位置（fragment.x/y）或
    shrink-to-fit height（fragment.width.max(font_size)）在 vertical 模式下偏移。
  1.28% 跨用例一致（非随机 Ahem 噪声，否则会跳动）→ 系统性，可定位。

缺口 B（direction 分支缺失，rtl ~5.03%，是 ltr 的 ~4×）：
  vrl-012/122/130（direction:rtl）diff 5.03%，显著高于 ltr 1.28%。
  §10.3.7：left/width/right 全 auto 时，ltr→left 置静态；rtl→right 置静态（镜像）。
  现静态位置修正**不读 direction**（line 1396-1399 只判 top/bottom auto），故 rtl 的
  静态位置镜像分支缺失 → 4× 残差。这是 WM-1 最清晰的修复信号（残差最大、机制最确定）。

【次要】line 1401 守卫 all_inset_auto：§10.3.7 还有 mixed-auto 分支（一 inset length、
  一 auto→solve），当前完全跳过。但现 14 失败用例多为 all-auto 型，mixed-auto 影响
  有限，先做 direction 分支 + ltr 残差定位。

5. 与既有结论的一致性
────────────────────────────────────────────────────────────────────
