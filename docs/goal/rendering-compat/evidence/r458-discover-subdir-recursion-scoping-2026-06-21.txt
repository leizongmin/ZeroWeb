2. 隐藏 bug: ref 路径解析（line 73-77）
================================================================
- line 77: `ref_path = os.path.join(category, ref_href)` —— 相对 **category 顶层**。
- 但 WPT 约定 ref_href 相对 **test 文件自身目录**。扁平目录（test_path=category/name）
  时 dirname(test_path)==category，巧合正确；**递归后 test_path=category/subdir/.../name，
  dirname != category**，line 77 会把 `reference/foo.html` 误解析到 category/reference/ 而非
  category/subdir/reference/。⇒ 递归改动必须同步把 ref 解析改为相对 `os.path.dirname(test_path)`。
- `/`-绝对（仓库根相对）分支（line 74-75）不变。

4. rate-limit 注意（实施前必读）
================================================================
- gh_api (line 26-31) 无 auth（仅 User-Agent header）。GitHub Contents API 未认证 = 60 req/hr。
- 递归 = 1 + 子目录数 次调用: css-text 31 次（单目录 OK）/ CSS2 44 次（单目录 OK）。
- ⚠️ 连续跑 css-text(31) + CSS2(44) = 75 > 60/hr ⇒ 中途 403 rate-limit。
  缓解: ① gh_api 读 GITHUB_TOKEN env 加 Authorization header（→ 5000/hr，~2 行）；或
        ② 两目录间隔 >1hr；或 ③ 改用 git Trees API（单调用取整子树，但重构多）。
  推荐 ①（最小、复用 fetch_raw 的并行优势）。
