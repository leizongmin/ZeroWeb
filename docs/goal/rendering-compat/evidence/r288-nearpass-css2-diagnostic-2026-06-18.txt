# R288 — near-pass CSS2 攻坚诊断（验证 R287 pipeline + 定位 td-border bug）

日期：2026-06-18
轮次：R288（承接 R287「攻 near-pass CSS2 clean win 候选用 STRICT env 度量增量」。本轮对前 20 个候选逐类诊断，确认分布 + 定位 1 个真实 table bug）

## 1. 结论（验证 master.md「clean win 穷尽」）

对 R287 列出的 strict-diff<1% 前 20 个 CSS2 near-pass 候选抽样诊断，两类分布：

| 类别 | 代表案例 | 性质 | 可修性 |
|------|----------|------|--------|
| **AA/定位噪声** | colors-007 (0.49%)、color-applies-to-001 (0.12%) | test/ref 同为 ZeroWeb 渲染，差异在字形 AA 边缘（max channel diff 大但分布散在 glyph 边缘）；颜色/布局本身正确 | ❌ 不可单点修（fontdue AA，非 bug） |
| **table 布局 bug** | background-043 (0.50%) | 真实 bug（见下），但根在 table 子系统（高风险） | ⚠️ 需专项攻坚（见 §3） |

**colors-007 实测**：CSS 颜色解析全对（4 个 `<p>` 全绿，含 `color: g\re\45n` 转义→green、`color:'red'`/`#red` invalid→忽略回退 green）。test/ref 均渲染 4 行绿色文本，y 位置相同（[29-37]/[64-72]/[99-107]/[135-143]）。0.49% 差异 = 字形 AA 边缘噪声，**非 bug**。

**color-applies-to-001 实测**：table-row-group `color:green` 正确应用（文本绿非红）。0.12% 差异 = table 布局 vs div 布局的亚像素文本定位差。

## 2. background-043 — 真实 td-border bug 定位（高价值发现）

**用例**：`background: url(blue15x15.png) repeat-x bottom` on `<div border:3 height:200>`（test）vs `<table height:206><td border:3 valign:bottom><img height=15>`（ref）。两者应同产 206px 黑框 + 底部 15px 蓝条。

**像素级诊断**（REFTEST_DUMP + PIL）：
- TEST（div）：四边框齐全（top y=70-72 / bottom y=273-275），蓝条 y[258,272] flush 于 content bottom（273）。**几何正确**。
- REF（table td）：**仅顶边框渲染**（y=70-72，206px 宽 x=8-214）；**底/左/右边框全部缺失**（全图无其他宽黑线、无竖直黑线）。蓝条 y[264,278]（比 test 低 6px）。

**差异** = 蓝条垂直偏移 6px（test y[258,272] vs ref y[264,278]，重叠 [264,272]，各 6px×200=1200 + 1200 = 2400px = 0.50%）。

### 根因收窄（排除法，read-only）

1. ❌ **非 zero_box_model**（table.rs:294-307）：仅对 **row / row-group**（§17.5.3/17.5.4 无视觉效果）归零 border/padding/margin，**不对 table-cell**。cell border 不被此处清零。
2. ❌ **非 collapse 解析**（table.rs:319-331 resolve_collapsed_borders）：border-collapse 默认 **Separate**（default_impl.rs:94 正确），collapse 解析在 separate 模式 `if !is_collapsed { return }` 早退，不运行。
3. ✅ **converter 正确**（converter/mod.rs:110-117）：对**非 table-internal**（含 TableCell）正确设置 taffy border 四边（`border_left/right/top/bottom = convert_length_to_lp(style.border_*_width)`）。test_computed_style_border（1584-1594）证实四边 1/2/3/4 正确映射。
4. ➡️ **根因在 extract_layout 读回 LayoutBox 或 painter**：converter 写入 taffy 的 td 四边 border 正确，但渲染只剩顶边。疑为 **td border-box 几何**在含「显式 table height + valign:bottom img」时计算错误（box 高度被当成仅顶边框高度→只画顶线；img 经 replaced-element/IFC 独立定位到 264-278）。需运行时探针确认 td LayoutBox.border_bottom/left/right 与 border-box height 的实际值。

### 为什么 defer（非本轮安全修复）

- table 子系统经 R117/R168/R177b 等多轮精细调校，**border/height/cell-width 高耦合**，单点改动高风险回归。
- background-043 的 td-border-only-top 可能是**配置特异**（显式 table height + valign:bottom img 触发），未必影响通用 table（table reftest 基线多通过）。需先确认通用性再决定修复范围。
- 正确修复需先运行时探针 td LayoutBox 几何（border_bottom 是否=0、border-box height 是否退化），定位是 extract_layout 还是 painter，再针对性修 + 全量 table 回归。

### 下一步（建议）

1. 加临时 env-gated 探针（extract_layout 对 table-cell 打印 border_top/bottom/left/right + border-box x/y/w/h），渲染 background-043-ref，确认 td box 几何退化的具体字段。
2. 若 border_bottom/left/right=0 → extract_layout 对 cell 的 border 回读 bug；若四边=3 但 box height 退化 → 几何/裁剪 bug。
3. 针对性修 + make reftest 全量 table 回归（438/490 基线）+ STRICT 度量 background-043 增量。
