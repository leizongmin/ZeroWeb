## 1. 真根因链（全源码核实，闭合）

**step 1（触发源）**：committed `ua_default_display`（style-system/src/lib.rs）block 列表**不含 `article`**：
```
"html"|"address"|"blockquote"|"body"|"dd"|"div"|"dl"|"dt"|"fieldset"|"figcaption"|"figure"|
"footer"|"form"|"h1".."h6"|"header"|"hr"|"legend"|"li"|"main"|"nav"|"ol"|"p"|"pre"|"section"|
"summary"|"ul" => DisplayValue::Block
```
`article` 未列出 → 函数返回 `None` → 元素回落 CSS 初始 `display:inline`。同样缺失：`aside`/`details`/
`hgroup`/`menu`/`search`（HTML Living Standard UA 样式表应均为 block）。

**step 2（R109 触发）**：article 计算为 inline + 含块级子（h2/p/h3）→ `inline_has_block_child`
（inline_block_split.rs:59-61 检查 `display==Inline`）**返回 true** → tree.rs:546 `r109_segments=Some(...)`
→ 进入 559-591 匿名块生成。

**step 3（盒模型泄漏）**：tree.rs:386 `let computed = styles.get(&dom_id)`（= **article 的计算样式**，
含 `.article{min-height:200;margin:4em}`）；tree.rs:571-572 每个 R109 匿名块用
`computed_style_to_taffy(&computed, ...)` 构建（强制 display:Block）→ **匿名块继承 article 的
min-height:200 + margin:4em**。每对块级子间一个匿名块 = h≥200 + margin 64/64 = **328px/对**。

**step 4（4× 高）**：article 内每对 block 兄弟间插 328px 幻影盒，累积 ~4.2×（ZW body 25301 vs
CHR 5981）。R253 dump 的 328/328/328/328 间隙 + 「幻影嵌套 article h=200 w=4」（实为带 article
node_id 的 R109 匿名块，dump 标签 b.node_id→DOM labels 取 article）全部吻合。

## 2. 纠正 R256（我的错误）

R256（1b39ab3）读 build_subtree 后断言「article 是 Block → R109 不触发 → build_subtree 不生成
幻影盒 → R255 机制被否定」。**代码路径阅读本身正确，但前提「article=block」错误**——article 实际
计算为 inline（step 1）。故 `inline_has_block_child(article)=true`，R109 **确实触发**，R255 的
「.article 盒属性泄漏到幻影匿名盒（R109 谱系）」机制与 328=200+64+64 算术**全部正确**。

**R256 须降级为「基于错误前提的部分分析」**：它正确指出 converter 映射无误、build_subtree 对
*真正 block 容器*不生成幻影盒——但这些对 morning-work 不适用（article 非 block）。R256「勿据 R255
改 build_subtree/converter/R109」的*操作结论*仍成立（缺陷在 ua_default_display，不在这些模块），
但其「R255 机制被否定」的*定性结论*错误。本 R257 取代 R256 的定性。
