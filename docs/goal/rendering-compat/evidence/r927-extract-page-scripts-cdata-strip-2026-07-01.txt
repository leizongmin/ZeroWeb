R927 — extract_page_scripts 剥 XHTML CDATA 包装（harness JS vein 续·CSS2 +1·DC-1 正确性）
==============================================================================================

承 R926「下会话 baseline §4.4 A/B 其他目录 / 结构性 lever」。本轮扫 box-display worst
（insert-* 动态簇 20-40%）定位到下一个 harness JS 缺口。

缺口机制
--------

`extract_page_scripts`（crates/engine/src/pipeline.rs:745）取 `<script>` 的 `text_content`
直接当 JS 代码传给 V8。但 XHTML 脚本常以 `<![CDATA[ ... ]]>` 包裹（CSS21 测试套件 .xht
大量使用）；html5ever 按 HTML 模式解析会把 CDATA 标记作为文本保留 → 传给 JS 引擎的内容
以 `<![CDATA[` 开头 → **`Compile error: SyntaxError: Unexpected token '<'`** → 整个脚本失效
（函数未定义 → onload 回调再抛 `ReferenceError: xxx is not defined` → `[reftest JS] onload
handler warning: Runtime error: exception`）。

实证：insert-block-in-inlines-beginning-001.xht 修复前 `[reftest JS] Script execution warning:
Compile error: SyntaxError: Unexpected token '<'`；修复后无警告，JS 正确执行（createElement +
insertBefore + className 全工作，动态插入的块渲染出来）。

频率：全 wpt-data .xht/.xhtml **3196 个文件含 CDATA**（其中裸 `<![CDATA[` 3152 主导 +
`//<![CDATA[` JS 注释隐藏 46）。CSS21 测试套件（gtalbot 等）insert-* / delete-* 动态簇
全用此模式。

实施（LANDED）
--------------

pipeline.rs：
1. 新增 `strip_script_cdata(code: &str) -> &str`：兼容两种 CDATA 写法——裸 `<![CDATA[ ...
   ]]>` 与 `//<![CDATA[ ... //]]>`（JS 行注释隐藏，HTML/XHTML 双兼容）。起始剥
   `//<![CDATA[` 或 `<![CDATA[`，结尾剥 `//]]>` 或 `]]>`。与既有 `strip_cdata`（专 `<style>`
   CSS，R917-续 serializer 同族）独立——CSS 注释是 `/* */` 不会含 `//`。
2. `extract_page_scripts` 内 `text_content` 经 `strip_script_cdata(raw.trim()).trim()` 后
   再当 JS 代码。

意义
----

reftest harness 的 JS 执行从「能跑 DOM-mutating JS / 现代 reftest JS 模式 / named access /
createElementNS」（R917-R920）进一步到「能跑 XHTML CDATA 包裹脚本」。DC-1 真实正确性提升
——不再因 CDATA 标记致 3196 个 XHTML 测试的脚本静默编译失败。CSS21 测试套件（CSS2 大头）
的动态测试（insert/delete/dynamic-* 簇）现在 setup 脚本能正确执行，yield 阻塞转移到
R109 §9.2.1.1 匿名块生成（动态插入 block 到 inline 时匿名块盒拆分）等结构性渲染层。
