R841 — line-height-aware Ahem em-box 位（glyph 定位 line-height 依赖）LANDED
日期: 2026-06-30
性质: 有 net 源码（paint Path A stored Ahem 门控 + 单测）
前置: R839（glyph-position 是 compromise，chromium 有效 Ahem 位随 line-height 变）/ R837（全量 em-box REFUTED -25）

================================================================================
背景与上一轮交接
================================================================================
R839 实测：chromium 的有效 Ahem 方块位**随 line-height 变**——
  - line-height:1 fill 测试（line-height-128）：ZW 方块整体偏高，底部 [0.8fs, fs] 露红；
    em-box 位 [baseline−0.8fs, baseline+0.2fs] 才正确覆盖。
  - line-height>1 簇：em-box 位（R837）反致 -25 回归。
R839 裁决：glyph-position 非单值可解，须「协同改 baseline(strut)+offset+捕获 line-height 依赖」。

本轮：把「line-height 依赖」做成**显式门控**，而非盲目全量或盲目单点。

================================================================================

================================================================================

     全部是 line-height:0 测试簇（line-height-002/004/005/.../104，测 0px/0mm/0in/0pt）：
       font:20px/1 Ahem; line-height:0px;   ← 行盒塌缩，glyph 溢出

   lh:1 想要 em-box（baseline−0.8fs），lh:0/lh>1 想要 R817（baseline−fs）。

================================================================================
理论证明：strut+offset「协同改」不成立（推翻上一轮交接假设）
================================================================================
上一轮假设「协同改 strut_ascent + Path B offset + stored offset 可能解锁单点无法解锁的」。
本轮证伪：**glyph_y = baseline_y_abs − offset**。
  - layout strut_ascent 决定 baseline_y_abs。
  - paint offset 决定从基线向上多少放 glyph 顶。
  - 二者**耦合**：glyph_y 只取决于 (baseline_y_abs − offset) 的差，与二者如何分配无关。
  - 故「同时改 strut(+Δ) 和 offset(−Δ)」→ glyph_y 不变；不可能产生单点无法产生的位置。
真剩余自由度 = offset 本身（即 em-box 0.8fs vs R817 fs 的选择），已被 R837/R817 二分穷尽。
=> 单点 offset 二选一（R817 vs em-box）就是 glyph 定位的全部自由度；「协同」无额外空间。
   唯一未被前 5 轮（R833–R837）尝试的是**按 line-height 分段选择 offset**——本轮即此。

================================================================================
修复（R841）：line-height 门控 em-box 位
================================================================================
paint Path A stored 渲染循环（text.rs），真正 Ahem 字形（is_ahem_font）按 line-height 分段：

  let v_offset = if frag.is_ahem_font {
      if ahem_uses_embox_position(frag.height, frag.font_size) {
          frag.baseline_y_abs - 0.8 * frag.font_size - frag.y   // lh≈fs：em-box 位
      } else {
          frag.baseline_y_abs - frag.font_size - frag.y         // lh≠fs：R817 位
      }
  } else if frag.is_ahem { 0.0 } else { frag.font_size };

门控函数 ahem_uses_embox_position(line_height, font_size)：
  half_leading = (line_height − font_size) / 2;
  half_leading.abs() < 0.5   // lh ≈ fs（含 lh:1 / lh:1em / Ahem lh:normal=1.0）
frag.height = run line-height（inline_finalization 存储）；font_size = 片段字体大小。

分段依据（R839 实测）：
  - half-leading≈0（lh≈fs）：方块填满 line-box → em-box 位 [baseline−0.8fs, baseline+0.2fs] 正确。
  - half-leading 显著（lh:0 塌缩 / lh>1 含 leading）：保留 R817 baseline−fs（对多数更近 chromium）。

================================================================================
为什么前 5 轮（R833–R837）没找到这个
================================================================================
R833–R837 全部是**单点 offset 调参**（normal-ratio / strut_ascent 真实 ascent / Path B offset /
stored em-box），把所有 line-height 当一个总体优化 → 永远在 lh:1 与 lh:0/lh>1 之间妥协。
R839 发现了 line-height 依赖但没做成分段门控（仍试图找单值）。本轮把 R839 的观察直接
编码为 per-fragment line-height 门控，从而**同时**满足 lh:1（em-box）与 lh:0/lh>1（R817）。
