R331 — rustybuzz shaping 接入生产路径：多会话实施计划 + 子任务精确定位
========================================================================
日期: 2026-06-19
基线: self-source loose 438/490 (89.4%) / strict 295/490 (60.2%) / chromium-Oracle ~35.6%
承接: R330（@font-face 净负向，根因 = rustybuzz TextShaper 未接入生产）

动机
----
R330 确认 @font-face 字体能加载到光栅化（fontdue），但生产路径无 OpenType shaping
（ligature/kerning/GSUB/GPOS）→ 加载特性字体不应用特性，比 chromium 更远。
R330 标「真实多会话杠杆 = 接 TextShaper 入生产路径」。本轮精确定位该接入所需的全部子任务，
为后续多会话工作提供可执行起点（同 R319 column-aware IFC / R310 baseline-export spec 谱系）。

子任务定位（4 项，全部为多会话，单点不可解）
---------------------------------------------

(1) FontLoader 接入 Painter（plumbing）
    - 现状：`RenderPipeline`（pipeline.rs:48）只存 `font_resolver: HashMap<String,u32>`
      （族名→font_id），不存 FontLoader；`Painter`（painter/mod.rs:53）同样只存 resolver。
    - TextShaper::new 需要 `&FontLoader`（rustybuzz Face::from_slice 需字体原始字节）。
    - 接入：pipeline 加 `font_loader: Option<Arc<FontLoader>>` + `set_font_loader`，
      4 处 Painter 构造点（pipeline.rs:247/324/381/460 set_font_resolver 后）传 loader.clone()，
      Painter 加 `set_font_loader`。reftest harness（reftest.rs:985 附近）把 font_loader 包 Arc 传入。
    - 本轮已实验性实现并验证可编译 + 基线不变，但因 (2)/(3) 阻塞未保留（回退，避免死代码）。

(2) 【新发现·关键】光栅化须按 glyph index（非 codepoint）渲染
    - 现状：`cpu/mod.rs:485` `let ch = char::from_u32(glyph.glyph_id)` —— 把 glyph_id 当
      **codepoint**，fontdue 内部 cmap 查 glyph。生产 paint（text.rs:1057/1070）存
      `glyph_id: ch as u32`（即 codepoint）→ 光栅化正确（每字符 cmap 查对 glyph）。
    - 但 rustybuzz shaping 产出的是**字体内部 glyph 索引**（经 GSUB，可能 ligature 合并），
      若直接喂给 `char::from_u32` 会把 glyph 索引当 codepoint → 渲染错误字符。
    - 故 shaping 接入**必须同时改光栅化**：`GlyphPrimitive` 加 `is_glyph_index: bool` 标志，
      `draw_glyph_primitive`（cpu/mod.rs:462）分支：is_glyph_index=true 时用 fontdue
      `rasterize_glyph_index(glyph_index, size)`（按索引），否则保持 `char::from_u32`（按 codepoint）。
      同步 GPU 路径 + 所有 GlyphPrimitive 构造点（grep `GlyphPrimitive {` 全仓）加 `is_glyph_index: false`。
    - 这是 R330 未识别的隐藏子任务——shaping 接入比「paint 加 gate」深一层（跨 render-foundation）。

(3) TextShaper 单位/精度修复
    - shaper.rs:117-118 `x_offset: pos.x_offset as f32, y_offset: pos.y_offset as f32`：
      rustybuzz glyph_positions 的 x_offset/x_advance 是 **i32 26.6 定点**（1/64 像素），
      直接 `as f32` 得到 64× 偏移 → 位置严重错误。
    - shaper.rs:107-111 advance_x 取自 fontdue `metrics(code_point).advance_width`（像素，正确），
      但**忽略** rustybuzz `pos.x_advance`（kerning 调整未应用）→ kerning 实际未生效。
    - 修复：offset / 64.0；advance = fontdue base advance + (pos.x_advance as f32 / 64.0) 应用 kerning。
      ligature glyph（glyph_count < char_count）的 advance 须用 rustybuzz x_advance（合并宽），
      非 fontdue 单字符宽（现 shaper 取首 cluster 字符宽 = 过窄 bug）。

(4) paint 文本路径接入（env-gated 实验 → 生产）
    - text.rs:1047-1081 inline-fragment 逐字符循环：当 SHAPE_PAINT=1 时改用 TextShaper.shape_single_line
      产 ShapedGlyph，按 shaped glyph_id（is_glyph_index=true）+ advance_x + offset 定位。
    - 另 4 处 glyph 调用点（text.rs:341/541/677/1342/1426 per R330 agent）同源。
    - Ahem 跳过 shaping（FontLoader 特殊处理 Ahem，无真实字体数据）。
    - 高风险：shaped advance 改变 → 改变换行 → 触发 IFC/paint 死锁区（R125-R213）。
      须 env-gated 多轮 narrow 收敛 + 守 438/490。

advance-width 旁证（R225 死路确认，勿重试）
--------------------------------------------
本轮发现 IFC **layout**（inline/mod.rs:1366/1694）与 **paint**（text.rs:1077）**都用**
`estimate_char_width`（粗启发式：字母 0.55em / CJK 1em / 空格 0.25em）→ 两者**一致**
（test vs ref 同估计 → self-source 抵消通过）。改 paint 单侧用 fontdue 会与 layout 不一致
（致 intra-fragment 错位）；改双侧 = R223/R224/R225「三处同源替换」已证 reftest-oracle 26 案
零变化 + product-smoke ±0.03%（advance 非 chromium 噪声根因）。**advance-width 杠杆 R225 已封死**，
shaping 的价值在 GSUB（ligature）/GPOS（kerning/positioning），非 advance 替换。

裁决
----
rustybuzz shaping 接入生产 = **4 子任务多会话架构承诺**（plumbing + 光栅化按 glyph-index +
TextShaper 单位修复 + IFC gate），其中 (2) 光栅化按 glyph-index 是 R330 未识别的跨
render-foundation 隐藏子任务。单会话不可解（(2) 涉及 GlyphPrimitive 定义 + 全仓构造点 +
CPU/GPU 光栅化分支）。

与本会话代码变更
----------------
零（plumbing 实验 (1) 已实现验证可编译 + 基线不变，但因 (2)(3) 阻塞、避免死代码已回退）。
基线 self-source 438/490 / strict 295/490 持平。

下一步（多会话）
----------------
按 (1)→(3)→(2)→(4) 序实施：(1) plumbing + (3) TextShaper 修复 可先落（无生产影响，
TextShaper 仍仅单测用），(2) 光栅化 is_glyph_index 分支（含全仓 GlyphPrimitive 构造点更新 +
CPU/GPU），(4) 最后 paint gate 接入 + env-gated 多轮收敛测量。每步守 438/490 + clippy。
