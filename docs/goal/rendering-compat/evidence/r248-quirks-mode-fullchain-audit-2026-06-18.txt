【Style-system 层】✅ 3 个 quirks 调整，layout 前 pre-bake 进 ComputedStyle
  - crates/style-system/src/lib.rs:526  fn apply_quirks_mode_adjustments
    quirk ①（line 533-546）百分比高度 quirks：
        父元素 height==Auto 时，子元素 height:Percentage → Auto
    quirk ②（line 548-557）表格高度 quirks（CSS 2.1 §17.5.2）：
        <table> height 非_auto → 复制到 min_height，height 置 Auto
    quirk ③（line 559-564）inline 元素宽高 quirks：
        inline 的 width/height 保留（当前 inline→block 映射下天然生效，no-op）
  - 接线：lib.rs:420-421
      if quirks_mode == QuirksMode::Quirks {
          apply_quirks_mode_adjustments(&mut resolved, parent_style, tag_name);
      }
  - 继承 quirks：inheritance.rs compute_inherited_style_with_quirks
  结论：style-system 在 layout 之前把 quirks 值转换烘焙进 ComputedStyle。

【Layout-engine 层】⚠️ 零 quirks 字样，但非真缺口
  - grep -rn "quirk|Quirk" crates/layout-engine → 零命中
  - grep -rn "quirk|Quirk" crates/engine → 零命中
  - 架构判断（非缺口）：style-system 已把值转换类 quirks（①②）pre-bake 进
    ComputedStyle，layout-engine 作用于已纠正的值。layout-engine 无需独立
    quirks 层。故 goal doc line 356「layout engine 三层 quirks 调整」技术性
    夸大（layout-engine 实际不做 quirks 调整），但 ✅ 实质正确——quirks 工作
    正常。layout-engine 相关的几何解析（百分比高度定高判定）由
    engine.rs:1521 clamp_percentage_max_height 承担（R119 谱系），不依赖
    quirks 字样。

次要 spec 精度 nuance（非杠杆，仅记录）
================================================================
style-system quirk ①百分比高度仅查**直接父** parent_style.height（单层，
lib.rs:538-546）。CSS 规范（quirks.spec.whatwg.org）要求沿**包含块链**
向上查定高祖先。深层嵌套百分比高度在 quirks mode 下理论上可能精度不足。
但现有 ~3 个 quirks 用例全过（z_vs_chr≤0.13%），此为纯理论 nuance，
非实测缺口。
