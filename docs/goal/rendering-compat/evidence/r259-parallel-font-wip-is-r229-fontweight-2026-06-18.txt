## 2. 与「fontdue 光栅化停止」结论正交（澄清矛盾）

- **line 7 结论（R186/R187/AA-baseline）**：fontdue **光栅化**（给定 glyph → 像素）≈ chromium
  （W 0.1% / i 3.0%）→ fontdue 无需替换、光栅化非差异来源。**仍成立**。
- **R229 缺口**：ZeroWeb `find()` 一直忽略 `FontDesc.weight`（总挑 `ids.first()`=Regular）→ CSS
  `font-weight:600/700` 文本按 Regular 渲染（欠墨）→ welcome/morning-work 粗体文本 ink-mass 偏低
  （R229 CSS×ink 交叉验证：600/700 文本欠墨 10-66%）。
- **两者正交**：fontdue 把**任何**变体（Regular 或 Bold）的 glyph 光栅化得与 chromium 一致；问题是
  ZeroWeb **挑错了变体**（总 Regular）。修 font-weight 选择后，Bold 文本会用 Bold 变体 + fontdue
  正确光栅化 → 粗体正确。**无矛盾**：光栅化一直 OK，缺的是变体选择。

→ master.md line 7「字体攻坚停止」应理解为「**fontdue 光栅化替换**停止」（R186/R187 证伪 fontdue→swash
swap），**非**「所有字体工作停止」。font-weight 选择（R229）是另一条线，并行 agent 现正推进。
