R851 — DC-14 oracle 三态分类（真通过/近似通过/不一致）+ 全量 corpus 实测基线
=============================================================================

日期：2026-06-30
谱系：DC-14 unchecked 项「严格容差复跑 + 三态分类」+「唯一可信达标指标 = 严格容差真通过率」。
前置：R669 oracle harness 仅二态（z_vs_chr < 1% pass/fail），未暴露 strict-vs-loose 分布。

────────────────────────────────────────
1. 动机
────────────────────────────────────────

DC-14 spec（goal line 343）：「必须在文档锁定容差（布局 ≤ 0.1% / 文字 ≤ 0.5%）下复跑全量，
输出 **真通过 / 近似通过（超锁定容差但更宽松）/ 假通过（退化或同源）** 三态。唯一可信达标
指标 = **严格容差真通过率**。」

R669 oracle 仅报 binary oracle-pass (<1%)，无法区分「真严格通过」与「1% 容差下的近似通过」。
本轮在 oracle 报告加三态分类，首次产出严格容差真通过率（DC-14 核心指标）。

────────────────────────────────────────
2. 改动（tests/wpt-runner/src/main.rs cmd_reftest_oracle）
────────────────────────────────────────

results tuple 由 (id, has_oracle, z_vs_chr_pct) 扩为 (id, has_oracle, z_vs_chr_pct, strict_thresh_pct)，
strict_thresh = case.category.strict_max_diff_ratio() * 100（复用既有 ReftestCategory 方法：
Layout 0.1% / Text 0.5% / Unknown 0.1%，DC-14 锁定硬上限）。

三态分类（loose = pass_ratio，默认 1%）：
  - 真通过 (strict pass)：z_vs_chr < strict_thresh  ← DC-14 唯一可信达标指标
  - 近似通过 (near pass)：strict_thresh <= z_vs_chr < loose
  - 不一致 (mismatch)：z_vs_chr >= loose

报告新增三行 + strict_rate。零行为变化（不改 pass/fail 判定，只增分类报告）。

────────────────────────────────────────
3. 验证
────────────────────────────────────────

(A) 编译 + clippy -p zero-wpt-runner --all-targets -- -D warnings 零警告；fmt 干净。

(B) scoped oracle（css/CSS2/positioning，520 case，含 R850）三态输出正确：
      oracle-pass (z_vs_chr < 1.0%): 237 (45.6%)
      ── DC-14 三态分类 ──
      真通过 (< 布局0.1%): 3 (0.6%)
      近似通过 (strict..1.0%): 234 (45.0%)
      不一致 (>= 1.0%): 283
    守恒检查：3 + 234 + 283 = 520 ✓；strict(3) + near(234) = 237 = oracle-pass ✓。

(C) 全量 corpus 实测（10158 case with oracle，含 R850）：
      chromium-Oracle pass-rate (loose <1%): **38.4% (3905/10158)**  ← 全量诚实基线
    （7-主目录聚合 ~36.4% 同量级；全量含 css-text i18n/bidi/shaping/line-break 等 0-10% 子目录拉低）

────────────────────────────────────────
4. 关键洞察（DC-14 价值兑现）
────────────────────────────────────────

三态分类首次量化揭示：positioning dir 的 237 个 1%-通过中，**仅 3 个是严格通过（0.6%）**，
**234 个是近似通过（0.1%-1%）**。即绝大多数「pass」是 fontdue-vs-chromium 字体光栅噪声
（R388：per-glyph 一致但行级累积；单 Ahem glyph ~400px 已 > 0.1% strict 阈值），非布局精确匹配。

这正面兑现 DC-14 设计目的：1% 容差的 45.6% pass 含大量近似通过，**严格容差真通过率 0.6%**
才是诚实指标。DC-2~5「≥95%」达标须以 strict 真通过率为准——当前 0.6% (positioning) 距 95%
极远，主因 = 字体光栅（fontdue≠chromium 像素级）+ 布局结构性缺口（R109/multicol/taffy）。

────────────────────────────────────────
5. 对 DC-14 checkbox 的影响
────────────────────────────────────────

- DC-14「严格容差复跑 + 三态分类」：oracle 路径**现已支持三态**（本 R851）。self-source
  reftest 路径的 strict 复跑（ZERO_REFTEST_STRICT env，R280 既存）独立，未触动。
- DC-14「容差锁定不可放宽」：strict 阈值复用既有 strict_max_diff_ratio（已锁定 0.1%/0.5%），
  本轮未放宽，仅消费。
- DC-14「非平凡性检查」（退化/纯色假绿检测）：**仍未实现**，本轮未触及（后续可加：oracle
  frame 近纯色 + 低 diff → 标可疑）。

────────────────────────────────────────
6. 意义 + 下一步
────────────────────────────────────────

诚实化 DC-14 测量：从 binary 38.4% 细化为三态，揭示 strict 真通过率（0.6% positioning）
才是达标基准。这对路线图有校正意义——**字体光栅像素级对齐（fontdue→chromium-matching）**
是 strict 真通过率从 ~0.6% 提升的唯一路径之一（另一为布局结构性修复），属 out-of-single-
session 大工程（R849 font-metric net-negative 证；fontdue 替换）。

下一步：DC-14「非平凡性检查」可作下一 harness 增量；pass-rate 真 lever 仍为多会话结构性
（taffy R304 / Phase A IFC / fontdue 替换）。
