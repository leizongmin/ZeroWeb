================================================================================
实现（对齐 CPU apply_transform_post，逐字语义）
================================================================================
CPU 侧（cpu/mod.rs:720 apply_transform_post）核心算法：
  - 仿射矩阵 |a c tx| 的逆矩阵在 CPU 算：det=a*d-b*c；|det|<1e-10 跳过
                |b d ty|
  - 对 rect 内每个目标像素 (x,y)：px=x-ox, py=y-oy（ox/oy=origin*scale）
    src_x = inv_a*px + inv_c*py + inv_tx + ox
    src_y = inv_b*px + inv_d*py + inv_ty + oy
  - 先把整块 rect 清白 [255,255,255,255]，再 round() 取整最近邻回填逆映射落在
    rect 内的源像素；落在 rect 外的位置保持白色（clear-to-white）

GPU 侧接线（gpu/renderer/mod.rs + gpu/pipeline.rs）：
1. TRANSFORM_SHADER（pipeline.rs，本轮修正）：
   - 全屏三角形 vs_fullscreen，uv→dst_px = uv*screen
   - fs_transform：逆矩阵重采样，**无条件 textureSample + select**（修正起草版的
     `if` 分支内 textureSample——wgpu 校验要求 textureSample 在 uniform control flow，
     故改为无条件采样后 select(white, sampled, inside)，避免 validation error）
   - uniform 布局 TransformUniforms（64 字节）：screen(vec2)+origin(vec2)+inv_row0(vec4
     =[inv_a,inv_b,inv_c,inv_d])+inv_row1(vec2=[inv_tx,inv_ty])+rect_min(vec2)+
     rect_max(vec2)+pad(vec2)
2. RendererState 新增字段 transform_pipeline + transform_uniform_bgl（#[allow(dead_code)]
   因仅在 headless 路径调用，window 路径不触达）
3. from_device 创建两者（复用 blur_bgl 作 group 1 源纹理布局）
4. collect_transforms（自由函数，镜像 collect_color_filters）：CPU 侧预计算逆矩阵
   （逐字复刻 apply_transform_post 的 det/inv_* 公式），奇异矩阵跳过 → TransformPost
5. apply_transform_filters_headless（方法，镜像 apply_color_filters_headless）：
   ping-pong A→B→scissor pass→B→A，uniform 上传 16 f32，**Nearest sampler 匹配 CPU .round()
   整数采样**（Linear 会双线性插值与 CPU 不一致）；headless-only
6. render_full_scene_gpu：在 blur 后处理之后 collect_transforms + 调用
   （无 transform 时不触发 → 零默认回归）

(28,16) 蓝 B>200/R<30/G<30。**单测 PASS**（纯 0/255 通道值 sRGB 往返精确）。

环境 flake（既有，非本轮引入）
================================================================================
`cargo test -p zero-render-foundation --lib`（并行，默认多线程）在本 WSL 偶发 SIGSEGV
（signal 11）。经 git stash + 在 HEAD（3a3530f，无本轮变更）复跑 3 次：run1 ok / run2
SIGSEGV / run3 ok——**证明该 flake 既有**（R277 GPU blur ping-pong 增加 software wgpu
后端并发 contention 后出现的并行设备竞争；read_pixels 的 device.poll(Wait)+map_async
跨多个 fallback adapter 并发触发 native 后端崩溃）。单线程 --test-threads=1 稳定
488/488。本轮新增的 transform 测试**未恶化**该 flake（HEAD 同样 flaky）。
make test（全工作区）在干净单次运行可达 doctests（exit 0，全绿）；偶发需要重试。
未改 production GPU 代码修该 flake（避免 scope creep + 死锁风险）；记录备查。

================================================================================
对 DC-9 / 优先级队列的影响
================================================================================
DC-9 GPU 前进：opacity（f6fed44）→ brightness+contrast（fc86937 color-filter）→
blur（3a3530f）→ **transform（本轮）**。剩仅 **blend_mode**（R269：CPU apply_blend_mode
是 NO-OP STUB，GPU 真实现需 source+dest 双图层新机制，与 CPU no-op 分歧破坏对齐，是
比 opacity/blur/transform 大的独立特性）。transform 落地后 DC-9 GPU 剩 blend 一项。
transform 经独立 WGSL pipeline（TRANSFORM_SHADER + create_transform_pipeline）渲染，
满足 DC-9 非 passthrough + DC-14。
