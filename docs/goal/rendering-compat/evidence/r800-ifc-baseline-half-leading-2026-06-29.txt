R800 — IFC 行盒 baseline = half-leading + ascent（CSS §10.8.1）·替代 line_height*0.8·spec-correct·小正收益·零回归
================================================================================
日期: 2026-06-29
性质: 源码修复（IFC apply_vertical_alignment 行盒基线公式）+ 小正收益；零回归
承: R799 audit 后定位「文本基线偏低累积」为 welcome ~17% 候选根因之一（R790 谱系）

================================================================================
1. Bug：strut_ascent = line_height*0.8 随 line-height 增长过快，基线偏低
================================================================================

inline/mod.rs apply_vertical_alignment（line 1738+）：
  旧：strut_ascent（文本行）= line_height * 0.8；max_ascent = max(strut, run.font_size)
  → baseline_y = max_ascent。

  对 line-height=1.5、font_size=F：line_height=1.5F，strut=0.8*1.5F=1.2F → baseline_y=1.2F。
  chromium（CSS §10.8.1）：baseline = half-leading + ascent = (line_height - em)/2 + ascent。
  em≈F、ascent≈0.8F → baseline = (1.5F - F)/2 + 0.8F = 0.25F + 0.8F = **1.05F**。
  → ZW 基线 1.2F vs chromium 1.05F，**ZW 文本基线偏低 0.15F**，跨行累积（welcome 候选根因）。
  旧 0.8*line_height 随 line-height 线性增长过快（line-height 2.0 → ZW 1.6F vs chr 1.3F，差 0.3F）。

  ★ 这是 R790 未测的 seam：R790 测的是 NORMAL_LINE_HEIGHT_RATIO（line-height:normal），
  本修复改的是 **baseline 定位公式**（apply_vertical_allocation），不同代码路径。

================================================================================
2. Fix：strut/run ascent 用 half-leading + ascent 公式
================================================================================

  strut_ascent（文本行）= (line_height - dominant_fs)/2 + dominant_fs*0.8
    （half-leading = (line_height - em)/2，ascent = 0.8*em；dominant_fs = 行内最大 font_size）
  run 文本 ascent：run.font_size → run.font_size * 0.8（真实 ascent 近似，原 font_size 偏大）
  atomic-only 行（无文本）：strut = container_font_size * 0.8（不变）

  对 line-height=1.5、dominant_fs=F：(1.5F-F)/2 + 0.8F = 1.05F ✓ = chromium。
  仍用 0.8 ascent 常数近似（真实 ascent 因字体而异，DejaVu/Ahem 不同），但公式结构正确。

4. 诚实裁决：spec-correct + 零回归 + 小正收益；font-wall 限制增益
================================================================================

  本修复把 baseline 公式从「line_height*0.8 近似」改为 CSS §10.8.1 正确的
  「half-leading + ascent」，spec-correct 且**零回归**（css-fonts 50/50、self-source
  test+ref 同步移基线）。收益**小正**（welcome +0.05pp、text-decor oracle +0.4pp）。

  ★ **关键裁决（font-wall 确证）**：welcome 仅 +0.05pp 证明 welcome ~17% 主因**非** baseline
  公式，而是 **font-wall**（ZW DejaVuSans vs chromium 系统字体的字形/advance/ascent 固有差异）。
  即使 baseline 公式修对，不同字体的固有 metric 仍发散。★ **font-wall = font mismatch**
  （非 metric tuning 可解），真修须 ZW 用与 chromium 相同的字体（bundle NotoSansCJK/系统字）。
  本 R800 修对 baseline 公式（spec-correct、为 font-wall 解后铺路）+ 小正收益 → ship。

  类 R776/R793 spec-correct pattern（区别：增益被 font-wall 限制，但仍 spec-correct + 零回归）。
