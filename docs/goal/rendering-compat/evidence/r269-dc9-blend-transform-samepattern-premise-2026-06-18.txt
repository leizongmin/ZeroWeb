## DC-9 三缺口逐项核实（blur/transform/blend）

### ① Blur — SOUND（有真实 CPU 参考，ping-pong 同模式）

CPU `apply_filter` 的 `FilterKind::Blur(radius)`（cpu/effects.rs:36-41）调 `apply_box_blur(fb, left, top, right, bottom, r)` 区域盒模糊——**真实实现**，区域 post-process。GPU 可同 opacity ping-pong 模式（采样邻域、写第二纹理）。**同模式扩展成立**。✓

### ② Transform — 真实近似参考（可 ping-pong 复刻，但更复杂）

CPU `apply_transform_post`（cpu/mod.rs:720-786，**确实被调用** :169/:257）：
- 保存 rect 区域像素 → 清区域为**白色** → 反向采样（每输出像素逆矩阵映射到源像素 copy）。
- **真实但近似**：暴露区（变换后露出的）填**白**而非真背景；源仅限原 rect（裁剪）；round() 整数采样（非插值）。
- GPU 可 ping-pong 复刻（读源纹理区域→逆采样→写第二纹理），但须**匹配这些近似 quirk**（白填暴露区/rect 裁剪/整数采样）才能 CPU/GPU 对齐——比 opacity 区域乘复杂得多。「同简单模式」是**过度简化**，非不可行但需逐 quirk 对齐。

### ③ Blend — FLAWED（CPU NO-OP STUB 无参考，非 opacity 同模式）⚠️

CPU `apply_blend_mode`（cpu/effects.rs:331-345，**被调用** :179/:252）：
```rust
pub fn apply_blend_mode(fb, blend, scale) {
    let left/right/top/bottom = blend.rect 缩放钳界;
    if left>=right||top>=bottom { return; }
    // CPU 渲染器中混合模式的简化实现：
    // Normal 模式不需要做任何事情
    // 其他混合模式在 CPU 渲染器中效果有限（完整实现需要「源」和「目标」两个图层）
    let _ = (left, top, right, bottom); // 丢弃
}
```
→ **NO-OP STUB**：计算 rect 后直接丢弃，**blend 实际不渲染任何东西**（CPU 与 GPU 均无 blend 渲染）。注释明确「完整实现需要源和目标两个图层」。

**含义（为何「同模式扩展」flawed）**：
- blend 无 CPU 参考可锚定（opacity/blur/transform 都有 CPU 参考，blend 没有）。
- blend 需 **source（元素）+ destination（背景）两图层**做合成——与 opacity 的「区域 RGB 乘」**根本不同机制**，opacity ping-pong 模式**不适用**。
- 若 GPU 真实现 blend（满足 DC-9 覆盖），会**与 CPU no-op 分歧** → 破坏 DC-9/DC-14 想要的 GPU==CPU 对齐（GPU 渲染了 blend，CPU 没有）。
- 故 DC-9「blend 覆盖」≠ opacity 那样「GPU 复刻 CPU」；需**同时**在 CPU+GPU 从零实现 blend（backdrop 图层分离），是比 opacity 大得多的特性，非「同模式 follow-on」。

## 对优先级队列的影响

- **DC-9 opacity（R268 sound）+ blur（本轮 sound）= 可同 ping-pong 模式推进**，有真实 CPU 参考，GPU 复刻对齐。
- **transform = 可推进但需逐 quirk 对齐**（白填暴露区/rect 裁剪/整数采样），非简单同模式。
- **blend = 非「同模式 follow-on」**：CPU stub 无参考，需 source+dest 双图层新机制 + CPU+GPU 双端从零实现。DC-9 的 blend 项**实质比 opacity/blur 难得多**，1d50409 spec 的「blur/transform/blend 后续同模式扩展」对 blend **过度乐观**。建议并行 agent 先 opacity→blur（同模式），transform 单独处理 quirk，blend 标记为更大独立特性（可能 defer 或需 backdrop-layer 架构）。
- 不改变「DC-9 是当前唯一 active forward motion」结论；但细化：opacity/blur 可快速 follow，transform 中等，blend 难——避免后续据「同模式」乐观低估 blend。

## 方法学沉淀（延续 R266/R267/R268）

「同模式扩展」前提须逐项核上游参考是否存在 + 机制是否真同：
- opacity/blur：有 CPU 真实参考 + 同 post-process 机制 → sound。
- transform：有 CPU 近似参考但机制更复杂（逆采样+quirk）→ 部分同模式。
- blend：无 CPU 参考（stub）+ 不同机制（双图层）→ flawed「同模式」假设。
**教训**：不要据「都是后处理图元」望文推断「同模式」，须核每项的 CPU 参考 + 合成机制（区域单层 vs 双图层）。
