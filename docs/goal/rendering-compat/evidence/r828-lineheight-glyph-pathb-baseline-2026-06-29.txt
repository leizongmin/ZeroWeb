R828 — line-height>1 字形垂直错位根因窄化（Path B paint baseline 忽略 line-height）
日期: 2026-06-29
性质: 纯调查（read-only 探针 + 临时插桩已全部回退），零 net 源码变更
前置: R822（va-117a 24%→13%）/ R823-R827（残余归因 fontdue deep-plateau / margin-collapse refuted）

================================================================================
背景
================================================================================
R827 把 va-117a 残余 13.59% 的 `<p>` 偏移归为「fontdue 首行 baseline deep-plateau」
（vague）。本轮用直接 chr-vs-ZW 像素探针 + LAYOUT_DUMP + 临时 paint 插桩，把
「deep-plateau」窄化为**一个具体的、可定位的 paint bug**，并修正 R827 的归因。

================================================================================
探针 1：va-117a 像素分解（midline x=400 垂直扫描）
================================================================================
ZW:  white→(y48 grey)→yellow 52-104→blue(span) 104-144→yellow 144-226→white
CHR: white→yellow 68-114→blue 114-154→yellow 154-244→white
- ZW div yellow 52-226 (174px)；CHR 68-244 (176px)。**div 总高一致**（~175px），ZW 整体高 16px。
- blue span: ZW 104-144，CHR 114-154（ZW 高 10px）。
=> 16px 偏移来自 div 上方的 `<p>` 区（ZW `<p>` 区更矮），非 div 本身高度错。

================================================================================
探针 2：隔离 line-height>font-size 的块（body margin:0, 单 div）
================================================================================
最小复现: `<body margin:0><div style="background:yellow;font:40px/130px Ahem">XXXX</div></body>`
渲染实测（ZeroWeb CPU）:
- line-height:40px (==font-size): yellow 0-31（top=0 ✓ 正确）
- line-height:130px:           yellow top=27 bottom=129 height=103（top=27 ✗ 应 0）

关键：x=200（glyph XXXX 之外）yellow = 0-129（h=130 ✓ 背景正确！）；
      x=50（glyph 内）y=0-26 = BLACK（glyph），y>=27 = yellow。
=> **背景填充正确（0-130），错的是字形：XXXX 字形渲染在 div 顶部（y=0-26），
   而非按 line-height 居中的基线位（~y=37-77）。**

================================================================================
探针 3：LAYOUT_DUMP（layout 是否正确？）
================================================================================
`div abs_y=0.0 h=130.0 mt=0.0 pt=0.0 x=0.0 w=800.0`
=> **LAYOUT 正确**（div 在 y=0，高 130）。background paint 也正确（paint_background
   收到 abs_y=0 h=130，fill Rect(0,0,800,130)）。错仅在 **glyph 垂直定位**。

================================================================================
探针 4：paint 路径（use_stored 临时插桩）
================================================================================
R828_DBG: `use_stored=false width_matches=false ilw=0 ifcw=800 il_some=false`
=> 该 pure-Ahem div **未存储 inline_layout**（inline_layout_width=0），
   故走 **Path B（非存储 paint 路径）**，而非 R817 修好的 stored 路径。

================================================================================
根因（精确定位）
================================================================================
Path B 非 multicol 渲染循环（crates/engine/src/paint/painter/text.rs:1325-1341）：
  for fragment in fragments.iter() {  // fragments = all_fragments_with_line_y()
      let baseline_fs = stored_fs.unwrap_or(fragment.font_size);  // = font_size
      render_fragment!(fragment.x, fragment.y, baseline_fs, ...);  // baseline_offset = font_size
  }
glyph_y = content_y + fragment.y + baseline_offset(+ty)
        = content_y + fragment.y + font_size

- Path B 把 **font_size 当作基线偏移**，从 fragment.y（line-height>1 时为负，
  = baseline_y - line_height）起算 → line-height>1 时字形爬到行盒顶部/越顶。
- 对比 R817 stored 路径（text.rs:1308-1309）：
    v_offset = frag.baseline_y_abs - frag.font_size - frag.y  // 用 line.baseline_y ✓
  glyph_y = content_y + line.y + line.baseline_y - font_size（正确基线位）
- 即 **stored 路径用 line.baseline_y（含 half-leading），Path B 用 font_size（忽略 line-height）**。
  line-height==font-size 时二者相等（故普通文本无碍）；line-height>1 时分歧。

影响面：所有「未存储 inline_layout + line-height>font-size + 含文本」的块。
未存储的原因（ilw=0）：compute_final_inline_layouts 存储未覆盖到该 div 的 painted box
（box-tree 生命周期/重建分歧，Phase A 域）——pure-Ahem 理论应存储（守卫 line 524-528
放行），但实测 il_some=false，说明存储与 paint 消费的 box 不是同一棵/未传递。

   TextFragment.y 在 line-height>1 的精确语义 + 提供 line baseline（threading），非一行可成。

================================================================================
对 R827 归因的修正
================================================================================
R827「`<p>` offset = fontdue 首行 baseline deep-plateau」**部分不准确**：
- 该偏移**非** fontdue 光栅化噪声，而是 Path B paint 用 font_size（非 line.baseline_y）
  作基线偏移的**确定性 paint bug**，对 line-height>1 的块可复现、可定位（text.rs:1332）。
- 「deep-plateau」表述应改为「Path B glyph baseline 忽略 line-height（Phase A 可修）」。
- R826/R827 margin-collapse 结论不变（taffy 确折叠，refuted 正确）。
