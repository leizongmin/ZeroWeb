1. Bug：overflow clip_rect 用 content box，CSS 要求 padding box
================================================================================

R792 修复「自身直属文本漏裁」后，核查 clip_rect 本身的盒模型：

  paint_node / paint_node_in_rect 的 needs_clip 分支（原代码）：
    let clip_rect = Rect::new(
        abs_x + border_left + padding_left,      ← 起点：content box 左上
        abs_y + border_top + padding_top,
        content_width,                            ← 尺寸：仅 content
        content_height,
    );

  即裁剪到 **content box**（padding 之内）。

CSS §11.1.1（overflow）/ CSS Overflow L3 + 全部浏览器（含 chromium）实际行为：
  overflow 裁剪到 **padding box**（内容 + padding，border 之内）。
  → content 边与 padding 边之间的「padding 条带」内的溢出内容，chromium 保留可见，
    ZeroWeb（content-box 裁剪）多裁掉。

复现（手算几何）：
  父盒 overflow:hidden，border=0，padding=20 四周，content 10×10：
    content box = [20,30]×[20,30]
    padding box = [0,40]×[0,40]
  子盒红背景 100×100 从 content 原点 (20,20) 溢出到 (120,120)。
    chromium（padding box）：红可见 [20,20]→[40,40]（保留 padding 条带）
    ZW 修复前（content box）：红可见 [20,20]→[30,30]（多裁 padding 条带）
  → 真实 CSS-correctness bug（影响 overflow + padding + 溢出内容的真实页面与 reftest）。

================================================================================
2. Fix：clip_rect 改为 padding box 几何（双路径）
================================================================================

paint_node + paint_node_in_rect 的 needs_clip 分支：
    let clip_rect = Rect::new(
        abs_x + border_left,                                             ← padding box 左上（border 之内）
        abs_y + border_top,
        padding_left + content_width + padding_right,                    ← padding box 宽
        padding_top + content_height + padding_bottom,                   ← padding box 高
    );

  → 裁剪到 padding box（border 之内，含 padding），与 chromium 一致。
  顺带修正 paint_node_in_rect 处 stale 注释「裁剪到内容盒范围内」→「padding box（CSS §11.1.1）」。

  border 仍不裁（CSS：overflow 不裁盒子自身 border/background，仅裁内容到 padding box）。

4. 诚实裁决：spec-correct 修复，零回归；oracle divergence 影响【未实测】
================================================================================

本修复在已测路径（overflow 单元测试族 + overflow/max-width self-reftest + welcome
product-smoke）**零回归**，是明确的 CSS-correctness bug 修复（spec §11.1.1 + 浏览器
实际行为 = padding box，原 content box 裁剪错误）。

★ oracle divergence reduction **未实测**：本机无缓存 oracle-shots（capture 需 chromium
+ 网络/代理），故未能像 R792 那样给出 max-width-106 -7.57pp 的量化。但：
  - 修复方向**确定正确**（content box → padding box 对齐 chromium，非推测）。
  - 影响范围**确定存在**：任何 overflow:hidden/scroll/clip + 非零 padding + 溢出内容
    的盒子，padding 条带内的内容现保留（原被多裁）。
  - 预期影响量级：与 R792 同类（divergence-reduction，非必然 PASS flip）——多数 overflow
    用例内容远溢出 box，padding 条带差异小；近边界用例（溢出量 ≈ padding 宽）可能改善。

裁决：ship（spec-correct + 零回归 + 单元测试区分 + 几何可证）。区别 R792（有 oracle 量化）：
本修复 oracle 影响待后续轮 reftest-oracle 实测补量；spec 正确性本身已确证（不依赖 oracle）。
