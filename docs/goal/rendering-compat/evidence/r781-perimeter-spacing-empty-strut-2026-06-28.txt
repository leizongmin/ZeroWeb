## 背景：R780 诊断不完整

R780 把 visibility-collapse-border-spacing-002（7.07%）的残余归因为「空 cell 行 20px 默认
最小行高」。R781 直接渲染对比（product-smoke + PIL）发现真因是 **两个独立 bug 叠加**：

ZW 渲染 border-spacing-002（1 列 100px + border-spacing 50px 100px + 空 rowspan cell 跨折叠行）：
  - 红 strip 100×20（空 cell 的 20px strut）
  - 绿表仅 100×100（应 200×200）
chromium oracle：
  - 绿表精确 200×200（x[8,207] y[50,249]），0 红像素

7.07% 发散 = ~6.6%（表尺寸 100×100 vs 200×200，缺周界 spacing）+ ~0.4%（20px strut）。
R780 只看到 strut（0.4%），漏掉了主导的周界 spacing（6.6%）。

## Bug 1：border-spacing 周界缺失（separated borders model）

CSS 2.1 §17.6.1：separated borders 模型下 border-spacing 不仅分隔相邻 cell，还构成表格四边
「周界 spacing」（外缘 cell 与 table 边缘之间）：
  - 1 列：[左周界 50][cell 100][右周界 50] = 200
  - 2 列：[左 50][c1][50][c2][右 50]

旧实现 `spacing_total_x = (col_count-1)*spacing_x` 只计列间 spacing，漏掉左右周界（各
spacing_x）和上下周界（各 spacing_y）→ 带非零 border-spacing 的表尺寸偏小、cell 紧贴
table 边缘。

**fix（crates/layout-engine/src/table.rs，5 处，全 gated on `border_collapse == Separate`）**：
  1. position_cells `table_content_width`：`col_sum + spacing_total_x + 2*perimeter_x`
  2. position_cells `row_y` 起始：`perimeter_y`（顶周界；循环每行 +spacing_y 自然产生底周界）
  3. position_cells `cell_x` 起始：`perimeter_x`（左周界）
  4. apply_table_size_constraints `intrinsic_width`：`total_col + spacing_total_x + 2*perimeter_x`
     （intrinsic_height 由 total_row_height=row_y 自动含上下周界，无需单独改）
  5. update_row_group_positions `row_y` 起始：`perimeter_y`（与 position_cells 对齐，否则行组
     与行错位）

**关键设计**：row_y 起始 = perimeter_y + 每行 +spacing_y 的推进，自然产生 (visible_rows+1)*spacing_y
= 顶周界 + 列间 + 底周界（collapsed 行跳过 spacing 故不破坏周界语义）。border-spacing-002
实测：row_y=100(顶) + row0(0) + 100 = 200 ✓。

**blast radius 控制**：border-spacing 默认 0 → 多数表 perimeter=0 无变化；仅非零 border-spacing
的 separated 表受影响。collapse 模式 gated out（collapse 忽略 border-spacing）。

## Bug 2：空 cell 20px strut 错误

旧实现对「无内容的空行」应用 20px 默认最小行高 strut（`if h==0 { 20 }`，3 处）。
chromium 对 padding:0 的空 cell 渲染 0px（无 strut）。

**fix**：移除 3 处 20px 默认（content_row_heights / position_cells row_height /
update_row_group_positions），空行高度 = 0。`else { 20.0 }` degenerate fallback（无 row_box）
同步改 0.0。

**验证（decisive experiment）**：先单独测「移除 strut」A/B → css-tables 59→60（+1 PASS）+
CSS2/tables 44→44（零回归）→ 证实 strut 普遍错误（非仅 collapse 特例）。

## 方法论

R780 的「空 cell 20px strut」诊断只覆盖 7.07% 中的 0.4%（PIL 只数了红 strip）。R781 用
「product-smoke 渲染 + PIL 完整几何分析」（green bbox 100×100 vs chromium 200×200）定位
主导的周界缺失。**教训**：divergence 归因须量化各成分（strut 2000px vs 尺寸差 30000px），
不能只看最显眼的红 strip。decisive experiment（移除 strut 单独 A/B）区分了「strut 普遍错」
vs「strut 仅 collapse 特例」。
