R244 — DC-9 GPU alpha groundwork 精确 spec（read-only，无代码提交）
===================================================================
日期：2026-06-18
角色：rendering-compat 调研与文档维护（本角色不改源码）
来源：R220（DC-9 真实范围纠正：GPU 缺口仅 transform/filter/blend）+ R228b（GPU
color_to_f32 全局丢 alpha）+ R241（contained clean win 穷尽，DC-13/DC-9 为高价值方向）。
本调研独立于并行 agent 的 IFC WIP（不动 layout-engine/inline/engine paint）。

【背景】DC-9（GPU 渲染器 13 图元独立 WGSL pipeline，禁 CPU passthrough）是硬 Done Criterion。
R220 纠正：clip 为 no-op（engine 不生成 ClipPrimitive），真实 GPU 缺口仅 **transform/filter/blend**
三项（engine 在 effects.rs:266/289/313 生成，GPU 全量路径静默丢弃）。R228b 记 GPU `color_to_f32`
（mesh.rs:11）全局丢 alpha。本轮精确定位 GPU alpha 通道缺口 + ping-pong groundwork。

────────────────────────────────────────────────────────────────────
1. 精确缺口：GPU 顶点色丢 alpha = CPU R228b 的 GPU 类比（实证）
────────────────────────────────────────────────────────────────────
- mesh.rs:11 `color_to_f32(color) -> (f32,f32,f32)` 只返 RGB，丢 color.a。
- mesh.rs:16 `push_fill_quad` 顶点 = `[x,y,u,v,r,g,b]`（7 float，无 alpha）。
- pipeline.rs 顶点格式 `@location(...) color: vec3f`（fill :35、rounded_rect :42/:297 等）。
- pipeline.rs:54 fragment `return vec4f(in.color, alpha)`——`in.color` 是 **vec3f RGB**，`.a` 槽填的是
  **coverage alpha**（纹理 R 通道或圆角检测/1.0），**不是 CSS 色彩的 alpha**。
- pipeline.rs:462/540/617/676 各 pipeline 已配 `wgpu::BlendState::ALPHA_BLENDING`——output merger
  能 alpha 合成，但**源 alpha ≡ coverage/1.0**，CSS `rgba(255,0,0,0.5)` → vec4f(1,0,0, 1.0) = 实色红。
⇒ **所有 GPU 图元渲染成不透明**（与 CPU R228b「fill_rounded_rect 硬编码 alpha=255」同源不同层）。
半透明 fill/rounded_rect/gradient/shadow 在 GPU 全部失真——影响面远超 DC-9 三项，是**基础渲染保真缺口**。

────────────────────────────────────────────────────────────────────
2. Groundwork 修复（per-primitive alpha 前置，contained）
────────────────────────────────────────────────────────────────────
为让 GPU 支持任意图元半透明（并为 blend-mode 图元铺路），需把色彩 alpha 打通顶点→片元：
  (a) mesh.rs：`color_to_f32` 改返 `(r,g,b,a)`；`push_fill_quad` 等改推 8 float `[x,y,u,v,r,g,b,a]`。
  (b) pipeline.rs 顶点布局：fill/rounded_rect 等的 color 属性 `vec3f`→`vec4f`（ShaderLocation 不变，
      array_stride +1 float），FILL_VERTEX_CHANGES 等常量同步。
  (c) pipeline.rs WGSL：VertexInput `color: vec3f`→`vec4f`；fragment 合成 **色彩 alpha × coverage alpha**
      （如 `let a = in.color.a * coverage; return vec4f(in.color.rgb, a)` 或 premultiplied
      `vec4f(in.color.rgb * a, a)`），不再硬填 1.0。
  (d) Blend state 已 ALPHA_BLENDING ✓（无需改）；若用 premultiplied 需配 `BlendComponent::PREMULTIPLIED`。
- **范围 contained**：仅 mesh.rs + pipeline.rs（顶点布局/WGSL），不动 renderer 渲染流（render_full_scene_gpu
  单 pass 结构不变）。零行为变化（当前所有 CSS 色彩 alpha 默认 1.0，改后仍 1.0；只有显式 rgba<1 才生效）。
- **验证**：单测输入 `FillPrimitive{color: rgba(255,0,0,0.5)}` 渲染到 framebuffer，断言结果像素 = 红×0.5+
  背景 blend（非实色红）；附 GPU headless 截图 vs CPU blend 对照。make reftest 同源不回归（CPU 已正确）。

────────────────────────────────────────────────────────────────────
3. 超出 alpha 的 DC-9 三项（transform/filter/blend）= ping-pong 结构项
────────────────────────────────────────────────────────────────────
alpha groundwork 落地后仍缺 transform/filter/blend（需 **ping-pong 后处理**）：
- 现状：render_full_scene_gpu（renderer/mod.rs:651）**单 render pass** 直接合成到 headless/surface 纹理，
  无中间纹理回读。wgpu 不能同 pass 读写同一纹理，filter（blur/opacity 作用于已渲染内容）/transform
  （仿射作用于子图元）/blend（mix-blend-mode 取底色合成）均需「渲染元素到 offscreen A → 后处理 pass
  读 A 写 B（或回 framebuffer）」。
- R220 记：headless_texture offscreen target 就绪，**差第二张纹理 + post-process pipeline**。
- 最小首步 = **filter:opacity**（但注意：全元素 opacity 在 alpha groundwork 后可经顶点 alpha 直达，
  惟 filter:opacity 作用于**已渲染子内容**仍需 ping-pong）。次选 filter:blur（box-blur/Gaussian pass）。
- **范围**：renderer/mod.rs 加第 2 offscreen texture + post-process render pass + 新 WGSL（filter/transform/
  blend 各一），属结构多轮项（非 contained 单点），是 DC-9 真正大头。

────────────────────────────────────────────────────────────────────
4. 推荐执行顺序 + 与既有结论一致
────────────────────────────────────────────────────────────────────
1. **alpha groundwork（§2，contained 先做）**：打通色彩 alpha，修 GPU-R228b-analog，提升基础保真 +
   为 blend 铺路。zero-regression（alpha 默认 1.0）。
2. ping-pong 地基（§3，filter:opacity/blur 先行）：DC-9 transform/filter/blend 三项。
3. 验证：每新增 WGSL pipeline 配 framebuffer 像素断言单测（M7 要求，禁「看起来对」）。
- 不与 R220 冲突（本调研细化其「ping-pong 缺第二纹理」为「先 alpha groundwork 再 ping-pong」）。
- 不与 R228b 冲突（CPU 已修，本调研补 GPU 同源层）。
- 独立于并行 agent IFC WIP（DC-13 morning-work）；DC-9 GPU 为正交方向。
