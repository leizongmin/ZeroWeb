结论 1：R368 width-shrink 是真实 DC-14 大胜（非 self-source 假象）
================================================================
ifc-011 z_vs_chr：**12.30% → 2.22%（-10.08pp 真 chromium 改善）**。R368 不只是
self-source 改善（self REF 是 ZeroWeb 自渲染会抵消），而是把 span 从满宽堆叠
（w=784, y=101，与 chromium 的 w=90 同行 y=51 完全不同区域）修正到接近 chromium
的窄 inline-block 同行布局。R368 commit 8db89df 在诚实指标上**确证为真实大胜**，
保留合理。

================================================================
结论 2：border-box ib_sizes DC-14 终局证伪（self-source 曾误导）
================================================================
border-box 让 ifc-011 self-source 1.23→1.04%（看似改善，span2 x=62→102 匹配
ZeroWeb-REF），但 z_vs_chr **2.22→2.50%（+0.28pp 真 chromium 退步）**；multicol-
dynamic-change z_vs_chr 1.42→1.50%（亦退步）。

机制：border-box 同时改 ib_sizes 的 (w, h)。span2 line-height:10px → content_h=10，
border-box h=50。IFC 用 h 算 inline-block 的 baseline（inline-block baseline=底部=h）
和 line-box 高度。content-box 时 h=10，border-box 时 h=50 → span2 的 glyph 基线/
垂直位置改变 → 与 chromium（正确 baseline 合成）发散。即 border-box 修正了 span2
的 **x 位置**（重叠→分离）但破坏了 span2 的 **glyph 垂直位置**（baseline 高度改变），
两者耦合，净退步。

【此即 R367「border-box net-negative」+ R368「border-box net -1 self-source」之后的
第三层证伪】前两层只看 self-source，本轮 DC-14 真值证伪更严格：border-box 在诚实
指标上对两案均退步，非阈值假象、非 input 特例、非守卫可救。**border-box ib_sizes
彻底关闭，勿再以任何变体重试。**

结论 3：multicol-dynamic-change 是 self-source 假通过（DC-14 实证）

multicol-dynamic-change z_vs_ref=0.97%（self-source PASS）但 z_vs_chr=1.42%（chromium

================================================================
ifc-011 残余 2.22% z_vs_chr = 多会话架构（inline-block baseline/line-box 合成）
================================================================
R368 后 ifc-011 真 chromium 一致率 2.22%。残余 = span2 x 重叠（border-box 解 x 但
破 glyph baseline，耦合不可单点）+ div h=50（无背景，零像素影响）+ glyph 度量。
border-box 实验证：x 位置与 glyph baseline 在当前 IFC 架构下耦合，须**正确的
inline-block baseline/line-box 合成**（CSS §10.8 line-height 半行距 + inline-block
baseline=最后一行 baseline）才能同时修正——即 Phase A IFC 统一 / inline→block 映射
重写的多会话硬里程碑。单会话杠杆确已穷尽（width-shrink 是最后一个，border-box 三层
证伪关闭）。
