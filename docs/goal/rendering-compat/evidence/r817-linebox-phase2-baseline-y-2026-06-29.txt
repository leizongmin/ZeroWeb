R817 — linebox 度量统一 Phase 2：paint Path A is_ahem glyph 用 frag.baseline_y 定位
日期：2026-06-29
承接：R816（Phase 1 加 baseline_y/ascent/descent 字段，行为不变）/ linebox-metric-unification-rfc.md Phase 2

================================================================================
根因（实证定位，非推断）
================================================================================

paint Path A（stored 片段）对 is_ahem 字形用启发式 v_offset：
  text.rs: `let v_offset = if frag.is_ahem { 0.0 } else { frag.font_size };`
glyph 位图顶 = content_y + frag.y + v_offset，其中 frag.y = line.y + f.y，
baseline 对齐片段 f.y = baseline_y - run.height（run.height = line-height × font-size）。

LAYOUT_DUMP 实测 vertical-align-117a（font:2.5em/3.25 Ahem = 40px/130px）存储片段：
  line[0] y=0 height=130 baseline_y=77 ascent=77 descent=53
  "TTTT"        x=0   y=-53  h=130 fs=40  (baseline)
  "MustBeAbove" x=160 y=0    h=130 fs=40  (text-bottom span)
  "TTTT"        x=600 y=-53  h=130 fs=40

→ is_ahem v_offset=0 把 glyph 放在 frag.y。line-height>1 时 frag.y = baseline_y - run.height
  = 77 - 130 = -53（行盒顶部之上 53px，被裁剪/错位）。glyph 应在基线 = baseline_y - font_size
  = 77 - 40 = 37（Ahem 方块底边齐基线，ascent=font_size）。
→ line-height:1 时 frag.y = baseline_y - font_size，v_offset=0 恰好把 glyph 放在基线（旧启发式
  仅在此情况正确，font-051 line-height:1 因此 PASS）。这是 RFC「墙③ v_offset/baseline 语义分歧」。

================================================================================
修复（R817 Phase 2）
================================================================================

paint Path A stored 渲染循环（text.rs）改为按片段**实际字体**定位：
  let v_offset = if frag.is_ahem_font {
      frag.baseline_y_abs - frag.font_size - frag.y   // 真正 Ahem：glyph 顶 = 基线 - font_size
  } else if frag.is_ahem {
      0.0                                              // 容器 Ahem 但片段非 Ahem：保留旧行为
  } else {
      frag.font_size                                   // 非 Ahem 容器：保留旧行为
  };
  // 推导：glyph_y = content_y + frag.y + v_offset
  //      = content_y + (line.y+f.y) + (line.y+baseline_y - font_size - (line.y+f.y))
  //      = content_y + line.y + baseline_y - font_size  （基线处，f.y 抵消）

配套存储改动（Phase 1 字段已存，Phase 2 消费 + 新增 is_ahem_font）：
  - types/mod.rs InlineLayoutFragment 加 is_ahem_font: bool（片段实际字体，区别于容器级 is_ahem）
  - inline_finalization.rs 两处构造点从 frag.is_ahem（IFC run.is_ahem_font 实际字体）填充
  - text.rs PaintFragment 加 baseline_y_abs（= line.y + f.baseline_y，container-rel）+ is_ahem_font

关键：is_ahem_font 区分「真正 Ahem 方块字形」与「Ahem 容器内的非 Ahem 片段」。font-051 的
span {font: serif} 是无效 shorthand（serif 单独非法）→ 整条 font 声明被拒 → span 继承 div 的
100px/1 Ahem，故 is_ahem_font=true、line-height:1 → v_offset 退化为 0（A3 不变量，零变化）。
