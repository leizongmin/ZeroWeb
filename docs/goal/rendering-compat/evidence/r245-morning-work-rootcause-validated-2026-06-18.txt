1. 根因实证确认（回答 R243 的 LAYOUT-vs-PAINT 判别）
────────────────────────────────────────────────────────────────────
R243 留的二分：morning-work 压缩是 (a-LAYOUT) 布局 pre content_height 欠算 还是 (a-PAINT) 盒高对但字只在顶。
读并行 agent WIP（inline/mod.rs break_into_lines）确认 = **a-LAYOUT 主因**，且比 R243 推测更精确：

  **CSS Text §3.1 换行符保留缺失**：`break_into_lines` 收集文本时**无条件**调
  `collapse_whitespace(&text_data.content)`——该函数把 `\n` 折叠成普通空格。但 `white-space: pre /
  pre-wrap / break-spaces`（CSS Text §3.1）应**原样保留空白含 `\n`**，`\n` 作为强制断行机会。
  morning-work 的 `.article pre{white-space:pre-wrap}` + 代码块源码显式 `\n`（C 代码 ~12 行、bash 多行）
  → 被 collapse_whitespace 折成单行 → **12 个多行 `<pre>` 全塌缩为单行** → 正文高度 ≈ 1/预期 →
  内容物理压缩进 y=150-300，y=300-525 空白。正是 R228b 区域分析观测的现象。

  次要（同 a-LAYOUT）：即便 `\n` 作为「空字符串标记」保留进 split_into_words，旧 `break_into_lines`
  对空词直接 `continue` **静默丢弃**强制换行标记 → 仍塌单行。

  互补（a-PAINT）：painter/text.rs 非存储路径改用 `all_fragments_with_line_y()` 把每行 `line.y`（容器内
  垂直偏移）加到片段 y——确保多行 pre 在 paint 阶段各行正确定位（修 a-LAYOUT 后的 a-PAINT 配套）。

⇒ **R243 判别结论 = a-LAYOUT 主因**（换行符保留缺失致行数欠算），非 R84 存储 guard 本身、非 font-size。
R242「pre 高度欠算」方向正确；R243 把范围缩到 LAYOUT；本轮实证到**精确 bug = break_into_lines 无条件
collapse_whitespace 破坏 pre-wrap 换行符**。

────────────────────────────────────────────────────────────────────
2. 这不是 Phase A 存储 guard 问题（澄清）
────────────────────────────────────────────────────────────────────
R242/R243 曾疑 R84 多行守卫（engine.rs:1909 不存多行 inline_layout）相关。实证：守卫影响 paint 用存储 vs
非存储路径，但**根因在 break_into_lines 的换行符处理**——即便走存储路径，collapse_whitespace 也会先把多行
折成单行。故修复 break_into_lines 的 pre-wrap 保留是**前置必要条件**，独立于 Phase A 存储统一（R82/R101/R125）。
Phase A 存储 guard 的放宽（R101/R125/R210 实证 net-negative）与本次换行符修复**正交**——换行符修好后，
多行 pre 的行盒度量才正确，后续 Phase A 存储讨论才有意义。
