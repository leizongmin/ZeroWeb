## 2. 插入点（multicol.rs layout_multicol 末尾）

`layout_multicol(container, info)`（multicol.rs:244）流程：收集 child_info → 分配 `assignments:
Vec<Vec<ColumnFragment>>`（balanced/sequential/with-breaking）→ `position_multicol_children(container,
&assignments, info)` 设位。**在 position_multicol_children 之后**，各子元素在列内位置已定，可计算导出
baseline。建议新增 helper（如 `compute_multicol_exported_baseline(container, &assignments) -> Option<f32>`）
在 layout_multicol 末尾调用，写 `container.taffy_baseline`。adjust_multicol_layout（multicol.rs:57）对每个
multicol 容器调 layout_multicol，故每个容器各自的 baseline 在其 layout_multicol 内就地写入。

## 3. 坐标系（taffy_baseline = 盒内偏移，非绝对）

engine.rs:988-992 消费点：
```
if let Some(taffy_bl) = child.taffy_baseline {
    if taffy_bl > 0.0 && taffy_bl < child.content_height {   // ← 守卫：盒内偏移语义
        return Some((node_id, taffy_bl));
    }
}
```
→ **`taffy_baseline` 是相对该盒自身内容盒原点的偏移**（0 = 内容顶，content_height = 内容底），非绝对
坐标。故 multicol 容器写入的 exported baseline 必须是「首列首行文本 baseline 相对 multicol 容器内容盒
顶的偏移」。消费侧 §8.5 容器基线合成时把 child（=multicol item）的 taffy_baseline 当盒内偏移用。

## 4. 算法（first baseline，8 用例主体）

CSS Multicol §2.9 / CSS Align §baseline-export：multicol 容器导出 first baseline = **首列第一行文本的
baseline**；last baseline = 末列最后一行（last-baseline 对齐用，次要）。

`assignments[0]`（首列片段）首个片段对应的子元素（设位后其 y 已定）。该子元素的 `taffy_baseline`
（由 extract 在 228 行写入，= 子元素首行 baseline 相对子盒内容盒原点）已可用。故：

```
first_baseline = （首列首子元素 border-box 顶 相对 multicol 容器内容盒顶 的偏移）
               + （首子元素 border-top + padding-top）          // 到子元素内容盒顶
               + 首子元素.taffy_baseline?                         // 子元素首行 baseline
```
即「multicol 容器内容盒顶 → 首子元素内容盒顶 → 首行 baseline」累加。具体 LayoutBox.y 约定（相对父
border-box vs content-box）由实现者按现有约定匹配（extract_layout 内同约定）。

**守卫**：仅当算得值 `0 < v < container.content_height` 才写（对齐消费侧守卫）；超界或首子无
taffy_baseline（如首子是嵌套 multicol / 空 / 无文本）→ 不覆写，保留 taffy 通用值（退化安全）。

**last baseline（defer）**：需末列末子元素的「末行 baseline」，而 taffy_baseline 只给首行——需 IFC 额外
暴露 last-line baseline 或从子元素 height 反推，非单点。8 用例主体为 first baseline（baseline-alignment
默认 first），last baseline 留后续轮。

## 6. 风险与边界

- **波动面**：taffy_baseline 被 flex/grid §8.5（engine.rs:988）+ 可能其他点消费。multicol 覆写仅影响
  **multicol 容器自身**的 taffy_baseline（非全局），故仅影响「multicol 作 flex/grid item 且参与
  baseline 对齐」的用例（正是 8 baseline-export 用例）。非 multicol 容器不受影响。
- **taffy cached_baselines 仍写错值**：extract(228) 给 multicol 容器写的 taffy 通用 baseline 被本修复
  覆写（264 之后），但 taffy 内部 cached_baselines 仍是错值——只要所有消费点走 LayoutBox.taffy_baseline
  （而非直接读 taffy cached_baselines）即无碍。须 grep 确认无消费点绕过 LayoutBox.taffy_baseline 直读
  taffy cached_baselines（extract_baselines_recursive 是唯一写者，消费走 LayoutBox 字段，应安全）。
- **非撞车**：multicol.rs 干净（并行 agent WIP 在 font/paint/IFC/pipeline/app_platform/reftest，不含
  multicol.rs）；engine.rs 消费点（988）与并行 agent painter/text.rs WIP 不同区。
