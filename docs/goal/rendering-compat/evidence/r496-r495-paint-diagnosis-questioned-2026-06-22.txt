## 1. 代码核查：paint 读 box_node.height（非 taffy measured）

| 证据 | 位置 | 内容 |
|------|------|------|
| ① 默认 bg-clip = border-box | `style-system/property/default_impl.rs:279` | `background_clip: BackgroundClipComputedValue::BorderBox`（spec 正确） |
| ② border-box bg 用 `box_node.height` | `painter/mod.rs:1165` | `BackgroundClipComputedValue::BorderBox => (abs_x, abs_y, box_node.width, box_node.height)` |
| ③ 主背景 rect 用 `box_node.height` | `painter/mod.rs:753` | `let rect = Rect::new(abs_x, abs_y, box_node.width, box_node.height);` |
| ④ deferred fixed/abspos 子元素走同一 `paint_node` | `painter/mod.rs:620-625` | `self.paint_node(child, …)`（无单独 fixed paint 路径） |
| ⑤ paint 读 `layout_result.root` | `pipeline.rs:237/320/379` | `painter.paint(&layout_result.root, &styles, Some(&doc))` |

**推理链**：override 设 `child.height=600`（LayoutBox.height，R495 LAYOUT_DUMP 证）→ paint 读 `layout_result.root`（= LAYOUT_DUMP 的 `result.layout.root`，render_html 返回同一 painted layout）→ bg-clip=border-box → 用 `box_node.height`（600）→ **paint 应渲染 div 白背景高 600，非 19.2**。

**R495「paint 读 taffy measured (19.2)」与上述链不一致**：painter 无读取 taffy 直接 measured 的路径（grep `content_height` 仅用于 scroll/clip 容器 line 333/589/613/1138，非 bg rect）；bg rect 一律 `box_node.height`。

## 2. 可能解释（R495 像素 19.2 的真因候选）

1. **pixel test 跑在 override 未编译进的 build**（最可能）：code agent 可能 revert 了 engine.rs 后才跑像素（或跑了旧 binary）→ 像素反映 pre-override 状态（19.2），但 LAYOUT_DUMP 来自 override 生效的 build → 二者 build 不一致致「诊断」错觉。
2. ~~override 作用在与 paint 不同的 tree 实例~~ **❌ RULED OUT（本轮 call-site 核查 2026-06-22）**：`adjust_fixed_to_viewport`（`engine.rs:230`）+ `adjust_absolute_pct_to_viewport`（`engine.rs:286`）均在 `compute_with_img_sizes` 内对 `root_box` **原地修改**（`&mut root_box`）；`pipeline.rs:226 layout_result = compute_with_img_sizes(...)` 返回该 `root_box` → `pipeline.rs:237 painter.paint(&layout_result.root)`。**post-process（含 R495 override 若置于 `adjust_absolute_pct_to_viewport` 后，同 `root_box`）修改的就是 paint 读的同一 `root_box → layout_result` 树** → override 必达 paint，「不同 tree 实例」假设排除。剩 (a) pixel test 用未编译 override 的旧 binary，或 (c) 未发现的 paint 路径（主 bg rect 753 + bg-clip 1165 + deferred fixed 620-625 均已查用 `box_node.height`，c 不太可能）。
3. 存在未发现的 paint 路径读 content_height/taffy——本轮核查主 bg rect (753)、bg-clip (1165)、deferred fixed path (620-625) 均用 `box_node.height`，未发现；但 painter 大，不排除遗漏。

## 3. 建议（给 code agent）

**勿据 R495 诊断直接追「paint-path 修尺寸源」**——R493b post-layout height override **可能本就有效**，R495 的回退或基于误诊。re-verify 步骤：
1. 重新 apply `stretch_fixed_abspos_viewport_height`（engine.rs post-extract）。
2. **确认 override 编译进 pixel-test binary**（`cargo build` 后跑，非旧 binary）。
3. 在 **paint 时** dump `box_node.height`（非仅 LAYOUT_DUMP 的 extract 层）——加临时 eprintln 在 painter 1165 行，确认 paint 读到 600。
4. 若 paint 读到 600 且像素仍 19.2 → R495 诊断成立（有未发现路径），追 paint-path。若 paint 读到 600 且像素变全白 → **R495 误诊，post-layout override 有效，R491 可净正**（001-004 翻回）。
