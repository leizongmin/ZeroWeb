全量 make test：1 synthetic 单测失败（锁定 Phase A blocker）
================================================================
1148 passed; 1 failed: tests::pipeline::test_pipeline_consecutive_different_renders

失败案：html2 = `<span class="b">Second</span>`，`.b { background:blue; width:300; height:150 }`
  - assert fills2 > 0（第二次渲染应产生填充图元）→ fills2 == 0（span 蓝背景消失）

根因（精确锁定）—— **inline-ownership split**：
  1. span display:inline + 显式 height:150（ZW 错误地应用于 inline，但确实如此）→
     抑制门控 height(150) > 1.5×16 触发 → box-level bg 被抑制。
  2. span 文本 "Second"（单行）由**父级（body）IFC** 绘制（inline-ownership split：
     span 有 box 存 bg/border，但文本被父 IFC 收集）。
  3. render_fragment 宏的 box_node 是 **IFC owner（body）**，非 inline（span）本身 →
     宏门控 box_node.height（body 高）≠ inline.height(150) → body 若矮则门控 FALSE →
     per-fragment bg 不绘。
  4. 结果：抑制（span box 上）触发，per-fragment（body paint_text 中）不触发 → span 蓝背景消失。

=> **抑制（inline box 上）与 per-fragment（IFC owner box 上）在文本处于父 IFC 时分歧**。
   这是 inline-ownership split 的直接表现：box_node 在宏中是 IFC owner 非 inline，
   两者用不同 box 的 geometry，无法一致。

text-indent-wrap 为何 work：span 自身 paint_text 绘其文本（span 自有 IFC，跨多行），
   box_node=span，抑制与 per-fragment 同 box → 一致。
