# welcome.html 产品 smoke 28% diff 区域分析（R226）

**日期**: 2026-06-17
**目的**: advance-width 证伪（R225）后，重新定位 welcome.html vs chromium 28.34% diff 的真因。
**方法**: ZeroWeb CPU PNG（product-smoke 800×600）vs chromium Oracle PNG，按 y 带/象限/x 带统计 diff 密度 + 关键像素采样 + 扫描线。

## 核心结论

**28% diff 主因 = 页面顶部 ~36px 垂直偏移**（ZeroWeb 内容比 chromium 低 36px），级联致整页内容 y 错位 → 每个像素错配。

非 font/advance-width（R225 已证伪）、非 body 背景缺失（角点 ZW=CH=(244,246,248) body bg 正确应用）、非纯光栅化噪声。

## 数据

### y 带密度（top→bottom，8 带）
```
y[  0- 75]:  9.8%   ← hero（低）
y[ 75-150]:  9.4%
y[150-225]: 12.9%
y[225-300]: 28.1%   ← cards grid 开始升高
y[300-375]: 41.9%   ← shortcuts grid
y[375-450]: 27.3%
y[450-525]: 41.4%   ← quick-links grid
y[525-600]: 43.4%   ← footer
```
底部（grid/flex 区）远高于顶部（hero）。

### 关键：垂直内容起点
```
first non-bg pixel at x=300:  ZW y=72  vs  CH y=36   → ZW 低 36px
content y-range at x=300:     ZW [72,583]  CH [36,534]  → ZW 长 ~49px
```
**整页内容下移 36px**。底部 grid/flex 区因级联偏移最大（cards/shortcuts/quick-links/footer 全部 y 错位）。

### 扫描线 y=350（应为 cards/shortcuts 行）
ZW：x=80-790 全是内容（白色 card + CT 文本/边框）。
CH：x=0-790 全是背景灰（244,246,248），**无内容**。
→ ZW 内容在 y=350，chromium 该处为空 → 内容 y 错位（ZW 内容占 y=350，CH 内容在别处）。

## 根因推断（待证实）

ZW 内容起点 y=72，CH y=36，差 36px。结构：body → .page(margin:0 auto, padding:20px 40px 24px) → .hero(padding:16px 0 20px) → .hero-accent(height:4px)。

36px ≈ .page padding-top(20) + .hero padding-top(16)。疑似 ZeroWeb 对 body/page margin 折叠或 padding 累加与 chromium 不一致（如 body UA margin-top 8px 双重应用、或 .page margin:0 auto 的 auto 在窄视口被误算、或 margin 折叠缺失）。

**下一步**：dump ZeroWeb body/.page/.hero 盒几何（margin/padding/border/y），对比 chromium，定位 36px 偏移的确切来源（margin 折叠？padding？UA body margin？）。修后预期 diff 大幅下降（整页对齐）。

## 策略意义

welcome 28% diff **非字体/度量噪声**（R225 已排除 advance-width；AA 基准排除光栅化），是**布局垂直定位 bug**（顶部 36px 偏移级联）。这是可定位、可修复的真实 bug，区别于 reftest 平台期的结构性聚类。DC-13 产品 smoke 真杠杆 = 修此 margin/padding 偏移。
