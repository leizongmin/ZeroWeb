4. ★ 新发现：负值拒绝（numbers-units-006）非 clean slice 的精确机制
============================================================

假设：height: -1px 应被拒绝（CSS §10.5 负值非法）→ 保留 height: 1in = 96px 黑方块。
实验：apply.rs 给 width/height/min/max/padding 加 is_negative_px 拒绝（镜像既有 border-*-width 模式）。
结果：numbers-units-006 仍 1.92% FAIL（values 套件 17/26 不变，零效果）。已 REVERT。

★ 精确机制（既往未记录）：
  cascade.rs:140 cascade() 用 max_by_key(order) 每属性选「单一 winner」。
  `height: 1in; height: -1px`：-1px 后声明 order 更高 → winner = "-1px"，1in 被整体丢弃。
  apply 阶段才拒绝 -1px → 回退到 **initial（Auto）**，**非** 恢复 1in（已丢弃）。
  而应用 -1px（taffy 钳到 0）与回退 Auto（无内容→0）对无内容 div **都给 0 高** → 同样无黑方块 →
  diff 不变（1.92%）。

→ 正确修复须 **cascade-level 有效性校验**（选 winner 时跳过非法 -1px，让 1in 赢）。cascade 仅存
  原始 string，须加 per-property 合法性校验（重复解析 + 全声明行为变更，回归风险中高）。非单会话
  clean slice。border-*-width 的 apply-time 拒绝有同源 latent bug（仅当负值是唯一声明时才生效）。

教训：apply-time 值校验对「先合法后非法」多声明用例无效；CSS 合法性须在 cascade 选 winner 时判定。
       勿再以 apply-time 负值拒绝为单会话 lever 重试。
