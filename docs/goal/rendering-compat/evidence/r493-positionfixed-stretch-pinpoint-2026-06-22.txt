## 1. LAYOUT_DUMP 实测（positioning/abspos-containing-block-001.xht，test-guard 包裹）

测试结构：`body{background:red;margin:100px 100px}` + `div{background:white;position:fixed;top:0;right:0;bottom:0;left:0}`（fixed 白 div 应覆盖整个视口遮住 body 红）。

ZeroWeb layout（test 渲染）：

```
html   abs_y=0.0   h=100.0  x=0.0   w=800.0   (html 高 100，非视口 600)
 body  abs_y=100.0 h=0.0    x=100.0 w=600.0   (body margin 100，高 0——div 出流)
  div  abs_y=0.0   h=19.2   x=0.0   w=800.0   (fixed div：w=800 ✓，h=19.2 ✗)
```

**非对称 stretch（关键）**：
- **水平 stretch 工作**：div w=800（= 视口宽，§10.3.18 left+right 全定义 + width:auto → width=CB−left−right）。
- **垂直 stretch 失败**：div h=19.2（= 一行文本固有高，§10.6.4 top+bottom 全定义 + height:auto → height 应=CB−top−bottom=600，实落固有）。

像素复核（R492）：oracle 99.8% 白（fixed div 覆盖红画布），ZW test 97.4% 红 + 白 div 仅 11194px ≈ 800×19.2 中非文本部分 → div 是 800×19.2 顶部白条，红画布（R491 传播 body 红）从下方透出。

## 2. 6 案 position 类型（修复 scope 须覆盖混合类型）

| case | position | 结构 |
|------|----------|------|
| 001 | **fixed** | body 红 + fixed 白 div 全 inset 覆盖 |
| 002 | **absolute** | 同结构（absolute 无 positioned 祖先→CB 应=视口） |
| 003 | **fixed** | 同 001 |
| 004 | **absolute** | 同 002 |
| 005 | relative + **absolute** | absolute 在 relative 祖先内，`width/height:100%` + 全 inset 0 |
| 006 | relative + **absolute** | 同 005 |

→ 非「仅 fixed」：fixed(001/003) + absolute(002/004) + absolute-in-relative(005/006) 三类，但共享同一垂直 sizing 失败机制。

## 3. 代码核查：ZeroWeb 无活跃的 Length-inset 垂直 stretch

`crates/layout-engine/src/engine.rs` abspos/fixed 后处理三函数：

| 函数 | 行 | 状态 | 处理 |
|------|----|------|------|
| `adjust_fixed_to_viewport` | 1557 | **活跃** | 仅修正 **position**（x/y 视口相对，R324）；**不碰 size** |
| `adjust_absolute_to_initial_containing_block` | 1591 | **`#[allow(dead_code)]` 禁用**（注释「导致多个回归，暂不启用」） | **本会 stretch width+height**（auto 时 `+= viewport - content`），但禁用 |
| `adjust_absolute_pct_to_viewport` | 1649 | **活跃** | 仅重解析 **Percentage** width/height/left/top（Length 不动） |

**结论**：Length-inset（top/bottom=0）的垂直 stretch **无任何活跃函数处理**。水平 stretch 由 taffy 0.7 自身完成（CB width 恒 definite → §10.3.18 生效）；垂直 stretch 失败因 taffy 把 fixed→absolute 的 CB height 解析为**非定**（in-flow 祖先 body/html，高 auto/100，非视口 600），§10.6.4 要求 CB height definite 才 stretch → 回落固有 19.2。

被禁用的 `adjust_absolute_to_initial_containing_block`（1614-1619）正是会补 height stretch 的位置：
```rust
if matches!(style.width, LengthValue::Auto) { child.width += (viewport_width - content_width).max(0.0); }
if matches!(style.height, LengthValue::Auto) { child.height += (viewport_height - content_height).max(0.0); }
```
但全量启用回归（static-inside-inline-block、background-329——主因是同时改 width/x-y 偏移）。

## 4. 修复建议（代码 agent）

**根因**：abspos/fixed 元素的**垂直 sizing**（§10.6.4 inset stretch + height:% 百分比）在 CB height 非定时回落固有；ZeroWeb 无活跃 post-process 补垂直 stretch（水平靠 taffy）。

**Scoped 修复方向**（降旧回归风险）：
- 仅补**垂直** stretch（水平已由 taffy 工作，勿动 width/x-y——避开旧 `adjust_absolute_to_initial_containing_block` 回归根源）。
- 触发条件：`is_fixed`（或 abspos 无 positioned 祖先）+ `top`/`bottom` 均为 Length（非 auto）+ `height==Auto` → `height = viewport_height - top - bottom`（§10.6.4，CB=视口 ICB）。
- 镜像 `adjust_absolute_pct_to_viewport` 的 Percentage 路径模式（1649），加 Length-inset 垂直分支。
- 005/006（absolute in relative 祖先 + height:100%）：CB=relative 祖先，若其 height 非定则 height:% 回落——需 relative 祖先 height 解析或独立处理（更难，可能 defer）。

**预期收益**：001/003（fixed）+ 002/004（absolute 无 positioned 祖先）= 4 案翻回 PASS（CB=视口定高 600）；005/006 视 relative 祖先 height 而定。修后 R491 净 +5~7（R492 标称的 +7 上限）。

**验证**：`LAYOUT_DUMP=1 ./target/test-guard -- cargo run --bin zero-wpt-runner -- reftest-upstream abspos-containing-block-001`（filter 单案）→ div h 应 600 而非 19.2；全量 CSS2 re-dump + cross-validate 确认 6 positioning 案翻回 + 无新回归。

## 5. 性质裁决

- **ZeroWeb-side**（非 taffy-blocked）：水平 stretch 已工作证 taffy 能做 inset stretch；垂直失败是 CB height 解析 + 缺 post-process，可在 ZeroWeb 后处理补（fixed CB 无歧义=视口，低风险）。
- 属 **R98/R124 abspos-CB/inset 谱系**（master.md plateau 已标 taffy-bound，但本轮细化=垂直子问题可 scoped 修，非全谱系阻塞）。
- R491（canvas 传播）**spec 正确**，此 6 回归是 R491 暴露的 latent 缺口，修复后 R491 净正。
