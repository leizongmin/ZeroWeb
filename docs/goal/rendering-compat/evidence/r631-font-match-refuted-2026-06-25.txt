================================================================================
调查：ZW 实际用什么字体
================================================================================

product-smoke（zero-wpt-runner，reftest.rs:create_font_loader）：
  主字体（default_id=0）= DejaVuSans.ttf（第一个加载），fallback NotoSansCJK + Ahem。
  system-ui/sans-serif 经 build_font_resolver → resolve_generic_family([DejaVu Sans,...])
  → 找到已加载 DejaVu → 解析到 DejaVu。

browser（apps/browser，app_platform.rs:load_system_fonts）：
  主字体优先 NotoSans-Regular → Cantarell → LiberationSans → DejaVuSans（Linux）。

fontconfig（chromium 经此解析 system-ui）：
  fc-match sans-serif / fc-match system-ui → 均解析到 NotoSansCJK-Regular.ttc（"Noto Sans CJK SC"）
  ——因为 NotoSansCJK 覆盖拉丁+CJK，fontconfig 选它作最强匹配。

→ ZW product-smoke 拉丁字符用 DejaVu，chromium 拉丁字符用 NotoSansCJK（的拉丁字形）。
  这是 R374「字体不匹配」的具体机制（若归因成立）。

================================================================================
A/B 实验（env ZERO_FONT_PRIMARY_CJK=1，已回退）
================================================================================

改 create_font_loader：primary_cjk=1 时优先加载 NotoSansCJK 为 default_id(0)，
且跳过 DejaVu/Liberation 加载，强制 build_font_resolver 的 sans-serif/system-ui
resolve_generic_family 找不到 DejaVu → 回退 default_id=NotoSansCJK，真正对齐 fontconfig。

结果（product-smoke，post-R630 基线 morning 17.16% / welcome 17.27%）：
  morning:  DejaVu 17.16% → NotoSansCJK 17.15%  (Δ -0.01pp)
  welcome:  DejaVu 17.27% → NotoSansCJK 17.20%  (Δ -0.07pp)

→ **几乎零变化**。即使 ZW 拉丁字符用 chromium 同款 NotoSansCJK，diff 仍 17%。

================================================================================
裁决：R374「字体不匹配」归因证伪
================================================================================

字体选择（DejaVu vs NotoSansCJK）**不是** morning/welcome 17% diff 的主因。
结合：
  - R229c：font-weight 加粗证伪（ZW 字体 ≠ chromium，加粗放大差异）
  - R388/AA-baseline：fontdue 与 chromium 同 glyph 光栅化几乎一致（W 0.1% / i 3.0%）
  - R631（本轮）：字体选择对齐零变化

**「字体问题」是误诊**——三角度（加粗 / 光栅化 / 选择）全证伪字体为 diff 主因。
morning/welcome 17% 真因 = **布局/行盒度量**（line-height / baseline / 行间距 / 多行结构），
与 DC-14 注释（rendering-compat.md line 311）「大头是布局/度量，非字体光栅化」一致。

R630（paint 多行 y 堆叠修复）后的残余（wrap 用例 y 跨度 50px vs 期望 72px）正是行盒度量
不足（行间距/line-height 计算与 chromium 分歧），非字体。

（line-height/baseline，R630 残余 wrap 50px→72px 缺口）。
