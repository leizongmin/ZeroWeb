1. Bug：dashed dash/gap 固定 6:4，与边框厚度无关（chromium 按 2:1 缩放）
================================================================================

R794 调查发现 root-element 簇（border:5px dashed）stretch 后发散增大，根因疑 dashed 渲染。
本轮实测 chromium 的 dashed 模式：

  render-foundation/src/cpu/stroke.rs:82-83（render_stroke → render_dashed_line 调用）：
    LineStyle::Dashed => render_dashed_line(..., 6.0 * scale, 4.0 * scale);
                                          ↑ dash_len    ↑ gap_len
  scale = 渲染 DPR（half_w = stroke.width*scale*0.5），非边框厚度。
  → dash/gap 固定 6px/4px，与 border-width 无关。

probe 实测（/tmp/dash-probe.html，div border:8px dashed，chromium headless + ZW CPU 各渲染），
PIL 沿 top-border 扫描 black-run/white-run（dash/gap 像素长）：

  CHROMIUM（8px 边框）：dash=16, gap=8  → 2:1 = 2×width / 1×width
  ZEROWEB（修复前）：   dash=6,  gap=4  → 3:2 固定（与 8px 厚度无关，错）

  chromium 对任意 width：dash = 2×width、gap = 1×width（CSS 规定 dash 尺寸 implementation-
  defined，chromium/Skia 实际用此比例）。ZW 固定 6:4 致所有 dashed 边框与 chromium 发散
 （root-element 簇 + c5517 + outline-dashed + border-conflict-dashed 等）。

================================================================================
2. Fix：dash/gap 改为相对 stroke.width（2×width / 1×width）
================================================================================

stroke.rs Dashed 分支：
    render_dashed_line(..., stroke.color, stroke.cap,
        2.0 * stroke.width * scale,   // dash = 2× border 厚度（match chromium 实测）
        stroke.width * scale,         // gap = 1× border 厚度
    );

  stroke.width*scale = 像素边框厚度（=2×half_w）。chromium 实测 8px→dash16/gap8 验证此式。
  ×scale 保持 DPR 一致（与 half_w 同乘 scale）。

4. 诚实裁决：spec-correct + 零回归 + probe 字节证；oracle yield 窄（类 R793）
================================================================================

本修复把 ZW dashed 模式从固定 6:4 改为 chromium 实测的 2×width/1×width——**probe 字节级
证明 ZW 现与 chromium 完全一致**（16/8 = 16/8）。CSS 规定 dash 尺寸 implementation-defined，
对齐 chromium（DC-14 oracle 目标）是正确方向。

★ **严格非负**：修复使 ZW dashed 像素 = chromium dashed 像素，任何含 dashed 的 oracle 测试
发散只减不增（不存在「匹配 chromium 反增发散」的场景，区别 R794 几何 fix 暴露更多错 dash）。

★ **oracle PASS-flip yield 窄**（类 R793）：多数含 dashed 的测试（c5517 多样式 groove/ridge
主导 / border-conflict 表格 collapse 复杂 / root-element 需 two-pass）有**其他**主导致散，
dashed 修对不必然翻 PASS；但发散确定减少（dashed 部分现匹配）。root-element 簇仍需
two-pass layout（R794 几何 + R795 dash 都修对后，重应用 R794 stretch 即可能解锁，待 two-pass）。

裁决：ship（spec-correct + 零回归 + probe 字节证 + 严格非负）。类 R776/R792/R793 spec-correct
pattern；probe 实测是强证据（直接对比 chromium，非推断）。
