症状与定位（REFTEST_BBOX + PIL 像素分析）
------------------------------------------
flexbox_flex-0-0-N-shrink.html：test=flex（div width:12em=192px，4 span flex:0 0 4em=64px
each，shrink:0 不收缩，总 256px>192px → 单行溢出）；ref=block（div width:12em=192px，
white-space:nowrap，4 span display:inline-block width:4em=64px，总 256px>192px）。

REFTEST_BBOX：9 案均 y=[30,256]（垂直跨度异常，test 内容止于 y=145=div 底，ref 延伸到 y=256）。
PIL 逐行扫描：
  TEST line1 y=80：span1[9,73]+span2[73,137]+span3[137,201]+span4[201,265]（4 盒单行，正确溢出）
  REF  line1 y=80：span1[9,73]+span2[73,137]+span3[137,201]+border[201,202]（仅 3 盒！）
  REF  line2 y=200：span4(grey)[9,73]（第 4 盒被换到第二行）
→ REF 把第 4 个 inline-block 换到了第二行，尽管容器设了 white-space:nowrap。

根因
----
adjust_inline_block_positions（engine.rs:930）构造 IFC 定位 block 容器的原子行内级
子元素（inline-block/img），但**未把容器 white-space 传给 IFC**（no_wrap 恒 false）。
IFC 的 inline-block 换行判定（inline/mod.rs:1328）虽有 `!self.no_wrap` 守卫，但 no_wrap
从未被设为 true → nowrap 容器内 inline-block 超宽仍被换行。

对比：inline_finalization.rs:359（文本主布局路径）和 painter/text.rs:915（paint 侧）
都正确从 style.white_space 派生 no_wrap 并 with_no_wrap；唯独 engine.rs 的 inline-block
定位路径漏了。

CSS：white-space:nowrap/pre 禁止换行（CSS Text §3.1），原子行内级盒（inline-block）参与
IFC 且 nowrap 下应溢出而非换行。

修复（engine.rs adjust_inline_block_positions，~6 行）
------------------------------------------------------
  + use WhiteSpaceValue
  + let no_wrap = styles.get(&container_node_id).is_some_and(|s| {
        matches!(s.white_space, WhiteSpaceValue::Pre | WhiteSpaceValue::Nowrap)
    });
  + IFC builder 链 .with_no_wrap(no_wrap)

精准：仅设 no_wrap（nowrap→false preserve_whitespace 默认值即正确）；不动 preserve_whitespace
（避免影响 inline-block 间空白处理，非本 bug scope）。

意义
----
R537 收尾 flexbox_flex cluster（R536 +52 + R537 +9 = 59 案全过）。修复 white-space:nowrap
对 inline-block 换行的语义缺口——三条 IFC 构造路径（文本主布局/paint/inline-block 定位）
此前只有两条传 no_wrap，第三条漏了致 nowrap 下 inline-block 错误换行。
教训：同一属性（white-space）在多个 IFC 构造路径须一致传播；新增 IFC 构造点时核对
no_wrap/preserve_whitespace/word_break 三件套是否从容器 style 读取。
