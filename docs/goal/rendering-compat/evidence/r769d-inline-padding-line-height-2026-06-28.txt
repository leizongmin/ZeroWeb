R769d — inline 垂直 padding/border 不影响 line box 高度（CSS §10.8.1/§8.4）
日期: 2026-06-28
状态: LANDED（待 clippy + make test 全绿后提交推送）

================================================================================
背景 / 承接
================================================================================
承 R769c CONTINUE，R740 战略②扫 CSS2/normal-flow oracle top 发散。
blocks-019（11.83%）assert："Top padding on inline elements has no effect on layout"。

================================================================================
直接对比定位（product-smoke + PIL）
================================================================================
minimal 复现 `<div bg:red><span padding-top:100px bg:green>X</span></div>`：
  ZeroWeb（修前）：red y8..127（div 高 120px），green X 在 y84..103（被下推）
  → inline padding-top:100px 被加进 line box 高度，div 120px 而非 20px
  chromium：inline padding-top 无布局效果，div 20px，X 在顶部

blocks-019 同因：`span.test{padding-top:10em}` 撑高 line box，绿 control 被下推暴露 red。

================================================================================
根因（inline/mod.rs TextRun::box_height line 113）
================================================================================
    pub fn box_height(&self) -> f32 {
        self.line_height + self.padding_top + self.padding_bottom + self.border_top + self.border_bottom
    }

注释（错误）声称「CSS 2.1 §10.8.1: padding 和 border 会额外增加行盒中该元素占据的垂直空间」。
但 CSS 2.1 §10.8.1 + §8.4 实际规定：inline 非替换元素的垂直 padding/border **只绘制**
（向 line box 上下方延伸），**不影响 line box 高度**。WPT blocks-019 + chromium 同此。

box_height 用于 line 1078-1299 `current_line.height.max(run.box_height())` —— 即 line box
高度计算，inline padding/border 在此错误撑高 line box。

================================================================================
修复（inline/mod.rs，1 行实质改动）
================================================================================
    pub fn box_height(&self) -> f32 {
        self.line_height
    }

（padding/border 仍在 paint 路径绘制，只是不进 line box 高度。）
