# R393 — line-box 半行距垂直定位非 clean lever（strut_ascent 已近 chromium）

**日期**：2026-06-22
**触发**：R392 text-emphasis 失败归因 line-box 垂直定位，CONTINUE 指向查 `strut_ascent`
（`apply_vertical_alignment` 的基线计算）是否为 narrow 可修缺口。

## 调查

`crates/layout-engine/src/inline/mod.rs:1700` `apply_vertical_alignment`：
```rust
let strut_ascent = if line.runs.iter().any(|r| r.font_size > 0.0) {
    line_height * 0.8   // 文本行：近似 leading 对半分布的基线位置
} else { ... };
let baseline_y = strut_ascent;  // → 文本 run.y = baseline_y - height
```

**疑点**：`line_height * 0.8` 对 line-height:5（80px）给 baseline=64；教科书半行距
`(L+font_size)/2 = (80+16)/2 = 48`。差 16px。疑为可修公式 bug。

## 实测（text-emphasis-style-property-012，line-height:5，CJK 文本）

```
ZW-test CJK 文本 band:  (64-79)   → 文本顶 y=64
oracle   CJK 文本 band:  (69-98)   → 文本顶 y=69
```

**ZW 文本比 chromium 高 ~5px**（ZW 64 vs chr 69）。

## 裁决：非 clean lever

1. **方向反了**：把 `line_height*0.8` 改成教科书 `(L+font)/2` 会把 baseline 64→48
   （文本上移），但 ZW 文本**已经比 chromium 高 5px** → 改了更发散，非更近。
2. 故 `line_height*0.8` **本就比教科书公式更近 chromium**（chromium 实际 ascent/leading
   与教科书不同，0.8 启发式碰巧更近）。~5px 残余是 font-metric 近似噪声，**非可修公式 bug**。
3. R392 text-emphasis 失败的真因是**标记的 line-box-顶相对定位**（paint 侧需 line-box
   几何，且 32 案全 line-height:5 放大度量差），**非文本 baseline 定位**。文本 baseline
   本身只差 ~5px（小）。

## 结论

- line-box 半行距垂直定位（strut_ascent）**非 clean lever**——公式已近 chromium，
  改了反向发散。加入 plateau 第 5 项确认（R384/R389/R390/R392/R393）。
- text-emphasis 真正阻塞 = paint 侧标记 line-box 相对定位（需把 line-box 顶/底几何
  传入 render_fragment!，且 ZW line-box 度量与 chromium 本就差，= Phase A / IFC 垂直
  positioning 谱系，多会话）。
- 真实 forward motion 仅剩多会话架构（Phase A IFC）。单会话 clean-win 经 5 轮确认穷尽。
