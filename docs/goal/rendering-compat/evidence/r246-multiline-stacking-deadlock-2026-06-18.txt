# 多行文本垂直堆叠 bug + Phase-A 死锁冲突（R246）

**日期**: 2026-06-18
**目标**: DC-13 morning-work 67% 内容纵向压缩根因深挖与修复尝试
**结果**: 定位 3 处耦合缺陷；落地 2 处安全的 IFC 修复（零回归）；paint 侧修复实证
**净 -11 回归（Phase-A 死锁类）已回退**，记录为多轮架构问题。

## 根因链（product-smoke + 探针实证）

morning-work 67% diff 的「内容纵向压缩」真因 = **多行文本垂直堆叠**：ZeroWeb 把
所有多行块（`<pre>` 的 `\n` 多行 + 长文本自动换行）的所有行渲染在**同一 y 坐标**，
而非逐行下移。实测：
- isolated `<pre>` 3 行 → ZeroWeb 渲染 h=13（1 行），chromium h=51（3 行）
- auto-wrap `<div>` 长文本 → ZeroWeb h=17（1 行），chromium h=107（多行）

经探针（eprintln + LAYOUT_DUMP）定位 3 处耦合缺陷：

### 缺陷 1：`collapse_whitespace` 无条件折叠 `\n`（inline/mod.rs:309 / 调用点 :816）
`collect_inline_items` 对文本节点**无条件**调用 `collapse_whitespace`，把 `\n` 折叠
为普通空格 → `pre`/`pre-wrap` 模式下 `\n` 从不到达换行逻辑。CSS Text §3.1：
pre/pre-wrap/break-spaces 模式下空白序列（含 `\n`）应原样保留。

**修复**（inline/mod.rs:822）：`preserve_whitespace` 时保留原始内容（不 collapse）。
单测 `test_white_space_pre_newline_forces_break` / `_no_wrap` 覆盖。**安全，零回归**。

### 缺陷 2：`split_into_words` 的 `\n` 强制换行标记被静默丢弃（inline/mod.rs:1273）
`split_into_words`（preserve_whitespace 模式）为每个 `\n` 推入空字符串作强制换行标记，
但单词循环旧实现对空字符串只 `continue` 丢弃标记 → 即使 `\n` 保留，也不产生新行。

**修复**（inline/mod.rs:1274）：`preserve_whitespace && content_word.is_empty()` 时
flush 当前行 + 开始新行（同 `InlineItem::Br` 处理）。**安全，零回归**（单测验证）。

### 缺陷 3：paint 非多列路径用 `all_fragments()`（行内相对 y）→ 多行堆叠（painter/text.rs:934）
`all_fragments()` 返回的片段 `y` 是**行内相对**（恒 0.0，见 break_into_lines 所有
`TextFragment{ y: 0.0 }`）；`line.y`（容器内行偏移）只在 post-process 赋给 `line`，
不进片段。paint 非多列路径用 `all_fragments()` → 多行的片段都渲染在 `content_y`，
**垂直堆叠**。正确应用 `all_fragments_with_line_y()`（片段 y += line.y）。

**修复尝试**（painter/text.rs:934 改 with_line_y）：实证**净 -11 回归**（reftest
438→427，multicol -8 / CSS2 -3），已回退。回归用例（multicol-breaking-*、
column-height-009、column-balancing-paged）= 明确高度的 multicol 容器，走非多列
fragments 路径；这些用例的 test/ref 此前都**堆叠渲染（test==ref 同错）**故同源通过。
正确修复（line.y 应用）使它们「正确」但 ref 仍堆叠 → 同源 FAIL。

## Phase-A 死锁结论（与 R125/R198 同类）

缺陷 1+2 已安全落地（IFC 现能正确计算多行），但**单独无效**——paint 路径缺陷 3
仍堆叠。缺陷 3 的正确修复（with_line_y）破坏 11 个同源 test==ref 用例（自渲染 ref
同样堆叠）。这是「paint IFC 与 layout IFC 两趟、多行 line.y 应用破坏自源匹配」的
Phase-A 死锁（同 R125 三路 / R198 ancestry 墙 / R205 font_size 单字段）：

> 任何让 paint 渲染正确多行 line.y 的单点改动，都破坏「test/ref 同样堆叠」的同源
> 用例，净回归。需架构性统一：paint 完全不重跑 IFC（用 compute_final 存储的正确
> 多行 line boxes），但 R84 单行+Ahem 守卫使非 Ahem 多行不存储 → 死锁。

## 本轮落地

- inline/mod.rs：缺陷 1（collapse_whitespace preserve 守卫）+ 缺陷 2（空字符串
  强制换行）— 单测覆盖，零回归，默认启用。
- 缺陷 3 with_line_y 回退（净 -11）。
- 意义：缺陷 1+2 是缺陷 3 修复的**前置**（IFC 先能正确算多行，paint 才能正确渲染），
  落地后缺陷 3 成为下一明确目标（需破 Phase-A 死锁，多轮架构）。

## 方法论

- LAYOUT_DUMP + eprintln 探针精确定位 LAYOUT 路径（compute_final 多行 3 行正确）vs
  PAINT 路径（堆叠）分歧；A/B（with_line_y on/off 全量 reftest）量化回归。
- 印证 R203：paint 侧单点 line.y 修复须全量实证，不能据推断落地（with_line_y 推断
  正确但破 11 同源用例）。
- 自源 reftest 对「test/ref 同错」的修复天然 FAIL（非「零回归」）——同 DC-14 假通过
  的反面：自源通过掩盖真 bug，但自源失败也会误杀正确修复。须 chromium Oracle A/B
  判真价值 + 同源 count 双标。
