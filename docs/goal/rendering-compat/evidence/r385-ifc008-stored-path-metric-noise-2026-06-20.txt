# R385 — ifc-008 stored-path 发散 = 散布 fontdue 度量噪声（关闭 R355-regression lead）

**日期**：2026-06-20
**触发**：R381 发现 R355 使 ifc-008 chromium-Oracle 从 pre-R355 1.82% 退步到 7.89%（+6.07pp），疑 stored-path line.y offset miscalibrated。本轮像素级实证关闭该 lead。

## 方法

- 像素分析 ifc-008 ZeroWeb-test PNG vs chromium oracle PNG（PIL，2px 采样）。
- ifc-008 = large-font（`font: 100px/1em Ahem; height/width: 2em=200px`），div1 含 `<div>XX XX</div>`（2 行 100px Ahem 填 200×200，"no red"）。
- 关键澄清：pre-R355 ifc-008 **非空 styles**——R207/R84 的 `font_size_overrides` 已让 paint IFC 用 fs=100（故 pre-R355 z_vs_chr 1.82% 低）。R355 改用 **stored path**（多行存储）后 z_vs_chr 7.89%。

## 实证结果

- 总发散 **7.80%**（9364/120000 @ 2px 采样），**散布于 rows 18-250 / cols 8-240**（114 行 × 113 列）——**非均匀偏移**（若是单一 offset bug，发散会集中为轮廓位移，而非覆盖整个内容区）。
- ZW-test 非 白 bbox：x=8-240（宽 232）/ y=30-250。
- oracle 非 白 bbox：x=8-206（宽 198）/ y=18-248。
- 差异：ZW 内容更宽（232 vs 198，+34px≈fontdue 100px Ahem advance 偏大）+ ZW 起始更低（y=30 vs 18，<p> 行定位/行高差异）。

## 结论

**R355-regression lead 关闭**：ifc-008 stored-path 的 7.89% 发散是**散布的 fontdue 度量噪声**（100px Ahem 的 advance width + line-height/baseline 度量 fontdue vs chromium），**非可修的单一 offset bug**（line.y offset 逻辑本身正确——多行存储必须加 line.y 否则全堆 y=0）。stored path 暴露了 overrides path 偶然掩盖的固有度量发散（overrides 用 fs×1.2 默认 line-height 偶然更近 chromium 的某些度量）。

**与已知死路一致**：R225/R375（advance-width/fontdue 度量死路——accurate fontdue advance 反使 ZeroWeb 偏离 chromium system-ui）、R174/R187（fontdue AA/度量噪声）。fontdue 度量层是不可修的字体加载问题（ZeroWeb 无 chromium 实际字体），非计算 bug。

**启示**：R355 stored-path 的 chromium 退步**不可单点修**（度量噪声非 offset bug）。Phase A「stored path 权威化」的剩余精度问题 = fontdue 度量死路（非架构能解，需替换字体栈或加载 chromium 字体，超出 rendering-compat 单会话/中会话范围）。**ifc-008/009 的 chromium-Oracle 改善须等字体层突破**，非 Phase A narrow slice 能解。

## 本轮零代码变更

read-only 像素分析 + lead 关闭。诚实 plateau 不变（443/490 self-source / 35.8% chromium-Oracle 真一致）。
