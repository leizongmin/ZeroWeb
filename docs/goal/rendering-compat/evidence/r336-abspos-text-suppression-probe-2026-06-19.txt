抑制机制精确定位（探针 PROBE_ABSPOS，env-gated，已回退）
----------------------------------------------------------
R334 PNG 分析发现 green "X" 完全未绘制（span 区域 100% red）。本轮插桩 abspos span 的
paint_text 路径（text.rs:679），实证：

1. **span 的 paint_text 被调用**（fs=80 正确、color=Rgba(0,128,0,255)=green 正确、
   content_w=80、has_direct_text=true），但 **painted_contains=TRUE** → 在 text.rs:690 守卫
   `fragment_node_ids.is_none() && painted_inline_nodes.contains(&node_id)` 处 return →
   **span 自身绘制被抑制**。

2. **谁标记了 span？** 探针 div 的 IFC fragments：node_id=34(span) text="X"（其余 node 30/33
   为 div 自身文本）。collect_inline_items（inline/mod.rs:1066-1118）对 inline 元素用
   `doc.text_content(child_id)` 收集文本，node_id=child_id=span，**不检查 position**——故
   abspos span 的 "X" 被收入 div 的 IFC，render_fragment!（text.rs:1125）insert span 进
   painted_inline_nodes → 抑制 span 自身 paint。

3. = R334/R335 推断的「容器 IFC 收集 abspos 后代文本」机制精确实证。CSS §9.8：abspos
   out-of-flow，其文本不应参与父容器 inline 流；当前 collect_inline_items 违反此（layout 侧
   依赖它算静态位置，故不能在 collect 层排除——见下）。

skip 探针实现（refined，已回退）
--------------------------------
在非多列 fragment 循环（text.rs:1201 use_stored / 1219 非存储）加 skip：owner 为 abspos/fixed
且 owner≠self（abspos 元素自身绘制时不跳过）的后代文本片段跳过——容器不绘 + 不标记 painted。

探针实证（PROBE_ABSPOS）：
- div(box 32) 绘 "X"(node 34, owner=span≠div) → skip=true（正确，div 跳过 span 文本）。
- span(box 34) 绘自身 "X"(node 35, owner=span=self) → skip=false（正确，span 绘自身）。
- span 的 painted_contains 翻转为 **false**（抑制解除）。
- **但 span 的 IFC fragment fs=16**（paint-IFC 空 styles 默认值，非 80）= Layout/Paint IFC
  double-path（gap #4）。span 的 paint-IFC 用空 styles → font_size 默认 16 → green "X" 即便
  绘制也是错误尺寸/位置。

裁决
----
1. **skip 探针 net-neutral，已 100% 回退**（git checkout text.rs）。即使抑制解除（span
   painted_contains=false），span 自身 paint-IFC 因空 styles 产出 fs=16，green "X" 仍错——
   = Layout/Paint IFC double-path（Phase A）。suppression 修复须 **同时** 解 double-path
   （paint 复用 layout 存储的 font_size/行盒）才生效，即 Phase A 整体。
2. **WM-1 Phase A 第三角度确认**：R334 positioning（镜像修复正确但 0 win）→ R335 color
   （net-negative，paint-IFC 位置错）→ R336 suppression（net-neutral，span 自身 paint 被
   double-path 降级）。三角度一致指向 Phase A IFC 双路径。
3. collect_inline_items（inline/mod.rs:1066）不排除 abspos 文本是**有意为之**——layout 侧
   fix_vertical_mode_abs_pos（engine.rs:1330）依赖 IFC fragment 算 abspos 静态位置。故不能
   在 collect 层排除；只能在 paint 层跳过（本轮 skip），但 paint 层跳过受 double-path 阻塞。

Phase A 设计补充
----------------
本轮精确化 Phase A 的 WM-1 表现：paint IFC 把 abspos 后代的 inline 文本当正常流绘制（位置错）
**且** 标记 painted_inline_nodes 抑制 abspos 元素自身 paint_text；即便解除抑制，abspos 自身
paint-IFC 用空 styles 产出错误 font_size（16px 默认）。Phase A 须同时：(a) paint 复用 layout
存储的 abspos 位置/font_size；(b) 容器不收集/不绘 abspos 后代文本。两者均非单点。
