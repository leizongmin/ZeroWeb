# R229 font-weight 未落地：精确方案与资源/接线核实（read-only 调研，docs-only）

**日期**: 2026-06-17
**承接**: R228（welcome 剩余 17% = font-weight 未落地）。本轮把 R229 从假设细化为精确的「资源 + 接线」两部分方案，全部 read-only 核实。

## 证据加固（CSS-weight × ink-mass 交叉验证，推翻 size-forcing 替代假设）

曾怀疑是「paint IFC font-size 强制 16px（Phase A 死锁）」而非 weight。逐元素核实 welcome CSS font-weight 声明 vs ink-mass：

| 元素 | CSS font-weight | CSS font-size | ZW ink / CH ink | 判定 |
|------|-----------------|---------------|-----------------|------|
| .version | **600** | 11px | **10%** | 欠墨 |
| .title | **700** | 42px | **22%** | 欠墨 |
| .section-title | **600** | 12px | (eyebrow 带) 10% | 欠墨 |
| .card h3 | **600** | 16px | **66%** | 欠墨 |
| .tagline | 400 | 15px (CJK) | 165% | 过墨 |
| .card-desc/p | 400 | ~13px | 203% | 过墨 |

**关键判别**：`.version`(11px, weight600) ink 仅 10%。若是 font-size 强制 16px（Phase A），11px 应渲染成 16px→**更粗更多墨**（>100%），但实测 10%（远少于 CH）→ **与 size-forcing 矛盾，与 weight-not-honored 一致**（600 渲染成 normal 细字，11px 下细笔画几近消失）。故 font-weight 未落地是主因（过墨的 normal 文本是 fontdue vs chromium 小字号 hinting 的次要残差，另议）。

> 注意：R228 证据文件曾据「title cap-height 17px vs 32px」推断，该像素扫描受 AA/多 span 干扰噪声大，**应以本表 CSS-weight × ink-mass 交叉验证为准**。

## 根因核实（两部分，均必需）

### A. 资源缺口：仅加载 -Regular，无 Bold/Medium 变体
- `apps/browser/src/app_platform.rs:391 load_system_fonts`：主字体路径表 `chrome_ui_primary_font_paths`（:355-388）Linux 分支全为 `-Regular`：`NotoSans-Regular.ttf` / `DejaVuSans.ttf` / `LiberationSans-Regular.ttf` / `Cantarell-Regular.otf` —— **无任何 -Bold / -Medium**。
- CJK 回退（:410-417）全为 `NotoSansCJK-Regular.ttc` / `NotoSansSC-Regular.otf` —— 无 Bold。
- 故即使接线完成，`font-weight:700` 也**无 bold 字节可供选择** → 必须先补 bold 变体文件（`DejaVuSans-Bold.ttf` / `NotoSans-Bold.ttf` / `NotoSansCJK-Bold.ttc` 等系统已存在的同族粗体）。

### B. 接线缺口：weight 维度全程被忽略（数据模型已存在但未用）
- `crates/render-foundation/src/font/mod.rs:13 FontDesc` **已有 `weight: u16` 字段**（:17），`FontDesc::bold()`→700 / `::new(family, weight, italic)`（:51）—— 数据模型就绪。
- `crates/render-foundation/src/font/loader.rs:103 find(&FontDesc)`：`family_map.get(&desc.family).and_then(|ids| ids.first().copied())` —— **完全忽略 `desc.weight`**，只取该族首个 id。
- `build_font_resolver()`（:108）：返回 `family_name → 单 id`（`.first()`），paint 用此 map，**无 weight 维度**。
- `crates/engine/src/paint/` 全目录 grep `FontDesc` **零命中** —— paint 从不构造 FontDesc，font-weight 根本未进入字体选择。

## R229 精确方案（两部分，供实现轮）

**前置**：确认系统已安装同族粗体（`fc-list | grep -i bold` 看 DejaVuSans-Bold / NotoSans-Bold 是否存在；WSL 通常有）。

**B-1（接线，可先于资源做、自源中性）**：
1. `FontLoader`：`family_map` 改为按 (family, weight) 索引，或 `find()` 在 `ids` 中按 `desc.weight` 最近匹配选（CSS font-matching §5.2：≥400 取最小不小于目标的 weight，<400 取最大不大于）。`load_font` 时解析字体内嵌 weight（OS/2 usWeightClass）一并存。
2. `build_font_resolver` → 改为 `(family, weight) → id` 或暴露 weight-aware `find_for(family, weight)`。
3. paint text.rs：从 ComputedStyle 取 `font_weight`，构造/查询 weight-aware 字体选择，传入 fontdue 光栅化。

**A（资源）**：`chrome_ui_primary_font_paths` + CJK 回退补 `-Bold`（与 -Regular 同族）路径，`load_font` 时按 weight 入 `family_map`。

**成功标准**：welcome `.title`(700)/`.card h3`(600)/`.section-title`(600)/`.version`(600) ink-mass 回升到 ~100% CH（product-smoke 复测 ink 比值）；reftest 自源中性（438 不变，Ahem 不走此路径），但提 DC-14 chromium 一致率。

**范围/冲突**：仅 render-foundation/font/{loader,mod}.rs + engine/paint/text.rs + app_platform.rs 字体路径；**不碰 table.rs / cpu/mod.rs**（并行 agent WIP：colspan/`<col>` border-collapse + rounded_rect alpha blend）。

## 附录（R230 补充，2026-06-17）：资源前提实证 + 杠杆范围界定

### A. 资源前提实证可用（fc-list）
`fc-list` 确认本机已装全部所需粗体变体：
- `/usr/share/fonts/truetype/dejavu/DejaVuSans-Bold.ttf`
- `/usr/share/fonts/truetype/noto/NotoSans-Bold.ttf`
- `/usr/share/fonts/opentype/noto/NotoSansCJK-Bold.ttc`（SC/TC/JP/HK/KR）
- `/usr/share/fonts/truetype/liberation/Liberation*-Bold.ttf`
→ R229 资源修复 = 仅向 `load_system_fonts` 路径表追加已存在 `-Bold` 路径，无需 fetch/打包。
**关键细节**：DejaVu/Noto 仅有 Regular(400)+Bold(700)，**无独立 Medium(500)/SemiBold(600)** → CSS weight 500/600 须按 §5.2 fallback（600→Bold 700 或 Regular 400），实现须遵循 §5.2 否则 600 仍落 Regular。

### B. font-weight 杠杆范围 = welcome 专有（非跨页通用）
wintertc PNG（24.25% diff，ink-mass 测）主导是**橙色/彩色内容**（top-area 橙色 ink 仅 CH 26%、band[180,240] 橙调不同），非 welcome 那种 bold-vs-normal ink 分裂。wintertc 24% 主要是橙色按钮/块 + 可能图片/logo 缺口，**非 font-weight**。⚠️ wintertc PNG stale（06-16，早于 R227 + 图片管线），且当前重渲染会被并行 agent 未提交 cpu/mod.rs alpha WIP 污染 → 待并行 agent 提交后用干净 build 重渲染再诊断（独立 bug 类）。
→ R229 仍是对 welcome 17% 的干净单点杠杆 + 含 font-weight 的 reftest 用例，但非拉起所有产品页的通用杠杆。
