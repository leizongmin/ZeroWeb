# R390 — 系统审计资源解析 gap + 补齐 css-multicol swatch（第三/四处资源 gap）

**日期**：2026-06-21
**承接**：R388（Ahem oracle）+ R389（../support/ 图片）暴露「资源解析 gap 制造假状态」
模式。本轮系统审计 wpt-data 全部 test/ref 的资源引用，定位更多假状态。

## 审计方法

脚本扫描 1023 个 test/ref HTML，提取全部 `<link href>`、`<img src>`、`url()` 引用，
绝对路径解析到 wpt-data root、相对路径解析到文件目录，校验文件存在性。排除
http/data/mailto/# 及 email 类 href。1099 个引用中 42 个缺失字符串，影响 100 个文件。

## 本轮修复：css-multicol swatch 补齐

css-multicol/support/ 原有 swatch-{gray,pink,purple,white}.png，缺 blue/orange/yellow。
8 个 multicol 测试的 **ref** 引用它们（multicol-clip/block-no-clip/collapsing/count-computed/
columns-invalid 等 ref）。从 css/CSS2/linebox/support/ 复制（md5 与 borders/normal-flow/
colors 各目录完全一致 = WPT 标准纯色 swatch，86-87 字节）。

**实测影响**：
- self-source 全量 **443/490 (90.4%) 零变化零回归**（验证：临时移除 swatch，multicol-clip-001
  仍 PASS 0.56%；有 swatch 0.22%——swatch 仅降低发散量，不翻 pass/fail）。
- multicol ref 现渲染真实 swatch（非 broken 占位），发散量度量更诚实（multicol-count-
  computed-003 1.78%→0.85%、multicol-clip-001/002 ~0.56%→0.22/0.39%、multicol-columns-
  invalid-001 ~0.82%→0.65%）。
- **honesty-only，零 pass-count 增益**（这些 test 本就在 1% loose 容差下 PASS）。

## 结论

- 资源解析审计完成：除 R388（Ahem，已修，真 +12 一致）/ R389（../support/，已修，honesty）
  外，**其余缺失资源均为 honesty-only 或 out-of-rendering-scope**（writing-modes 方向图须
  上游下载但 test 已 pass；/common/*.js 属 JS 类；字体文件属 rustybuzz-未接生产）。
- **R388 是唯一带来真 pass/一致增益的资源修复**；R389/R390/swatch 为度量诚实性。
- large-font 簇（R388）仍是唯一被 oracle 证伪的渲染归因；其余 plateau 结构性归因不变。
- 真实 forward motion 仍需多会话架构（Phase A IFC / Phase 2 multicol / flex-definite-size /
  baseline-export），单会话 clean-win 经 R384（oracle-无关）+ 本轮资源审计双确认穷尽。
