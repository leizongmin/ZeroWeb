============================================================
背景（纠正 R945–R952 八轮误归因）
============================================================

R945–R952 八轮把 vertical-align 簇（117a 等 6 案 13–21%）归因为
「Ahem valign glyph 定位（stored path frag.y 消去 / half_leading 反推错）」，
6 轮公式级微调全 net-negative。

本轮（R953）empirical per-case 像素级 forensics（CONTINUE 建议角度，区别
6 轮公式级）推翻该归因：

1. stored-path valign glyph 定位**已 div-rel 正确**（R822 Phase 3 frag_baseline_y
   已编码 valign 偏移）。实施 embox-always + half_leading(=frag.height−fs/2)
   组合（PHASEA_VALIGN env）实测 117a 黑 [90,130] / 蓝 [45,85] div-rel **像素级
   精确匹配 ref**，但 oracle **更差**（13.59→14.03%）。→ 该角度 net-negative，
   已回退（零 net 源码）。

2. **真 dominant error = 默认字体 <p> 块首行垂直定位**。117a 的 `<p>Test passes
   if...</p>` 走**非存储路径**（R84 空-styles 墙，仅 pure-Ahem 才 store）。
   ZW 把 <p> 文本放在 p_top+11.2（frag.y=−4.8 + baseline_offset=font_size=16），
   chromium 放 p_top+1.6。→ ZW div 在 y=51，chromium div 在 y=68（**ZW div 高 17px**），
   这是 117a 13.59% 的 dominant 来源，非 Ahem glyph。

============================================================
根因（非存储路径 baseline_offset）
============================================================

crates/engine/src/paint/painter/text.rs 非存储路径（~1345）：

  glyph_y = content_y + frag.y + baseline_offset
  旧 baseline_offset = font_size = 16

frag.y = run 顶 = baseline_y − run.height（行盒相对）。
glyph 顶（行盒相对）应 = half-leading = (line_height − font_size)/2（em-box
在行盒内居中，**与 ascent 无关**）。故：

  frag.y + baseline_offset = (height − fs)/2
  baseline_offset = (height − fs)/2 − frag.y
                  = (height − fs)/2 − (baseline_y − height)
                  = height − (baseline_y − (height−fs)/2)
                  = height − ascent          （baseline_y = half-leading + ascent）
                  = height − 0.8·fs           （ascent≈0.8·fs，apply_vertical_alignment
                                            line 1634 同启发式）

旧 baseline_offset = font_size 把 glyph 顶放在 frag.y + fs = 基线位，致每行
偏低 ≈ 9.6px（fs − (height−0.8·fs) = fs − height + 0.8·fs = 1.8·fs − height；
fs=16/lh=19.2 → 28.8−19.2 = 9.6）。

修复：baseline_offset = fragment.height − 0.8·fragment.font_size（仅文本运行 fs>0；
inline-block/原子盒 fs==0 保留旧 baseline_fs）。

战略意义
============================================================

1. **纠正 R945–R952 八轮误归因**：vertical-align 簇 dominant error 是默认字体 <p>
   块非存储路径定位（R84 空-styles 墙的一个具体、可修子症状），非 Ahem glyph。
   Ahem valign glyph 角度（embox-always / half_leading / run.y / v_offset）6+1 轮
   全 net-negative，勿再试（R950 已声明 + 本轮 PHASEA_VALIGN 再证）。

2. **R84 空-styles 墙有可修子症状**：本轮证明该墙并非全有或全无——非存储路径的
   glyph 定位公式（baseline_offset）可用行盒 half-leading 修正，无需打通全
   style→paint 链路。这为 font-features（R513）/ large-font（R101）的同类子症状
   修复提供新角度（区别 R945「须架构性 Path B 消除」全有或全无判断）。

3. **残余真字体墙**：0.8·fs 是 Ahem 启发式；真字体（welcome/morning system-ui）
   ascent≈0.9·fs，故 welcome 净 +0.77pp。理想修 = paint 路径接 fontdue 真 ascent
   （per-font metric），font-metric 墙多会话（R374/R631/R876 谱系）。
