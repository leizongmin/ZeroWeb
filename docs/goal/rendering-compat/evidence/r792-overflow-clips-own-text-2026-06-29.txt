1. Bug：overflow!=visible 的盒子不裁剪**自身直属文本**（仅裁子节点）
================================================================================

调查 max-width-106（float+overflow:scroll+直属文本 "XXXXXXXXXXXX"）发现 ZW 渲染
红色文本**外溢可见**（向右延伸到页面边缘），chromium 裁掉（无红可见）。chromium oracle
**无 scrollbar widget**（headless），故非 scrollbar 缺口——是文本未裁。

根因（paint 双路径 paint_node + paint_node_in_rect）：
  paint_node 流程：
    paint_background/border/outline（装饰）
    paint_text（盒子**自身**直属文本）← 发射 glyphs 到 self.primitives.glyphs
    counts_before_children = snapshot(...)          ← 快照在 paint_text 之后！
    paint children
    if needs_clip { clip_all_primitives_to_rect(counts_before_children, content_rect) }
                                                       ↑ 裁剪范围 [snapshot..end] 只含子节点

  clip_all_primitives_to_rect 确实裁 glyphs（helpers.rs:411 clip_glyphs），但 from.glyphs
  取自 paint_text 之后的快照 → 自身文本 glyphs 不在裁剪范围 → 漏裁。

  验证（minimal 3-way probe /tmp/clip-test.html，60px overflow:hidden box）：
    Row1 直属红文本 "AAAA..."：OVERFLOW（未裁）  ← bug
    Row2 子 div 蓝文本：clipped（子节点裁剪工作）
    Row3 子 div 绿填充：clipped
  → 确认仅「自身直属文本」漏裁。

================================================================================
2. Fix：counts_before_children 快照前移到 paint_text 之前
================================================================================

paint_node + paint_node_in_rect 双路径：
  - 在 if-else 之前声明 `let mut counts_before_children = snapshot(...)`（默认覆盖
    匿名文本项/无样式分支）。
  - 有样式分支在 background/border/outline/clip-path 指示绘制**之后**、paint_text
    **之前**重赋值 `counts_before_children = snapshot(...)`。
  - 删除原 paint_text 之后的快照声明。
  → 裁剪范围 = list marker + img + content + 自身文本 + 列背景 + 子节点；
    background/border/outline/shadow/clip-path 指示/backdrop-filter 保持不裁
    （CSS：overflow 只裁内容到 padding-box，盒子自身装饰不裁）。

  PrimitiveCounts 是值快照（无 borrow 持有），重赋值与后续 &mut self.paint_* 无冲突。
