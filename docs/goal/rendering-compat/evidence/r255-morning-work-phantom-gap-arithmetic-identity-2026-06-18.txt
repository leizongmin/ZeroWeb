# morning-work 4× 高度幻影间隙 — 算术恒等式定位触发因子（R255）

**日期**: 2026-06-18
**目标**: 回答 R253 morning-work（evidence/r253-morning-work-4x-height-phantom-gaps-2026-06-18.txt）
开放问题 #1「BISECT 哪个 CSS 触发 ~300px gap」——**纯 read-only 文本核对**，不改源码、不跑渲染。
**结果**: 触发因子已精确定位为 `.article` 容器的盒属性 `{min-height:200px; margin:4em 0}`，
幻影间隙 **328px = 200(min-height) + 64(margin-top 4em) + 64(margin-bottom 4em)** 恒等式与 R253 dump
的 4/5 个间隙完全吻合；R253 最小复现失败的根因已找到（复现缺 `.article` 容器）。

## 决定性证据：328 = 200 + 64 + 64

R253 LAYOUT_DUMP 的 article 子元素 y 序列，逐对间隙：

```
h2  abs_y= 521.2 h=30  mt=52   (前言)
p   abs_y= 879.2 h=85  mt=16   间隙 = 879-(521+30)  = 328px
p   abs_y=1236.2 h=56  mt=16   间隙 = 1236-(879+85) = 272px
h2  abs_y=1620.2 h=30  mt=52   (问题分析) 间隙 = 1620-(1236+56) = 328px
h3  abs_y=1978.2 h=28  mt=16   间隙 = 1978-(1620+30) = 328px
p   abs_y=2334.2 h=28  mt=16   间隙 = 2334-(1978+28) = 328px
```

5 个间隙中 **4 个 = 328px**（与元素类型无关：h2→p / p→p / p→h2 / h2→h3 / h3→p 全 328），1 个 = 272px。
328px 不是任何单条声明的值，但恰为 `.article` 盒属性之和：

```
.article { min-height: 200px; margin-top: 4em; margin-bottom: 4em; }
  min-height: 200px        → 200
  margin-top: 4em  (16px)  → 64
  margin-bottom: 4em (16px)→ 64
  合计                      → 328px   ← 与 dump 4/5 间隙精确一致
```

来源核对：`.article` 盒属性在 article.html **内联 `<style>`** 第 77-81 行（非 article.css）；
`.article { font-size: 16px }`（article.css）确认 4em = 64px。body 亦 16px。

## 关键否定：幻影盒非 HTML 字面重复（是 ZeroWeb 生成）

R253 记"另有幻影嵌套 article：article.article abs_y=257.2 h=200.0 w=4.0"。逐行核对 article.html：

```
168:  <article class="article">
352:  </article>
```

**全文仅 1 个 `<article class="article">`**，无嵌套 article。故 dump 中那个 `h=200 w=4` 的幻影 article
**不是 HTML 字面第二个 article**，是 ZeroWeb 在布局中生成的盒子。其 `h=200.0` 又精确等于
`min-height:200px` → 与上述恒等式同源：**ZeroWeb 正在按 `.article` 盒模型（min-height:200 + margin:4em）
生成幻影盒子**，至少 1 个被显式 dump 出来（w=4 那个），且 ~328px/对的间隙表明这类幻影盒（或其
min-height+margin）被插在每个 block 兄弟边界处。

## 为什么 R253 最小复现未重现（根因）

R253 用最小 h2+p+pre 复现 328px gap **失败**。现可解释：该最小复现**没有 `.article{min-height:200px;
margin:4em}` 包裹容器**，故不触发 ZeroWeb 对 `.article` 盒属性的幻影盒生成。触发因子不是 h2/p/pre
标签本身，也不是 line-height/word-break，而是**带 `{min-height:200px; margin:4em}` 的 `.article` 容器
内多个 block 子元素**这一组合。

**修正后的最小复现（应能重现 328px/对间隙）**：

```html
<!DOCTYPE html><html><head><style>
  .article { min-height: 200px; margin-top: 4em; margin-bottom: 4em;
             font-size: 16px; line-height: 1.75; }
</style></head><body>
  <article class="article">
    <h2>前言</h2>
    <p>第一段正文。</p>
    <h2>问题分析</h2>
    <p>第二段正文。</p>
  </article>
</body></html>
```

预期：ZeroWeb 渲染下 h2/p 间每对间隙 ≈328px（chromium 下应 ≈16/52 正常 margin）。

## 机制假设（待运行时确认）

`min-height` 与 `margin` 是 CSS **非继承**属性，匿名盒本不该从 `.article` 父继承它们。dump 却显示
带 `.article` class 标签的幻影盒（h=200=min-height）→ 指向**选择器过匹配 / 幻影盒被赋予 `.article`
身份 / inter-block 空白文本节点被包成匿名块且该块错误套用 `.article` 规则**之一。属 R109 谱系
（ZeroWeb 匿名块 / inline→block / IFC 边界处理）的相邻缺陷，而非新机制。

- w=4.0 细节**次要未释**（real .article 全宽；幻影 w=4 可能是塌缩/测量产物，h=200 才是信号）。
- 272px 离群 ≈ 328 − 56，疑某边界 margin 折叠抵掉一部分；主信号 328 不受影响。
