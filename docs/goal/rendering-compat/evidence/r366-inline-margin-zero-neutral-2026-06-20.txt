实验
================================================================
CSS 2.1 §8.3/§10.2：display:inline 元素的 margin-top/bottom 无视觉效果（仅 left/right
生效）。ZeroWeb 把 inline 映射为 block（taffy），故 vertical margin 被错误应用
（empty-inline-002 的 <span style="margin:100px"> 实测 mt=100 被应用）。

修复（converter/mod.rs）：加 is_pure_inline = display==Inline（不含 inline-block/
inline-flex 等原子行内级盒），在 taffy margin 块把 top/bottom 归零。

================================================================
- empty-inline-002：self 25.78% → 25.26%（仅微移），**TEST vs chromium-Oracle = 23.20%
  修复前后完全不变**（red 区域仅位移非缩小）→ 修复对该案 oracle 零改善。
- 全量 self-source：**442/490 净中性，零翻转**（48 失败列表 diff 为空）。
- 裁决：CSS 正确但**两个指标均零杠杆**——empty-inline-002 发散由 block-mapping +
  padding/border 作为 block 盒（非 inline line-box）主导，vertical margin 非主因。
  按 code-guidelines「不做零价值/推测性修改」**回退**（git checkout converter/mod.rs）。

================================================================
追加（同轮）：Phase A inline→block 重写只读探针——锚定入口 + 证伪 safe-staging
================================================================
探针目的：为多会话 inline→block 映射重写定位安全分阶段迁移切片。
发现：
1. **映射入口**：converter/mod.rs convert_display() 第 43 行
   `DisplayValue::Inline | InlineBlock | Flow | FlowRoot | ListItem | Contents => Block`。
   纯 Inline 元素被 taffy 当 block 子布局，获 block 几何（mt/mb/w/h）。
2. **paint 消费**：painter/mod.rs:398-415 用 box_node（taffy block 几何）绘制
   background/border，包括 inline 元素——故 inline 的盒装饰按 block 盒画（错）。
3. **IFC 不追踪 inline 盒范围**：IFC（collect_inline_items / fragments）只处理文本，
   不产出 inline 元素的盒装饰范围（用于 paint bg/border/padding）。故无现成 inline-box
   几何可供 paint 消费——重写须先在 IFC 侧生成 inline 元素盒范围。
4. **无 safe-staging 切片**：纯文本 inline（无盒装饰）现行 block-mapping 已无害
  （空 block 盒不可见，文本由 IFC 定位）；有盒装饰的 inline（empty-inline-002 的 span）
   需完整 inline-box 模型（margin/padding/border 按 line-box 绘制）。两类之间无安全中间档
   ——重写对盒装饰 case 是 all-or-nothing。
结论：Phase A inline→block 重写**无 safe single-session staging**，须多会话整体推进
（IFC 生成 inline 盒范围 → paint 消费 → 从 taffy block 树剥离 inline）。surface patch
（R366）与 clean-win（R352-R365）双穷尽后，此为唯一路径但非单会话可成。

追加：R367 inline-block border-box 尺寸实验（net-negative，已回退）
================================================================
假设：adjust_inline_block_positions 传 inline_block_sizes 用 content_height（ifc-011
span1 border:20px → content_height=50）而非 border-box（90），致 IFC 行盒过短（div h=60
应 90）+ span2 vertical-align:top 错位。
实验（engine.rs ib_sizes：content_{w,h} → child.{w,h} 即 border-box）：
- ifc-011：11.27% → **13.73%（更差）**，span2 101→141（更错位），div h=60 不变。
- 裁决：**net-negative 回退**。div h=60 是 taffy 主布局的行盒高度（不由 adjust_inline_block_
  positions IFC 决定）——inline-block 的 line-box 高度须在 taffy 层容纳，IFC sizing 改不动，
  仅重新定位 inline-block 致更错。证实 ifc-011 的 inline-block baseline/line-box 簇是
  **taffy-level 结构性**（须 baseline 合成多会话架构，非 IFC 表面修复）。
结论：R366（margin 归零 net-neutral）+ R367（border-box net-negative）双实验关闭 inline/
inline-block IFC 表面修复微路径——此簇唯 taffy-level baseline/line-box 重写可解。
