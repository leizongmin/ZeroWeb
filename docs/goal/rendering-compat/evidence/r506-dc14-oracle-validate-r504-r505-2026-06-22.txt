4. 发现 1 个 POLLUTED（self-source 假通过，真 bug）
============================================================

abspos/static-inside-inline-block:  self-pass 0.00%  z_vs_chr=2.02%  ⚠ POLLUTED

诊断（REFTEST_DEBUG fills + PIL + LAYOUT_DUMP）:
  结构: <p>Test passes...</p> + 3 个 inline-block（第 2 个红 bg 含 abspos green）
  ZW-test:  红 inline-block (112,16,100,100) + 绿 abspos (112,16,100,100) — y=16
  CHR-test: 绿 y=50（<p> 之后）
  <p>: abs_y=16 h=19.2 mt=16

★ 真因: inline-block（inline-level）跟在 block <p> 之后时，ZeroWeb 把 inline-block
  行放在 y=16（<p> 的 content top）而非 y=50（<p> 之后）—— inline 内容未在 block
  之后下移，与 <p> 重叠。这是 block/inline-flow（anonymous block box 包裹 inline
  内容应流过 block）bug。

★ 可修性: IFC Phase-A entangled（R247 multiline-stacking deadlock 同类——auto-wrap
  div ZW h=17 vs chr h=107 即 inline/block 流不推进）。非单点 clean fix，须 Phase-A
  IFC 架构统一。本轮不修（code-guidelines §2 不投机），记录为 Phase-A lever 证据。

5. JS 执行缺口确认（非 bounded lever）
============================================================

reftest harness 的 execute_scripts（reftest.rs:675）用 V8Sandbox 跑 JS 但**无 DOM
绑定**（注释明言「不影响渲染输出」）—— `target.style.opacity=1` 等 DOM 改动不作用
于实际文档，render_html 总渲染初始 HTML。487 CSS2 文件依赖 JS。修 = 建 DOM-JS bridge
（script-sandbox ↔ engine，核心浏览器引擎特性，milestone 规模），非单会话任务。
opacity-change-twice/transition 的 2.08% 即此缺口（chromium 跑 JS 改 opacity，ZW 不跑）。
