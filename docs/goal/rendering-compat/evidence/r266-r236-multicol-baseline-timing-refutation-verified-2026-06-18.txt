## 证伪链条（全源码闭合）

### 1. baseline-export 用例结构 = 块级 flex（非 inline-flex）

实测用例 HTML（tests/wpt-runner/wpt-data/css/css-multicol/baseline-0XX.html）：

baseline-000.html:
```html
<div style="display:flex; align-items:baseline;">
  PA
  <div style="columns:2; column-fill:auto; height:5em;">SS <br></div>
</div>
```

baseline-007.html:
```html
<div style="display:flex; align-items:baseline; line-height:40px;">
  <div style="width:50px; background:green;">...</div>
  <div style="columns:3; width:50px; background:green;">...column-span:all...</div>
</div>
```

→ baseline-export 全族用 **`display:flex`（块级 flex）+ `align-items:baseline`**，其中一项是 multicol（`columns:N`）。**非 `inline-flex`**。

### 2. flex 基线对齐发生在 taffy 内部（早于 extract_baselines）

`crates/layout-engine/src/engine.rs::compute()` 后处理顺序（节选）：
- 步骤 1-3：taffy compute（flex 布局，含 flex 项按 baseline 对齐）—— flex 项位置在此**确定**
- 步骤 3.5（engine.rs:228）：`extract_baselines_recursive` —— 从 taffy `cached_baselines()` **拷贝**到 `LayoutBox.taffy_baseline`
- 步骤 9（engine.rs:264）：`crate::multicol::adjust_multicol_layout` —— multicol post-pass
- 步骤 10（engine.rs:267）：`adjust_inline_block_positions` —— 唯一 `LayoutBox.taffy_baseline` 消费者

→ block flex 项按 baseline 对齐在步骤 1-3（taffy 内部）完成，taffy 用 multicol 项的 **taffy 内部缓存基线**（generic block baseline，非首列导出）定位。到步骤 9（multicol post-pass）时 flex 项**已定位完毕**。

### 3. 唯一 taffy_baseline 消费者的 guard 排除 display:flex

workspace 非测试代码 `LayoutBox.taffy_baseline` 用法（grep `\.taffy_baseline`，排除 tests/）：
- engine.rs:484 — 写（extract_baselines_recursive）
- engine.rs:988 — 读（adjust_inline_block_positions 内 `baseline_overrides` 计算）

engine.rs:978 的消费 guard：
```rust
let is_horizontal_flex = matches!(style.display, DisplayValue::InlineFlex | DisplayValue::InlineGrid)
    && matches!(style.flex_direction, FlexDirectionValue::Row | FlexDirectionValue::RowReverse);
if !is_horizontal_flex { return None; }
// 优先使用 taffy 缓存的基线
if let Some(taffy_bl) = child.taffy_baseline { ... }   // line 988
```

→ 消费者仅覆盖 **`InlineFlex | InlineGrid`**，**不覆盖 `display:flex`（块级 flex）**。baseline-export 全族（block flex）的 taffy_baseline **没有任何 ZeroWeb 后处理读取用于重对齐**。

### 4. 覆写 LayoutBox.taffy_baseline 不触及 taffy 内部缓存

extract_baselines（228）是从 taffy `cached_baselines()` **拷贝**到 LayoutBox.taffy_baseline（ZeroWeb 自用副本）。multicol post-pass（264）覆写的是**这个副本**，**不动 taffy 树节点内部缓存**。而 block flex 项位置由 taffy 内部缓存决定（步骤 1-3）→ 覆写副本对已定位的 flex 项**无影响**。

## 结论（强化前序提示）

R260「multicol.rs 填 `container.taffy_baseline` → +8」**不成立**。对 8 baseline-export 用例（全 block flex）：
- 覆写 taffy_baseline **无人消费**（唯一消费者 :988 guard 排除 block flex）→ **净 0**：不修 007/008 失败，不破 000-006 偶然通过（000-006 系简单结构 taffy generic baseline ≈ 首列 baseline 偶然对齐；007/008 复杂结构 column-span/line-height 致 generic ≠ 正确）。
- R260 之所以误判：读了消费者存在（:988）+ 守卫存在（0<v<content_height），**未核 guard 的 display 覆盖语义**（InlineFlex|InlineGrid 排除 block flex）。R260 自称「仅波及 multicol 作 flex/grid item 参与 baseline 对齐」——但该 consumer 只处理 inline-flex/grid baseline 合成，不处理 block flex/grid item 对齐（后者 taffy 内部）。

**真实修复路径（结构性多轮，非单会话 contained）**：
- 选项 A：pre-pass 估测 multicol 首列基线喂 taffy（chicken-and-egg：列结构 post-pass 才定，需迭代/近似）。
- 选项 B：post-alignment 调整——multicol post-pass 算正确 baseline 后，回溯调整同 flex line 其他项 y（须识别 flex 容器 + 同 line 项，复杂，回归风险高）。
- 两选项均同 R131 multicol column-aware IFC 谱系。**勿以「填 taffy_baseline」重试 R236**（净 0，浪费 + 潜在回归）。
