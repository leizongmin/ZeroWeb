R332 — SHAPE_PAINT 环境门控探针：paint-only shaping 净负向（需 layout 同源）
==========================================================================
日期: 2026-06-19
基线: self-source loose 438/490 (89.4%) / strict 295/490 (60.2%) / chromium-Oracle ~35.6%
承接: R331（shaping 接入 = 4 子任务多会话；标 paint gate 为子任务④）

动机
----
R331 定位 shaping 接入的 4 子任务（plumbing / 光栅化按 glyph-index / TextShaper 单位修复 /
paint gate）并判定多会话。本轮实现全部 4 子任务（high-bit 哨兵法避免 GlyphPrimitive 加字段
触发的 55 处构造点改动），用 SHAPE_PAINT 环境门控做 R327 式实证，决定 paint-only shaping
是否已是可单会话落地的净正杠杆。

实现（实验，已回退）
--------------------
- (1) FontLoader→Painter plumbing：pipeline + painter set_font_loader（Option<Arc<FontLoader>>），
      reftest harness Arc 包裹；4 处 Painter 构造点传 loader.clone()。
- (2) 光栅化按 glyph-index：FontLoader::rasterize_glyph_index（fontdue rasterize_indexed）+
      cpu/mod.rs draw_glyph_primitive 加 high-bit 哨兵分支（glyph_id & 0x8000_0000 → 按索引，
      否则 char::from_u32 当前行为）。**生产 codepoint < 0x110_000 永不置高位 → 零行为变更**，
      无需改 GlyphPrimitive 定义或其 55 处构造点。
- (3) TextShaper 修复（**保留**，见下）：advance_x 用 fontdue metrics_indexed(glyph_index)
      （ligature-correct，旧实现取首 cluster 字符宽度过窄）；x_offset/y_offset 用
      pos.* * font_size / units_per_em（旧实现 raw i32 = 字体单位，未缩放）。
- (4) paint gate：text.rs:1047 inline-fragment 循环，SHAPE_PAINT=1 时用 TextShaper.shape_single_line
      产 glyph（glyph_id 置高位哨兵 + shaped advance + offset），否则当前 estimate 循环。

实证结果（test-guard 包裹，chromium-Oracle cross-validate）
----------------------------------------------------------
self-source reftest-upstream（SHAPE_PAINT=1）= **438/490 (89.4%)**，与基线**逐目录完全一致**
（css-fonts 60/60、各目录不变）。→ shaping 对 test/ref 同向作用，self-source 天然抵消（同 R330）。

chromium-Oracle（475 可比 case，OFF vs ON dump 各 490，cross-validate.py）：
- 污染（self-pass 但 chr 不一致）：**OFF 157 (48.0%) → ON 159 (48.3%)**（+2，略恶化）。
- 逐 case chr-diff 变化 >0.3pp：**0 case**（无改善、无显著退化；+2 污染为 <0.3pp 微增跨 1% 阈值）。
→ **paint-only shaping 净中性偏负**（pollution +2，零改善 case）。

根因（为何 paint-only 无效）
----------------------------
IFC **layout**（inline/mod.rs:1366/1694）仍用 estimate_char_width 做换行决策；shaping 只改
**paint** 的 glyph 位置/索引。故 layout 按估计宽度断行，paint 按 shaped 宽度定位 glyph →
**layout/paint 不一致**（glyph 可能溢出/不足其行盒）→ 不更接近 chromium（chromium layout+paint
同源 shaping）。这与 advance-width「三处同源」问题同构（R223/R225），但作用于 shaping 而非
advance：**shaping 须 layout+paint 同源应用才有效**，paint 单侧无增益。

裁决
----
paint-only shaping（子任务④单点）**净中性偏负**（pollution +2），证伪「paint gate 是可单会话
落地的净正杠杆」。shaping 真正价值须 layout+paint 同源 = Phase A IFC 统一（R125-R213 P0 多会话
死锁区）+ shaping 一体化，非单会话。这把 R331 的「4 子任务多会话」精确化：**子任务④（paint gate）
不能独立先落地**——必须与 layout shaping 同步（否则如本轮 net-negative）。

保留与回退
----------
- **保留 (3) TextShaper 修复**（shaper.rs）：真实 bug 修复（ligature advance + offset 单位），
  修正既有已提交代码（TextShaper 当前仅单测用，但 advance 取首 cluster 字符宽度、offset 未缩放是
  实打实错误）；fontdue metrics_indexed/units_per_em 已验证可用；27 单测全过；未来 layout+paint
  shaping 同源接入时即正确，无需重做。
- **回退 (1)(2)(4)**（plumbing + 光栅化哨兵 + paint gate）：paint-only 净负向，gate 关闭即死代码，
  违 code-guidelines §3。layout+paint shaping 同源落地时再按 R331 计划重建（含 high-bit 嗦兵法，
  已验证可避免 55 处构造点改动）。
