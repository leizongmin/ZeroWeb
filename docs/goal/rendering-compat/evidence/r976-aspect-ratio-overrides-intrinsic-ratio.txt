## 测试结构
```html
<!-- test -->
ul.container{display:grid;grid-auto-flow:column} > li >
  div{inline-block} > div{grid} >
  img{block-size:55vw; aspect-ratio:2/1}   <!-- src=colors-8x16.png 固有 8×16 -->

<!-- ref（同 CSS，简单结构）-->
ul > li > img{block-size:55vw; aspect-ratio:2/1}
```
@800px viewport：55vw=440；aspect-ratio 2/1（w:h）→ 期望 img 880×440（溢出 viewport，测试本意）。

## 诊断（env-gated R976_PROBE 探针，捕获后即删）
`apply_replaced_element_sizing`（tree.rs）对 colors-8x16.png 的 img 实测：
  attr_w=None  css_w=Auto  css_h=Px(440.0)   ← block-size:55vw 已被 converter 正确解析为 Px
  aspect_ratio=Some(2.0)                      ← CSS aspect-ratio 已正确解析
  intrinsic=Some((8.0, 16.0))                 ← 解码固有尺寸

即所有 computed 值正确。bug 在 `_` 分支（无 HTML attr、回退 img_intrinsic_sizes）：
  旧代码 line 290：width = ch * w / h = 440 * 8/16 = **220**（用**固有**比 0.5）
  spec（css-sizing-4 §4）：CSS aspect-ratio 优先 → width = ch * aspect_ratio = 440 * 2 = **880**

差 4 倍 → img 渲染 220×440 而非 880×440 → 64% diff。机制清晰、单点、spec-correctness。

## 修复（crates/layout-engine/src/tree.rs `_` 分支）
引入 `eff_ratio = computed.aspect_ratio.unwrap_or(w / h)`（CSS aspect-ratio 若设则优先，
否则固有 w/h），auto 侧按 eff_ratio 推导：
  - height 显式、width auto：width  = ch * eff_ratio
  - width 显式、height auto：height = cw / eff_ratio

对称覆盖两侧。HTML-attr 分支（211-256）不受影响（其 auto 侧本就交给 taffy 按 aspect_ratio
推导，已与 CSS aspect-ratio 一致）；仅 `_`（intrinsic）分支旧实现恒用固有比是 bug。

## 单测（crates/layout-engine/src/engine/tests/tests_10.rs，2 个新测）

   img 无 HTML attr、intrinsic 8×16、CSS height=440 + aspect-ratio=2.0 → 断言 width≈880
