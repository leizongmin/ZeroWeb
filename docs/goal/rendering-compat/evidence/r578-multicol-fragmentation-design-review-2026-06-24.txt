================================================================================

1. **Round 1'（baseline-export，类 D 最大 near-pass 簇）= ZeroWeb 后处理侧 ruled out**（R316 四轮：
   R310 探针 / R312 双侧 / R313 baseline_overrides 证伪 / R316 flex 后处理回归）。真修复须 **taffy
   inline-level-box baseline 合成或升级 taffy 0.8+（baseline_overrides，R304 DEFER prohibitive）**。

2. **Round 2'（breaking wiring，类 C multicol-breaking-004/005/006/nobackground-*）= paint-side
   4 轮证伪 ruled out**（R157/R198/R203/**R317**）。R317 实测放宽 text.rs:713 `height_auto` 门控 =
   multicol 40/57→35/57 净 -5 回归（balance 侧大面积 FAIL）+ 目标 multicol-breaking-004 反恶化。
   **真修复须 layout-side column-aware IFC**（R131/R317 重定向）：layout 阶段计算 multicol IFC 行盒
   按列高预算碎片化到各列，存 LayoutBox，paint 直接消费（不再走 text.rs:713 paint 门控重算）。
   = **多 session spec-rfc**（设计 doc §R317 明示）。

3. **Round 3'（column-rule §5.2 + 精度）= 非单点安全**（R201 column-rule-002 回归）+ 类 A 残余精度
   = advance-width 谱系（R225 证伪独立死路）。

4. **碎片化算法已存在**（R201）：`multicol.rs::assign_children_to_columns_sequential`（顺序填充+列高
   预算）+ `_with_breaking`（块级子碎片化）= CSS Multicol §6 fragmentation 所需。缺口 = **接线到
   inline 内容的 layout-side 列分配**（非新建算法，纠正 R113「循环依赖」+ R199「balance 工具」误判）。

5. **列分配（balance）方向已关闭**（R200）：旧 `total/col_count` 顺序填充 + 平衡高度**本就正确**
   （chromium §8 也是顺序填充），类 A 低 diff 残余是精度（列宽/glyph x/平衡高度精确值）非算法。
