──────────────────────────────────────────────────────────────────────────────
【类 A】007 / max-007 — min/max-width on display:table-cell
──────────────────────────────────────────────────────────────────────────────
测试结构（007 为例，max-007 对称）：
  #table { display:table; table-layout:fixed }
  #row   { display:table-row }
  #cell  { background:black; display:table-cell; height:1in;
           min-width:1in }            ← min-width 在 cell 上，cell 无 width
  assert：min-width applies to table-cell → 黑色 cell ≥1in 宽 → 96×96 方块
max-007：cell { max-width:1in; width:3in } → assert max-width applies → 上限 1in → 96×96

★ 根因（实证代码读 + grep）：
  cell_used_width 闭包（table.rs:1091-1126，compute_column_widths Pass 1 调用）：
    - auto 分支（css_width_auto=true，即 cell 无 width）：w = intrinsic（仅内容固有宽）
    - explicit 分支（cell 有 width）：w = explicit.max(intrinsic)
  → 两个分支【从不读取 cell 的 min_width / max_width】。
  全仓库 grep 确认：cell 级 min_width/max_width 仅在 colgroup 路径（table.rs:1144/1151
  = resolve_col_min/resolve_col_max，R548 新增）读取；cell 本身的 min/max-width 无任何
  消费点 = 缺口就在 cell_used_width。

  后果：
    - 007：cell 空（intrinsic=0），min-width:1in 被忽略 → 列宽 0 → 黑 cell 0×96（非方块）→ FAIL
    - max-007：cell width:3in=288px，max-width:1in 被忽略 → 列宽 288px（过宽）→ FAIL

★ 修复 seam（hand to code agent）：
  cell_used_width 内补 cell min/max-width 读取（仅 Px，同 R548 col 路径口径）：
    - 读 cell style.min_width（Px）作列宽下限、max_width（Px）作上限；
    - auto 分支：w = intrinsic.max(min_width_px).min(max_width_px)
    - explicit 分支：w = explicit.max(intrinsic).max(min_width_px).min(max_width_px)
  blast radius 评估：min/max 仅在有显式 min/max-width 声明的 cell 上生效（gated on 属性）；
  当前 css-tables 全量无 cell+min/max-width 测试（R548 已证 col/colgroup 路径零回归），
  但 cell 级是新路径，须 A/B 守 css-tables 全量 + normal-flow。

★ yield 预估：007 + max-007 = 2 self-source PASS（若 max-008/max-013/max-014 对称机制
  同属 cell/inline/table display，见类 B/C 评估）。

──────────────────────────────────────────────────────────────────────────────
【类 B】013 / max-013 / 014 / max-014 — min/max-width on display:table / inline-table
──────────────────────────────────────────────────────────────────────────────
测试结构（014 为例，table；013 = inline-table 对称）：
  #table { display:table; table-layout:fixed; min-width:1in }   ← min-width 在 table 上
  #row   { display:table-row }
  #cell  { background:black; display:table-cell; height:1in }   ← cell 无 width，空
  assert：min-width applies to table → 整张 table ≥1in 宽 → 黑 cell 填满 → 96×96 方块

★ 关键发现（反直觉）：table 的 min/max-width【已被读取】——
  apply_table_size_constraints（table.rs:1852）正确做了
    final_width = intrinsic_width.max(min_width).min(max_width)   （table.rs:1890-1910）
  并更新 table_box.width / content_width（table.rs:1988-1989）。
  → 即 table 容器会被 floor 到 min-width:1in=96px。

★ 但仍然 FAIL 的真因：
  apply_table_size_constraints 在 position_cells（table.rs:1561）【之后】由
  layout_table 末尾调用（table.rs:1842）。position_cells 用的是【原始】compute_column_widths
  返回的 col_widths（未含 table min-width 扩展）。apply_table_size_constraints 把
  table_box 撑宽到 96px 后，【不重新扩展内部 cell 列宽】——cell 列仍保持原始宽度
  （空 cell = 0px 列宽）。
  → 结果：table 容器 96px 宽，但内部唯一 cell 列 0px → 黑色背景仅占 0px → 非 96×96 方块 → FAIL
  （即「列不填满 table 宽」——R548 doc 记录的机制描述）。

  另：013（inline-table）可能叠加 inline-table 位置偏移（inline-level 定位）子问题，
  但主因同为 cell 列未随 table min-width 扩展。

★ 修复 seam（hand to code agent）：
  当 apply_table_size_constraints 因 min-width 把 table 撑宽（final_width > intrinsic_width）
  时，需把【扩展量分配到列】（仅 auto 列 / 或唯一列），再重新 position_cells（或直接扩列宽）。
  这是 table.rs 内 table-sizing 与 column-sizing 的协调缺口（同 R117 cell_box.width 全宽误用谱系
  的反向：这次是 table 宽正确、列未跟上）。
  blast radius：较高——动列宽分布会影响所有 css-tables 用例。须 A/B 守 css-tables 全量
  + normal-flow，重点查 colspan/col-definite-size/扩展填满类（R177 谱系 line1675
  load-bearing）。

★ yield 预估：013 + max-013 + 014 + max-014 = 最多 4 self-source PASS（若 4 案同机制）。
  但修复复杂度（列宽重分配）+ 回归风险高于类 A，ROI 中等。

──────────────────────────────────────────────────────────────────────────────
【类 C】008 / max-008 — min/max-width on display:inline  ⚠ 非 min-width bug
──────────────────────────────────────────────────────────────────────────────
测试结构：
  div { background-color:red; color:green; display:inline; font:100px/1 Ahem;
        min-width:200px }
  <div>A</div>
  assert：min-width does NOT apply to inline → 绿色 "A"（Ahem 100px）保持自然内联宽
  ref：filled green 100px square，no red

★ 根因（实证 grep）：ZeroWeb 的 inline/IFC 路径【从不读取 min_width/max_width】——
  grep `min_width|max_width` 全 crates/layout-engine/src/inline.rs + inline/ = 空；
  engine.rs inline 路径也无 min_width 应用。即 ZeroWeb 已正确【忽略】inline 的 min-width
  （符合规范）。→ 008 的失败【不是 min-width 应用错误】。

★ 推测真因（fontdue 度量，已 ruled-out 家族）：
  div 的 background-color:red 应被绿色 Ahem "A" 字形完全覆盖（Ahem 字形填满 em-box）→
  "no red" 通过。若 fontdue 光栅化的 "A" 字形【不填满 100px em-box】（典型 fontdue vs
  Skia 字形度量差异，welcome ~17% 残余同源，R174/R229 字体攻坚已停），则红色背景从字形
  边缘外露 → 红 → FAIL。这与 min/max-width 无关，属【fontdue 字形度量】已 ruled-out 家族
  （advance-width R225 / AA R174 / Bold R229 三谱系均实证死路）。

★ 建议（hand to code agent）：【勿以 min-width 为入口修 008】。先用
  reftest-upstream min-width-applies-to-008 单案 PIL dump 确认红色位置——若红在字形边缘外
  露 = fontdue 度量（defer，同字体攻坚停止）；若红在别处 = 独立 inline 背景/行盒 bug。
  ★ 当前判断：008 大概率非 clean lever（font-metric），列为最低优先 / 验证后关闭。
