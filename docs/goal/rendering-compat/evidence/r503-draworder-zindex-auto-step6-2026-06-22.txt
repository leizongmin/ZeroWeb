背景
================================================================================
承接 R502：abspos `<img>` 图元正确生成+绘制，但在生产 render_draw_order 路径中
被其后绘图元整片覆写（abspos positioned descendant 在 draw_order 中位置过早）。
R502 指出「draw_order 覆写」是 R501 presentational-hints ZERO-YIELD 的阻塞之一。

兄弟覆写（违反 CSS 2.1 Appendix E step 6：positioned descendants 应晚于 normal
flow steps 3-5 绘制）。

================================================================================
static-inside-inline 回归机制（已知 tracked gap，非 fix 缺陷）
================================================================================
static-inside-inline-001 结构：
  <body>
    <div id="red"></div>           <!-- abspos red，body 的较早子节点 -->
    <div id="wrapper">              <!-- in-flow，body 的较晚子节点 -->
      <span id="inline"><div id="abspos"></div>X</span>  <!-- 嵌套 abspos green -->
    </div>
  </body>

期望（Appendix E step 6）：#red 与 #abspos 同属 body SC 的 positioned
descendants，按 tree order 绘制 → #red（较早）先、#abspos green（较晚）覆之 → 无红。

painter 为 per-node 递归（ordered_child_indices 排每个节点的直接子节点）。body 层
排序：#wrapper(1,0 in-flow) → #red(3,0 positioned) → 即先绘 #wrapper 整棵子树
（含 #abspos green），再绘 #red → #red 覆 green → 红可见 → FAIL。

根因 = per-node 排序无法实现 step 6 的**全局** tree-order 收集。旧值 (1,0) 让
positioned 与 in-flow 同级交错（嵌套 positioned tree-order 偶然正确，但 positioned
会被其后的 in-flow 兄弟覆写，abspos-016 等错）；新值 (3,0) 修正后者但破坏前者。
两个模式在 per-node 排序下不可兼得。

★ 正确修复 = 全局 positioned-descendant 延迟（per-stacking-context 收集所有
z-index:auto positioned 后代，normal flow 之后按 tree order 统一绘制）。
painter 已有局部先例：`defer_abspos`（mod.rs:535-542）对非 positioned overflow
元素延迟 abspos/fixed 子元素到裁剪之后。通用化 = 多会话架构项，记为 R503 follow-up。
届时 static-inside-inline-001/003 自然恢复 PASS（全局收集保留 tree order）。
