结论 1：advance-width 非 morning cascade 根因（R374 推断证伪）
================================================================
若 cascade 是 advance-width，精确 advance 应改善 morning。实测反而 +2.7pp 退步 → cascade
**非 advance-width**。R374 的「换行级联 = advance-width」推断**错误**，已纠正。

================================================================
结论 2：morning cascade 是**字体不匹配**（非 advance 计算错误）
================================================================
机制：morning 用 `font-family: system-ui`（chromium 用 OS 系统 UI 字体，如 Linux 的
Sans/Firefox Sans）。ZeroWeb fontdue 用**捆绑字体**（非 OS system-ui）。DejaVu 表是第三种
字体的度量。三者（crude 0.55 启发式 / DejaVu 表 / chromium 实际 system-ui）中：
  - crude 0.55「所有字母等宽」**碰巧接近 system-ui 的平均字宽** → morning 16.41%
  - DejaVu per-char 表与 system-ui 的 per-char 分布**不同** → 换行点偏离 system-ui 更多 → 19.14%
即 advance-width 改善须用**chromium 实际字体的 advance**（OS system-ui），而 ZeroWeb 无该字体
（fontdue 捆绑字体≠system-ui）。故 advance-width 在当前字体栈下**不可修**——是字体加载/匹配
问题（须加载与 chromium 相同的 system-ui 字体），非 advance 计算问题。

================================================================
结论 3：advance-width lever DC-14 终局关闭（强化 R225）
================================================================
R225「reftest-oracle 26 case 零变化」+ 本轮「morning DC-13 +2.7pp 退步」= advance-width
bilateral 改善在 DC-14 真值上对 Ahem（reftest）零变化、对非 Ahem（morning）负向。**R224 回退
非 false-revert**——accurate advance 确实不帮助（与 R209 不同，R209 是 self-source 假阴性而
chromium-Oracle 真改善；advance-width 是 chromium-Oracle 真退步）。**advance-width lever
DC-14 终局关闭，勿再以任何变体（静态表/FontLoader/shaper 接线）重试**——根因是字体不匹配，
非 advance 计算。

================================================================
启示：morning cascade 下一步方向（非 advance-width）
================================================================
morning 16.41% cascade 既非 advance-width，则候选 = **line-height**（fontdue line metric≠
Skia）或 **glyph 渲染**（fontdue AA/度量≠Skia，DC-14 line 311 说 AA 基本一致，但 line metric
可能差）。二者均 fontdue vs Skia 字体层差异，非布局 bug，须字体光栅器升级（多会话/架构）。
**勿再以 morning cascade 为单会话 layout 杠杆**——已证非 advance-width，剩余是字体层。
