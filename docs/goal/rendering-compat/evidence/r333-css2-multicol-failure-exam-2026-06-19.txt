审视结果（5 用例，逐项定位根因）
--------------------------------
1. **border-bottom-width-006 (2.86%)**：`display:inline-block; width:1in; border-bottom:96px; height:0`。
   ZeroWeb 把该 inline-block（border-bottom 填满 0 内容盒）定位比 REF 的 `<img height=96>` 高 ~13px。
   根因 = inline-block 基线/vertical-align 对「height:0 + 厚 border-bottom」盒的基线计算与替换元素
   （img baseline）不一致。属 **inline-box 模型 / vertical-align**（master.md 已标 P1 结构性，
   与 Phase A IFC 耦合）。非单点。

2. **border-padding-bleed-001 (2.40%)**：inline `<span>` 的 border-top/padding-top 应绘制覆盖上一行盒
   （CSS 2.1 §10.8.1 inline 元素 padding/border 不影响行高但需绘制）。属 **inline-box 行盒绘制**，
   同 inline-box 结构簇。

3. **clear-float-003 (3.20%)**【新发现】：`clear:right; margin-top:-1in` + 兄弟 `margin-bottom:1in`。
   REF 期望 div4(green) 在 y=131（clearance + margin 折叠后），ZeroWeb 渲染在 y=51（覆盖 div2，
   80px 过高）。**根因**：grep 确认 ZeroWeb 把 `clear` 仅 `convert_clear→bool` 传 taffy 0.7，
   **无 ZeroWeb 侧 clearance 后处理**。clearance + margin-collapse 交互是 taffy 0.7 能力范围——
   **clear+margin 类用例 = taffy-0.7-bound**（同 R304 DEFER 升级；R323 margin 折叠探针覆盖基本折叠
   但不含 clearance）。新增 ruled-out 表条目。

4. **multicol-count-computed-003 (1.78%) / -004 (2.00%)**：column-count/width 伪算法。代码核查
   `compute_column_info`（multicol.rs:131）+ `compute_single_column_width`——**列数/列宽计算 spec-正确**
   （-003 column-count:3 → N=3, W=(13em-2×5em)/3=1em 计算无误）。REF 用手摆 swatch 图像编码期望几何；
   ZeroWeb 实算列几何正确，divergence 在**列内容分布 / column-rule 定位 / multicol 背景跨列绘制**
   （diff: TEST 黄背景区 vs REF 白区）= multicol 渲染结构性（同 R113/R131/R319 死锁）。

裁决
----
5 用例**全部结构性**：
- inline-box 模型（border-bottom-width-006, border-padding-bleed）= 与 Phase A IFC 耦合的 P1 结构簇；
- clear+margin（clear-float-003）= **taffy-0.7-bound**（新发现，ZeroWeb 无 clearance 后处理）；
- multicol 列几何（count-computed-003/004）= 计算正确，divergence 在内容分布/规则定位（multicol 结构死锁）。

DC-11 correctness 轴（R323 margin / R324 fixed / R325 img-aspect / R326 sticky）确已**穷尽**——
剩余 CSS2/multicol 失败全结构性，无可单点修的真实 bug。与 R305-R332 plateau 框架一致。
