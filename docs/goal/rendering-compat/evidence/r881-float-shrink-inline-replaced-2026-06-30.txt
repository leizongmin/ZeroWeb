R881 — float shrink-to-fit 纳入 inline-level replaced 子元素（CSS §10.3.5）
=========================================================================
日期: 2026-06-30
谱系: R129/R180 float/inline-block shrink-to-fit 谱系（R180 教训「inline 级求和 + block 级取最大」的 float 补全）。
有 net 源码: ✅ float_positioning.rs adjust_float_positions_with_context shrink 过滤器 + 1 单测。

测试
----
css/CSS2/normal-flow/max-width-110.xht (15.08% diff):
  div { background-color: red; float: left; }
  img { height: auto; max-width: 100px; vertical-align: bottom; width: auto; }
  <div><img src="support/green200x200.png" /></div>
  期望：200×200 img 受 max-width:100px 约束为 100×100（保比）；div{float:left}
  shrink-to-fit 包裹 img（100×100），green img 完全覆盖 div 红 bg → 无红外露。
  ZW 修复前：div 撑满 784px 满宽（w=784），img 100×100 在左侧 → 右侧 684×100=68400px 红外露。

根因（R881 LAYOUT_DUMP + 代码审查实证）
---------------------------------------
`adjust_float_positions_with_context` 的 float shrink-to-fit（float_positioning.rs:339-361）
只考虑 `is_block_level` 子元素（filter line 343），而 img 是 **inline-level replaced**
（`is_block_level=false`）。故 `div{float:left}` 仅含 `<img>` 时 content_child_widths 为空
→ `if !content_child_widths.is_empty()`（line 353）为 false → 跳过 shrink → div 保持
taffy 满宽 784。

这与 R180 inline-block shrink 教训一致（「content 宽须 inline 级求和 + block 级取最大」），
但 float shrink 漏了 inline 级。replaced 元素（img）已有确定 used 宽度（100，含 max-width
约束），无需 IFC 测量即可纳入 shrink。

修复
----
float_positioning.rs float shrink 过滤器：
  `.filter(|c| ... && c.is_block_level)`  →  `.filter(|c| ... && (c.is_block_level || c.is_replaced))`
变量 `block_child_widths` → `content_child_widths`，注释更新。
纯加性（仅多纳入 inline-level replaced，原有 block-level 行为不变）。
