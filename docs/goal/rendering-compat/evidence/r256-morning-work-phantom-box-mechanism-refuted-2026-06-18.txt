# morning-work 幻影盒机制【自我纠正 R255】：代码路径否定「盒属性泄漏到幻影盒」（R256）

**日期**: 2026-06-18
**目标**: 只读代码路径核实 R255「`.article{min-height:200;margin:4em}` 盒属性泄漏到 block 兄弟间
幻影/匿名盒」机制是否成立。
**结果**: **机制被否定**——build_subtree 对 block 容器不生成任何幻影/匿名盒；converter 的
min_height/margin 映射正确。R255 的 328=200+64+64 算术**相关性真实但无因果机制解释**，且 R253
的 dump 是**人为筛选的 6 行摘要**（非原始递归 dump），「幻影嵌套 article w=4 h=200」可能为摘要
伪影。本轮把 R255 的机制从「假设」降级为「未解释的相关性，须原始递归 dump 定性」。
**方法**: 纯 read-only 源码阅读（tree.rs build_subtree + inline_block_split.rs + converter/mod.rs），
不改源码、不跑渲染（工作树有并行 agent 未提交 style-system/src/lib.rs，脏树不宜出运行时证据）。

## 1. build_subtree 对 block 容器不生成幻影/匿名盒（决定性）

`<article class="article">` 是 `display:block` 容器，子元素为 block-level（h2/p/h3）+ 空白文本。
build_subtree（crates/layout-engine/src/tree.rs:362）路径：

- **R109 匿名块拆分不触发**（tree.rs:546）：`r109_segments` 仅当 `r109_wired() &&
  inline_has_block_child(...)` 才计算。`inline_has_block_child`（inline_block_split.rs:54-70）首条
  即要求 `styles[dom_id].display == Inline`——**article 是 Block → 返回 false → r109_segments=None**。
  故 tree.rs:553 `if let Some(segments)` 走 `else`（618），不进入 559-591 的匿名块生成。
- **非 flex/grid 容器只收 Element 子节点**（tree.rs:618-627 else 分支）：`children_with_order`
  循环里 `child_data.is_some_and(|n| matches!(&n.kind, NodeKind::Element(_)))`（623 行）——
  **文本/空白节点被显式跳过**（正确 CSS 行为：block 容器里 block 兄弟间的空白不生成盒）。
- **每个 element 子节点递归建一个 taffy 节点**（632-644 build_subtree），article 自己一个节点（654
  new_with_children + 660 node_map.insert(dom_id, taffy_id) 一对一）。无第二个带 article.node_id 的盒。

→ **article 的 block 子树里不存在 build_subtree 生成的幻影/匿名/重复盒**。R255 设想的
「inter-block 空白文本节点被包成匿名块且错误套用 .article 规则」**不成立**（空白在 623 被跳过，
匿名块只在 flex/grid 或 R109-inline-split 路径生成，二者 article 都不走）。

## 2. converter 的 min_height / margin 映射正确（排除误转）

converter/mod.rs:77-88：`size.height`←`style.height`、`min_size.height`←`style.min_height`（83）、
`max_size.height`←`style.max_height`、margin top/bottom←`margin_top/bottom`（96-97）。即
`.article{min-height:200;margin:4em 0}` 正确变成 taffy 的 min_size.height=200 + margin=64/64，
**只作用于 article 这一个节点**。taffy 让 article ≥200px 高，不影响子节点间距。
→ 328px 间隙**不是** min-height/margin 被错转到子节点/幻影盒。

## 3. R255 算术相关性：真实但无机制，且依赖人为筛选摘要

R255 的 328=200+64+64 与 R253 dump 摘要 4/5 间隙吻合是**统计上不像纯巧合**的相关性，但：

- **代码路径分析否定了我提出的全部 3 个因果子机制**（inter-block 空白→匿名块 / 幻影盒被赋 .article
  身份 / 选择器过匹配）——见 §1。
- **R253 的 dump 是人为筛选的 6 行序列**（"article 子元素序列"），**非原始递归 LAYOUT_DUMP**
  （reftest.rs:1033 的 dump 对每个盒按深度缩进打印 node_id/abs_y/h/mt/pt/x/w/dmt）。筛选摘要可能：
  (a) 跳过了 h2↔p 之间的中间层盒（abs_y 差并非真"间隙"而是跨层）；(b) 把某盒误标为"article.article"。
- **dump 标签语义**（reftest.rs:1043-1047）：`b.node_id → DOM labels`，缺 node_id 才标 `(anon)`。
  build_subtree 对每个 dom_id 只建一个 taffy 节点（660 一对一）→ 不应有第二个带 article.node_id
  的盒。故 R253「幻影嵌套 article w=4 h=200」若真实，必来自 build_subtree 之外（extract_layout /
  engine.rs post-pass），但目前无证据；更可能是摘要伪影。

→ R255 机制**降级**：从「`.article` 盒属性泄漏到幻影盒（R109 谱系）」→「未解释的相关性 +
可能摘要伪影，须原始 dump 定性」。**勿据 R255 机制去改 build_subtree / converter / R109**（无对应缺陷）。
