R662 — DC-13 line 321 zero-webview 直接渲染路径对比（产品层 ↔ WebView 层不互相掩盖）
日期：2026-06-26 | 类型：DC-13 line 321 交付（+ 新增 --via-webview product-smoke 模式）

================================================================================
0. 目标与裁决
================================================================================
DC-13 line 321：「同一输入通过 zero-webview 直接渲染路径截图，并与 Chromium 参考截图对比，
避免产品层和 WebView 层互相掩盖问题」。此前 product-smoke 只走 engine-direct 路径
（`reftest::render_to_framebuffer_with_base` → `RenderPipeline::render_html`），未覆盖
WebView 嵌入边界（`WebView::load_html`，含其内部 image/font/security 处理）。

★ 裁决：**WebView 嵌入层对自包含页渲染 byte-identical 于 engine-direct 路径**——
welcome.html 经 WebView 路径 vs engine-direct 路径 **diff 0.00%（0 px）**，两侧 vs Chromium
均为 16.16%（同字体墙）。证明产品层与 WebView 层**不互相掩盖**，DC-13 line 321 满足。

================================================================================
1. 实现（新增 --via-webview product-smoke 模式，可复用）
================================================================================
- `tests/wpt-runner/Cargo.toml`：加 `zero-webview = { workspace = true }` 依赖。
- `tests/wpt-runner/src/reftest.rs`：新增 `render_via_webview_to_framebuffer(html, config)`——
  建 `WebView`（WebViewConfig width/height）→ `load_html(html, None)` 走嵌入边界产出
  `RenderPrimitives` → 用与 product-smoke 同源的 `create_font_loader()` + `GlyphCache` +
  `render_full_scene` 光栅化（font_id 0 = default 在两侧对齐）。
- `tests/wpt-runner/src/main.rs`：product-smoke 加 `--via-webview` flag，置位时走 webview 路径。
- **范围**：仅自包含 fixture（无外链 CSS/`<img>`），因 `load_html` 不做 base_dir 解析
  （外链资源走 `fetch_url` HTTP 路径，非本轮范围）。welcome.html 即自包含（仅 favicon data-URI）。

================================================================================
2. 验证结果（welcome.html，800×600）
================================================================================
路径                       vs Chromium oracle    vs engine-direct
engine-direct（默认）        16.16%（77588 px）   —
via-webview（--via-webview） 16.16%（77588 px）   0.00%（0 px）★ byte-identical

- WebView 路径 vs Chromium = 16.16% = 与 engine-direct 完全相同 = 同一字体墙（fontdue 行度量）。
- WebView vs engine-direct = **0 px 差异**：WebView 嵌入边界（load_html 经其内部 RenderPipeline
  + font_resolver + 安全上下文）对自包含页**透明**，不引入也不掩盖任何渲染差异。
- 证据 PNG：`evidence/product-static/welcome-zeroweb-via-webview.png`。

================================================================================
3. 结论
================================================================================
- DC-13 line 321 满足：产品层（ZeroBrowser 走 WebView 图元消费 DC-10）与 WebView 层
  （WebView::load_html 嵌入边界）对自包含页渲染一致，无互相掩盖。残余 16.16% 仍是字体墙
  （R633 Phase A），非层间掩盖问题。
- 新增 `--via-webview` 模式可复用于未来任何自包含 fixture 的 WebView 层回归校验。
- make test 全绿（仅 zero-wpt-runner 加 webview 依赖 + 新增函数/flag，零既有行为变更）。
