# R490 — border-width medium 派生尝试（CSS §8.5.1）+ 回退；精度上限致 metric-negative

**日期**: 2026-06-22
**前置**: R489 把伪元素盒属性 border 不渲染归因「inline-element border 缺口」；本轮深挖发现**真根因 = border-width medium 派生缺失**（CSS §8.5.1：border-width 初始值 = medium 3px，ZeroWeb 默认 0 且无派生 → border-style:solid 未显式指定 width 时渲染 0）。

---

## 1. 真根因：border-width medium 派生缺失（CSS §8.5.1）

`computed.rs:282-307` 仅有「border-style:none/hidden → width=0」规则，**无反向派生**：border-style≠none 且 width 未显式指定时，应按初始值 medium（3px）渲染，但 ZeroWeb 默认 `border_*_width = Px(0.0)`（default_impl.rs:45）→ 渲染 0。实证 `after-inheritable-002`（`div:after{border-color:orange;border-style:solid;content:'PASS PASS'}`，无 width）：伪元素 border-width=0 → 橙边框缺失（chromium 按 medium=3px 渲染）。**这是 R489「盒属性 border 不渲染」的真根因，非 inline-element 缺口。**

## 2. 两条修复路径均不可行

### 路径 A（default=medium）：旁路路径回归
default border-width 0→Px(3.0)。**回退原因**：3 个 `cross_crate_pipeline::incremental_layout` 测试预构 `ComputedStyle`（不经 `resolve_computed_style`）→ 默认 3px 直达 converter → 元素 +6px（border 3+3）→ 断言失败（`高度应更新为 100px` 实得 106）。make test 7 fail（3 incremental + 其他）。任何不经 resolve 的旁路路径会渲染伪 3px 边框。

### 路径 B（resolve else-branch）：border:0-solid 回归
resolve 中 `style≠none && width==Px(0) → medium`。**不可行**：无法区分「未指定 0」与「显式 0」。CSS2 有 `border:0 solid`/`border-width:0;border-style:solid` 用例（inherit-border-padding-000、margin-collapse-028、c5515-brdr-w-002、border-width-009），显式 0 会被误派生为 medium。

### 路径 C（Auto 哨兵，本轮实现）：CSS-correct 但 metric-negative
default border-width → `LengthValue::Auto`（border-width 不接受 auto，作「未指定」哨兵）；`resolve_length_field` 保留 Auto（computed.rs:366）；resolve 增 `else if width==Auto → Px(3.0)`（style≠none 时）；converter `Auto→0`（converter/mod.rs:425，旁路路径安全）。**make test 12286/0 零 Rust 回归**（3 incremental 测试恢复，因 converter Auto→0）。

## 3. 实证：Auto 哨兵修复 borders chr<1% **−3（metric-negative）** → 回退

re-dump borders 子目录（506 案，REFTEST_DUMP=1 REFTEST_DUMP_PASS=1，test-guard 包裹）+ cross-validate：

| 指标 | BEFORE（R484） | AFTER（Auto 哨兵） |
|------|---------------|-------------------|
| borders chr<1% | 368/506 = 72.7% | **365/506 = 72.1%（−3）** |

**逐案**（join base/now）：**27 improved / 39 regressed**（净负）。模式：
- 改善：`border-left/right-width-001..078` 0.89→0.77（水平 border，幅宽变化小）。
- 恶化：`border-top/bottom-width-012..078` 2.47→3.33（**垂直 border 系统性 +0.86**，medium 3px 上下 border 改变元素高度→布局位移）；`border-width-009` 0.62→**1.70（pass→fail 跨阈值）**；`border-conflict-style-101-106` 0.65→0.99。

**裁决回退**：medium 派生 **CSS-correct**（border-width 初始 = medium），但渲染的 medium 边框**像素精度/布局位移未达 chromium**（垂直 border 改高度致更多案位移）→ 27 改善抵不过 39 恶化，net −3。同 near-miss 簇精度天花板（R174/R471 fontdue/IFC），非 medium 派生本身错。按 rally 反回归纪律（不 ship metric-negative，如 R125/R205/R229b）**回退**。`git checkout HEAD -- 4 files` 恢复 R489（default=Px(0.0)、无 medium 派生）。

## 4. 结论：伪元素盒属性 border 线 exhausted（精度天花板）

R485-R490（6 轮）伪元素工作总结：
- **::before/::after 文本内容渲染：完成+正确**（94.5% 纯文本伪元素经 IFC 渲染 color/font/inline；R486 parser+matcher、R487 compute+layout）。
- **盒属性 border：exhausted**。根因链：伪元素盒属性 border → 需元素注入（R489 hybrid）→ border 不渲染因 width=0（**medium 派生缺失**，CSS §8.5.1）→ medium 派生修复 CSS-correct 但 metric-negative（borders −3，精度/布局位移天花板）。**三条修复路径均不可行**（A 旁路回归、B border:0-solid 回归、C metric-negative）。
- **行定位精度**：全局 fontdue/IFC plateau（R488）。

**伪元素 chr<1% 提升的真实阻塞 = 渲染精度天花板**（fontdue 度量 + IFC 行定位 + border 像素精度），非伪元素特性逻辑缺陷。R487 文本内容渲染是有效交付（content 从 0 green pixels 到渲染）；盒属性 border 与精度须等 Phase-A/度量攻坚。
