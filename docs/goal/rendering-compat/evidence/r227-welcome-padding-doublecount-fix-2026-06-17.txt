# welcome.html 36px 顶部偏移根因与修复（R227）

**日期**: 2026-06-17
**目的**: R226 把 welcome 28% diff 定位到「页面顶部 36px 垂直偏移」后，dump 盒几何定位确切根因并修复。
**结果**: welcome product-smoke diff **28.34% → 17.06%**（-11.28pp），reftest **439/490 → 438/490**（净 -1，唯一回归为 borderline grid intrinsic-sizing）。

## 根因（确证）

taffy 0.7 的 `Layout::location`（即 ZeroWeb `LayoutBox.x/y`）是子节点 **border box 相对父 border box** 的偏移，
**已包含父 padding+border**。taffy 自身的 helper 印证（`crates/taffy-local/src/tree/layout.rs:314-322`）：

```rust
/// Get y offset of the node's content box relative to it's parent's border box
pub fn content_box_y(&self) -> f32 {
    self.location.y + self.border.top + self.padding.top  // ← location 是 border-box 相对
}
```

taffy-local block 计算中首个子节点 `location.y = content_box_inset.top`（`compute/block.rs:404,486`），
即首个子节点 location 已包含父 padding+border。

但 ZeroWeb 的绘制层（painter `paint_node`/`paint_node_in_rect`）与 inline IFC、abspos 线程一致采用
「子节点坐标相对父**内容盒**」的约定（painter 在 `child_offset` 上叠加 `padding+border`）。
于是 taffy 定位的块级/inline-block 子节点被**重复计入**父 padding+border：每个带 padding/border 的父容器
都把整棵子树整体下移/右移一份。

welcome.html 的 36px 偏移 = `.page` padding-top(20) + `.hero` padding-top(16)，两级都重复计入：
- LAYOUT_DUMP 实测（修复前）：`div.page abs_y=0 pt=20 → header.hero abs_y=40（应 20）→ div.hero-accent abs_y=72（应 36）`。
- hero.y=20（=page padding-top）、hero-accent.y=16（=hero padding-top）——两级各多算一份 padding。

## 为何 reftest 自源长期未暴露

自源 reftest 由 ZeroWeb 渲染 test 与 ref（同源），重复计入对两者一致 → 互相抵消 → 自源「通过」。
这与 DC-14「自源 46.5% 假通过」一致：该 bug 对 chromium Oracle（独立基准）才显现（welcome 28%）。

## 修复

在 `extract_layout`（`crates/layout-engine/src/engine.rs`）递归提取子节点后，对**水平书写模式**下、
**非 abspos/fixed** 的 taffy 子节点，把其 border-box 相对坐标换算为内容盒相对坐标（减去自身 `content_x/y`）：

```rust
if matches!(own_writing_mode, WritingModeValue::HorizontalTb) {
    for child in &mut children_boxes {
        if child.is_absolute || child.is_fixed { continue; }  // abspos 由 adjust_absolute_* 线程单独处理
        child.x -= content_x;
        child.y -= content_y;
    }
}
```

设计要点：
- **水平书写模式限定**：垂直模式轴交换路径另算，避免回归（与 declared_margin_top 同守卫模式）。
- **abspos/fixed 跳过**：abspos 由 `adjust_absolute_pct_to_viewport`/`adjust_absolute_to_initial_containing_block`
  线程按 border-box 相对约定单独处理，其坐标语义与绘制层双计补偿自洽；跳过保持既有行为（css-position 16/16 持平）。
- **float 无害**：`adjust_float_positions_with_context` 后处理会覆写浮动子节点位置，换算被覆盖。
- **inline IFC 子节点不受影响**：IFC 定位的 inline 内容不经 extract 的 taffy 子节点循环，本就内容盒相对。
- 修复后 LAYOUT_DUMP（painter 实际输出）：hero-accent 渲染于 **y=36**（与 chromium 一致）。

## 方案对比（为何选 extract 而非 painter）

最初尝试改 painter `child_offset` 不叠加 padding（Option A），welcome 同样修复（17.06%），
但导致 **-5** reftest 回归（4 multicol-clip/containing/columns-invalid + grid-flex-spanning）：
这些 case 的 **ref 用 inline 子节点**（IFC 定位，内容盒相对），painter 全局去掉 padding 会把 inline 子节点也左移父 border 宽度 → ref 错位。

Option B（extract 换算，painter 不动）只改 taffy 定位的块级/inline-block 子节点，inline 子节点不动 →
multicol ref 不受影响，回归从 -5 降到 -1。最终采用 Option B。

## 唯一回归：grid-flex-spanning-items-001（borderline，0.77% → 1.31%）

- 容器 `border:10px fuchsia`，grid `width:min-content`，#item 跨 2 列含 300px aqua filler；ref 为 30px holder + 300px aqua（溢出）。
- 修复**正确化**了 test 的 aqua 位置：aqua 从 x=28（旧，双计）移到 x=18（=content box 左，与 ref 一致）。
- 旧 0.77% pass 来自「aqua 错位(右偏 10px)」与「grid-vs-ref border 尺寸差」两误差部分抵消；修复消除 aqua 误差后，
  剩余的 border 尺寸差（grid min-content ≈320px vs ref 30px holder，本测试固有）不再被抵消 → 1.31%。
- 属 self-source borderline（DC-14 不可靠）；aqua 现已正确，剩余 diff 是测试固有的容器尺寸差。
