## table-grid-item-dynamic-004（500px 显式宽 table，隔离 HEIGHT）
结构: div{display:grid;height:100px} > table{padding-top:100px;height:100%;box-sizing:content-box}

| 渲染端        | table yellow bbox        | 说明                                   |
|---------------|--------------------------|----------------------------------------|
| ZeroWeb 修复前 | 500×116 (x[0,499] y[0,115]) | intrinsic(~16 内容)+100 padding，height 被忽略 |
| ZeroWeb 修复后 | 500×200 (x[0,499] y[0,199]) | height:100%×100=100 内容 + 100 padding  |
| Chromium      | 500×222 (x[0,499] y[0,221]) | 100 内容 + 100 padding + ~22 行高细节   |

chromium 一致率（max channel diff>5 像素比）: 11.12% → **2.98%**（< 5% 布局阈值 → chromium Oracle 实际通过）。
剩余 2.98% = chromium intrinsic 行高 ~122 vs ZW ~100（cell padding/border-spacing 细节，独立小差异）。

## table-grid-item-dynamic-003（width:auto table，HEIGHT + WIDTH 双差异）
修复后: ZW table 327×200（width shrink-to-fit 327）；chromium 800×222（width 拉伸到 grid 轨道）。
→ 003 的主导差异是 table 作为 grid item 的「宽度 shrink-to-fit vs grid-stretch」，与 height 修复独立。
   需 grid-item-table 拉伸单独处理（grid item width:auto 应拉伸到 track，但 table shrink-to-fit 覆盖）。

## 严谨禁用对照（确认修复是 004 改善唯一原因）
临时把 clamp 增长条件改为 `false`（禁用修复）→ 004 table 回到 500×116（unfixed）。
启用 → 500×200。排除巧合。
