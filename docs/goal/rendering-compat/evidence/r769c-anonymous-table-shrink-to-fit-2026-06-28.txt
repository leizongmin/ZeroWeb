直接对比定位（product-smoke + PIL 探针）
================================================================================
测试结构：
  <div style="display:table; height:100px; background:red;">
    <div style="display:table-row; background:green;">
      <div style="width:100px; margin:50px 0;"><div style="margin:50px 0;"></div></div>
      <div style="margin:50px 0;"></div>
    ...（正规 table-row，行内 cell 是匿名 block，§17.2.1）

ZeroWeb 渲染（修前）：绿色 784×100（满宽），ref 是 100×100 绿方块 → 表未 shrink-to-fit。

ZW_TBLDBG 诊断探针（cell_used_width）实证列宽计算正确：
  col_start=0 cell_box.width=100 style.width=Px(100) -> w=100
  col_start=1 cell_box.width=784 style.width=Auto -> w=9.6
  col 和 ≈ 109.6（正确）
故问题不在 compute_cell_intrinsic_width / cell_used_width，而在表宽→行宽传递。

================================================================================
真根因（table.rs position_cells line 1702）
================================================================================
  let table_content_width = table_box.content_width;   // 784（taffy 对 auto 表拉伸到容器）

position_cells line 1857: `row_box.width = table_content_width`（784），早于 line 2010
apply_table_size_constraints 收缩表盒到 col 和（~110）。后果：行（绿背景）保持 784
宽，而表盒收缩到 ~110 → 渲染看到 784 宽绿行。

================================================================================
修复（table.rs position_cells，+9 行）
================================================================================
  let col_sum: f32 = col_widths.iter().sum();
  let spacing_total_x = if col_widths.len() > 1 {
      (col_widths.len() - 1) as f32 * spacing_x
  } else { 0.0 };
  let table_content_width = table_box.content_width.min(col_sum + spacing_total_x);

auto-width 表：min(784, 110) = 110 → 行用收缩值。
explicit-width 表：compute_column_widths 已把 col 扩展到 explicit（has_explicit_width
触发扩展填满），col 和 ≈ content_width → min 取 content_width，无变化。
