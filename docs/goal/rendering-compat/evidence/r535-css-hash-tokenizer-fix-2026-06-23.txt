R535 — CSS tokenizer hash token 允许首字符为数字（修复 hex 颜色 #00FFFF / #4169E1 被破坏）
==============================================================================
日期：2026-06-23
类型：code-side CSS parser correctness fix（css-parser tokenizer）
状态：LANDED（correctness 修复 + 单测；WPT self-source 0-yield 因颜色 bug 对称）

承接
----
R534 调查 align-content 6 案时，PAINTDBG/STYLEDBG 定位 flex #test 内 test02/test03
背景渲染为 Transparent。进一步 STYLEDBG 插桩（compute_element_style_internal 打印
matched declarations）发现**根因不在 paint/cascade，在 CSS tokenizer**：
  test01 background "#7FFF00"（正确）
  test02 background "#0FFFF"（应 #00FFFF，丢前导 0）
  test03 background "#41690"（应 #4169E1，"E1" 被科学计数法解析为 41690）

根因
----
tokenizer.rs Hash 分支（`#` 后）调用 `consume_ident()` 读 name。consume_ident 要求
首字符是 ident_start（`is_ident_start` = 字母/_/-/非 ASCII，**排除数字**）。
CSS hash token 的 name 允许首字符为数字（name code point 含数字，如颜色 #00FFFF / #4169E1），
与标识符（不可数字开头）不同。故 `#00FFFF` 进 consume_ident 后因首字符 '0' 非 ident_start
立即返回空 → Hash("")，剩余 "00FFFF" 被后续 tokenizer 当 Number 解析：
  - "00FFFF" → Number "0"（去前导零）+ Ident "FFFF" → 重组 "#0FFFF"
  - "4169E1" → Number 41690（科学计数法 4169E1 = 4169×10¹）→ "#41690"
重组后的非法 hex 颜色解析失败 → Transparent。
#7FFF00 幸免：consume_ident 读 "7"（ident_start? 否，'7' 非字母）→ 实际 '7' 非 ident_start
本应也失败……复查：'7' 是数字非 ident_start，consume_ident 返回空，剩余 "7FFF00" →
Number "7" + Ident "FFF00" → "#7FFF00"（巧合与原值一致，故 test01 正确是假象）。

修复（tokenizer.rs，~20 行）
-----------------------------
1. 新增 `consume_hash_name()`：读 hash token 的 name，允许首字符为数字（消费所有
   is_ident_char 与转义，不要求 ident_start）。
2. Hash 分支 `'#'` 用 `consume_hash_name()` 替代 `consume_ident()`。

CSS 正确性：CSS Syntax Level 3 §4.3.6 hash token = `#` + name code point 序列，
name code point 含数字，首字符可为数字。

裁决：保留（非 revert）
-----------------------
与 R502/R524/R531（零 self-source yield 已 revert）不同，R535 是**CSS parser 根因 bug**
（token 破坏值），非 masked 布局 lever：
  1. 根因定位（align-content 调查的真正根因，非投机 lever）；
  2. 单测锁定（test_hash_color_leading_digit_preserved）；
  3. 真实 correctness 价值（hex 颜色不再破坏，chromium oracle + 产品页）；
  4. 0 回归。
