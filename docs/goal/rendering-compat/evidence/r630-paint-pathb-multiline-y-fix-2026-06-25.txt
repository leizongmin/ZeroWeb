================================================================================
根因（确证）
================================================================================

paint Path B（对未存储 inline_layout 的容器重跑 IFC）取 fragments 时：
- preserve_whitespace（pre/pre-wrap/break-spaces）→ all_fragments_with_line_y()（y = run.y + line.y，多行正确分行）
- 其他（white-space normal/nowrap，即 auto-wrap 多行）→ all_fragments()（y = run.y 恒 0，**多行全堆在同一 y**）

`all_fragments()` 返回行内相对 y（注释 text.rs:939 自承「恒 0」），paint 渲染多行时丢掉 line.y →
**layout 算对多行高度，paint 把多行画在同一 y → 用户可见的「文字堆叠看不清」**。

最小用例确证（font-size:16px line-height:1.5，排除 large-font/字体干扰）：
- wrap（width:300 长文本自动换行）：修复前 y 跨度 13px（堆叠）→ 修复后 50px（分行，期望~72px）
- <br> 多行：修复前 14px → 修复后 53px（期望~58px）
- LAYOUT_DUMP: div h=92px（layout 正确多行），paint 堆叠在 16px

welcome 卡片正常（走 stored Path A），触发条件 = 走 Path B 的容器（div 直接含文本 + 宽度限制换行）。
