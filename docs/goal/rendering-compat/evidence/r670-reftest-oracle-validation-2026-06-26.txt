2. ★ false-pass 抓取：table-cell-overflow-explicit-height-001/002（41.53%，2 案同根）
================================================================================
- **self-source**：test==ref（ZW-test blue 116614px ≈ ZW-ref blue 116828px，均渲染 300px blue
  div）→ **self-source PASS（match）**。
- **oracle**：ZW-test 41.53% ≠ chromium（CHR blue 21340px = clipped to 20px）→ **oracle FAIL**。
- **= DC-14 false-pass**（self-source 假通过，oracle 揭真失败）——reftest-oracle 工具**成功抓到
  self-source 漏掉的假通过**，验证 DC-14 anti-false-pass 价值。
- **根因**：`table.rs:1880/1897-1907` **刻意遵循 CSS 2.1 旧行为**（comment：「CSS 2.1 规定
  即使 overflow:hidden，表格单元格仍须增长以包含内容」）→ ZW cell 长到 300px content。
  chromium 用**现代行为**（Mozilla bug 1880550：cell overflow:hidden + explicit height → 裁剪）。
- **历史**：master.md tech-decision 2026-06-08「table cell explicit height 保留」曾尝试修
  （「保持 taffy 计算的原始高度」），但**仅修了 self-source match（假通过），未真修到 chromium
  一致**——taffy 仍把 cell 长到 content 300px。
- **fix 可行性**：overflow_y 可访问（engine.rs:683-691 把 cell style overflow → cell_box.
  overflow_y）；explicit height 可读（s.height LengthValue::Px）。但 fix **entangled**——cell 高度
  finalization（table.rs:1907）与 row-height 分布（table.rs:1780 循环用 content-based cell height）
  chicken-and-egg：clip cell 到 20px 须先于 row-height 计算，否则 row=300px 覆盖。**需多点协调
  （row loop + finalization + clip），非 clean 单点**，defer 为 characterized table-layout 任务。
