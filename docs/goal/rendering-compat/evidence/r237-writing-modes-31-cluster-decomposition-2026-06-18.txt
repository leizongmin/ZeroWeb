【WM-1】abs-pos-non-replaced vrl/vlr —— 14 case，self-fail，Oracle 1.3%–5.3%
  abs-pos-non-replaced-vlr-{003,007,009,013,155,163}（1.28–3.97%）
  abs-pos-non-replaced-vrl-{002,004,006,012,122,130}（1.28–4.60%）
  abs-pos-non-replaced-icb-vrl-{004,008}（5.00–5.28%）
  + abs-pos-vlr-border-001 / abs-pos-vlr-padding-001（均 4.10%）
  · 特性：vertical-rl/lr 下 absolute 定位的 inset 解析。
  · 代码面：crates/layout-engine/src/engine.rs adjust_absolute_to_initial_containing_block
    (:2205) / adjust_absolute_pct_to_viewport (:2263)。R98/R123 在水平模式建立的 abspos
    inset 解析未对 vertical-rl 的 block-flow 方向（块自右向左流）做调整。
  · 非图片 → 无 swatch 缩放噪声；diff 是结构性定位偏移。
  · 评估：**最大且最干净的候选**（14 case 全 self-fail、无图片噪声、单一代码面 abspos 解析）。
    机制待实验确认（疑似 abspos CB origin / block-start 在 vertical-rl 的右起 vs 左起）。

【WM-2】clip-rect vlr/vrl —— 12 case，self-fail，Oracle 0.43%–2.49%
  clip-rect-vlr-{011,013,015,017}（1.67–2.49%）
  clip-rect-vrl-{002,004,006,008,010,012,014,016}（0.43–2.24%）
  · vrl-002/006/008 均恒定 0.52%/0.43%/0.43% → 同源系统性小偏移（单一根因）。
  · 规范锚点（关键）：测试 meta link §7.6 "Purely Physical Mappings"，assert 明确——
    vertical-rl 下 clip: rect(0,50,50,0) 使 **top-left corner** 外不可见。即 clip: rect()
    的 top/right/bottom/left **恒为物理坐标**，不随 writing-mode 轴交换。
  · 代码面：crates/engine/src/paint/painter/mod.rs:678-691 是 style.clip 的**唯一消费点**，
    构造 clip rect 只用物理坐标 (abs_x+l, abs_y+t, r-l, b-t)，不读 writing_mode —— 这本身
    正确（§7.6 物理语义）。故真 gap 不在 clip rect 坐标，而在 **abspos replaced image 盒
    在 vertical-rl 的物理放置**（abs_x/abs_y 或 image box geometry 的轴处理），clip 只是
    把错位的盒子裁出来。
  · ⚠️ 保留：12 例多为 image（pattern-*.png 100×100）+ 小 diff，部分可能被 swatch 缩放
    噪声（master.md 卡点#8）放大，非纯 clip 缺口；clean-win 须实验验证，勿据推断算 +12。

【WM-3】abs-pos-border-offset + abs-pos-replaced-vrl —— 4 case，3 POLLUTED，重 diff
  abs-pos-border-offset-001 POLLUTED 16.10% / -002 POLLUTED 28.10% / -003 self-fail 1.81%
  abs-pos-replaced-vrl-001 POLLUTED 13.13%
  · POLLUTED = 同源「通过」但 chromium 强不一致（同源假通过掩盖的真 bug）。
  · -002 28% 为全 dir 最差；POLLUTED 性质=自渲染 test/ref 同错致同源 0%。
  · 评估：硬骨头（POLLUTED 自洽错配），低优先；属 abspos-in-vertical 的极端 case。

【WM-4】box-offsets-rel-pos vrl/vlr —— 2 case，self-fail，超大 diff
  box-offsets-rel-pos-vrl-004（self 25.50% / Oracle 23.15%）
  box-offsets-rel-pos-vlr-005（self 22.72% / Oracle 4.38%）
  · 测试 help link §7.1 vertical-layout，assert：vertical-rl 下 relpos box offsets（物理）
    相对盒子自身边。
  · 代码面：engine.rs resolve_relative_inset (:1967)。relative inset 在 vertical-rl 的解析。
  · vlr-005 self 22.72% 但 Oracle 仅 4.38% = ZW 离 chromium 近、离自渲染 ref 远（自渲染 ref
    更怪异，同 R164 vrl-004 现象）。
  · 评估：diff 极大但仅 2 case；机制疑似 relpos inset 未对 vertical 做物理化（§7.6 物理语义
    下 top/right/bottom/left 恒物理，relpos 不该轴交换）。
