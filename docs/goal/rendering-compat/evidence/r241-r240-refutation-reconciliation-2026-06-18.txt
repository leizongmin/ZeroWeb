1. R240 错在哪（实证推翻）
────────────────────────────────────────────────────────────────────
R240 据 tree.rs:186 `if tag != "img" { return; }` **推断**：form control 未被当替换元素 → abspos
半替换拉伸缺失 → #6/#10 为 contained 修复目标。

实证（r239 §2 product-smoke A/B，2026-06-18）推翻此推断：
  #6 position-absolute-semi-replaced-stretch-input   ZWt-vs-ZWr=0.00%  ZWt-vs-CHR=23.03%  ZWr-vs-CHR=23.03%
  #14 stretch-grid-item-button-overflow              ZWt-vs-ZWr=0.05%  ZWt-vs-CHR=8.17%  ZWr-vs-CHR=8.15%

关键判据：**ZWt-vs-ZWr=0.00%** = ZeroWeb 把 test（auto-stretch）和 ref（显式 calc(100%-6px)）渲染成
**同一几何**（input 已正确拉伸填满 CB-insets）。test 的 `.abs{width/height:auto;top/right/bottom/left:3px}`
经 ZeroWeb abspos 拉伸 == ref 的 `.abs{width:calc(100%-6px);height:calc(100%-6px)}`。即 ZeroWeb **几何
完全正确**，tree.rs:186 不影响此场景的几何结果。23% chromium 差异 100% 在**控件绘制层**——chromium 画
原生 input widget（按钮边框/内边距/默认字号/UA chrome），ZeroWeb 画 styled box + lime outline。
⇒ **#6/#10/#14 是原生表单控件外观 feature gap，非布局 bug**。改 apply_replaced_element_sizing 对
chromium-diff **零改善**（实证：test==ref 已是 stretch 几何）。

这是 R164/R203 教训再次印证：**架构性/单点修复的推断必须实证，不能据代码推断**。R240 的消歧（通用 abspos
works → form-control-specific）方向对，但「specific = 可修布局缺口」结论错——实为 paint 层 feature gap。
R240 末尾自己加的「R164 教训：可能含 form-control UA 外观差异」已半预见，但未据此降级结论。
