## 2. 镜像原理（vertical-rl static-x 应镜像）

CSS writing-modes：vertical-rl 块流向右→左（block-start=视觉**右**），vertical-lr 块流向左→右
（block-start=视觉**左**）。abspos all-inset-auto 的静态位置 = block-start 边。故：
- vertical-lr：静态视觉 x ≈ 0（左）。
- vertical-rl：静态视觉 x ≈ CB视觉宽 − 元素视觉宽（右）= **lr 的镜像**。

当前代码对两者都用 `fragment.x`（疑为 lr 模型值 ≈0）→ lr 对(1.28%)、rl 错(5.03%，应在右却在左)。
**修复原理**：`if is_vertical_rtl { child.x = mirror(fragment.x) }`，mirror 围绕 CB 块方向视觉宽度。

## 3. 镜像公式不能纯只读确定（须探针实证）⚠️ 诚实局限

mirror 的精确式取决于三个**纯只读无法确定**的坐标语义：
1. `fragment.x` / `child.x` 是**轴交换(swapped)模型**坐标还是**视觉(unswapped)**坐标？（extract_layout
   是否已 unswap？）
2. CB 块方向视觉宽度 = `root.content_height`（注释 1367）还是其他字段？
3. 元素视觉宽度 = `child.height`（轴交换后块方向=size.height→视觉宽）还是 `child.width`？

候选式（须探针二选一/校正）：
- 若坐标已视觉化：`x_rl = CB_visual_width − element_visual_width − x_lr`
- 若坐标仍 swapped：`x_rl = content_height − child.height − fragment.x`（content_height=块方向视觉宽）

**故本 spec 为「半 turnkey」**：位置+hook+原理确定，公式须代码 agent 用探针实证（见 §4）。这比 R254
「加 direction 分支」更具体（给了 hook + 原理 + 探针），但**不假装能纯只读给出最终公式**（避免
R255→R256 那种「推断被实证推翻」教训）。

## 5. 次要：residual A（all_inset_auto 未查 left/right）

line 1396-1399 `all_inset_auto` 仅查 `top==Auto && bottom==Auto`，**未查 left/right**。CSS：abspos
静态位置仅在「该轴 insets 全 auto」时用；若 left/right 指定，元素由 left/right 定位非静态。当前对
「top/bottom auto 但 left/right 指定」的元素也强行 `child.x=fragment.x`（覆盖 left/right 定位）→
residual A（ltr 1.28%）可能部分源于此。**修复（独立于 mirror，可同 PR 或分步）**：all_inset_auto
拆为 `_y_auto`(top+bottom) 与 `_x_auto`(left+right)，仅当对应轴全 auto 才用 fragment 修正该轴。
但这会改变现有 vrl/vlr 用例行为，须全量验证（可能影响非 residual 用例）。
