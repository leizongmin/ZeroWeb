# multicol baseline-export 精确方案（R236，read-only，docs-only，基线 438/490 持平）

**日期**: 2026-06-18
**承接**: R235 标 multicol baseline-export(8，css-align §baseline-export) 为 contained 候选（6 例恒 1.1% POLLUTED）。本轮追踪 wiring 给 R229-style 精确 spec。

## 测试机制（baseline-001 实证）
`<div style="display:flex; align-items:baseline;">` 含一个 multicol 子项 `<div style="columns:2; height:100px; column-fill:auto;">`。
→ multicol 容器须**导出自身 first baseline**（§baseline-export：从其各列内容基线派生，"highest baseline of all columns"）供外部 flex baseline 对齐参与。ZeroWeb 导出基线略偏 → 文本小错位 1.1%。

## wiring 状态（plumbing-gap 模式，同 R229/R234）
1. **基线读取 = taffy cached_baselines**：`extract_baselines_recursive`（engine.rs:474-484）从 `taffy.cached_baselines(taffy_id).y` 写 `box_node.taffy_baseline: Option<f32>`。
2. **flex/grid 消费**：engine.rs:1003-1040 baseline 对齐用 `child.taffy_baseline` 计算 baseline 贡献。
3. **multicol 缺口**：`multicol.rs` 全文 grep `baseline` **零命中**——multicol 布局（ZeroWeb 自建列布局，在 taffy 把它当普通 block 之上的后处理）**完全不计算/存储基线**。故 multicol 容器的导出基线 = taffy 的**通用 block 基线**（非 §baseline-export 列派生语义）→ 1.1% 系统偏移。
4. **模式同构**：taffy_baseline 字段 + flex 消费路径**已存在**，multicol 仅未按 §baseline-export 正确填充——与 R229(font-weight) 字段存在但 find/paint 不用、R234(font-kerning) parse 但不 wire 同构。

## R229-style 精确方案（供实现轮）
1. multicol.rs 列布局后，按 §baseline-export 计算容器导出基线：first baseline = 第一列首行/首子的基线（具体语义须对 spec + baseline-001~008 ref 核实——"highest baseline of all columns"）；last baseline = 末列末行基线。
2. 写入 multicol LayoutBox 的 `taffy_baseline`（覆盖 taffy 通用 block 基线），使外部 flex/grid baseline 对齐消费到正确的列派生基线。
3. 各列首/末基线需从列内 IFC 行盒基线收集（IFC 已有行基线）。

## 范围/风险
- 触及 multicol.rs + 可能 engine.rs 的 taffy_baseline 写入；**不碰 table.rs/cpu（并行 agent WIP）**。
- 8 例恒 1.1% POLLUTED 暗示单一基线计算缺口，contained 修复预期解锁 8 例（baseline-000~008）；自源中性下提 DC-14 chromium 一致率。
- 风险：§baseline-export first/last 语义细节（哪一列、box 还是 line 基线）须对照 spec+ref，否则可能如 R235 breaking 的 paint 侧那样 net-negative；**实现轮须 per-case 验证（baseline-000~008 逐个 set-diff）**。

## 对结构性多轮优先级的强化（R235 结论）
DC-14 结构性大头 multicol 31 = breaking(8 多轮硬) + **baseline-export(8 contained，本 spec)** + break/clip(9)。**baseline-export 是结构性 DC-14 中最 tractable 的切入点**（有界特性，plumbing-gap 模式，8 例系统性偏移），建议实现轮从 baseline-export 先行（含本 spec），再攻 breaking（column-aware IFC 碎片化，multi-round）。
