self-source reftest（追踪主指标）
---------------------------------
全量 reftest-upstream: **438/490 (89.4%) 持平**（css-fonts 60/60 持平）。
→ @font-face 对同源通过率零影响（test/ref 两侧同字体处理，self-source 天然抵消）。

chromium-Oracle 影响（DC-14 真通过口径）
-----------------------------------------
cross-validate.py（target/reftest-dump vs oracle-shots），css-fonts 56 可比 case：
  54 case 不变（chr-diff 变化 <0.3pp）
  2 case 退化（均为 font-feature 依赖）：
    alternates-order.html        chr: 6.28% → 13.81%  (+7.53)
    font-features-across-space-1 chr: 2.68% →  3.63%  (+0.95)
  css-fonts 污染率仍 ~46%（无改善）。
→ **净轻微负向**：无 case 改善，2 case 退化。@font-face 未改善 css-fonts chromium-Oracle 聚类。

根因（代码追踪，关键发现）
--------------------------
@font-face 字体能到达**光栅化**（fontdue），但生产路径**完全绕过 OpenType shaping**：
  - rustybuzz TextShaper（crates/render-foundation/src/font/shaper.rs，GSUB/GPOS 实现）
    **仅在单元测试中使用**（render-foundation/src/lib.rs:1032-1052），生产 paint/layout 路径零调用。
  - 生产 paint 路径（crates/engine/src/paint/painter/text.rs:1057-1075）逐字符映射
    glyph_id = ch as u32，无 ligature/kerning/alternates。
  - 故加载带 OpenType 特性的字体（FontWithFancyFeatures.otf）但不应用其特性 → 渲染
    「基础字形」比 chromium（应用特性后的字形）更远（alternates-order 6.28→13.81 即此机制）。
  - 纯度量字体：fontdue 度量与 chromium 差异 ≈ 旧 fallback 度量差异 → 净中性（font-default-02
    加载后仍 3.45%，几乎不动）。

WOFF 缺口
---------
17 个字体中 6 个为 .woff（AD/Revalia/GentiumPlus/LinLibertine/LigatureSymbols/Lato-Medium-Liga）。
fontdue::Font::from_bytes 仅支持 TTF/OTF，WOFF 静默加载失败 → 这些 case 回退 fallback（不变）。
但据 OTF 实证（加载后仍中性），即使加 WOFF 解码也预期净中性（fontdue 度量问题，非格式问题）。
本轮未加 WOFF 解码（避免推测性工作，code-guidelines §2）。

裁决
----
@font-face 加载（R329 + 内联 <style> 修复 4fc4caf）**正确实现且字体确实加载**，但对
reftest 主指标（self-source 438/490）零影响、对 chromium-Oracle **净轻微负向**（2 feature 依赖
case 退化，根因 = 生产路径未接 rustybuzz shaping）。

保留 @font-face 加载（开），理由：
  (1) 正确浏览器能力，DC-13 产品 smoke 需要（真实站点用 @font-face）；
  (2) 2 个退化 case 均不可单点修复（需完整 shaping），属结构性；
  (3) 关闭/gate 会掩盖 fontdue shaping 缺口，违反 DC-14 诚实原则；
  (4) 退化反映**真实状态**（加载自定义字体但未 shaping），比旧「fallback 假一致」更诚实。

被证伪的假设
------------
R311 建议「@font-face 字体加载特性是 css-fonts polluted 聚类（24 案）的解锁钥匙」。
**本轮证伪**：@font-face 净负向，不解锁 css-fonts 聚类。与 advance-width(R225/R320)、
font-weight-Bold(R229b)、AA 噪声(R174) 三谱系同源——fontdue/simple-shaping 是结构性瓶颈，
@font-face 是其第四条死路。真正杠杆 = 把 rustybuzz TextShaper 接入生产 paint/layout 路径
（多会话架构，非单点）。

下一步（多会话，非单会话）
--------------------------
1. 将 TextShaper::shape_single_line 接入 paint 文本路径（替代 text.rs:1057-1075 的
   glyph_id=ch as u32 逐字符循环）→ 启用 ligature/kerning/alternates。高风险（IFC/paint
   文本路径 = R125-R213 P0 多会话死锁区，shaping 改 advance/position 可能级联回归），须多轮
   narrow 收敛 + 守 438/490。
2. 接入后 @font-face 才可能转正（feature 依赖 case 才有 win 路径）。
3. WOFF 解码（fontdue 前 unwrap WOFF→sfnt，或加 woff crate）—— 仅在 shaping 接入后才有价值。
