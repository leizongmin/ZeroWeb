chr<1% near-threshold cluster 量化（POLLUTED@1-2% = fontdue-releasable 大簇）
日期: 2026-06-22 ｜ 类型: doc-side read-only 分析（零代码变更，零新 compute）
数据源: code agent `/tmp/r500cv-pos.txt`（positioning/ 519 案 cross-validate，WITH-R500，
        `| safe_id | 判定 | z_vs_ref | z_vs_chr |`，与 doc-agent 独立 PIL 互证一致）

================================================================================
背景
================================================================================
R500 chr<1% 验证（evidence §9）发现：self-source +33 中 22 bottom/position-applies-to
卡在 1.01-1.43%（fontdue 文本噪声钉 1% 线外，POLLUTED），实证 chr<1% = threshold metric
under-reward。本分析把该问题推广到 positioning/ 全量：near-threshold 簇到底多大？

================================================================================
positioning/ z_vs_chr × judgment 分布（518 案）
================================================================================
判定说明（cross-validate.py）：
  self-pass  : self-source 通过 AND chr<1%（真通过）
  POLLUTED   : self-source 通过 BUT chr>=1%（假通过 = ZeroWeb 渲染 test==ref 一致，
               但与 chromium 差 1%+）
  self-fail  : self-source 也失败（真布局缺口）

分布：
  self-pass : 206  (chr<1%)
  POLLUTED  : 167  (self-source pass but chr>=1%)
  self-fail : 145  (real layout gap)

POLLUTED 按 z_vs_chr 分桶（★ 关键）：
  1-2%  (fontdue-releasable): 139
  2-5%  (maybe layout):        28
  >5%   (structural false-pass): 0
  → 全部 POLLUTED <5%，且 139/167=83% 集中在 1-2%

self-fail 分桶（真布局缺口）：
  1-2%: 27  | 2-5%: 43  | >5%: 75

================================================================================
★ 核心结论
================================================================================
1. POLLUTED@>5% = 0：**每一个 self-source pass 案都 <5% chr 差**（无一 gross 误渲染）。
   = ZeroWeb 的 test/ref 一致渲染在结构上接近 chromium，差距集中在 metric 噪声而非
   gross 布局错。这**推翻「positioning/ 主要 structural-blocked」的隐含假设**。

2. POLLUTED@1-2% = 139 案（positioning/ 的 27%）：self-source 正确但 chr 卡 1-2%。
   大头是 fontdue 文本度量噪声（R500 §9 实证的 22 applies-to 即此簇子集；"Test passes
   if..." 文本在多数 positioning 测试中出现，fontdue 度量差 ~1% 系统性钉这些案在 1% 外）。
   caveat：139 中或含少量「test==ref 同错」的 engine-level 小布局 bug（非纯 fontdue），
   但 POLLUTED@>5%=0 说明即便有也不是 gross；fontdue-releasable 子集占多数。

3. **fontdue/Phase-A 文本度量 lever 的量化 upside**（positioning/ 单目录）：
   若 fontdue 度量改善把这 139 案拉到 <1%：
     chr<1%: 209 → 348（+139，+26.8pp），positioning/ 40.3% → 67.1%
   这是迄今识别的**最大 chr<1% lever**（远超 R500 的 +10）。

================================================================================
对「95% 目标路径」的重构
================================================================================
- 10-dir chr<1% = 36.3%（R500 后），距 95% 缺 ~59pp。
- 本分析（positioning/）+ 顶部 image-fidelity threshold-metric 推论 → 缺口大头可能不是
  「未实现的 CSS feature」而是「已实现但被 fontdue/IFC 度量噪声钉在 1-2% 线外」。
- 若 fontdue 文本度量（Phase-A 谱系，R174/R225/R471 长期记为死路）能有突破，释放的将是
  各文本承载目录的 POLLUTED@1-2% 大簇（positioning/ 139 仅是 1/10 目录的样本）。
- ⚠️ 但 fontdue 攻坚历史（R174 AA/R225 advance-width/R229b Bold）均证伪为死路；本分析
  不推翻那些证伪，而是**量化了若能突破的 upside**（给未来 fontdue/Phase-A 投入以量化依据）。
- 真 forward-motion 仍需「降低 fontdue 度量噪声」的具体可行路径（未识别；Phase-A IFC
  统一 R125/R198/R205 + 字体度量精度 = 多会话架构项）。
