本轮动作（纯移动，不改逻辑）
-----------------------------
按职责抽出两个内聚模块（沿用既有 multicol.rs / table.rs / intrinsic_sizing.rs 同级模块模式）：

1. **`inline_finalization.rs`（950 行）** = Phase A 目标代码集中地：
   - resolve_text_align, store_inline_layout_results, store_font_sizes_from_ifc,
     sync_inline_child_boxes_from_ifc, InlineVisualMetrics, resolve_px_length,
     extract_inline_visual_metrics
   - compute_final_inline_layouts（Gate 1/Gate 2 + stored 行盒，Phase A 核心）
   - measure_text_content, has_direct_text, has_inline_content
   - remeasure_text_with_float_exclusions, remeasure_inline_only_containers
2. **`float_positioning.rs`（742 行）** = 浮动定位后处理：
   - adjust_float_positions, adjust_float_positions_with_context（551 行最大单函数）
   - shrink_vertical_blocks_to_content, shrink_inline_blocks_to_content
   - mark_anonymous_table_roots

依赖分析（移动前已验证，单向干净）：
  - float_positioning 仅依赖 crate::margin_collapse::* + 标准导入，与 inline_finalization 无相互调用。
  - inline_finalization 仅依赖 crate::inline / crate::types / crate::multicol::balance_column_geometry + 标准导入。
  - 两组互不调用；均仅被 engine.rs 主循环/measure callback 调用。
  - engine.rs 通过 `use crate::{float_positioning,inline_finalization}::*;` glob 引入（与 lib.rs 既有
    `pub use engine::*` 风格一致），无需逐调用点改名。

可见性：被 engine.rs 调用的迁移函数改 `pub(crate) fn`；InlineVisualMetrics 改 `pub(crate) struct`
（修复「pub(crate) fn 返回 private struct」可见性 warning）。
