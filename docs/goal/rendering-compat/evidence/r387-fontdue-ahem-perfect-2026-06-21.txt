# R387 — fontdue Ahem 光栅化完美（16/48/100px），终结 fontdue 字体层归因

**日期**：2026-06-21
**触发**：R174 AA 基准仅测 DejaVu 48px（W/i），未覆盖 100px 大字号 Ahem（ifc-008 等大字体簇）。R385 把 ifc-008 7.89% 归为「fontdue 度量噪声死路，须字体层突破」。本轮补上 100px Ahem 实证，终结该归因。

## 方法

扩展 `crates/render-foundation/examples/glyph_aa_dump.rs`（R174 诊断工具）加 Ahem 多字号光栅化：`FontLoader::rasterize_glyph(Ahem.ttf, ch, fs)` for fs ∈ {16, 48, 100}, ch ∈ {X, x, space}，报告 width/height/advance 及其与 font_size 比值。Ahem.ttf = `tests/wpt-runner/fonts/Ahem.ttf`。

## 实证结果

```
Ahem fs=16  'X': width=16  height=16  advance=16.0  (w/fs=1.000 adv/fs=1.000)
Ahem fs=16  'x': width=16  height=16  advance=16.0  (w/fs=1.000 adv/fs=1.000)
Ahem fs=48  'X': width=48  height=48  advance=48.0  (w/fs=1.000 adv/fs=1.000)
Ahem fs=100 'X': width=100 height=100 advance=100.0 (w/fs=1.000 adv/fs=1.000)
Ahem fs=100 'x': width=100 height=100 advance=100.0 (w/fs=1.000 adv/fs=1.000)
space: advance=font_size (width=0 正确，空格无形体)
```

**fontdue 在所有字号（含 100px 大字号）渲染 Ahem 完美**：width = height = advance = font_size，精确 1em 方形。

## 结论

**fontdue 字体层（光栅化 + advance）对 Ahem 完全正确**。ifc-008 等 Ahem-reftest 的 chromium 发散（7.89%）**非来自 fontdue**，而在 **layout 定位层**（line-height 计算、baseline Y、容器/段落 margin、IFC 行盒/片段位置）。

**推翻 R385「须字体层突破」推断**：R385 据 ifc-008 散布发散推测 fontdue 度量噪声不可修，本轮实证 fontdue Ahem 完美 → 发散在 layout 定位（可调查的方向），**非不可修的字体层死路**。亦印证 R174「fontdue 无需替换」结论对大字号 Ahem 同样成立。

**重新聚焦**：大字体簇（font-051/ifc-008/009/011/empty-inline-002）的剩余 diverge 应查 **compute_final_inline_layouts 的行盒/片段 Y 定位** vs chromium（stored path baseline 计算、line-height 1em 处理、margin 折叠），非字体。但 R306 证伪了「geometric baseline (frag.y+height) 作 render baseline」（font-051 offset→16.67% FAIL），故 Y 定位修复须避开 R306 死路（可能需 layout 侧存储正确 baseline_y 字段，paint 消费——属 Phase A broad）。
