R777: visibility:collapse on table-row LANDED (row collapse, mirrors column collapse)
================================================================================
Date: 2026-06-28
Round: R777 (continuation; prior R776)
Status: LANDED, +1 PASS zero regression (CSS Tables §4.1 row-collapse facet)

Summary
-------
ZeroWeb implemented `visibility:collapse` for table COLUMNS (§4.1: collapsed
column width=0, no spacing) but NOT for table ROWS — an asymmetry. A row with
`visibility:collapse` was laid out at full height (default 20px min for empty
rows) instead of 0. This fix mirrors the column-collapse logic for rows:
collapsed row → height 0, no border-spacing contribution. The rowspan/colspan
cell-rendering sub-facet (cells spanning collapsed rows) is a SEPARATE spec
section and remains a residual.

Root cause
----------
- `crates/layout-engine/src/table.rs` `TableGrid` had `collapsed_cols` but no
  `collapsed_rows`.
- Row-height computation in `position_cells` (content_row_heights + the row
  loop) and `update_row_group_positions` never checked `visibility:collapse`,
  so a collapsed row kept the 20px default min height and contributed spacing.
- Paint side was already correct: `painter/mod.rs:414/556` treats
  `visibility:collapse` as hidden, and visibility inherits, so cells in a
  collapsed row are already not painted. Only the LAYOUT was wrong.

Fix (bounded, mirrors column collapse)
--------------------------------------
- New module `crates/layout-engine/src/table_visibility.rs` with
  `detect_collapsed_rows(table_box, grid_rows, styles) -> Vec<bool>`: for each
  non-anonymous table-row, checks its computed `visibility` for `Collapse`
  (anonymous rows have no element and cannot collapse).
- `TableGrid` gains `collapsed_rows: Vec<bool>`, populated in `build_grid`.
- Three layout touchpoints, each gated on `collapsed_rows[i]`:
  1. `content_row_heights` (row_extras precompute): collapsed → 0 (skip 20px default).
  2. `position_cells` row loop: collapsed → row_height 0 (skip default + row_extras),
     and `row_y += row_height + (0 if collapsed else spacing_y)` — collapsed rows
     don't contribute border-spacing.
  3. `update_row_group_positions`: same collapsed→0 + skip-spacing, so row-group
     (tbody/thead/tfoot) geometry stays consistent.

Why a new module: `table.rs` is pre-existing over the 2000-line guideline
(2265 lines; split deferred per master.md). The detect function is extracted to
`table_visibility.rs` to avoid growing `table.rs`; the struct field + 3 layout
edits are inherently in `table.rs` (~12 net lines).

Why zero regression is structural, not lucky
--------------------------------------------
The fix is provably gated: `collapsed_rows[i]` is `true` ONLY when row `i` is a
non-anonymous table-row whose computed `visibility == Collapse`. For every
ordinary table (no collapsed rows) the vector is all-`false`, so every new code
path returns early / adds 0 / is skipped — byte-identical behavior. Only tables
that actually use `visibility:collapse` on a row are affected.

Residuals (deferred, separate spec facets)
------------------------------------------
1. Rowspan/colspan cells spanning collapsed rows (CSS Tables §visibility-collapse-
   cell-rendering): cell height should shrink when a spanned row collapses.
   visibility-collapse-border-spacing-002 / rowspan-005 / colspan-003 unchanged.
   Needs cell-height model change (structural, multi-session).
2. row-visibility-003 (8.09%): multi-row collapse residual.
3. visibility-collapse-border-spacing-001 residual 1.65% (>1%): red table-bg +
   table-sizing quirk, not the row-collapse height itself.
