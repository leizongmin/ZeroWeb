正确返回 None，line 150）。div 内容为彩色 span（#pink/#orange/#purple/#gray），

line2="PurP gray"，各 span 按自身 color（粉/橙/紫/灰）。

像素分析（diff bbox x[28,267] y[28,67]，240×40 两行）：
  TEST glyph x-range（y=32/52 一致）: x[28,107] + x[128,207]  ← 换行正确（4ch+gap+4ch）
  REF glyph x-range（y=32/52）: 无黑色像素  ← REF 文本是彩色（粉/橙/紫/灰），非黑
  diff colors: black(6400) + yellow(3200) = TEST 全黑 + 底黄；REF 是彩色 span

**换行正确，唯一差异 = color**：TEST 把所有 span 文本渲成 **黑色（div 的 color:black）**，
REF 期望各 span 自身 color。根因 = 存储 IFC 片段（InlineLayoutFragment，layout-engine）
**不携带 color 字段**——paint 存储路径（text.rs:821 stored_fragments）所有片段用容器 color。
div 是纯 Ahem / 非多列 / 非浮动 → Gate 2 存储 → paint 走 use_stored 存储路径 → 丢色。

═══════════════════════════════════════════════════════════════
为何不在本轮修复（裁决：与 R335/R336 abspos 抑制耦合，Phase A）
═══════════════════════════════════════════════════════════════
存储路径 per-fragment color 修复看似 narrow（给 InlineLayoutFragment 加 color + paint 用），
但 **abs-pos-non-replaced-vrl/vlr 簇（R335 回归集）也走存储路径**——abs-pos-non-replaced-vrl-002
同为纯 Ahem（font:80px/1 Ahem，非多列非浮动）→ Gate 2 存储 → use_stored。

R335 实证：存储路径 per-fragment color 使 abspos 绿色 X 用 green 绘在 paint-IFC 位置（正常流）
而非 ref 期望的 abspos 静态位置 → 4 case diff 上升（vrl-002/vrl-012/vrl-130/vlr-163）。
故安全修复须对 abspos 片段**保留容器 color**（= 当前行为，不激活 green-X 可见性），但 abspos
文本仍在 paint-IFC 位置绘制（错位）——R336 证抑制 abspos 文本需解 layout/paint double-path
（abspos span 自身 paint_text 产 fs=16）。故 per-fragment color 修复与 abspos 抑制耦合，
非单点 clean win，属 Phase A paint-IFC 双路径统一。
