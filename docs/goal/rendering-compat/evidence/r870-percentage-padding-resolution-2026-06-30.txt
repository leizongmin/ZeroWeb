R870 — CSS §8.3/§8.4 百分比 padding 相对 CB 内容宽度预解析（taffy 0.7 Percent padding bug）
==============================================================================
日期：2026-06-30
谱系：R869 后续 normal-flow/margin-padding-clear worst 扫描。发现 padding-percentage-inherit-001
（13.05%）、padding-em-inherit-001（11.17%）簇。逐案隔离定位到真根因 = 百分比 padding 完全失效。

根因（LAYOUT_DUMP 实证 + taffy 0.7 bug）
----------------------------------------
CSS §8.3/§8.4：百分比 padding 相对**包含块的内容宽度**解析（与元素自身宽度无关）。
converter（convert_length_to_lp）正确把 Percentage(20) → taffy LengthPercentage::Percent(0.2)
（test_computed_style_padding_percentage 断言）。但 taffy 0.7 的 Percent padding 在多数布局
路径解析为 0：

  探针 A：`#box{width:150px;padding:20%}`（body，CB=视口 800）
    期望 pt=160（20% of 800）   实测 pt=0   ✗
  探针 B：`#cb{width:300} > #box{padding:20%}`
    期望 pt=60（20% of 300 CB）  实测 pt=0   ✗
  对照：`padding:60px`           实测 pt=60  ✓（px padding 正常）
  对照：`margin:20%`             实测 mt=60  ✓（百分比 margin 正常，不依赖自身宽）

即 taffy 0.7 把 LengthPercentage::Percent 的 padding 丢弃为 0；百分比 margin 正常（margin 不参与
元素自身宽度计算故无循环）。这是真实 box-model bug（百分比 padding 在真实网页极常见）。

实现
----
crates/layout-engine/src/engine.rs 新增 `resolve_percentage_padding` 两趟后处理（compute() 步骤
3.2 之后，与 R695 apply_indefinite_percent_height_to_auto / intrinsic_content_sizing 共用一次
taffy 重算）。非循环（百分比 padding 仅依赖父级内容宽，第一趟已知）：自顶向下遍历第一趟 LayoutBox
树，携带父级内容宽；对每个含 Percentage padding 的元素，按 pct/100 × parent_content_width 解析为
绝对 px，改写 taffy style padding.{top,right,bottom,left} = Length(px)，set_style + mark_dirty。
仅改写百分比的边（其它值保留 taffy 已转换值）；仅水平书写模式；vertical-WM 保守跳过。
