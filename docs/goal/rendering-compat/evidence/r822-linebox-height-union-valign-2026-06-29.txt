R822 — line-box 高度 = strut ∪ valign 偏移盒（CSS §10.8.1）+ Phase 3 valign-aware baseline_y
日期：2026-06-29
承接：R821（定位真 blocker = div line-box 高度对 line-height>1 错误）

================================================================================
根因（REF 实证）
================================================================================

va-117a（`div{font:2.5em/3.25 Ahem}`=40px/130px，span vertical-align:text-bottom）：
ZW line-box = strut only = 130px，div 块高度 ~140px；REF（vertical-align-117a-ref.xht）
显式 `div{height:175px}` + abspos 图，chromium Oracle div ~180px。

CSS §10.8.1：line-box 高度 = 所有 inline box（含 strut）经 vertical-align 定位后的**并集**。
text-bottom 把 span 的 line-height box（130px）移到 box-bottom 对齐父 content-area 底
（= half_leading + font_size = 45+40 = 85），故 span box = [85-130, 85] = [-45, 85]
（line-box 相对，顶越过 strut 顶 0 共 45px）。strut = [0, 130]。并集 = [-45, 130] = 175px。

ZW 旧实现 line.height = break_into_lines 算的 max(run.box_height) = 130（valign 前），
apply_vertical_alignment 重定位 run 后**不重算** line.height → line-box 偏矮 45px → div
块高度不足 → va 簇（117a/118a）24% 发散。

================================================================================
修复（R822）
================================================================================

(1) apply_vertical_alignment（inline/mod.rs）：run.y 定位循环后，按 valign 语义算 line-box
    扩展量并撑高：
      text-bottom → 向上扩 half_leading；text-top → 向下扩 half_leading
      super → 向上扩 0.3·fs；sub → 向下扩 0.3·fs
      baseline/top/bottom/middle → 不扩（box 在 strut 内）
    half_leading = (line_height - strut_fs)/2（strut_fs = 行内主导 font_size）。
    扩展：line.height += top_extend + bot_extend；line.baseline_y/ascent += top_extend
    （strut 在更高 line-box 内下移，保持绝对字形位置由 paint baseline_y_abs 决定）；
    line.y/run.y 不动。

(2) inline_finalization storage site（compute_final_inline_layouts 内，唯一活路径；
    store_inline_layout_results 是死代码）：per-fragment valign-aware baseline_y
      text-bottom → line.baseline_y - half_leading（glyph 上移到 strut 之上）
      text-top → line.baseline_y + half_leading
      sub → line.baseline_y + 0.3·fs；super → line.baseline_y - 0.3·fs
      其余 → line.baseline_y（Phase 2 行为）
    half_leading 由 line.ascent 反解（strut_fs=(ascent-height/2)/0.3）。

两改动协同：(1) 撑高 line-box 使 div 块高度正确（130→175），strut 下移；(2) 把 text-bottom
span glyph 放到 strut 之上（baseline_y - half_leading）。绝对位置：TTTT(baseline) 不动，
span 上移到 TTTT 之上（test 期望）。

================================================================================
未跨 1% 的原因（下一步）
================================================================================

117a/118a 残余 13%：re-render 显示 span/TTTT 的精确 y 与 chromium 仍有 ~20-40px 偏差。
根因候选：① half_leading 用 (line_height - strut_fs)/2 近似（chromium 用真实 font
ascent/descent 度量，Ahem 可能非整数比）；② strut_ascent 用 0.8·fs 近似（R800）vs
chromium 真实 ascent；③ text-bottom 的 "父 content-area 底" 用 half_leading+font_size
近似 vs chromium 真实 (ascent+descent) 度量。这些是 font-metric calibration，独立可调，
非架构阻塞。
