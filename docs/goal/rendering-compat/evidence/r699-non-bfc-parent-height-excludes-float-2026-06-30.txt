R699 — CSS §10.5.1 非 BFC 块 height:auto 忽略浮动子元素
日期：2026-06-30
状态：LANDED（clean spec win，+2 Oracle PASS / 0 回归）

============================================================
1. 缺口（anchor）
============================================================
css/CSS2/normal-flow/block-non-replaced-height-011.xht — chromium-Oracle 16.10%

结构：
  #div1 { background:red; height:auto; }            ← 非 BFC（overflow:visible）
  div div { float:left; height:1in(96px); width:1in; overflow:visible; }

  <div id="div1"><div></div></div>

CSS §10.5.1：块级非替换元素 height:auto + overflow:visible 时，高度 = 最顶 in-flow
子元素 border-top 到最底 in-flow 子元素 border-bottom 的距离——**浮动子元素显式忽略**。
div1 唯一子元素是 float → 应被忽略 → div1 height=0 → 红背景 0 区域 → 「无红」(PASS)。

ZW 旧行为（LAYOUT_DUMP）：
  div(#div1) h=96   ← WRONG（float 子被当 in-flow 计入）
    div(float)  h=96
根因：taffy 0.7 把 float 当 in-flow block 计入父 content height（float_positioning.rs:16
注释明言）。非 BFC 父被 float 子撑高，红背景显示 → FAIL。

============================================================
2. 修复（exclude_floats_from_non_bfc_auto_height，engine.rs）
============================================================
新增后处理 pass（步 5.2，adjust_float_positions 之后）。自底向上（后序）递归：先修正
子元素，父级重算时读到已修正的子高度（级联自然传播）。

机制：对每个 `style.height == Auto` 且 `!establishes_bfc`（margin_collapse.rs:33，已含
overflow!=visible / float / abspos / flow-root / flex-grid-table / multicol 全条件）的
块级元素，重算 content_height = in-flow 子元素（非 float、非 abspos）border-box 底边
最大值（无 in-flow 子 → 0）。

★ 关键守卫（首轮 net -13 回归后的修正）：**仅当存在 float 子元素时才重算**。无 float
子元素时 taffy 的 content_height 已正确——max(child.y+child.height) 公式对负 margin /
margin 折叠不精确，无 float 时强行覆写会误收缩非 float 用例（如 root-box-001 的
p{margin:-1em}，无 float 却被首轮版本误收缩，致 normal-flow -13）。
