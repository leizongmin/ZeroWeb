## 实现（text.rs ellipsis 后处理，direction + writing-mode 门控，无 kill-switch）

- `is_rtl_horizontal = direction: rtl && writing-mode: horizontal-tb`（竖排维持旧行为，
  vertical ellipsis 独立域）。
- **检测镜像**：RTL 从行尾（右）向左扫，`g.x < content_left` 判溢出。**严格小于**——
  右对齐行「恰好装满」时首字形 origin == content_left，`<=` 会误触发（见试错）；溢出行
  起点 = content_right − line_w < content_left 恒严格成立，判据无损。
- **裁剪镜像**：LTR 从尾部 skip(cutoff) 截；RTL 从头部截——保留 cell 起点 ≥
  ellipsis 盒右缘（content_left + '…'宽 − 0.5 容差）的字形，其左全裁（glyph_id=0 哨兵）。
  找不到保留侧（整行在省略号盒之左）时全裁，与 LTR cutoff_start=0 兜底对称。
- **定位镜像**：'…' 单字形锚 content_left（RTL inline-end = 左缘）；LTR 锚
  content_right − 宽不变。
- ZW 行内 RTL 无逻辑序重排，镜像取纯几何：字符全同的行（rtl-001 的 p 列）像素可与
  chromium 一致；逻辑序敏感场景见家族地图。

## 试错

首版检测用 `g.x <= content_left`：div2 `pppp`（4 cell = 400px 恰满 400px 盒）首字形
origin == content_left 误判溢出 → 首 p 被裁换成 '…' 方块（[8,108]×[150,250]）→ 与 ref
（4 个真 p，无省略号）差 8000px。像素差分定位后改严格 `<`，rtl-001 翻绿。教训：与 LTR
判据逐字对称（`>=`↔`<=`）不等于几何对称——LTR 恰满行末字形 origin = content_right −
advance 严格小于边缘，天然不触发；镜像判据须按本侧布局几何重新推边界。
