根因 1：flex-basis 的 em/rem/ch 未在 computed style 解析为 px（VERIFIED）
--------------------------------------------------------------------
FBDBG 插桩（taffy-local flexbox.rs determine_flex_base_size）实证：
  node flex_basis(local)=Some(4.0)  ← 应为 64.0（4em × 16px font-size）
  node main_size(size)=Some(80.0)   ← width:5em 正确解析为 80

链路：
  - parse_flex_basis（parse.rs:268）正确解析 "4em" → FlexBasisValue::Length(Em(4.0))
  - expand_flex（shorthand/mod.rs:690）正确展开 flex:0 0 4em → flex-basis:4em
  - convert_flex_basis（converter/mod.rs:486）→ convert_length_to_dimension(Em(4))
    → `LengthValue::Em(v) => length(*v as f32)` = length(4.0)（**em 当裸数字**！）
  - main_size(size) 走 width，width 的 em 已由 compute_style（computed.rs compute_style）
    的 resolve_length_field 解析为 Px（故 5em→80 正确）。
  - **但 compute_style 的 resolve_length_field 列表（width/height/min/max/margin/
    padding/border）不含 flex_basis**（flex_basis 是 FlexBasisValue 非 LengthValue）。
    → flex_basis 的 em 从未解析 → converter 当裸数字。

code-side fix（已 REVERT）：computed.rs compute_style border_left_width 解析后加
  if let FlexBasisValue::Length(ref mut lv) = resolved.flex_basis {
      resolve_length_field(lv, font_size_px, viewport_width, viewport_height);
  }
+ import FlexBasisValue。CSS-correct（em/rem/ch→Px，Percentage 保留）。
LAYOUT_DUMP 实证：span 宽 80→64（正确），flexbox_flex-0-0-N diff 5.13%→1.71%。

根因 2：inline-block 垂直 margin 在 IFC 未应用（self-source REF bug，masking）
---------------------------------------------------------------------------
但 flexbox_flex-0-0-N 仍 FAIL（1.71% > 1.00% 阈值）。残余 = 垂直偏移：
  TEST（flex）：span abs_y=33（content-top 17 + margin-top 16，正确）
  REF （block+inline-block）：span abs_y=17（margin-top 16 **未应用**）
span margin-top:1em 记录为 mt=16 但未偏移 box 位置（abs_y=17 应为 33）。

这是 ZeroWeb IFC 对 inline-block 垂直 margin 的处理 bug（ref 侧）。因 reftest 是
self-source（ZeroWeb 同时渲染 test+ref），test 侧（flex，正确）与 ref 侧（block，
错误）的垂直差（16px≈1.71%）持续超标 → 即使 flex-basis em 修对，仍 FAIL。
★ 这是 DC-14 self-source 假失败的实例：test 正确但 ref 错误 → 误判 FAIL。

教训
----
1. self-source reftest 的「test 正确 + ref 错误」会 mask 真实 fix 的 yield（DC-14
   假失败）；fix 改了 primitives 但 reftest 不动时，须检查 ref 侧是否独立 bug。
2. computed style 的 resolve_length_field 列表是 em/rem/ch→Px 的单一 chokepoint；
   新增「长度型」属性（如 flex_basis 包装的 LengthValue）易遗漏加入此列表。
3. 零 yield 但改了 primitives 的 fix（非 byte-identical）与 byte-identical 零 yield
   性质不同——前者有「被 mask」可能，后者是「fix 真无效」。后者果断 revert，前者须
   查 mask 来源再裁决。
