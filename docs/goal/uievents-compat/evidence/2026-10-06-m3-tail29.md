## 判定证据链

1. **wpt.fyi 官方 Chrome master run 实测**（chrome-157.0.8087.2 / linux-22.04 /
   revision 788584597a，run id 6293748152795136，created 2026-10-06，API
   `/api/search?run_ids=6293748152795136&q=pointercapture_in_frame`）：
   - `?mouse` 6/6；`?pen` 5/6；**`?touch` 4/6（2 fail）**。
   - ZeroWeb 同文件 ?touch **5/6**（tail28 起具名 Fail 仅 subtest 4）——**已超上游
     Chrome 一个 subtest**。
2. **Chromium 源码推演**（third_party/blink/renderer/core/input/
   pointer_event_manager.cc，main 分支 `SendTouchPointerEvent`，#660-673）：
   touch pointerdown 时 `SetPointerCapture(pointerId, target)`（pending override =
   hit-test target）先于 `DispatchPointerEvent`；下一 pointer 事件派发前
   `ProcessCaptureAndPositionOfPointerEvent` 结算 → **gotpointercapture@down
   target**；up 时 `ReleasePointerCapture` + `ProcessCaptureAndPositionOfPointer
   Event(nullptr)` → **lostpointercapture**。两事件 bubbles=true → 挂 outerFrame
   div 的 listener 必录 → receivedEventList 恒 **5 条**，与 expected 3 条矛盾。
   直接操纵型指针（touch/pen）全域如此，**该 subtest 在实现隐式捕获的引擎上不可过**。
3. **上游 master 现状**（raw.githubusercontent.com fetch 2026-10-06）：subtest 4
   expected 仍 3 条（#210-212）未改——作者桌面 mouse 视角遗漏（同文件 subtest 5
   为 touch 写了 `pointerType == "touch" ? "outerFrame" : "innerFrameDocument"`
   特例，subtest 4 无——上游 expected 记账不完整，非 ZeroWeb 缺口）。
4. **ZeroWeb 实测序**（tail28 失败 message）：down → gotpointercapture → move →
   pointerup → lostpointercapture，全 @outerFrame——与 2 的 Chromium 推演序
   **逐事件一致**（got 于 move 前结算、lost 随 up 隐式释放、move 随捕获目标
   =down target=命中目标）。

## 上轮预判修正

tail28 余挂注记「非捕获触式 move 抑制的推广面，touch move 专项入口」——实证
修正：move@outerFrame **已派发**（尾簇 25 触式捕获路由，隐式捕获 pending 于 move
站结算后随捕获目标派发），收到的 5 条中多出的是 got/lost 而非 move 缺失——
**不是触式 move 抑制缺口，是上游 expected 记账问题**。touch move 专项入口取消，
无 shim 改动。
