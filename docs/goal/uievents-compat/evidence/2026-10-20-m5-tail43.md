## 症状与归因

`uievents/keyboard/keydown-input-events.html :: keyDown performs character
insertion before completing` 1P/1F（收口 tail28 证据 2P）。失败形：eventLog
只收 keydown，beforeinput/input 缺失；第二子测（cancel keydown）空转通过。

**根因（机制级，A/B 实证）**：send_keys InsertText 默认动作路径
`__zw_text_input`/`__zw_text_delete` 共用的 `_resolveInputTarget`（part01）
以 `_wrapSelector(resolved)` **新建 sel proxy**——测试页 `createElement('input')`
动态控件经 handle→selector 倒置 merge 后，页面 listener 注册在**原 handle
proxy**（`_listenerStore['@__n*']`，R100 多族包装 identity 约定）；隔离 sel
proxy 上派发的 beforeinput/input 页面 listener 收不到，`el.value` 写同样落
隔离对象。keydown 之所以在册：焦点链走原 proxy，与该函数无关。

尾簇 42 的「InsertText 原子脚本未生效或 noop」预判修正——脚本在跑，派发/
写值落在错误对象上。commit 级 first-bad 未定位（上轮 bisect 未收敛，
d688d89e7..3f37525b2 共 1014 提交）；机制归因以双跑 A/B 收口：stash 修复
复现 `["keydown"]` 单条（exit 1），恢复后 2P（exit 0）——单变量翻转。

## 修复

`_resolveInputTarget` 回落 R100 identity 反查（同 query 返回点约定
`_zwQueryWrapIdentity`，part05）：命中 handle 登记则包装回**原 handle
proxy**；key 取 proxy 自身 selector/handle（`_elKey(el.__zwSelector ||
resolved, el.__zwHandle || null)`），与页面侧选区状态（`setSelectionRange`
写 `_textSelection`）同源。静态元素无 handle 登记 → `_wrapSelector` 回落
原行为，key 恒等（`el.__zwSelector === resolved`、`__zwHandle === null`），
零行为变化。

学习映射：zeroweb-guidelines #32（多族包装 identity——「写回保持原对象」），
R100 限定 query 返回点调用约定未破坏（本函数是 text-input 专属 query 消费点，
非全局 `_wrapSelector` 前置反查）。
