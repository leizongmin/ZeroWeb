## 缺口

`pointerevent_click_during_parent_capture`（mouse default variant）：expected mouseup/
click 的 composedPath 不含 `div#target`（= 捕获元素 parent 落点），got 恒含——

1. `capturedSel`（click 组合目标的捕获落点）读在 **pending 换防前**：pointerdown 里
   `setPointerCapture(parent)` 只入 `st.pending`，换防发生在 pointerup 派发内的
   `_zwProcessPendingCapture`——晚于 capturedSel 读取 → 恒 null/旧值。
2. compat mouseup 以 `upSel`（真实命中元素）派发：pointerup 派发内的隐式释放
  （buttons 归零）已清 capture，`__zw_dispatch_event` 内部 `_m3Cap` 重定向到此
   已不可达。

## 修复（shim `__zw_pointer_up_sequence` 两件）

1. **pending 换防前移**：capturedSel 读取前显式 `_zwProcessPendingCapture('1')`
  （guard `!st.processingCapture`）——PE spec §9.2 Process Pending Pointer Capture
  「before dispatching the next pointer event」，gotpointercapture 站序仍先于
  pointerup listener。
2. **compat mouseup 落点分流**：mouse → `upEff`（捕获有效落点——Chrome 语义 compat
  mouse 随指针捕获落点）；**touch → `upSel`**（真实命中——同测试 touch 面「mouseup
  path 含 target」+ touchend「always fired on same target as touchstart」语义；首版
  统一 upEff 曾回归 touch mouseup，-1 轮修正）。无捕获时两者 === upSel 零变化。
