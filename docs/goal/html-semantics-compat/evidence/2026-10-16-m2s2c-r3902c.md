# M2 切片 2c — valueAsNumber/valueAsDate IDL 面 + stepUp/stepDown 全类型 spec 步进算法（2026-10-16）

## 范围（shim R3902c）

切片 2b 账本 stepping 簇清零 + 2b 遗留 WIP（valueAsNumber/valueAsDate
getter/setter）收口验证：

- **stepUp/stepDown**：从 number/range 桩升级为 HTML §4.10.5.4 全七类型
  步进算法（date/datetime-local/month/number/range/time/week）。方法对
  全部 INPUT 暴露；非步进类型抛 InvalidStateError（WPT input-stepup
  INPUT_TYPES_THAT_CANT_STEP 15 类型断言面）；`step='any'` 抛
  InvalidStateError；缺省/无效（0/-2/bogus）→ 缺省步长×比例因子。spec
  全步：min>max 不动；[min,max] 无格点不动；value 解析错误 → 0；步进基
  min→value 内容属性→类型缺省基（week=1970-W01 周一 −259200000 ms）→0；
  离格向步进方向 snap 最近格点；越界对齐界内最近格点（非 clamp 界值——
  step=3/max=7/stepUp(3) → 6）；步进反向回退不动。
- **valueAsNumber**（getter/setter）：数值类型 parseFloat 面 / date 族 ms /
  month 月数；setter NaN→''、数值类型 String(n)、date 族 ms→格式化、
  month→`_formatHtmlDateValue`；写 `_inputValues` 脏缓存 + default 捕获。
- **valueAsDate**（getter/setter）：date/month/week/time 门（datetime-local
  → null）；setter Date→`_formatHtmlDateValue`。

## 与 spec 文本的两处偏差校正（运行期实证）

- **反向回退的解析失败例外**：spec 字面（回退 → return 不写值）与
  stepdown-02「value=''/min=7 → 期望 7」矛盾——当前值解析失败（→0）时
  Chromium `ApplyStep` 跳过回退判定（`!current_was_invalid`，源码实证）。
  带例外后「''/7 → 7」与「3/7 → 3」双断言同时成立，实现照此并注明。
- **sel 路径 latest-wins 读**：doc 元素代理 handle 为空（getElementById/
  querySelector 走 sel-only 键），`_suAttr` 原用裸 `__zw_get_attr`（读快照）
  漏同 turn IDL `min`/`step` 写——定向首轮 stepdown-02 3F/stepdown T1
  失败根因。改 `__zw_get_attr_lw`（与 R3037 getter 同款）+ 类型改走
  `_reflectedTypeEnum`（缺省 Text 状态/非法回退/ASCII 小写）。
