## 1. 根因

`HTMLImageElement.decode` 无实现（get trap 无 decode 臂，`img.decode`
undefined → TypeError），image-decode 族 60 子测试全红。SVGImageElement 同
缺（`decode is not a function`，svg.tentative 三文件）。

同步即决版（中断前遗留稿）三缺口（探针页 zz-probe-s69-decode 实证，验证后
已删）：

1. **同步即决**：②终态/③available-images 在 decode() 调用当拍即决 resolve
   ——spec decode 无同步 settle 面，同 turn 的 adopt（adopted-into-inactive
   案）在决断点不可见 → 误 resolve。
2. **pinned 恒拒臂**：detached 文档 createElement img 产物 decode 钉死恒拒
   ——adopt 进活跃文档后仍拒（adopted-inactive-into-active 案期望 resolve）。
3. **候选重读**：settle 时重读选中源会把「同 turn attach 进 picture」误判成
   未变异——spec decode 跟随**调用时**的 current request。

## 2. 修复面（R5276）

1. **共享解码核 `__zwImgDecodeCore(self, directCand, key)`**（part03 SVG 接
   口环后，IIFE 顶层，三调用方复用）：
   - 候选 = select-image-source 近似：nearest ancestor picture 的首个含
     srcset 的 `<source>` 首 token 优先（data: URL 不被逗号截断），否则
     directCand()；**调用时捕获**，settle（fetch 链）与快捷面（终态/
     available-images）复检变异 + 活跃性。
   - 活跃判别：ownerDocument 改指 + parentNode 链 root doc 非主文档兜底
     （探针 A 实证 adopt-out 后两者均正确改指）。
   - **恒异步 settle**（微任务决断）。
   - decode 只读：不写 `_resourceStates`/`_zwAvailableImages`、不派
     load/error——settle 写路径仍归 setter/sweep 单通道。
2. **part04 资源 trap IMG decode 臂**：瘦身为闭包供给（R3204 latest-wins 属
   性读通道 + 资源 key），决策移入核。
3. **part03 detached 产物动态臂**：调用时 parentNode 链判活跃——inactive →
   EncodingError；active（adopt-in 后）→ 走核。directCand 读属性空时回落
   `_dcE.src` expando（plain `_zwMEl` 无 src IDL setter）。
4. **SVGImageElement.prototype.decode**：href → xlink:href 候选走核。
5. **extract.rs collapsible_if**（s68 遗留 clippy 告警收口，非本切片行为变
   更）：`collect_fragment_imgs` 嵌套 if 折叠。
