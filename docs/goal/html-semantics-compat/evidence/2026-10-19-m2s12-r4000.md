# M2 切片 12 — populateForm 同 turn 二次插入 sibling 断链修复 R4000（2026-10-19）

## 范围（shim R4000）

切片 11 唯一挂账：`/common/targetted-form.js` `populateForm` 同 turn
两次 `body.insertAdjacentHTML('afterbegin')`，第二次批次的
`getElementsByName(frameName)[0].nextSibling` 返 null——
form-submission-algorithm t2/t3（firing submission events flag 契约，
切片 11 已就位）被挡。

- **根因**（part03 `_zwPendingParsedForSel`，R3254-K3 sel→pending 归一
  门）：候选收集循环内 `if (candCount > 1) return;` 把**签名盖章**
  （`nd.__zwSig3k = tag|id|name|class`）截断到前 2 个候选。hits 循环按
  `__zwSig3k === selSig` 全量比对——同 turn 第二批 insertAdjacentHTML 的
  pending 解析节点（第 3 个起）永无签名章（`sig=undefined`）→
  `hits=0` → 门判负 → nextSibling 落到 live/snapshot 视图（该节点只在
  apply-pending 视图存在）→ null。单批场景（keyboard goal 原始用例，
  ≤2 个顶层候选）侥幸通过；注释宣称的「签名歧义 → 保守不归一」实际由
  hits 侧 `hits === 1` 唯一性判定实现，候选数截断不是其实现且属缺陷。
- **修复**：删除该提前 return（一行），全量盖章；歧义保守语义不变
  （多节点同签名 → hits≥2 → 不归一，旧行为）。诊断过程（埋 tap 观测
  `cands/sig/hits` 与 bucket dump：第二批 iframe 过候选过滤但
  `sig=undefined`、修复后 `cands=4 hits=1 ret=Y`）存本轮会话账本，
  tap 已剥除。
- **已知面变化**（保守方向）：form 无 name 的多批场景，裸 tag sel proxy
  的签名从「误配第一批」变为「歧义不归一」——按 helper 注释语义本就
  应如此；corpus 全量零移动证实无回归面。
- part59 新增 `test_r4000_populateform_second_batch_sibling_chain`
  契约 1 测（W11）：targetted-form.js 形状两批插入，两批 iframe 的
  nextSibling/previousSibling 链按 composed 视图解析，form identity 用
  target 属性钉住（第二批 nextSibling 必须是第二批 form），first-child
  previousSibling 恒 null。期望串 `FORM|ftt-0,FORM|ftt-1,null,FORM|ftt-1`。
