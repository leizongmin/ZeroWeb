**spec 算法**（the-details-element exclusive accordions）两 prong：

- **others**（open 写入面，仅真开变迁）：subject 刚 open → 关组内全部其他
  open（spec「closing other elements if needed」；conforming 态组内至多一
  其他 open，本实现关全部与 spec 单关等价）。
- **given**（插入面 / name 变更面）：组内任一其他 open → 关 subject 自身
  （spec「closing the given element if needed」——insertion steps + name
  attribute change steps）。

组口径：同树根（parentNode 链顶，不跨 shadow 容器）+ 同名非空 name +
DETAILS；空/缺失 name 不成组。

**关键 trace 结论**（实现口径的两块基石）：

1. parser 元素创建时不在树内 → 创建面组空 no-op；互斥实际发生在
   insertion steps——解析场景树序第一 open 胜出、后续让位（test 2
   [true,false,false] 与 test 15 attribute order 无关性均由此解释）。
2. attribute change steps 随 parser 插入也运行 → 解析 open 面须排程
   toggle（test 16 `expect_opening(watch_e0)` 依赖）。与 test 3 的期望序
   ["e3","e2","e1","e0"]（要求解析面无 toggle）互斥——取 spec 字面口径
   （排程），test 3 维持 F（原也 F），净 +13P 且清 file Timeout。
