## 范围（shim R3903）

- **showPicker 族清零**：part03 方法分发区（stepUp/stepDown 同款模式）新增
  `input.showPicker()`——spec method steps（HTML §4.10.5.4）：
  ①不可变检查（disabled，或 readonly 适用 12 类型的 readonly）→
  InvalidStateError，此检查在激活检查与消费之前——readonly 抛错**不消费**
  激活（show-picker-disabled-readonly「User activation is not consumed」
  断言面）；②跨源 SecurityError 面不实现（归 navigation-compat M3 iframe
  门控域，本 headless 同源环境无此面）；③无瞬态激活 → NotAllowedError
  （hidden/button 等 mutable 类型同面）；④show the picker：同步消费瞬态
  激活（`_zwTransientActive = false`，spec 消费步在「不支持 picker →
  return」之前，headless 无 picker UI 消费不变）后返回，不触发 focus。
- **复用既有激活基础设施**：`_zwTransientActive`（part06 `__zwUserActivate`
  注入 / part02 `navigator.userActivation` 读取 / part04 fullscreen 消费
  先例），零新增状态通道。
- **readonly 适用面**：HTML §4.10.5 内容属性表 12 状态（text/search/tel/
  url/email/password/date/month/week/time/datetime-local/number）；
  WPT noReadonlySupport 10 类型之反面。
- 属性读走 latest-wins 三级回落（`__zw_has_attr_handle`/`__zw_has_attr_lw`/
  `__zw_has_attr`，disabled 属性分支 R2997 同款）——同 turn setAttribute 后
  立即调用不漏 pending 写。
- part16 新增 `test_input_show_picker_r3903` 行为契约单测（方法恒暴露 /
  NotAllowedError / 消费翻转 / disabled 与 readonly 适用类型抛
  InvalidStateError 不消费激活 / readonly 非适用类型不抛照常消费）。
