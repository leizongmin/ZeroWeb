R57 DC-11 text path unification: space advance fix + placeholder rendering
=======================================================================
Date: 2026-07-04
Branch: ui-sdk
Commit: (pending)

Summary
-------
Fixed bridge draw_text to handle whitespace/zero-size glyphs with real
fontdue advance instead of size_px * 0.5 fallback, matching the hand-drawn
`measure_advance` path. Enabled placeholder text "Search or enter URL..."
in AddressBarWidget with semantic token-derived color.

Changes
-------
1. ui/adapters/render-foundation/src/lib.rs: draw_text space handling
   - Old: match guard `Ok(bmp) if bmp.width > 0 && bmp.height > 0` dis-
     criminates; spaces (zero-size bitmap with non-zero advance) fall to
     `_` branch using `size_px * 0.5` as fallback advance.
   - New: `Ok(bmp)` always advances by `bmp.advance`; emit_glyph_image
     only for non-zero-size glyphs. Aligns with `raster_runs` pattern
     (always advance, skip image for zero-size).
   - `Err(_)` still uses `size_px * 0.5` as fallback (font error path).

2. browser-ui/chrome/src/render.rs: AddressBarWidget placeholder
   - New field `placeholder_color` derived from `on_surface.mix(surface,0.55)`
     ≈ hand-drawn `address_bar_placeholder` (muted gray).
   - paint() renders "Search or enter URL..." when text is empty, using
     placeholder_color. Replaces old skip-guard that deferred placeholder.

3. New tests (adapter-render-foundation):
   - `draw_text_with_spaces_advances_correctly`: "a b" emits 2 images
     (space zero-size → no image); 'b' x > 16px (past 'a' + space advance).
   - `draw_text_preserves_advance_for_non_emitting_glyphs`: "a b" vs "ab";
     space advances pen_x, making 'b' significantly more right.
