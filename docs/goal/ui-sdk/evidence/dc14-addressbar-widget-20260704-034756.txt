DC-14 chrome parity — AddressBarWidget 真实地址栏 pill
======================================================
Round 51（2026-07-04 03:47 UTC）

摘要
----
把 SDK `browser.AddressBar` 从 `ChromePanel`（44 高全填充、无 border）升级为真实
`AddressBarWidget`：32 高 pill（对齐手绘 `address_bar_layout` inset 6）+ 双层 fill_rounded_rect
border（外 address_bar_border 218 + 内 bg 248 inset 1px，镜像手绘 `render_address_bar`）+
URL 文本。chrome 区像素 diff 从 Round 50 的 4.43% 降到 **3.25%**（-1.18pp）。

实现
----
1. `ChromeTabColors` 加 `address_border: Color`（light=218,220,220 来自 address_bar_border）：
   - `from_tokens` 近似 `on_surface.mix(surface, 0.84)`（测试用）。
   - `sdk_chrome_tab_colors`（app_platform.rs）从 `ChromePalette.address_bar_border` 精确注入。
2. `AddressBarWidget`（render.rs，真实 impl Widget）：
   - 几何常量对齐 apps/browser/src/layout.rs：ADDRESS_BAR_HEIGHT=32（=44-2×6 inset）、
     RADIUS=16（=bar_h×0.5 完整半圆 pill）、BORDER_WIDTH=1。
   - paint：外层 `fill_rounded_rect(rect, 16, border_color)` + 内层 `fill_rounded_rect(inset 1,
     15, bg)`——**双层 fill 实现 border，复用现有原语，无需 stroke_rounded_rect**。
   - URL 文本 `draw_text` 在 security slot 之后（text_x = border + INNER_PAD_H + LEADING_SLOT
     = 1+12+28 = 41），文案色 = on_background token（对齐 address_bar_text）。
   - layout：宽填满（flex）+ 固定 32 高。
3. `register_chrome_factories`：`browser.AddressBar` 改注册 AddressBarWidget（传 tokens + tab_colors）。
4. `shell.rs` Desktop/Tablet toolbar 行：
   - 加 `cross_axis_align="center"`（容器属性）：address pill 32 高在 44 行垂直居中
     （bar_y = toolbar_top + 6），nav/security/menu 44 高（=行高）居中偏移 0 不受影响。
   - 移除原 address 节点 corner_radius=18（widget 自带 radius=16）。

诊断过程（关键定位）
--------------------
首版把 cross_axis_align 设在 address **子节点** → diff 反升至 5.91%（pill 顶部对齐 y=40
而非居中 y=46，整体偏移 6px）。读 host.rs `arrange` 确认 cross_axis_align 是**容器**属性
（line 1191 从 container node props 读），移到 toolbar 行后 pill 居中正确，border 像素对齐。

crate 零新依赖。
