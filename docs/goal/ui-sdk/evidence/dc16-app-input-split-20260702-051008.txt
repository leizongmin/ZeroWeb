## DC-14 替换式迁移设计备忘（本轮调查结论，供 GUI 会话执行）
- **overlay（additive）固有限制**：SDK DesktopBrowserShell 的 PageViewportFrame leaf 以 viewport-bg
  （background token = 白）填满内容区 → additive overlay 中 SDK viewport 白覆盖页面内容。这是 additive
  的固有结果（compose_overlay_rasterizes 测只验证 SDK chrome 像素可见，未验证页面可见）。
- **替换式迁移正确路径**（需 GUI 可视验收）：①build_scene 分离主 chrome（bg/tab_strip/tabs/address/
  nav/separator/bookmarks）/页面内容（gutter/frame/page_content→append_webview_primitives）/overlays
  到不同 fills/glyphs 缓冲（feature-off concat = 逐位不变，product-smoke 守）；②composition 改顺序：
  SDK chrome（不含 viewport 填充，或 viewport 改为 frame/border）→ 页面内容在其上（webview 覆盖
  viewport 区）；③render_page_content 用 render_chrome_via_sdk_with_layout 返回的 SDK viewport rect
  定位（SDK chrome 拥有布局）；④feature-on 跳过手绘 chrome；⑤GUI 可视验收。
- **关键设计决策**：SDK PageViewportFrame 当前是 solid fill（应改为 frame/border，让 host 内容透出），
  或 composition 保证页面内容在 SDK viewport 之上绘制。
