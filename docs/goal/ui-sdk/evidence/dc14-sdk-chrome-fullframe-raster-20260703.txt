DC-14 headless 可视验收推进：SDK chrome 替换路径完整帧 → 像素光栅
日期: 2026-07-03
分支: ui-sdk

================================================================
背景：本轮发现的 headless 验收缺口
================================================================
此前 DC-14 的 headless 像素证据仅覆盖：
- `compose_overlay_rasterizes_to_visible_framebuffer`：只测 **additive overlay** 路径
  （compose_sdk_chrome_overlay，旧方案：SDK chrome 叠加在手绘 chrome 之上）。
- `compose_replacement_*`：只验证 **scene 构造**（fills 置底 / page 翻译 / 无 viewport
  fill），未光栅为像素。

缺口：`render_cpu` 真实消费的 **替换式迁移路径**（compose_sdk_chrome_replacement_with_webview
→ webview surface 合成 → render_full_scene）的完整浏览器帧从未在 headless 下光栅为像素验证。
即「替换路径完整帧 → 顶部 chrome 区像素」未被自动化证据覆盖。

================================================================
本轮实现（纯测试代码，零生产路径变更）
================================================================
1. 新增 `#[cfg(all(test, feature = "sdk-chrome"))] pub fn render_full_scene_sdk_chrome_for_test`
   （apps/browser/src/app_platform.rs）：与 `render_cpu` 的 feature-on 装配**逐位一致**
   （build_scene → compose_sdk_chrome_replacement_with_webview 替换手绘 chrome + webview
   surface → render_full_scene），但返回 FrameBuffer 而非 present 到 softbuffer。镜像
   render_cpu 既有 disjoint-field borrow 模式（shell/tabs/font_loader/glyph_cache 不相交借用）。

2. 新增测试 `sdk_chrome_replacement_full_frame_rasterizes_visible_chrome_region`
   （sdk_chrome_tests 模块）：
   - BrowserApp::new(Cpu) + 1280×800 + scale 1.0 + 默认 active tab（image_cache 为 Some）。
   - fb = render_full_scene_sdk_chrome_for_test(1280, 800)。
   - empty_fb = render_full_scene(default RenderPrimitives) 作基线。
   - 断言①：整帧与空 scene 有差异（SDK chrome bars + 页面 surface 贡献像素）。
   - 断言②：顶部 chrome 区（y < 90，SDK chrome bars ≈ toolbar36+tab32+bookmarks28≈96）
     与空 scene 有差异 —— 证明 SDK chrome 在真实 render_cpu 装配下渲染到顶部 chrome 区像素，
     而非只在页面区/overlay 区贡献。
