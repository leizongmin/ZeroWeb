=======================================================================
Date: 2026-07-04
Branch: ui-sdk

Summary
-------
Completed the font metrics pipeline from the shared FontdueBackend through
WidgetHost to PaintCtx and all SDK chrome widgets:

1. PaintCtx.font_metrics: Option<(f32, f32)> field + line_metrics()
2. WidgetHost.font_metrics field + set_font_metrics() method
3. sdk_render.rs: inject_font_metrics() helper queries FontdueBackend
   and sets per-px normalized ratios on the host
4. Both render_chrome_via_sdk_with_layout and
   render_chrome_via_sdk_with_webview_surface now inject font metrics
   before painting

Metrics stored as normalized ratios (per-px of font_size) so widgets
using different font sizes get correctly scaled metrics.

Pipeline: FontdueBackend::line_metrics(FontId(0), 13.0)
  → WidgetHost::set_font_metrics(ascent/13.0, descent/13.0)
  → paint_node injects into PaintCtx.font_metrics
  → widgets call ctx.line_metrics(font_size) returning real metrics

The +0.02pp (27px) vs heuristic 2.00% is within debug noise. The real
metrics from FontdueBackend use the same font data as hand-drawn
chrome's FontLoader, so baseline calculation is now architecturally correct.

Remaining architecture gap
--------------------------
FontId(0) in sdk_font_backend()'s FontdueBackend and the primary
font_id in FontLoader are not explicitly mapped. Both load the same
font data (chrome_ui_primary_font_data) but assign independent IDs.
The FontLoader provides shared_id_of(rf_id) → FtFontId mapping but
this isn't used by inject_font_metrics. Fixing this would require
either passing the correct FontId from the browser app or sharing the
same FontdueBackend instance between SDK and FontLoader.
