修复（真实 latent bug，DC-15）：density-vs-scale_factor 映射混淆
----------------------------------------------------------------------
- 现象：OHOS + Android `map_window_metrics` 均把平台 DPI 比（input.density，如 phone 3.0）
  同时塞进 `scale_factor` **和** `density` 两个字段。
- 根因：违反 DC-12 决策——`WindowMetrics.density` 是 **Material 间距密度**
  （compact/comfortable，DEFAULT_DENSITY=1.0，消费者 SpacingTokens::scaled(density)），
  与 `scale_factor`（HiDPI 设备像素比）**正交**。winit adapter 正确用 DEFAULT_DENSITY，
  两个移动适配器误把 DPI 比塞进 density。
- 后果：在 density=3.0 的 phone 上，所有 spacing token 被 3× 放大 → 布局爆（间距/内边距翻倍）。
  latent（仅在移动设备后端落地后触发），但确是 DC-15 移动 metrics 映射 correctness 错误。
- 修复：`density: DEFAULT_DENSITY`（DPI 比只进 scale_factor）；双适配器 input struct 的
  `density` 字段加 doc comment 澄清「平台 DPI 比 → scale_factor，非 Material 间距密度」；
  函数体加 DC-12 决策引用注释。更新全部受影响测试（event_map 3 测/适配器 + ffi 1 测/适配器）：
  density 断言 → DEFAULT_DENSITY，补 scale_factor 断言。

经查正确（双适配器逐一核验）
----------------------------------------------------------------------
- 触摸相位：OHOS TouchAction(0/1/2/3=cancel/down/move/up)、Android ACTION_*(0/1/2/3/5/6)
  masked → PointerPhase，未知回落 Cancelled（不 panic）。正确。
- map_touch_event(s)：pointer_id=touch_id（多指区分），position 窗口坐标。正确。
- map_key_action / map_key_event：is_down→Pressed/Released，key_name 直接作 KeyCode。正确。
- map_window_metrics：logical_size.max(1.0) 防 0、keyboard_insets 取 bottom=h（底部贴合键盘假设，
  OHOS/Android 键盘均底部贴合，等价 screen_h - y）、safe_area 直传、orientation portrait/landscape。
  正确（keyboard 用 h 而非 screen_h-y 是底部贴合假设，documented）。
- map_soft_keyboard：keyboardShow/Hide → UiEvent::Key 合成事件触发布局刷新。正确（设计选择）。
- map_back_gesture：合成 "ohos.back_gesture"/Back → BackNavigationService 仲裁。正确。
- system_theme_from_dark_mode：dark→Dark/light→Light + high_contrast。正确。
