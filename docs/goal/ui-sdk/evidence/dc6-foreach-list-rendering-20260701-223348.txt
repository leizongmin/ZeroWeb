DC-6 列表渲染（for_each materialization）— 2026-07-01
=========================================================

里程碑：M3（DC-6 表达式/DSL），SDK-only（未触碰 render-foundation / apps/browser，无 product-smoke 风险）。

缺口（修复前）
-------------
- `for_each` + `item_alias` 仅在 loader 解析为 `ForEachSpec`（ui/core），但 eval 层**无 item 作用域物化**。
- 即 spec §8.4.7 主示例（`for_each: "$browser.tabs"` + `item_as: tab` + `$tab.title`）无法端到端求值，
  DC-6「列表渲染」（FR-008「列表渲染」）缺失。

实现（ui/dsl/src/for_each.rs，新增）
------------------------------------
- `materialize_for_each(spec, engine, ctx) -> Result<Vec<WidgetSpec>, DslError>`：
  1. 求值 `for_each.source` → `Value::Array`（Null→空列表；其它→Typecheck 错）。
  2. 对每个元素构造 item 作用域（克隆 ctx，注入 `item_alias → item`，原 ctx 不变 = 无副作用）。
  3. 在 item 作用域内：
     - 求值模板每个 `binding.source` → 写入 `binding.target` prop（列表渲染核心数据通路）。
     - 求值模板 `visible_when`：假值项**跳过**（条件纳入）。
     - 求值模板 `enabled_when`：结果编码为字面 `"true"`/`"false"` 字符串写回子节点
       （下游 host 在无 item 作用域时也能正确求值）。
  4. 产出具体 `WidgetSpec`，稳定 id = `<模板 id 或组件名>@<index>`。
- 安全（DC-6 资源上限 / spec 约束 7）：
  - 迭代受 `EvalContext::max_iterations` 约束，超限 → `DslError::EvalResourceLimit`。
  - 模板表达式**预解析一次**（避免每项重复 parse）。
  - 复用 Engine 四阶段管线，**不引入** lambda/递归/状态写入（文法封闭 + sandbox 安全）。
- 错误处理：缺 `control.for_each` / 缺子模板 → `Validate`；source 非数组 → `Typecheck`；
  迭代超限 → `EvalResourceLimit`；表达式 parse/eval 错误透传。

模块接线（ui/dsl/src/lib.rs）：`pub mod for_each;` + `pub use for_each::materialize_for_each;`。
