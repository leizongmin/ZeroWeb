## 目的

DC-2 终端「真实 EventLoop::run 阻塞壳」的设计前置：把建树 + 工厂注册 + 首帧从阻塞的 GUI
run loop 中抽离为 headless 可单测的 setup 核心，解决「driver 需在 begin 前注册工厂」的
设计 blocker（WinitDriver 需工厂注册后才能 begin，但 PlatformRuntime::run 的
`&mut dyn UiApp` 签名不暴露工厂注册）。launch 用 register 闭包承载应用特定工厂注册。

## 交付（ui/adapters/winit/src/runtime.rs）

新增 `WinitRuntime::launch<'app>(app, metrics, register: impl FnOnce(&mut WidgetHost)) -> WinitDriver<'app>`：
1. `WinitDriver::new(app, metrics)` 构造 driver。
2. `register(driver.host_mut())` 经闭包注册应用控件工厂（在 begin 前）。
3. `driver.begin()` 产出首帧（reconcile + layout + paint）。
4. 返回 driver 供真实 run loop 继续喂事件。

文档化的真实 run 形态（GUI-gated，本轮不实现）：
    let mut driver = WinitRuntime::launch(app, metrics, register);
    event_loop.run(|ev, _| {
        driver.pump_event(&event_map::map_*(ev));
        driver.pump_frame();
        render(driver.host().scene());  // 经 zero-ui-adapter-render-foundation 光栅
    });

## 测试（headless）

    $ ./target/test-guard -- cargo test -p zero-ui-adapter-winit launch
    test runtime::tests::launch_registers_factories_before_begin_and_returns_drivable_driver ... ok

`launch_registers_factories_before_begin_and_returns_drivable_driver`：
- 经 launch 注册 _Box 工厂（闭包）。
- 断言 register 在 begin 前调用：_Box 挂载 + 首帧 paint → scene 非空（否则组件未知为空）。
- 断言返回的 driver 可继续驱动：点击 → _Box emit "box.click" → _App.dispatch Handled →
  重建（out.emitted_actions==1 / spec_rebuilt）→ pump_frame；driver 作用域外 app.clicks==1。

## 风险 / 剩余

- SDK-only（adapter 未触渲染像素/浏览器）→ 无 product-smoke 风险。
- **DC-2 剩余唯一项 = GUI-gated 的 event_loop.run 包壳**（EventLoop::new / Window / GPU surface
  + 阻塞 loop，需 GUI 验证首帧）。launch 是其可测试 setup 核心；真实 run 只需在 launch 外
  包一层 EventLoop + event_loop.run（调用 driver.pump_*）。本环境无 GUI，留 GUI 会话落地。
- 其它终端门禁（DC-14 浏览器迁移 GUI 可视 / DC-15 真实移动后端首帧 / DC-8 真实平台 a11y）
  均需 GUI/设备环境。
