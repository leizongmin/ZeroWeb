Summary
-------
Added `PaintCtx::line_metrics(font_size) -> (f32, f32)` method providing
font-agnostic (ascent, descent) metrics for baseline calculation. Updated
all SDK chrome widgets (AddressBarWidget, BrowserTabStripWidget,
BookmarksBarWidget, FindBarWidget, SecurityBadgeWidget) to use the same
baseline formula as hand-drawn chrome's `ui_text_centered_in_height`:

    let (ascent, descent) = ctx.line_metrics(font_size);
    let line_h = ascent - descent;
    let text_top = (box_h - line_h) * 0.5;
    let baseline = text_top + ascent;

This replaces the previous per-widget hardcoded heuristic
`h * 0.5 + 13.0 * 0.36` with a centralized method that future font
backend integration can override with real font metrics from
`FontdueBackend::line_metrics`.

Changes
-------
1. `ui/core/src/widget.rs`: Add `PaintCtx::line_metrics()` method with
   default heuristic (ascent=font_size*0.92, descent=-font_size*0.23 ≈
   typical UI font ratios). Docstring includes usage example matching
   hand-drawn `ui_text_centered_in_height`.
2. `browser-ui/chrome/src/render.rs`: Update 5 widget implementations:
   - AddressBarWidget: `(h + ascent + descent) * 0.5` baseline formula
   - BrowserTabStripWidget: same, using TAB_BAR_HEIGHT as box height
   - BookmarksBarWidget: same, using size.height
   - FindBarWidget: same, using size.height
   - SecurityBadgeWidget: same, using size.height

Architectural significance
--------------------------
`PaintCtx::line_metrics` is the single injection point for real font
metrics. When the bridge (`RenderFoundationBackend`) or host later has
access to `FontdueBackend` at paint time, it can set a custom provider
on the paint context and all widgets automatically inherit the correct
baseline calculation — no per-widget heuristic updates needed.
