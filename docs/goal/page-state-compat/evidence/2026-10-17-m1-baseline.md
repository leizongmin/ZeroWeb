## M2 输入（本轮已实证的规范/协议事实）

**Beacon processing model**（w3c/Beacon index.bs，main）：URL 解析失败或 scheme 非
http/https → TypeError；data 提取字节流（keepalive 旗标），64KB 配额超 → 返 false；
CT 非 safelisted → corsMode cors（safelisted → no-cors）；**先 return true 再并行
POST**（method POST、credentials include、initiator type "beacon"）。

**Origin header**（fetch.spec §append-a-request-origin-header，whatwg/fetch fetch.bs
实证）：非 GET/HEAD 非 cors 请求按 request referrer policy 序列化——`same-origin`
策略跨源 → `Origin: null`（`header-origin-same-origin.html` 的 meta
`content='same-origin'` + 跨源腿期望 `"null"` 的规范依据，2024-02 #44731 引入）；
`no-referrer` → null；降级策略 https→非https → null；`origin`/`origin-when-cross-origin`/
`unsafe-url` → 文档 origin。

**fixture 协议**（pin 版 .py 源实证；runner 侧 Rust 等价实现，upload.py 先例）：

- `beacon/resources/inspect-header.py`：`put` → stash[id] = 指定请求头值（缺 → ""）；
  `get` → take 语义，有值则回 `x-request-<header>` 响应头（空值也回）
- `beacon/resources/content-type-and-body.py`：`put` → stash[id] = `CT: body`；
  `get` → take，无值 400
- `beacon/resources/url-echo.py`：`store` → stash[id] = 原始 query 串（utf-8 百分号
  编码形态）；`stat` → take，无值空体

**runner 页锚**：`https://wpt.test/<case>`（page-state 通道全 https）——referrer 用例
的 http 目标腿（`get_host_info().HTTP_ORIGIN` 等）为跨源 + 降级复合面；beacon POST
路径不做 mixed content 阻断（FIXME 记账，corpus 对阻断腿以 mayBeBlockedAsMixedContent
容忍 false，但非阻断腿期望真投递）。
