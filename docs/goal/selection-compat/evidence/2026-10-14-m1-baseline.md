## 失败清单（5）

1. `selection/anchor-removal.html :: anchorNode snaps up to parent when
   removed (no asserts)` — Actions 拖选未构建选区（runner Actions shim 只有
   pointer 事件序列，无坐标→文本偏移命中）。
2. `selection/anchor-removal.html :: anchorNode snaps up to parent when
   removed (with asserts)` — 同上（with-asserts 变体，首断言
   `anchorNode before move expected Text node but got null`）。
3. `selection/script-and-style-elements.html :: Selection: STYLE and SCRIPT
   elements should be included in Selection.toString() if they are
   display!=none` — toString 走 raw data 拼接，未实现 rendered text 语义
   （display:none 剔除 + 空白折叠 + 块级折行）。期望值（测试内
   `\r\n`→`\n` 归一后）：
   `'\nstyle { display:block; color: green; } script { color: blue; }\nfunction test_block_script() { let pre = document.createElement("pre"); pre.append(document.createTextNode("PASS")); document.getElementById("p1").append(pre); }\n\nPASS'`
4. `selection/Document-open.html :: Selection must not be replaced with a new
   object after document.open()` — `iframe.contentDocument.open is not a
   function`，document.open() 未实现；用例断言 open 后 Selection 单例恒定 +
   rangeCount 保持 1。
5. `editing/event.html :: Changing selection from handler: input event` —
   execCommand input 事件 target 语义，**goal 边界显式排除域**（editing 域）；
   与已归档 editing-contenteditable csv 行（2999/2994）记录的失败集一致。

## 语义参考（toString 修复依据）

- selection-api §Selection stringifier：
  https://w3c.github.io/selection-api/#dom-selection-stringifier ——
  「concatenation of the rendered text」+ textarea/input 例外（value 子串）。
- HTML Standard rendered text collection steps（innerText 同源算法）：
  https://html.spec.whatwg.org/multipage/dom.html#rendered-text-collection-steps
  ——display:none 子树不产出（not being rendered → return items）、Text 按
  CSS white-space 处理、块级元素首尾各记 1 个 required line break（RLBC
  margin-collapsing 式合并）。
- 互操作注记：现代 Chromium（本轮 v-pw chromium-1243 实测）对该 WPT 用例
  文档产出 `"A\nB\nPASS"` 形态（无首行换行、pre 前单换行），与 WPT 期望串
  `"\nA\nB\n\nPASS"` 不一致——期望串编码的是旧引擎（`\r\n` 时代，测试内
  `.replace(/\r\n/g, "\n")` 即为其痕迹）行为。本仓验收以 WPT 期望串为准，
  修复按期望串落实现，该分叉记为已知互操作缺口。
