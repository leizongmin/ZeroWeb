## 二、RFC 交付（docs/specs/p1b-l2d3-unified-matcher-identity-bridge-rfc.md v0.1）

- **四对象域盘点**（代码核实）：A. sel proxy（`_wrapSelector`，host 快照元素）/
  B. handle proxy（`_makeProxy`，createElement/shadow/fragment）/
  C. mutTree 节点（`_zwMEl`，唯一有真实子树链接）/ D. 解析 wrapper
  （`_zwParseEl`，JSON 往返只读快照）。跨域既有桥接仅三个局部点
  （R100 sel→handle 反查 / R163 fragment 真实节点优先 / R164 doc 纯 tag 直出）。
- **identity 桥设计**：模块级 `node → 首次暴露对象` 登记表（首登记者胜、
  4096 上限全清、树代际 bump 全清、key 恒 plain 节点）；d3a 只登记，
  d3b 消费归一。
- **统一匹配器**：复用既有件——`_queryTreeByCompound`（R165）+
  part05 `_handleSubtreeNodes`+`_matchComplexAgainst`（handle 域已是完全
  本树化的完整选择器引擎，四组合器+结构伪类——**这是目标形态的已存在先例**）。
- **切片序**：d3a 桥基建登记（零行为变化）→ d3b 查询产物归一 →
  d3c doc compound gate → d3d element/fragment 本树化 → d3e 组合器/伪类
  本树化。每片独立 land，全量双路径 net≥0。
- **明确不做**：A/B 域不迁 C 域（host 权威节点视图，强行本树化 = 重造 host
  同步协议，R133 已否决）；JSON 往返永续保留为回落。

## 三、d3a 落地（代码）

| 件 | 内容 |
|----|------|
| 桥本体 | `_zwNodeBridgeMap` + `_zwBridgeSet`/`_zwBridgeGet`（part03 模块级） |
| 登记点 ×3 | queryBody L2-d1 真实节点直出 / fragment QSA real163 命中 / `_zwMEl` 工厂出口（全覆盖 cloneNode/树建/fragment 解析产物） |
| 失效 | 5 处树代际 bump/clear 点同步 `_zwNodeBridgeMap.clear()` |
| 导出 | `globalThis._zwBridgeSet/_zwBridgeGet`（R79 poke 模式） |
| 单测 | part22 三件：API 语义（首登者胜/miss/防御入参）、mutTree 登记 identity 稳定、fragment QSA 零回归 |

**实现过程坑（记档）**：桥首版误放 `_makeDetachedDocument` 内部——`_zwMEl`
（模块 IIFE 级）出口调用会 ReferenceError。**scope 分析方法论**：用 acorn
解析完整拼接 shim（8 parts 单独不可解析——行边界切分），walk AST 取
FunctionDeclaration 链定位 def/call 作用域。修法 = 桥提升到 `_zwMEl` 定义之前。

**活证据（四域分歧样本，d3b 输入）**：单测实证 createElement（handle 域）
appendChild 进 fragment 后，QSA 键匹配（tag+id+outer）对其 **miss**
（handle 元素 outerHTML 序列化与 mutTree 键形态不同源）→ QSA 返 wrapper ≠
`frag.childNodes[0]` 本体。这正是 RFC §1.1 域分歧的运行时样本。
