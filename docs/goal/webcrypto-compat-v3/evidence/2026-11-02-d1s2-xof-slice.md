## 切片内修复（定向语料暴露）

**digest name 单次读（cSHAKE 语料暴露——getter 式 transfer 探针组全组
Fail）**：digest 函数对 `algo.name` 读两次（null 检查 + 归一化），第二次读
对 getter 式 transfer 语料（xof_digest.js `during call` 变体）触发 getter
内 `buffer.buffer.transfer()`——首次 getter 调用时已 detach，再 transfer 抛
`TypeError: Cannot perform ArrayBuffer.prototype.transfer on a detached
ArrayBuffer`，`transferred buffer during call` 组全 Fail（stable 案
`transferBeforeCall: true` 同构面从未踩到此路径）。spec normalizeAlgorithm
对 "name" 恰取一次——改单次读存局部变量（`var algoName = algo.name`），
该组 24 案 → 0。既有 digest 面（SHA-1/256/384/512）同函数共享该修复，
全量锚对照零回归实证无外溢。

## KT256 24MB 案间歇 flake 专项（挂账归因，不阻塞域收敛）

**现象**：`digest/kangarootwelve.tentative.https.any.worker.js :: KT256
vector #9 (512 bit output, 24137569 byte input) and transferred buffer
after call` 间歇 `assert_true: digest matches expected … true got false`。
唯一复现案（24MB 输入 ×512 bit 期望，语料最大 wire 载荷），其余 591 子
测试稳定。加诊断版二进制内复现率约 1/6（6 次隔离跑 1 次），其余全绿。

**排查与证据链**（临时探针案 + host 指纹诊断，均已用后删除）：

1. **host 算法正确性独立验证**：scratch crate 以 k12 0.5.1 独立计算
   KT256(ptn(17⁶)) 64B，与语料期望 `0652b740d78c…004da` 逐字节一致——
   host `Kt256::default()` 分派与输出转换无误。
2. **现场捕获（探针案，window 腿 round 6/6）**：同一 24MB buffer 并行
   digest KT256/SHAKE256/SHA3-256 三族，**KT256 返回全长 128 hex 错值
   `7cc4e634152b4122…`，同轮同 buffer 的 SHAKE256/SHA3-256 正确**，输入
   抽样（首/中/尾字节 + 长度）完好，错值非截断/非空哨兵/非位翻转。
3. **输入损坏假设未排除（修正推理）**：KT 为随机预言机——任何损坏输入
   都产出「合法摘要」形态，故错值合法外观不能反推输入无恙；错值前缀在
   语料期望值全文检索无匹配（损坏输入非语料向量，一致）；13 组截断/偏移
   假设（分块边界 2²⁴、±1、半界、四处偏移）逐一独立计算全否。
4. **host 指纹诊断**（IN/OUT 双点 FNV + 长度 + 首尾 32 hex 落盘）：
   诊断在场 11+ 连绿（KT 语料 592 调用/轮 × 3 + 探针 8 轮）零复发；干净
   二进制 KT 语料 10+ 连绿零复发。诊断的 fs 写入改变分配/GC 时序——
   heisenbug 特征实锤。
5. **归因**：故障位点在 rquickjs 0.7 桥层 `Rest<Coerced<String>>` 参数
   拷贝（48 MB hex 字符串 JS→Rust 转换）或 QuickJS GC 时序交互，非 host
   crypto 实现面。修复面属 script-sandbox/引擎桥层，超出 D1 域切片授权
   范围。
6. **挂账决定**：按 DC-3「通过率 + 失败归因」口径落账（本节即归因账），
   不阻塞域收敛；后续每轮全量语料跑自然复跑该案，若再现按本节指纹法
   （host IN/OUT 双点诊断）续捕。域账面 KT 五文件按本轮全绿数计。
