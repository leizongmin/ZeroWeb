## host 实现

- **KMAC**（`crypto.rs` `crypto_subtle_kmac`，+143 行含单测）：SP 800-185
  §4.3 手写组装叠官方 cshake 0.2.1（D1 拍板③ option b——sha3-kmac
  MIN_KEY_SIZE 拒语料 16B/24B key，预检实锤）。组装 = `left_encode(rate) ||
  left_encode(|K|bits) || K || 补零至 rate 整数倍 || X || right_encode(L)`
  （X 裸拼接；bytepad 补零对齐 cSHAKE rate 吸收边界），rate 168/136；
  out_bits 上限护栏 16 MiB（同 xof digest 口径）；customization 经 cSHAKE S
  参数。NIST 全 6 向量单测随切片落仓（`kmac_nist_tests::nist_samples_all_six`，
  KMAC128×3 + KMAC256×3 逐字节）。**密钥材料零落日志**（key 仅经 CSV 桥）。
- **X448**（`crypto_asym.rs`，+342/−行 OKP 段参数化扩 X448）：`OkpKind` 三态
  （Ed25519/X25519/X448）、DER 前缀常量（spki `30 42 …2b 65 6f 03 39 00` /
  pkcs8 `30 46 …2b 65 6f 04 3a 04 38`）、`crypto_subtle_x448`——host 两条
  拍板义务落地：① import 无贡献性检查（`x448::Secret::from_bytes` 仅长度
  面；小阶点导入必须成功，语料正例）；② derive 全零/小阶 → 空串 ≡
  OperationError（`as_diffie_hellman` None + Some 全零双路径，RFC 7748 §6
  all-zero 判据）。host 单测 4（fixture KAT / 良构对生成 / 小阶导入成功 +
  derive 拒绝 / pkcs8 round-trip）。
- `callbacks.rs`（+2 注册）：`__zw_crypto_subtle_kmac`（arg[3]=out_bits u32
  String 桥）、`__zw_crypto_subtle_x448`。

## 切片内修复（定向语料暴露）

1. **KMAC newX 语义误读（NIST 全 6 向量不中，双实现互证不能发现的同源规范
   误读）**：初稿把 TupleHash 的逐元素 encode_string 串到 KMAC——
   `|| encode_string(X) ||`，而 SP 800-185 §4.3 原式 X 裸拼接。RustCrypto
   cshake crate 与独立纯 Python Keccak-f[1600]（先对 hashlib SHAKE128/256
   逐字节验证）两套实现产出同一错值——互证失效，最终对 NIST SP 800-185 原文
   + KMAC_samples.pdf 仲裁后修正，6/6 闭合。bytepad 零填充（同轮补上的正确
   改动）保留。语料期望值程序化解析取数（手抄长 hex 曾制造 S4/S6「前 16B
   一致后发散」假案）。经验沉淀
   [kmac-newx-raw-x](../../../../learnings/bugs/2026-11/2026-11-03-kmac-newx-raw-x-vs-tuplehash-encode-string.md)。
2. **KMAC 算法对象 name 二次读（transferred buffer 组 48 Fail）**：WPT
   mac.js shared driver 的 transferred 用例把 algorithm.name 设为 getter
   （每读一次触发一次 `buffer.transfer()`）；sign/verify 顶部读一次后，
   `_zw_kmacMac` 内部再读 `algo.name` 两次 → 第二次 transfer 在 detached
   ArrayBuffer 上抛错。修复 = name 作参数传入（`_zw_kmacMac(algoName, …)`），
   函数内不再读 algo.name。与 d1s2「digest name 单次读」同类（normalize
   get "name" 恰一次），HMAC 臂传 key.algorithm（普通对象）天然免疫故未
   暴露。
