关键 API 面（0.3.3 / 0.1.1 实测行级核对）：

- ml-kem：`Seed = Array<u8, U64>`；`DecapsulationKey::<P>::from_seed(seed)`
  （inherent，按值）+ `.encapsulation_key()`；`EncapsulationKey::<P>::new`
  + `Encapsulate::encapsulate()` → `(Ciphertext, SharedKey)`；`KeyExport::

  `.expanded_key()`；`ExpandedSigningKey::sign_deterministic(M, ctx)`（FIPS
  204 Algorithm 6 确定性变体；ctx > 255 → Err，shim 侧先校验同语义）；
  `ExpandedSigningKey::verifying_key()` + `VerifyingKey::decode` +
  `.verify_with_context(M, ctx, &Signature)` → bool；`Signature::<P>::
  try_from(&[u8])`（长度 + 范数双检——坏签名自然落 verify false 面）。

## 密钥线格式（fixtures 逐字节实测）

- **spki**（RFC 5280）：`SEQ { AlgId SEQ(13B), BIT STRING(0x00‖key) }`；
  AlgId = `30 0b 06 09 60 86 48 01 65 03 04 fam var`（NIST PQC OID
  2.16.840.1.101.3.4.fam.var；fam 0x04=KEM / 0x03=DSA，var 01/02/03 与
  11/12/13 按参数集）。
- **pkcs8**（RFC 5958 seed-only）：`SEQ { INT 0, AlgId, OCTET STRING {
  [0] 上下文原语 TLV(0x80‖seed) } }`（KEM 86B、DSA 54B——OCTET 内层
  [0] 标签形态由 fixtures 实测定谳，非直接裸种子）。
- **raw-public / raw-seed**：原始 ek/pk（KEM 800/1184/1568 B、DSA
  1312/1952/2592 B）/ 种子原样（KEM 64B、DSA 32B）。
- **jwk**：AKP（`kty:'AKP'`、`alg` = 算法名、`pub` = raw 公钥 b64u、私
  加 `priv` = 种子 b64u）；私钥导入做配对校验（种子派生公钥 == pub）。

## 切片内修复（定向语料暴露）

1. **DER AlgId 比对段错位（ML-KEM importKey 语料 pkcs8/spki 全组 Fail）**：
   `ml_spki_parse`/`ml_pkcs8_seed_parse` 对 `der_tlv_parse(body, 0x30)`
   返回值（SEQ **内容** = OID TLV 11B）与完整 13B AlgId SEQ TLV 全字节
   比对——恒失配 → DataError。修正为与 `alg_id[2..]`（OID 段）比对；
   scratch 逐字节复现验证后修复，两组全绿。
2. **encapsulateBits 双段序颠倒（encap_decap_bits basic 全组 Fail）**：
   host wire `ct;ss`（首段密文、次段共享秘密），shim 误将首段作
   sharedKey（`expected 32 but got 768`）→ 次段作 ciphertext 连锁
   round-trip OperationError。修正拆序。
3. **encapsulateKey/decapsulateKey usage 面误挂（encap_decap_keys 全组
   480 Fail）**：初版内部复用 encapsulateBits（校验 "encapsulateBits"
   usage），而语料密钥对 usages = ['encapsulateKey','decapsulateKey'] →
   InvalidAccessError。重写为自校验（"encapsulateKey"/"decapsulateKey"）
   + 直调 host + importKey 链（WICG §12.6/12.7 步序），240×2 全翻绿。
