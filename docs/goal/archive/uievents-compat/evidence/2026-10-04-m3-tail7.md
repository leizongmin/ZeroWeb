# M3 尾簇 7——R334 重插的同 turn 查询可见性（mouseover-at-removing 58F 收口）

**日期**: 2026-10-04
**结果**: corpus 1115P/743F/97TO → **1167P/684F/97TO（+52P，零真回归）**
**证据**: [2026-10-04-m3-tail7.json](2026-10-04-m3-tail7.json)

## 缺口

`uievents/mouse/mouseover-at-removing-mousedown-target.html`（?duration=16/42 两变体 × 30
promise_test 迭代）58F：i0 断言过，i1 起全链 `TypeError: Failed to execute 'appendChild'
on 'Node': parameter 1 is not of type 'Node'`。

## 根因链（zwprobe 三轮探针实证）

1. **测试形态**：每迭代 mousedown listener `child.remove()`，finally
   `parent.appendChild(child)` 复位，迭代间仅隔两个 rAF。
2. ** TypeError 的真身**：i1 起 `getElementById("child")` 返 **null**（非 brand-check
   失败）——`child.getBoundingClientRect()` 对 null 抛错，finally
   `appendChild(null)` 二次抛错替换原始错误。i0 的 finally 重插 shim 侧成功
   （parentNode/childNodes 对），但查询层看不见。
3. **单轮 microtask 塌缩**：i1 同步抛错（gBCR 前 no await）→ i2..i29 在**同一探测轮的
   microtask 级联**内依次失败——任何泵 turn 都不插入，永不自愈。修复必须使重插在
   **同 turn** 查询可见。
4. **查询断代窗口**：R334 sel 子重插的结构 wire（`InsertAdjacentSelElement`）异步
   drain，窗口内 host 视图/live doc 皆不含该子；`getElementById` →
   `querySelector('[id=…]')` → host 查询层 → miss。
5. **by-id 补偿路径失效原因**：R51c `_zwPAIdAdd` 以 `nd.id` 登记——重插子宿主侧已无
   节点，id 读链落空返 `''` → no-op（内置 addFlat 登记同病）。

## 修复（三件）

1. **by-selector 重插索引**（part05 `_zwPendReselBySel`）：以 R334 已知的
   `__zwSelector`（'#child'）为键直登节点；gEBI 在 pendingEarly 后查 `'#'+id`
   （in-doc 门 = `_zwSelPendingParent` 槽 parentSel 的 `_zwMutationInDoc` 判定）。
   表随 `__zw_reset_pending_state`（导航 + apply 代际 bump 共用体）清空——drain 后
   live doc 已含该子，无缝切常规读链。
2. **探测轮首 flush**（`WebView::flush_pending_shared_mutations` +
   `take_probe` 入口调用）：上一轮 JS 排队的结构 wire 在本轮 JS 前落活 DOM，跨轮
   查询/命中少断一代（真实浏览器 DOM 变更同步可见的近似；队列空 cursor 早退零成本）。
3. **variant 值大小写保真**（`case_variants`）：旧实现整体小写源码后提取
   `<meta name="variant" content>`——`?Shift`/`?pointerType=mouse&preventDefault=…`
   被写成 `?shift`/`?pointertype=…`，页面 `URLSearchParams.get`（大小写敏感）miss
   → modifier 族 `keyDown(undefined)` 16F、click_during_parent_capture /
   synthetic-button-state 的 pd=/buttonType= 变体**实际跑在 pd='' 配置**。修复后
   匹配在小写镜像上做、值切片回原文（ASCII 小写逐字节等长）。

## 排除路径（bisect 记录）

- `DetachedNodeStash`（尾簇 4）非本根因：runner env 的 remove→re-append 链 stash 命中
  正常（`frag_stash_hit=true`），问题在查询层不在宿主 apply 层。
- `with_query_view_doc` 把 `InsertAdjacentSelElement` 纳入 live_ok 排除 + 视图烘焙
  （已回退）：`live_ok` 扫的是 append-only 队列**全史**——任一 sel-insert 入队（即使
  已 drain）即永久切视图路径，视图基底缺动态创建子树 →
  `pointerevent_after_target_removed` 4P→2P 真回归。队列水位线（drain cursor 发布到
  callbacks 层）是后续可行方向，本轮不做。
