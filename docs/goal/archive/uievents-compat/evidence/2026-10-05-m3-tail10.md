## 缺口

`pointerevent_fractional_coordinates_untrusted.html` 352F（11 MouseEvent 型 × 32）：
`new MouseEvent(type, {clientX: -0.7, ...})` 读回 clientX=0（V8 ToInt32 truncate）、
`offsetX/offsetY` undefined（native 模板无此二属性）。同文件 PointerEvent（click/
auxclick/contextmenu floor、其余型 exact）与 WheelEvent/DragEvent 全走 shim
`_defineEventSubclass` → `_zwMouseCoordInit`（尾簇 6）已绿——**唯 native 模板构造的
MouseEvent 缺口**。

## 根因

R384 起原生绑定是唯一生产路径，但 native 模板只注册 Event/CustomEvent/MouseEvent/
KeyboardEvent 四类（R109 注记）——MouseEvent 的坐标族经 `init_int`（V8 `int32_value`
truncate toward zero）读入，且无 offsetX/offsetY/page 派生逻辑。尾簇 6 的
`_zwMouseCoordInit`（floor + page/offset 派生）只活在 shim 构造路径，native 路径
未对齐。

## 修复（`crates/engine/src/dom_bindings/event.rs` native_mouse_event_constructor_invoke）

1. **`init_floor_int` helper**：init dict 读 f64 → `floor()` → i32（非 finite → 0）。
2. **坐标族 floor**：screenX/screenY/clientX/clientY 改走 floor 读入。UI Events 的
   MouseEventInit 按 WebIDL 是 long（truncate），但双引擎实测对坐标统一 floor——
   WPT 对 `Math.floor`（负值 [-1.0,-0.5) → -1 非 0）逐位断言，浏览器现实为准。
3. **pageX/pageY/offsetX/offsetY 派生**：init 显式给了（非标准扩展面，shim R150
   同款兼容）→ floor 采信；缺省 → 派生 = floor(clientX/clientY)（target-less/
   undispatched 事件的 CSSOM-View 语义，Chrome/Firefox 同）。**`is_number` 门**：
   缺失键 `opts.get` 返 undefined，其 `number_value` 是 Some(NaN) 而非 None——NaN→0
   回落会以 0 压掉派生值（首轮实测 floor≠0 的 4 个范围 44×4 全灭，即此坑）。

## 排除路径（实证，勿重试）

- PointerEvent exact 分支判定不受影响：`(new PointerEvent("click",{screenX:0.1})).screenX`
  经 shim floor → 0 ≠ 0.1 → 测试走 floored 分支（与修复前一致）。
- 派生值不得读 `this`（已 set 的 clientX）——读 init dict 原值再 floor；两步结果
  一致但保持单一事实源。
- `movementX/movementY/button/buttons/detail` 保持 `init_int`（未在断言面，精准修改）。
