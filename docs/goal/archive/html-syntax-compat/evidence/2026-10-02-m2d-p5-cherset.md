## P5 首片：`<meta charset>` 预扫描 → `document.characterSet`（+2：quotes/meta 全绿）

spec「encoding sniffing → prescan」的字符串近似（runner 以已解码字符串载页）：

- **zero-dom**：`sniff_meta_charset`——前 1024 字符 `<meta` 扫描；charset 属性 > 
  http-equiv=content-type 的 content 属性（meta-inhead 面）；「提取 meta 编码」算法的
  **无闭引号 → failure**（quotes-in-meta 面）与 **label 不可识别 → 继续扫描**（spec
  prescan failure 规则）；属性值基础实体解码（dom_html **序列化快照重解析**形态——
  裸 `"` 序列化为 `&quot;`，不解码则引号语义失效——实测抓到）。`Document` 增
  `encoding_label` 字段；zero-dom 增 encoding_rs 工作区依赖（Cargo.lock +1 行）。
- **engine**：原生 getter（with_dom 读 label → encoding_rs for_label 归一名）+ 新回调
  `__zw_get_character_set`（dom_html 快照同款借用）；shim 主文档三面
  （characterSet/charset/inputEncoding）改读回调——旧常量 'UTF-8' 遮蔽真值是首跑
  失败根因。

## 工具面：`ZW_CORPUS_CASE_TIMEOUT_SECS` 案预算覆盖

runner 单案预算可按跑覆盖（缺省 30s 不变）。**过程记账**：初版 sed 把函数体内
`unwrap_or(CORPUS_CASE_TIMEOUT)` 也替换成自调用——无限递归在 case 线程栈溢出静默
abort，主进程 0% CPU 永久等待（构建 warning 才暴露）。已修 + 验证；html5lib 首轮
「悬挂」结论系该 bug 冤案（300s 预算复评未做，随下片）。
