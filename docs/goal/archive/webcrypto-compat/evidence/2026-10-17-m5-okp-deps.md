# M5 OKP 依赖选型（2026-10-17）

## 范围

OKP 家族（Ed25519 签名 + X25519 密钥协商）全链：importKey（raw/spki/pkcs8/jwk）、
generateKey、exportKey 四格式、Ed25519 sign/verify、X25519 deriveBits/deriveKey。
Ed448/X448 为 tentative 域，本次不引入。

## 选型

RustCrypto 之外的 dalek 系（curve25519-dalek 同一代的稳定封装，纯 Rust 无 C
依赖）：

- `ed25519-dalek = "3.0"`（RFC 8032 纯 EdDSA：`SigningKey`/`VerifyingKey`，
  签名经 `Signer` trait，验签用固有 `verify_strict`——拒小阶 R 与小阶 A，
  对应 WPT eddsa_small_order_points 伪造面，见 eprint 2020/1244）
- `x25519-dalek = { version = "3.0", features = ["static_secrets"] }`
  （RFC 7748：`StaticSecret::from` 标量钳位 + `PublicKey::from(&ss)`；默认
  feature 含 `zeroize`，`static_secrets` 才开放 X25519 静态标量构造）

DER 编解码按 RFC 8410 定长结构手写（Ed25519 SPKI 前缀 12 字节
`302a300506032b6570` + PKCS#8 前缀 16 字节 `302e020100300506032b6570042204
20`，X25519 仅 OID 字节 `2b656e` 之差，总长 44/48），不引 `pkcs8` feature、
无新底层 crate。MSRV：两 crate 均 1.85，与 workspace 一致。

## 对比

- dalek 系（3.0）**选**：curve25519/dalek 是 audited 系（curve25519-dalek
  经多次第三方审计），纯 Rust；ed25519-dalek 3.0 与 x25519-dalek 3.0 构建
  于同一 `curve25519-dalek 4` 代，去重同一实例。
- RustCrypto 侧无 curve25519 全功能对等实现（`ed25519` crate 只做签名
  编解码，X25519 需另行拼装），混两生态无收益。
- ring：非纯 Rust（C/asm），且与既有全 RustCrypto + dalek 栈冲突。

## 影响面

- Cargo.toml workspace deps +2（ed25519-dalek、x25519-dalek，叶子新增：
  curve25519-dalek 4 线无既有依赖共享面，无版本冲突）。
- crates/engine/Cargo.toml +2。
- 性能：Ed25519 签名/验签与 X25519 协商均在亚 ms 级，非热路径（subtle API
  调用粒度），无 bench-gate 敏感面。
