# M2b 依赖选型：AES-CBC / AES-CTR（2026-10-17）

## 需求

webcrypto M2b 补面：crypto.subtle AES-CBC（PKCS#7 padding）与 AES-CTR（128 位大端
计数器）encrypt/decrypt + generateKey/importKey/exportKey 扩展（WPT encrypt_decrypt /
generateKey / import_export 对应子域）。密钥 128/192/256 位、iv/counter 16 字节
（spec：iv≠16 → DataError；CBC padding 非法 → OperationError）。

## 候选

1. **RustCrypto `cbc` 0.1 + `ctr` 0.9 + `aes` 0.8**（选定）
   - `cbc` 提供 Pkcs7 pad/unpad；`ctr` 提供 Ctr128BE（spec 要求全 16 字节大端计数）。
   - 与既有 `aes-gcm` 0.10 同族：`aes-gcm` 0.10 已传递依赖 `aes` 0.8 + `cipher` 0.4，
     `cbc` 0.1 / `ctr` 0.9 同构建于 `cipher` 0.4——**零版本分叉**，显式声明 `aes` 0.8
     只是让传递依赖转正。
   - CBC 解密的 padding 校验由审计过的库实现：不可信密文的 unpad 是信任边界输入校验
     （准则 3），手写易犯 slice 越界 panic 或时序泄漏。
2. 手写 CBC/CTR（复用 `aes` 裸块加密）：~40 行。CTR 简单；但 CBC unpad 须自担
   上述安全面，且与「标准库/已装依赖优先」纪律相悖。HKDF/PBKDF2 手写先例是
   HMAC 薄组合、无 padding 类陷阱，不构成同类理由。
3. `ring` / `aws-lc-rs`：重量级（C/asm 工具链），与 workspace 纯 Rust 零 C 依赖
   路线（媒体解码 M1a 决策）冲突，仅为一组分组模式引入不成比例。

## 结论

workspace Cargo.toml 增 `aes = "0.8"`、`cbc = { version = "0.1", features =
["alloc", "block-padding"] }`、`ctr = "0.9"`；crates/engine 引用。锁文件收敛后
`cbc`/`ctr`/`aes` 均落在 cipher 0.4 族。

## 验证口径

- 引擎桥测试：CBC/CTR 加解密 roundtrip（128/192/256）、坏 padding → 空串（shim 映射
  OperationError）、iv/counter ≠16 → shim DataError。
- WPT 定向：FILTER=encrypt_decrypt / generateKey / import_export 分域比对。
