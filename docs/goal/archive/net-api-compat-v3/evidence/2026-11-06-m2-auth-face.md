# M2（二）：auth 面语义化——fixture 套件落地 + opaque origin cors check 修复

日期：2026-11-06。前置：M1b redirect 批次、M2（一）ws interfaces 批次
（基线 12,990P/1,644F/16T）。

## 一、改动内容

1. **auth fixture 套件**（testharness.rs，上游逐字，pin `315976933870`）：
   - `xhr/resources/authentication.py` + `auth1-11/{auth.py, corsenabled.py,
     corsenabled-no-authorize.py}`：token(X-User) stash 挑战流——无凭据记
     token 后 401 + `WWW-Authenticate: Basic realm="test"`；有凭据回显
     x-challenge DID/DID-NOT + XHR-USER/SES-USER + 体 `user\npass`。
     corsenabled 变体附 CORS 应答（ACAO 回显 + ACAC true + ACAH 按变体）。
     runner flat stash 与上游 per-token dict 形异——X-User 头即天然 per-UA
     键，无跨端点冲突（[[2026-11-06-flat-stash-key-collision-between-endpoint-fixtures]]
     教训先行核对）。
   - `fetch/api/resources/authentication.py`：**固定凭据校验版**（与 xhr 版
     token 挑战流不同源）——Basic user:password → 200 "Authentication done"；
     否则 401 + `WWW-Authenticate: Basic realm="?realm="`（缺省 test）。
     无 CORS 头（authentication-basic 相对 URL 同源取回）。`wpt_status_text`
     补 401 "Unauthorized"。
   - `dump-authorization-header.py` 补上游 OPTIONS 臂：`?strip_auth_header=`
     存在且预检 ACRH 含 authorization → 500 "fail"（跨源重定向后预检不得
     携 auth 头的探测面，无 CORS 头）。
2. **引擎修复（part01.js `_zwFetchApplyFilteredResponse`）**：cors check 按
   spec 步序重写并接收重定向链 opaque origin 标志——
   - https://fetch.spec.whatwg.org/#cors-check ：`*` 通配（步骤 3，非
     include）**先于** origin 比对；步骤 4 以 byte-serializing a **request's
     origin** 为准——跨源重定向链已把 request's origin 置 opaque
    （https://fetch.spec.whatwg.org/#http-redirect-fetch ），序列化为
     `null`，ACAO 须字面 `null` 即匹配。旧实现恒比对文档 origin，
     authentication-redirection 跨源腿（dump 回显 `null`）恒失配 → 误判
     network error。传参点：重定向臂终局 finishFetch 与每跳重定向响应门控
     （后者取先序跳的 opaque 态，与 spec 逐跳 origin 演进一致）。
   - 中间迭代踩坑：opaque 分支先行判 `null` 遮蔽了 `*` 步骤，cors-redirect
     "cors to another cors" 十案回退（preflight.py fixture 缺省 ACAO `*`）。
     修正后按 spec 步序：非 include + `*` 恒过，opaque 仅改比对基准串。
