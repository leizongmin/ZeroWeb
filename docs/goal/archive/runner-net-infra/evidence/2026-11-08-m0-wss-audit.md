## 一、wss 依赖面实数（本地质化）

上游 websockets 语料的 wss 依赖通过三条通道表达，逐条实测：

### 1. constants.sub.js 判定分支（wss 端点寻址的源头）

`websockets/constants.sub.js:4-15`：

```js
if (url_has_flag('h2'))            { __SCHEME='wss'; __PORT="{{ports[h2][0]}}"; }
else if (url_has_variant('wss') || location.protocol === 'https:')
                                   { __SCHEME='wss'; __PORT="{{ports[wss][0]}}"; }
else                               { __SCHEME='ws';  __PORT="{{ports[ws][0]}}"; }
```

三个 token 由 runner `apply_wpt_substitutions`（testharness.rs:5470-5472）替换——
**现状 ws/wss/h2 三 token 全映射到同一个明文 fixture 端口**（wss/h2 分支「落未走
分支」仅对不枚举变体的通道成立）。

### 2. `.html` 案 wss 变体（`<meta name="variant">` 声明）

实测（含顶层）：**41 文件 / 41 个 wss 变体实例**：

| 形态 | 实例数 | 目录分布 |
|---|---:|---|
| `?wss` | 34 | constructor 18 / binary 4 / opening-handshake 5 / closing-handshake 3 / security 2 / keeping-connection-open 1 / extended-payload-length（顶层）1 |
| `?wss&wpt_flags=https` | 7 | cookies/001-007 全数 |
| `?wpt_flags=h2`（排除） | 32 | 同目录分布 |

cookies/001-007 无裸 `?wss` 变体——其 wss 变体一律叠加 `wpt_flags=https`
（上游语义 = 页面走 https 锚交付；`document.cookie` Secure/SameSite 判据面），
即 **cookies wss 面同时依赖页锚 https**。

`?default` 变体（41 个实例）与基础 URL（无 query）行为等价
（`url_has_variant('wss')` 对无 query 返回 false → ws 分支）——通道现状
「基础 URL 单跑」已是 default 账。

### 3. 顶层 `.any.js` 案 wss 变体（`// META: variant=` 声明）

实测：**61 文件声明 `// META: variant=?wss`**（60 文件同时有 `?default`、
60 文件同时有 `?wpt_flags=h2`）。Close-*/Open-*/Send-*/Create-* 族主体在此。
注意 [`case_variants`]（testharness.rs:1961）**只解析 `<meta name="variant">`
标签，不解析 `// META: variant=` 注释**——.any.js 通道（run_any_js_window_case）
即使开变体枚举也提不出这些 query，扩面需补 META 注释解析臂。

### 4. `.https.` 命名案（页锚 secure-context 面）

全语料仅 2 文件：

| 文件 | 依赖面 | 现状 |
|---|---|---|
| websockets/mixed-content.https.any.js | https 页锚 + `CreateInsecureWebSocket()`（硬编码 `ws://` :ws 端口）断言 secure context 下明文 WS 连接**必失败** | skip 规则筛减（testharness.rs:4620）；解锁需 https 页锚 + 引擎 mixed-content ws:// 阻断语义（后者是引擎缺口，通过与否如实落账） |
| websockets/cookies/third-party-cookie-accepted.https.html | https 页锚 + `WSS_CROSS_SITE_ORIGIN`（wss 跨站）+ SameSite cookie 语义；**依赖 `cookies/support/websocket-cookies-helper.sub.js` 本地缺失**（需补拉） | skip 规则筛减；语料缺口单列，不冒充可解锁 |

### 5. 不受 wss 影响的面（零回归边界）

- **websockets/interfaces 74 案**：零 variant 声明、零 `.https.` 命名——连接全走
  default ws 分支（43 号交接档第三节已核），wss 解锁不动其分母。
- **通道现状账**：107 文件 377P/0F（43 号 M0 实测），全部经 ws 明文分支。

## 三、通道 scheme/端点寻址设计（M1/M2 实施蓝图）

**决策原则**：只动 fixture 管道与寻址，不改 `default_net_ws_host`/fetch_bridge
真栈语义（划界）；通道既有账（websockets 377P 面 + net-api 13,275P 面）A/B 零回归。

### D1 TLS 端点（M1）

- `ws_fixture.rs` 增设**第二条监听** `fixture_wss_port()`——独立端口对齐上游
  wptserve `{{ports[ws][0]}}` 与 `{{ports[wss][0]}}` 是两个监听的形态；同一
  `KNOWN_PATHS`/握手/帧/数据相 handler 复用（泛化 IO 层，明文/TLS 双流型）。
- 证书：进程内运行期生成自签证书（rcgen，SAN = DNS `localhost`/`wpt.test`/
  `*.wpt.test` + IP `127.0.0.1`），**仅驻内存，不落盘不入库**（划界「自签证书
  不出仓」）。
- 服务端 TLS 栈：rustls `ServerConnection`（workspace 锁定 rustls 0.23.46 +
  ring 0.17.14，与 tungstenite 同栈，零新增密码学后端）。

### D2 客户端信任旁路（M1）

- zero-net `websocket` 增进程级信任源覆盖钩子：未设置时保持
  `tungstenite::connect` 现路径**逐字节不变**（生产 webpki-roots 语义零变化）；
  设置后走 `tungstenite::client(request, Some(Connector::Rustls(cfg)))`。
- runner 侧在 fixture 启动时注入「仅 fixture 自签 CA」为信任根的 ClientConfig
  ——runner WS 宿主的 wss 面只信任 fixture 端点（比全局信任更收紧，防旁路
  外溢）；产品代码不设钩子，TLS 语义按「runner 测试环境旁路」处理（划界）。
- wss 端到端连通单测落 wpt-runner（fixture 起 TLS 端点 → `default_net_ws_host`
  真栈连 `wss://wpt.test:<port>/echo` → text echo 往返）。

### D3 token 映射（M2）

`{{ports[wss][0]}}` → `fixture_wss_port()`；`{{ports[ws][0]}}` 不动；
`{{ports[h2][0]}}` 维持现状映射（token 只落排除分支，改不改无观察面，保持
最小改动）。token 现值只落未走分支，改映射对通道既有账零观察面（A/B 兜底）。

### D4 变体枚举（M2）——最小分母方案

- net-api 通道对 **websockets 子树**开变体枚举（其余 corpus 分母不动）：
  - `.html` 案：枚举 `?wss` / `?wss&wpt_flags=https`；**跳过 `?default`**
    （基础 URL 单跑已是 default 账，避免子测试双计）与 `?wpt_flags=h2`
    （`.h2.` 排除口径延伸：runner 无 HTTP/2 WS 栈，32 实例排除记账）。
  - `.any.js` 案：`case_variants` 补 `// META: variant=` 注释解析臂
    （仅 net-api 通道 websockets 路径消费），枚举 `?wss`；`?default`/h2 同上
    处理（60 个 h2 实例排除记账）。
- 枚举池实数：**102 wss 变体案**（41 html + 61 any.js）。
- D5 页锚 scheme：variant 含 `wpt_flags=https`（cookies/001-007 七案）→
  页锚 `https://wpt.test`（secure-context 面，`document.cookie` Secure/SameSite
  判据前提）；裸 `?wss` 维持 http 页锚（上游 `?wss` 变体即 http 页 + wss 连接，
  非混合内容阻断面）。mixed-content.https.any.js 与
  third-party-cookie-accepted.https.html 的解锁在 G6 逐案重估（前者并记引擎
  mixed-content 缺口，后者并记语料 helper 缺口），不并入 102 池承诺。

### D6 零回归与复验面（DC-2/DC-4）

- 明文 ws 面：`{{ports[ws][0]}}`/KNOWN_PATHS/帧编解码不动，websockets 既有
  377P 面逐 subtest A/B。
- net-api 全通道：13,275P 面 A/B（枚举只增 websockets 变体案，不改既有案键）。
- 43 号非 wss 面基线零回归（依赖约束第 2 条：ws_host_factory 通道级隔离不变）。
