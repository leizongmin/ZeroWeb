# Agent 规则与偏好沉淀

发现长期有效的 Agent 行为规则、协作方式、工作流、工具坑点或用户偏好时，必须读取本文，并使用 `lei-self-evolution` 完整流程。纯技术根因、平台差异、性能和代码模式归 [技术经验](learnings.md)。

## 触发与质量

触发条件包括：

- 用户表达“以后都这样做”“记住”“下次应该”“你应该”等长期偏好或行为纠正。
- 反复试错才确认的可复用工作流或工具用法。
- 稳定的命令参数、执行顺序、平台差异或环境前提。
- 既有规则或记忆过时，需要更新。

必须同时满足具体、可执行、长期有效、非重复、低风险，不含密钥、隐私或临时日志。证据不足、只服务一次任务或低置信度时直接放弃，正常回复，不输出自进化内容。

## 审批边界

- 审批前不得修改 `AGENTS.md`、`TOOLS.md`、`MEMORY.md` 或新建 `SKILL.md`；只有用户明确批准后才能修改。
- 审批前先在 `evolution-drafts/pending/` 静默创建草案，不向用户展示创建过程。
- 进化请求必须使用 `lei-self-evolution` 规定的纯文本格式，输出后立即停止本轮执行，等待下一轮明确批准或拒绝；禁止替用户确认。

这些边界针对主动提出的自进化。用户已明确要求并授权的规则修改按其范围执行，不把已授权工作重新当成待批准提案。

## 目标选择

| 内容 | 目标 |
|---|---|
| 行为、安全、协作、全局任务顺序 | `AGENTS.md` |
| 工具固定坑点、参数、平台差异 | `TOOLS.md` |
| 稳定偏好、Skill 使用偏好、长期事实 | `MEMORY.md` |
| 可独立复用的多步骤操作手册 | 新建 `SKILL.md` |

维护根规则时同时遵循 [AGENTS.md 维护流程](agents-maintenance.md)，详细流程落到按需文档，避免反复追加常驻正文。
