# AGENTS.md 维护与精简

创建、合并、修改或精简根规则时必须读取本文。只审阅时交付建议；用户已授权修改时完成范围内整理，不自动启动多轮优化、安装工具或改变项目约定。

## 内容归属

`AGENTS.md` 保留影响日常决策的项目事实、必要命令、常驻约束，以及条件性流程的触发条件、授权边界和读取入口。详细步骤、示例、恢复与证据格式优先放到已有项目文档或 Skill 参考；无合适位置时使用 `docs/engineering/`。

流程入口写清“何时 → 必须读取哪份文件 → 做什么”，使用项目内普通相对 Markdown 链接，不自动导入全文。拆文件不代表宿主一定节省上下文；目录专属规则须确认加载范围后才能下放。项目规则独立可用，不依赖全局 Skill 安装路径。

## 维护步骤

1. 读取根规则、相关引用和已加载规则，核对来源、范围与实际命令；只处理本次影响，明确全文件精简时才检查全文。保留修改前基线与可复核差异，不重置用户改动。
2. 新内容先按条件和动作查重：已有覆盖则不写，部分覆盖合并原条目；细节更新原参考，不在根文末尾再追加完整流程。无有效变化保持文件与时间不变。
3. 搬移前核对条件、动作、强度、例外、授权、安全、成功判据和失败处理。先落地详细内容，再替换根文，保留能触发读取的短规则。来源不明或疑似过时内容不因太长删除，保留并说明疑点。
4. 检查根文和引用中的重复、矛盾、失效路径和未完成迁移；不把多行压成一个长段落冒充精简。
5. 同步生成模板、fallback、相关语言版本及实际维护入口，避免下一轮重新展开。源文件不在授权范围时报告缺口，不跨项目修改。本仓 `CLAUDE.md`、`.cursorrules`、`.github/copilot-instructions.md` 是相对 symlink，沿用；文档 cronjob 应遵循本流程。

合并编码准则时保留事实与假设的区分、已授权可逆选择的自主执行、额外建议的确认条件，以及测试对真实行为的验证要求。写作规则保留写作前主动应用可用 `lei-humanizer`、专用写作流程同样适用和技能缺失时的独立原则；已有同义内容合并原条目，不重复追加。根规则已定义这些原则，本流程只核对，不另存正文副本。

精简可以合并和搬移表达，不能取消有效要求、引入新制度或改变原授权。knowledge 和 verify 独立检测；存在入口只授权按需读取，不代表已采用提交前维护或已运行验证。网站任务双审查沿用其原流程，不能扩大为所有本地提交门禁。

## 验证与交付

检查相对链接可读取，原要求有对应落点，条件性引用有明确读取时机。统计根正文与新增/搬移参考的字节或字符，分别说明常驻正文与总体内容变化；不以固定行数或压缩率作门禁。

较大调整检查代表性场景：只读任务不加载维护手册；已有资产能找到详细流程；无资产按原规则跳过；新增同义规则不改文件；新增细节只更新对应参考；拒绝、失败与安全边界不遗漏。能力允许时在隔离目录检查真实产物、引用和副作用；未实测宿主加载如实注明，静态核对不证明行为无损或性能改善。

交付说明保留、合并、搬移和删除的依据，规模、引用/语义/场景检查及未验证项；完整迁移记录放交付说明，不写回根规则。若要评估要求是否无用或删除是否改善行为，使用 `lei-skill-creator` 的有效性评估，不从篇幅推断。
